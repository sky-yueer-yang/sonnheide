# 完整施工计划：先完成可编辑的三维像素世界，再接原创城市与完整社会

2026-10-08。当前顺序为 **11阶段（0—10）**，按[ADR 0012](../decisions/0012-editable-3d-pixel-world.md)和[v0.7设计](../design/Sonnheide_Design_v0.7_Pixel_World.md)重构。先完成原生主页面、Blank/Earth创建、真正360°三维像素地表、底栏与地形编辑、完整保存载入；基础体验验收后，阶段3立即开始正式原创建筑、块状人物和服装作者源/代表件。阶段0提前锁定这些资产的尺寸、接口、许可和预算，避免地表完成后才发现人物尺度或房屋入口不成立。每阶段3—5个中尺度工作包；阶段是结果与因果门槛，没有实际团队/设备/工作量依据前不虚构周历。

本计划只规定后续工程，不把本轮文档修订算作功能实现。[WorldBox研究与采纳矩阵](../research/WORLDBOX_PIXEL_REFACTOR.md)区分官方事实与本项目决策；[地形事务](../architecture/PIXEL_TERRAIN_TRANSACTIONS.md)、[像素渲染/资产](../architecture/PIXEL_RENDERING_AND_ASSETS.md)、[应用流程](../architecture/APPLICATION_FLOW.md)和[程序结构](../architecture/CLIENT_STRUCTURE.md)是接口依据。旧[阶段1验收](PHASE1_ACCEPTANCE.md)记录写实平陆/PBR/Hex/天空/静态远海及首存档的legacy证据，**不是新版像素阶段1或2已经完成**。原始v0.6逐字保存，旧规则由显式决策覆盖，不删历史来源和Release。

## 1. 先突破的因果链

新的关键链是“可追溯来源与profile→同一量化候选→有效高度/面层/水域拓扑→真正三维表面/拾取→可编辑事务→安全发布存载→建筑和居民也服从相同地表”。只将旧画面换像素滤镜，或者做完空世界后才研究有人的地形修改，都不足以完成重构。

|不可后补的边界|必须提前证明的事实|后续接入|
|---|---|---|
|同一地表|预览、World、碰撞/拾取、水深、导航、建址读相同量化revision；贴图texel不是地形格|阶段1列地形成立，阶段2事务与派生发布，阶段3—4生产接入|
|两种创建|Blank与Earth只在来源准备不同；量化、拓扑、最高预览、首checkpoint和发布相同|没有Blank/Earth两份核心，也不从现实地图生成居民城市|
|神力因果|一格海峡会影响远港；编辑提交同时使不再成立的通路/运营失效，并结算人货任务|阶段2先做OccupiedTerrainAdapter和占用fixture，阶段4接真实居民城市|
|强异常与身份|准备阶段不改当前世界；任何失败没有半写人、库存、账本、地形或continue指针|草案/异步mesh/路径结果不能替代单写者决定|
|原创高分辨率人物|块状几何、精细像素贴图、骨架、fit/衣层/入口净空分别有预算|早期锁合同，基础通过后正式制作，不使用MakeHuman新生产管线|
|神力与工程不同|Godterrain可改变有效地面且有后果；文明填海/地基仍有真实成本|Port看实际支承水深路线；来源标签不等于免费物料或运营资格|

地形格、建筑构件、导航净空和人物贴图是不同尺度。起始profile为**2m格、0.5m高度量化、64×64格chunk**，待样本测量准入；选定profile在单个World创建后冻结。有效地形可变，初始来源证明、创建参数、量化规格不可偷偷改写。所有列高、实体、工程面与运动使用同一游戏米，XYZ不独立拉伸；Earth现实X/Z按冻结水平比例导入，派生游戏Y明确不是真实海拔。首版水位0，低于水位均为湿格，四连通到有限外海源为SEA、其余为LAKE；不做洞穴、悬空自然陆块、高位湖、瀑布、体积流体或潮汐侵蚀。

### 基础体验必须通过的六条故事

1. 原生启动→已批准主页面→切英汉德→Blank草案/预览/取消→Earth可用区域/来源预览→两入口各确认成0人0楼；三维旋转、顶面立面、选中格和水深一致。
2. 在Blank造岛、丘陵山峰、湖与海峡，在Earth改有效地形；沙/土仅换材质与造陆模式区别清晰；切相机不改变仿真，外沿拒绝/预算拒绝，最高预览与发布算法一致。
3. 地形笔画预览取消、保护跳过、破坏批准/拒绝、采样/复制、有限撤销；用OccupiedTerrainAdapter fixture证明有居民/库存/楼/港时原子后果、远港拓扑更新和强异常保证。
4. Light/Darkness手动→auto/改时长→暂停/保存→返回→载入，同WorldId/terrain revision/来源hash/时钟/环境余量；同tick竞态与跨多个deadline加速对照，不使用墙钟或天体周期。
5. 保持当前World创建/加载另一World：缺源、坏档、超预算、迟到、取消均保旧World/profile/好存档，成功只换一次；反复循环后候选/GPU/身份/旧ref无残留。
6. 三语主页面/创建/底栏/参数/保存/错误、IME/DPI/focus/modal地图捕获和降低动态真实可用；草案不静默丢，字段不暴露实现术语，未知统计不假零。

### 基础体验不要求一次做完的范围

- 不要求40信息页/251关系、35法全文、完整经济宗教战争、全部生态生长或10000人口；但编辑后果adapter的真实结构fixture不能推到阶段4以后。
- 不要求完整全球可创建覆盖、真实DEM/海底测量、全部Steam设备发行；Earth首批已准入区域先通过，覆盖/精度单独披露。Blank不依赖这些数据。
- 不要求建筑/人物/服装正式作者源或完整动态水/完整Abyssal原生FFT；UI、地表像素纹理/天空/水、菜单等基础视觉可以先做，资产合同阶段0必须有。

## 15. 共同完成定义与统一批次验证

每项“真实输入→可信命令→单写者事务→真实领域结果→三语反馈/关联页→只读动画→保存/失败恢复→来源与不变量证据”才标implemented/verified；CPU fixture、网页prototype、原生GPU、实际城市和Steam设备范围分别写明。创建/加载还要证明旧World保护与成功一次发布。新文件和目录必须有内容与调用边界，不以目录数量代替进展。

**本轮仅设计。** 没有因此实现新三维像素地形/人物、Godterrain、全存载迁移或实际城市；旧有限实现和旧阶段1全部保留为有范围的legacy证据。旧“已经接入阶段1”与“本轮尚未实现创建世界”的混杂叙述在本计划中改成旧功能/新目标分别说明，不虚构旧实现消失或新功能已完成。

每一实施批次先完成所有模块修改、依赖同步、合同与资源审查，再统一编译全部目标并跑完整CTest；改核心按`python3 tools/build.py`，改事务/空间/存档再sanitizer，改目录/资产再重建并运行`tools/validate_project.py`。有失败先修复后统一复验，不每改一小文件重复全构建。仅文档本轮检查链接/机器合同/阶段与版本一致性，不声称已完成GPU或游戏行为测试。
