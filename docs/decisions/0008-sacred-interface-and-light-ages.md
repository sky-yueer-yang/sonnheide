# ADR 0008 · 深沉油画界面与光明/黑暗两种环境

日期：2026-10-07。状态：采纳用户视觉与环境要求；视觉按钮与品牌布局已按最新[ADR 0009](0009-monumental-minimal-interface.md)修正。补充[ADR 0006](0006-bottom-toolbar-trilingual-editing.md)的全域前端规范和[ADR 0007](0007-foundation-experience-first.md)的基础体验门槛。原始设计源逐字保留；其中旧昼夜/太阳运转描述不覆盖本决策。

## 1. 油画主页面与统一前端美感

主页面使用用户提供油画逐幅展示；最新ADR 0009只放开小范围中央亮焦点，大部分画面连续渐暗、边缘更深，覆盖上一版大范围明亮中心；原画字节不改，不用统一半亮度滤镜。纪念性极简新古典构图、金色与未来感留白保留；Sonnreich原创Logo品牌中心左上向内，结构为完整多圈内环/无射线空白环带/2—3道边外圈/仅从外圈发出的密集粗细长短射线，远端可越屏裁切；整组以该中心为锚点固定轻微顺时针倾斜，柔光静止。SONNHEIDE右移，主页字号较上一轮略小，右下纯文字菜单紧凑右对齐；主页文字/射线/光晕统一#fff6df、亮且带柔和静态光，不画按钮ring。庄严由构图、字形与暗边表达，不给动作加宗教图标或细碎小字，不生成宗教实体或绑定官方宗教。

每幅油画极缓慢、小幅度平移/缩放，前后画在同一屏幕渐变下交叠淡化，仅小中央焦点保留亮部、大部分渐暗，不闪白、不黑场切页或双层暗化。原型初值：停留68秒、交叠12秒、约120秒的位移轨迹；总位移不超过画面1%、缩放变化不超过2%。这些是表现调参值，不是仿真计时。画作装载失败保持上一张或深色静态兜底，不出现破图；按屏幕比例裁切并保留审阅的主体安全区。应用不因后台休眠补播整段轮播。降低动态时关闭持续移动与自动切画，保留静态油画和正常菜单。

油画背景属于应用表现，**主菜单小亮焦点/大部分渐暗的构图不受World的Light/Darkness影响**；不把中央亮部扩大成高亮背景。用户提供文件需记录原文件hash、使用来源和允许的托管范围；不得擅自标为CC0或给用户原创/提供内容附开源许可。派生预览与原始文件的关系进入manifest，个人Downloads路径不成为发布依赖。

**所有按钮禁止边框；禁止不必要的小字。** 最新ADR 0009已取消“所有按钮必须含图标”：主菜单必须纯文字、无图标，其他文字按钮也可以不带图标；图标仅用于确实帮助识别的功能。无边框覆盖主页面、创建、弹窗、底栏、Inspector、保存恢复、列表动作、语言切换及错误页，不允许用outline/focus ring绕过。分隔线不能围成按钮边界。悬停/选中/键盘焦点通过背景或文字明暗、字重表达，功能图标可有亮度变化；不用持续闪烁。Tab/方向键、触摸和键盘仍可完成全部动作。

功能图标保留简体中文/English/Deutsch的tooltip与accessible name；不可用动作在对应操作提供清楚原因，不能只降透明度。危险确认、错误、来源、选区与参数保留必要信息并使用正常可读字号；不常驻原型/技术小字或装饰性标签。界面有稳定可读对比，背景压暗独立于文字；世界渲染的暗环境不能压黑UI。公司Logo与放射线始终静止，油画计时与环境计时不驱动品牌动画。

## 2. 仅有两种环境，保留正常日历

世界环境只有 **Age of Light（光明纪元 / Zeitalter des Lichts）** 与 **Age of Darkness（黑暗纪元 / Zeitalter der Dunkelheit）**：前者天亮，后者天暗，合法可用的灯具可以点亮。它们是全世界统一环境状态，与上古/近代/工业等科技时代、人物年龄和宗教状态分别建模。Light不代表新增科技时代，Darkness不改变国民信仰。

不做日出/日落轨迹、逐日昼夜、自转、公转、季节太阳高度、月相或天文时间求解。仍保留唯一SimTick、TimeConfig与日/月/年，人物年龄、生产、税、工期照旧推进。“游戏日”继续是模拟时间单位，不自动产生一次太阳循环。

默认新世界为Light、手动模式，自动交替关闭。玩家可手动选择任一环境；手动选择**原子关闭自动模式**。可另外开启自动交替，并配置两种环境各自的有界整数游戏日时长；调参初值均为30游戏日，允许1—3600游戏日，尚非平衡结论。开启自动或修改时长从当前环境重新计满一个时段，不立刻跳到另一环境；关闭自动保留当前明暗，再次开启重新计满。

环境和自动规则通过单写者World事务生效、进入历史与存档；相机、locale、画质、菜单动画、主机真实时间不能推进交替。暂停冻结余量，加速依然处理真实到期边界；加载不补算离线时间。手动命令、配置编辑与到期任务用schedule generation去除竞态，细节见[LIGHT_AGES](../architecture/LIGHT_AGES.md)。

## 3. 灯光有真实对象边界

Darkness表达“天暗+可用灯具开灯”，不凭空生成灯、建筑、燃料、资金、供电或可用劳工。阶段0—2空世界只验证两种环境与控制/存载；没有灯具就不显示假城市灯。阶段3给原创设施制作发光部件与受限局部灯；阶段4起与实际采用的灯具/能源能力接入。无供给模型的表现试灯仅开发场景，不宣称真实生产供电。

已有太阳能交通技术合同继续有效；后续涉及环境的能力必须明确读Light/Darkness，不能把天暗后的视觉补光当真实太阳供给。具体能量接口尚待相应业务设计，不在本ADR扩展新电网或强制新增车辆燃料玩法。生育、衰老、饥饿、战争、劳动和宗教后果不因名称或漂亮画面自动改规则。

## 4. 工程顺序与验收边界

阶段0制作油画/静态公司Logo主页面、来源manifest、无边框纯文字/功能图标组件，落实无不必要小字、三语/焦点/降低动态。阶段1真实空世界提供两个固定环境profile与初始Light元数据。阶段2接入手动/自动/时长/到期规则、完整存载往返、旧档迁移和暂停/加速因果验收；通过后再制作建筑、人物与灯具。阶段3—4接入真实灯具表现和其已定义的可用性。

静态截图不能证明轮播运动、键盘焦点或自动交替正确；网页原型不能证明原生GPU或生产存档已实现。必须区分浏览器呈现、独立规则验证和正式World接入，具体证据在[VALIDATION](../planning/VALIDATION.md)记录。
