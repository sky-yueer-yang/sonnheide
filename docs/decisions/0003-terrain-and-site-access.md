# ADR 0003 · 真实高程、长方体地基与受保护的建筑接入

日期：2026-10-06。状态：**部分被 [ADR 0010 · 统一平坦陆地与海岸过渡](0010-flat-land-and-coastal-transition.md) 替代（2026-10-07）**。以下正文保留当时的决定与证据，不再作为当前真实高程、全球 DEM/DTM、XYZ 高程缩放、普遍长方体地基或内陆坡道的实施依据。

最新决定只使用真实全球海陆与岸线：内陆统一略高于静水面，只有海岸窄带逐渐下降至水面并在水下延续；普通内陆建筑不增加找平地基，沿海建筑有需要才采用局部地基。当前生产合同以 [地形与建址](../architecture/TERRAIN_AND_SITES.md) 和 ADR 0010 为准。下文涉及 ETOPO、垂直基准和坡地数学的部分仅为历史记录；已有 `TerrainGrid`/site oracle 尚未改造成新方案。

本 ADR 中的指定 Abyssal 水体、冻结天然水陆、逐格有材料劳动填海、Port 的 RECLAIMED 核心/WATER 泊位、联合建址批准、前侧真实配送、入口与车库通道、邻楼保护和铁丝网施工规则继续有效。移除真实高程不免除这些约束，也不授权海上地基冒充陆地。原始设计 v0.6 不变。

## 历史正文

## 1. 替换的旧决定

用户现在要求真实地表起伏和真实高度，并指定采用 [Abyssal Ocean](https://github.com/squall01337/abyssal-ocean) 的水体代码。房屋在建设时同时建造长方体地基，使全楼立在同一绝对标高的平面上；人必须能从地面走进入口，有车库时车辆必须能从地面开入。后建邻楼不得破坏已批准的接入。

因此覆盖原稿及旧工程文档中的以下约束：统一平坦陆地、没有高度场/坡度、没有高山、导航删除坡度成本、只缩放 X/Z 而高度保持独立基准，以及拒绝 FFT 水体作为选定方案。用户原稿仍逐字保留，原稿生成目录仍是源材料；新世界和生产定义必须显式应用本 ADR。

保留以下边界：不用游戏引擎；框架与建筑几何自行制作；天然水陆、真实岸线、世界尺度与天然高程在创建世界后冻结；没有抬高、压低、挖掘或平整天然地形的编辑器。地基不是天然地形笔刷。造陆仍逐格、四邻接、实际材料和劳动、完工才是 LAND；Port 仍要求 RECLAIMED 核心与合法 WATER 泊位。出现坡地不自动新增随机灾害、复杂气候或完整土力学。

## 2. 指定水体与全球高程基底

水体采用 Abyssal 的开放算法与 shader 作为 native 移植来源，固定原始源码、MIT 许可、提交和文件哈希。当前锁定记录是 [UPSTREAM.json](../../third_party/abyssal-ocean/UPSTREAM.json)，提交 `142265f5013b6f27bea4f4f819b832dec75c7bad`。原始浏览器版本使用 WebGL2/three.js；生产客户端将算法移植到既定 C++20/SDL3/bgfx 图形架构，不引入浏览器运行时或完整游戏引擎。当前 CPU FFT 参考不等于 native GPU 水体已经完成。频谱位移、泡沫和折射仅负责表现，不修改水陆、港口、航道或人物可站立事实。

全球高程基底选择 NOAA [ETOPO 2022 v1](https://www.ncei.noaa.gov/products/etopo-global-relief-model) 15 arc-second Ice Surface，WGS84 经纬与 EGM2008 正高，单位米；官方许可证据以 [原始 metadata](../../data/geo/sources/etopo2022_noaa_metadata.xml) 保留。当前实际取入的是阿尔卑斯约 45.9°N、7.0°E 的 **25×25 个原始像元中心**，并保留解码它们所需的原始 TIFF byte ranges、哈希与导入配方，见 [样本](../../data/geo/etopo2022_alps_sample.json) 与 [原字节窗口](../../data/geo/sources/etopo2022_n60e000_tile201.json)。没有声称已下载或生成全球游戏世界。更细的开放区域 DTM、其他 DEM/DSM 的地表含义与基准转换另行核验；粗网格插值不能制造真实的房屋尺度精度。

天然 LAND/WATER 来自独立冻结的岸线/水陆管线。不得用高程正负号判断海陆；低于海平面的陆地、湖面、岸线误差和数据缺口必须分别处理。不得默默将所有负高程陆地压到零。

## 3. 尺度与不可变事实

新世界采用相同的 `worldScale` 缩放投影 X/Z 与正高 Y：

```text
gameX = worldScale × projectedX
gameZ = worldScale × projectedZ
gameY = worldScale × (orthometricHeight − verticalOrigin)
```

投影与尺度共同决定地表几何；`verticalOrigin` 只作固定坐标平移，不是垂直夸张。人物、车辆与自制建筑仍保持游戏米制尺寸。创建时记录源分辨率、水平投影畸变、统一尺度与转换误差；不得通过未声明的 heightScale 把压缩的地图拉成不真实陡坡。大范围局部投影并非地球处处无畸变，创建器须沿用投影有效域与精度报告。

保存冻结高程结果、地表三角化/采样规则、垂直基准、源/配方哈希、天然水陆哈希和尺度。旧平地存档保留原世界 profile；升级数据源不重解释现有楼板、道路或城市。若要转成真实地形，必须有显式迁移/新世界，不能直接给旧楼脚下加山。

## 4. 建址作为一次完整批准

`SitePlan` 同时包含主体 footprint、长方体地基、每个必需入口的永久接入、地面卸料区及到货/退出路径、等待/转弯空间、施工网罩范围和所需物权/通行权。预览不预约；批准事务校验全部关联版本、实体、几何和权利后一次预约，失败不留下部分地基或部分禁建区。

地基顶面 `H` 不低于整个 footprint 上的最大冻结高程加楼板间距；底面 `B` 不高于最小冻结高程减埋入量。主体所有楼板、门、车库 socket 使用该实例标高，不随各自脚下地形漂移。最大外露高度、用地、基础与接入成本均受定义和预算约束。换外观不能改变平台、入口、空间和接入证书。

只证明地基合法不足以开工。必须证明从合法地面/道路接点到每个必需入口存在符合相应运动 profile 的完整通道。人行与车辆分别验证，不能用人能爬台阶证明车可入库；车辆不能只查二维 ROAD 连通或中心线坡度。无解时显示具体阻碍，允许旋转、移动、换合法接点或扩大有权使用的通道，不自动削山、借邻地或创造电梯。

## 5. 邻楼不得破坏现有通道

每栋批准建筑保存入口接入证书以及所依赖的有限通道保护域。后续建筑的主体、地基、接入构件、卸料区和临时网罩/工地不得侵入旧通道净空，也不得通过普通建楼事务移动公共道路标高或门口接点。

首个 oracle 保守保护这些空间的二维投影，不允许上下叠建；它可以拒绝某些几何上可能成立的立体方案，但不能放行会破坏旧路的方案。同一项目的人/车可使用完全相同矩形、同一 portal 和同一方向的接入表面，分别通过各自 profile；跨项目共享通道需要明确兼容表面与许可，当前 oracle 不实现跨项目共享。不能因两个坡道在地图上接触就自动互认通行权。

需要改路时先验证、预约有效替代路径，再由同一事务切换证书并释放旧路径。任何失败保留旧通道。此项保证指合法后续项目不能破坏已登记接入，并非承诺有限地块能容纳任意数量、任意位置的房屋，也不排除战争、事故以外已有规则允许的封锁与交通等待。

## 6. 与材料配送和铁丝网的关系

沿用 [ADR 0002](0002-building-construction.md)。材料由人物实际送达前侧；地基及房屋专用接入构件纳入该 Building 项目的配方和自动工期，没有人物现场砌筑劳动。外部公共道路/桥梁项目仍按其独立规则施工；不能以私家坡道名义免掉公共道路成本。

到货阶段的接货点必须在当前已存在的合法可达地面、网罩之外；未来平台/坡道不能被当作已完成的送货路线。项目显式绑定建筑前向、地面 delivery socket 与对应前侧网罩边；apron 必须沿这条边以正宽度触达接货接口，不能仅在远端道路上放一个合法 apron。人物退出后才封网。网罩覆盖同一项目中的建筑、地基和接入构件，使用合法的联合施工范围；范围可以由有界矩形罩组件组成，不为一个远端坡道生成侵入邻地的大包围盒。坡地底沿不得悬空露出可钻入的工地缝隙。

网罩逐层围起、包围、反向撤去只读工程快照。完工事务原子启用地基顶、永久接入面、入口和建筑功能；完成首帧让所有已开放通道处网片让行，不等动画结束。动画不能支付基础材料、修改天然高程或决定可达性。

## 7. 当前证据与下一步门槛

本轮以有限 C++ oracle 验证网格对齐地基、四向直线 C1 坡道、完整宽度上的地形穿入检查、真实现状地面配送和原子空间预约；接口为 [site.hpp](../../engine/include/sonnheide/site.hpp)，场景检查为 [site_tests.cpp](../../tests/site_tests.cpp)。它只接收可信的平地 `RoadPortal`/已有网络 ID，不证明该 ID 背后的全游戏交通网络。生产曲线转弯、台阶、复杂道路、共享权利、真实物流、存档迁移及 GPU 近景尚需接入。

prototype 当前只批准方案与保守保护域，没有配送/施工/完工阶段的 release API，临时配送和网罩范围也持续保留。上述完工启用入口与释放暂占是生产合同，不是已经接入的行为；将它与现有填海、完整 Building 任务、存档和多领域 world 合成仍是后续工程。

进入可玩切片前必须跑通：真实区域数据→冻结地形与水陆→原创坡地房屋/车库→地面到货→围网→自动地基/接入/主体完成→人物入门/车辆入库→邻楼批准或拒绝→存档往返。不能用开源水 demo、人工平坡或单独漂亮地基截图代替这条闭环。
