# ADR 0007 · 先完成启动、创建世界、初始地表与基础界面

## 决策

1. 第一目标是能实际使用的原生基础体验：启动→主菜单→创建世界→进入真实初始地表→基础游戏操作→保存/载入→返回主菜单。它通过验收以后，才开始新建筑、人物、服装及其他玩法资产的作者源制作与业务接入。现有灰盒和已核验资源保留，不删除既有成果。
2. 前三阶段固定为：0原生应用/主菜单；1创建世界/固定真实初始地表；2基础游戏界面/存档往返与失败恢复。阶段2退出是建筑工作的硬前置，不只是按钮或截图已经存在。之后阶段3做原创代表件与建址，阶段4做生活贯穿，其余领域顺延。
3. 基础体验先完成自己的视觉质量：主页面布局、三语字体/输入、底部工具栏、相机、统一陆台、真实岸线和水面/水边过渡。界面和地表必需的图标/材质允许制作；楼体、人物服装、军装与交通资产此前只整理尺寸合同、许可和技术约束，不以“并行准备”提前开始制作。
4. 创建世界只选择已取得许可、固定hash并通过覆盖/陆海/岸线精度校验的海陆数据包及其有效区域。世界发布前确定水平地图尺度与游戏米制的陆台/岸坡profile；发布后天然mask/岸线/worldScale/profile冻结。seed不随机改水陆；岸坡不随填海重算。ETOPO/DEM不再是创建依赖；完整全球可选海陆覆盖另有后续交付门槛。
5. 首个正式入口创建人口0、建筑0、没有自动文明的空世界。地表可观察、工具可找到、没有对象时有明确空态；未接入的放人/建设/经济/制度动作显示真实依赖，不假提交。原有18岁玩家放置和0岁合法出生在后续生活阶段接入。
6. 新建/加载使用隔离候选World。地理、定义、引用、内存/资源预算和首存档校验完成后，才原子发布新会话；失败/取消不破坏已有世界或继续游戏指针。WorldId与SessionGeneration共同隔离异步结果；个人视图与世界存档分别归属，不把前一个世界的对象、收藏或草稿串入新世界。
7. 主菜单提供新建、继续、加载、英汉德设置和退出。游戏内全局入口仍在底栏；返回主菜单遵循保存/未保存与草稿处理。新建取消、加载坏档、缺数据包、保存失败、重复进入退出都必须给可恢复的结果，不让玩家陷入半创建或空白窗口。

## 验收门槛与实现边界

一台真实设备上，从干净启动完成至少一个已校验真实海陆区域的空世界创建；能观察统一陆台/水边过渡/水陆、操作镜头与三语底栏、保存退出并加载相同冻结岸线/profile。再验证取消、失败、损坏存档、缺包、连续创建两个世界及加载同一WorldId时旧请求被拒绝。具体流程见[APPLICATION_FLOW](../architecture/APPLICATION_FLOW.md)，阶段包见[IMPLEMENTATION_PLAN](../planning/IMPLEMENTATION_PLAN.md)。

这一门槛不等待40类业务页、35法律结算、人物AI、完整经济或10000人口全部实现，也不降低这些后续完整游戏要求。第一批可用区域与完整全球包分开验收；原生GPU/IME必须以实际设备记录，不能由现有HTML示例代替。

本ADR和重排计划是设计结果。当前有限headless、地理窗口、规则oracle与浏览器原型的状态不因此变为“主菜单/创建世界/原生地表已完成”。
