# 地图中心的前端架构与三语交互合同

本合同落实[ADR 0006](../decisions/0006-bottom-toolbar-trilingual-editing.md)，补充[40类信息空间](INTERACTION.md)与[字段编辑合同](EDITING.md)。它是生产布局、输入、翻译和验收设计；原型已完成范围以实际验证记录为准。

最新施工前置按[ADR 0007](../decisions/0007-foundation-experience-first.md)：先主菜单、创建世界、真实初始地表与基础游戏界面，存档往返/取消失败恢复通过后再建筑。未创建世界时显示应用主页/创建流程，不制造假的World引用；进入空世界后才显示下述地图与底栏。主页的新建/继续/加载不属于游戏内地图工具，其布局与候选世界生命周期见[APPLICATION_FLOW](APPLICATION_FLOW.md)。全部40类业务页是后续完整范围，基础门槛先完成真实空态、三语、镜头、世界摘要、规则与存载返回。

## 1. 先解决四个耦合

底部工具栏是统一入口，不能只把原来的按钮移到页面底部。工具、窗口、镜头和领域提交各有状态：打开国家窗口不能留下不显眼的放置工具；工具按下后弹窗不能把抬手传播到地图；返回上一人物页不能回滚世界时间；切换德文不能清掉半填表单或写入国家语言。这些规则由单一输入路由器和窗口/草稿管理器承担。

第二个难点是可编辑性与因果后果。一个国家的宗教地位影响政治资格与法律，人物六轴影响行为，国旗颜色影响表现；它们不共用无约束setter。页面只表达有类型的草案、可读后果和结果，领域验证器决定真实提交。[EDITING](EDITING.md)定义每类字段、权限、拒绝及已实现边界。

第三个难点是规模与读一致性。40类页面的关系、计数、统计和历史依赖索引与不可变快照；不得逐帧遍历全部世界或读取仿真线程的可写map。视图历史保存引用、页签和滚动，快照失效后重新查询当前事实，不能缓存旧余额用于提交。

第四个难点是同一语义的三语。图标、按钮、错误、图表单位和键盘说明要用同一消息定义；德文长文本、中文IME和数字格式是首轮产品约束，不是最后补翻译文件。

## 2. 屏幕结构

```text
┌─────────────────────────────────────────────────────────────┐
│ 轻量只读HUD：世界名/时间/人口/通知；不堆全局工具按钮          │
│                                                             │
│                       地图                                 │
│    近景人物/建筑          远景国家与其他激活图层区域          │
│                                ┌─────────────────────────┐  │
│                                │ 对象标题/关闭/历史回退  │  │
│                                │ 概览/关系/资产/统计…    │  │
│                                │ 就地字段与程序性编辑    │  │
│                                └─────────────────────────┘  │
├─────────────────────────────────────────────────────────────┤
│ 当前工具/数量/范围/明确操作提示；必要参数                      │
│ 当前section的工具按钮：原创图标＋简短本地化名称                │
│ 观察 │ 人物 │ 文明制度 │ 建设资源 │ 经济物品 │ 世界 │ 设置    │
└─────────────────────────────────────────────────────────────┘
```

底栏始终贴视口底部，预留safe-area；地图内容、对象窗口、模态、tooltip、toast都尊重其实际高度。section/tool行分别横向滚动，按钮不得因窗口高度不足变成不可触及；切换后让当前项滚入可见区。320px宽也保留文字标签，不让用户靠图标猜含义。桌面对象窗可固定在右侧；窄屏以底栏上方抽屉显示，内部分页/滚动，不推动整个地图离开视口。

目录与搜索是主动打开的对象浏览窗，包含类型筛选、名称搜索、生命周期和关系口径；默认不占地图左侧。40种对象是领域注册范围，不是工具栏上40个常驻按钮。空对象列表显示原因；未接入能力明确显示未接入，不产生假的人口、余额、GDP或“已经建好”的建筑。

## 3. section职责与最短操作

|section|职责与典型入口|主要动作路径|
|---|---|---|
|观察|点选、搜索/目录、远近图层、收藏/标记、统计比较|点人→国籍→国家；点国→城市→企业；货物→运输单→合同→货主|
|人物|连续放置18岁人物、人员筛选、人物特性/任务查看、生命清理入口|选放置→地面点击→人物档案；编辑六轴→预览→提交|
|文明制度|国家/城市/联盟/文化/语言/宗教列表与图层，制度/法律编辑|点国家→编辑宗教地位/官方Religion→预览；法规搜索→草案→生效历史|
|建设资源|建址/地基/人车入口、原创建筑目录、道路/港口/填海、资源层|选建筑→整体地基与接入预览→申请；项目→送货/围网/工期|
|经济物品|企业、账户、真实衣物/货物、合同/运输/研究、生产与消费|人物衣物→实物所有者/耐久→需求/订单；企业→生产线/库存/合同|
|世界|世界信息/统计、四项World Laws、清理、历史、保存/载入入口|分类→范围→受影响对象/拒绝原因→明确提交；保存→版本与进度|
|设置|中文/English/Deutsch、界面尺度、输入/快捷键、画质/音量/帮助|改变UI语言立即重排当前窗口，草稿和世界不变|

该表是生产覆盖范围。原型工具是否可提交由其实际代码与验证确定；没有领域实现的建设/保存等入口只可说明依赖，不显示假成功。禁止的天然地形笔刷、灾害、非人种族、城墙和现代军备不因参考工具栏而添加。

地图动作通常一至两步抵达信息；关系跳转一步；简单编辑进入编辑页后就地变更。高影响操作增加有内容的后果预览，不增加没有意义的“你确定吗”。连续人物放置保持工具激活并显示18岁，离开危险操作类别回到点选；出生由调度，不能伪装成另一个放置按钮。演示繁衍按钮只用于明确标记的原型测试，不进入生产神力工具。

## 4. 工具与输入状态机

`Idle → Armed(tool) → PointerCaptured → PreviewReady → SubmitPending → Receipt`；只读点选、图层和窗口不进入世界提交。镜头、UI、地图工具的capture owner只能有一个，平台失焦/取消时释放；在UI上开始的pointer不派给地图，在地图拖拽结束后不能顺便触发工具栏按钮。

|输入情形|统一结果|
|---|---|
|点section|换工具集合，不执行世界命令；终止尚未提交地图stroke，不静默丢对象表单|
|点瞬时工具|开列表/窗口、执行视图动作或开始需要预览的程序；不伪装成持续刷子|
|点持续工具|醒目标出当前工具、合法范围、点击/拖拽含义与退出方法|
|打开模态|暂停地图工具输入；仿真是否暂停由明确时间设置决定，浏览本身不暂停|
|Esc / 返回|先关最上层浮窗/撤销未提交地图动作，再退浏览层；保留编辑草稿或显式丢弃|
|提交后等待|锁重复提交，命令ID重试同一回执；已提交事件不得靠关闭窗口取消|
|点击重叠对象|近景按可靠拾取代理/深度选择，歧义时给小候选列表；远景按激活区域图层|
|镜头拖动/旋转/缩放|不写领域、不消耗模拟RNG；不能等同神力抓取/迁移|

快捷键从工具注册表生成，帮助/tooltip显示真实当前绑定。字母键只在文本输入与IME组合之外有效；Enter优先处理输入/表单，Space不能抢中文候选字，Esc不能吞掉IME取消。首版允许鼠标/键盘与窄屏点击布局；完整触控手势在原生输入接入时单独验收，不能因HTML可触摸就声称所有平台支持。

地图屏幕→世界换算必须包含实际视口、letterbox、DPI和相机投影。HTML原型用逆SVG screenCTM；生产使用统一screenToWorldRay与冻结地形查询。禁止按div宽高比例猜坐标、把海面命中clamp为岸边，或让云/标签/矿物曲面截走法律地表命中。

## 5. 互通窗口与编辑

对象窗口只持有`EntityRef`，所有入口由一个`InspectorController`解析。保留有限浏览历史，显示当前生命周期；收藏引用死亡人物时进入同一档案。关系卡区分国籍、居住、雇主、服役国、语言、文化与信仰；实物区分货主、保管者、位置与在途。不用“所属”合并事实。

编辑控件按类型选择：布尔switch、受控enum、关联对象选择器、整数/比例输入、六轴slider+数字、预算表、颜色候选、可搜索法条列表。复杂JSON、英文内部ID和源设计条文堆叠不是产品表单。关联选择器显示名称/类型/状态并返回稳定引用，不能把实体名称当key。

草案包含读取revision、目标、操作、候选值与本地输入；预览显示实际改变、受影响范围、门槛、过渡与未接入后果。依赖变化使提交失败时保留草案，重新预览后提交新命令ID；不能自动用新revision重放旧政治决定。批量编辑显示共同字段、排除项和原子分组，避免“最后一个对象的数据覆盖其他对象”。

国家宗教编辑同时显示宗教地位、官方宗教及帝国/神圣资格依赖；解除绑定不删除个人信仰。国家法律显示解锁与批准、可用值和过渡范围，不能让开关凭空创造金融资产或改已签合同。人物六轴与自由文本简介分离；修改轴不恢复饥饿/生命、不改年龄与rig、亲属、先知或余额。所有页面的具体字段矩阵见[EDITING](EDITING.md)。

## 6. 英汉德消息与字体

|层|约束|
|---|---|
|消息ID|稳定语义key，与UI locale和游戏LanguageId分离；任何状态机判断不用翻译后的文本|
|词条|en/zh/de键集合相同、插值参数相同、无空值；缺词构建失败，运行时报告稳定key并显式回退|
|动态信息|事件与错误保存code/params/来源对象；显示时本地化；实体自名、文书正文和玩家备注保持原文|
|数值|locale只决定小数/千位/百分号和可读单位，核心固定整数/量纲；编辑解析不能将德文逗号静默读成整数|
|复数|数量与grammatical form分离；英文/德文单复数明确，中文不假拼英语词尾|
|文本安全|纯文本转义、不执行HTML/脚本；Unicode/UTF-8长度与规范化政策统一|
|排版|德文长名称/按钮可换行，最小点击尺寸与焦点环保留；中文IME候选与窗口边界不被工具栏盖住|
|字体|拉丁字体覆盖ÄÖÜäöüß/数字/符号，CJK指定经许可字体；atlas/字重/清晰度在真实DPI验证|

原型消息由项目JSON与内嵌离线镜像验证一致性；无需CDN、网络字体或浏览器翻译。生产cooker读取同一key契约生成C++/RmlUi消息表；所有字体先核验官方文件许可、固定hash并进入GitHub资源清单。当前未导入的字体不得标记已集成。中文输入、德文长文本、英文界面与设置在阶段0主菜单开始，阶段1–2验证创建/游戏界面/存档往返，见[施工计划](../planning/IMPLEMENTATION_PLAN.md)。

## 7.验收贯穿场景

1. 底部观察→点人物→国籍→国家→法律→预览→提交→历史→回退到人物；世界不因浏览回滚。
2. 六轴填到一半，换section、改德文、查询关联再返回；输入仍在，版本变化时拒绝旧预览且无半写。
3. 三语下运行收藏/物品关联/死亡档案/统计/比较/规则/清理，单位与未知数据语义一致，错误和aria无漏译。
4. 320px、常用桌面、200%字体/DPI，底栏与关闭/提交可触及；地图不会接收窗内点击，SVG留白/原生DPI坐标准确。
5. 国家宗教解绑不删除信仰、不改国籍；法律解锁/条约/帝国冲突被明确解释；新规则生效后原有库存/合同仍守恒。
6. 新世界0人，底部人物工具每次放置18岁，合法Birth为0岁且同身体；改locale/镜头不能新增人或赠衣。

上述是验收要求，不能因合同存在就登记全部通过。当前C++ oracle、Node模型测试、实际浏览器交互与未来原生GPU/IME分别记录证据。
