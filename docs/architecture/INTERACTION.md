# 统一信息页与世界工具合同

本合同落实 [ADR 0005](../decisions/0005-unified-inspectors-and-world-tools.md)。机器注册表为 [interaction_schema.json](../../data/interaction_schema.json)。注册不等于对应生产领域已实现；可运行展示原型、独立有界 oracle、完整 World 接入分别登记证据。

最新布局、英汉德三语与富编辑变更见[ADR 0006](../decisions/0006-bottom-toolbar-trilingual-editing.md)、[前端结构](UI_ARCHITECTURE.md)与[编辑矩阵](EDITING.md)。40类注册保持；全局入口改为地图中心的底部分区工具栏，目录按需打开，对象窗口保留局部页签、关系与编辑。程序/阶段见[CLIENT_STRUCTURE](CLIENT_STRUCTURE.md)及[施工计划](../planning/IMPLEMENTATION_PLAN.md)。

## 1. UI 与核心之间只有一份事实

```text
MapPick / Search / RelationLink / Favorite / HistoryLink
    → EntityRef → QueryRegistry → immutable InspectorSnapshot
    → common page + kind-specific sections
    → field editor / procedural action → PreviewCommand
    → trusted dispatcher → single writer → committed event + receipt
    → new snapshot / dependent index invalidation → refresh same page
```

`EntityRef{world_id, kind, id}` 为稳定值；`id` 在 UI/JSON 中使用非空十进制字符串，避免 JavaScript 大整数精度丢失。ID 不复用，姓名不参与身份，revision 是并发条件而非身份。跨 World/存档分支引用明确拒绝，不能在 A 分支点击 B 的同号人物。构建时检查 kind、页面 registry 和已知命令一一对应；未知 kind 展示不支持提示，不执行写入。

查询返回 snapshot revision/tick、对象生命周期 `active | archived | destroyed | deceased`、主要事实、关系页计数、可编辑字段的能力/原因、当前问题和分页游标。已归档目标返回历史页，不能当不存在去创建同名替身。查询、预览、页签切换、图表和打开历史不得推进日历、消耗 RNG 或 lazy-integrate 矿物。需要结算的 due 工作只能由仿真调度执行。

名称/笔记纯文本转义，受限语法字段不能执行脚本；UI 不接收裸引擎指针、文件路径或可调用表达式。客户端只读快照与原生事务是唯一生产集成方向；开发夹具状态必须明显标记。

## 2. 固定页面结构与导航

共同页签：**概览、关系、资产与任务、统计、历史、编辑**。每种对象默认概览，首先显示四项主要事实、一项当前问题和三至六项最相关动作；详细信息逐级展开。没有相关内容的页签可隐藏，不展示伪造零值、空卡片或原始 JSON。未知数据用“尚无记录”并附原因；未实现领域用“未接入”。

标题栏：对象名 + 类型 + 生命周期、收藏、定位、可用跟随、加入比较、前进/后退、关闭。点击关系卡打开同一面板并压入有限历史栈；返回恢复原页签、筛选、分页和滚动，**不恢复过去的世界状态**。编辑草稿离开时保留为本地草稿或明确丢弃，不自动保存世界修改。已删除目标保留墓碑页；旧快照带 stale 标记，相关写入重新预览。

所有关系列表支持点击与数量钻取；“在此城市居住的 532 人”打开带明确 residence 筛选的 Person 列表，不能误变为法定国籍列表。层级路径不是所有权路径；国家→城市→企业只表示当前浏览关系，不让 UI 自动改变任何法律身份。

人物页示例：

```text
姓名、年龄/日历经过时间、生命来源、当前位置、当前活动
法定国籍 → State        常住家庭 → Household
居住城市 → City        所在城市 → City（可能不同）
雇主 → Enterprise      实际服役国家 → State / 所在Army → Army
文化亲和 → Culture     语言技能 → Language
正式信仰 → Denomination → Religion / 服务教会 → Church
穿着 → Garment → 货主/保管者/发放Contract
当前任务 → Project/Contract → 预约Reservation → StockBatch/Account
```

军装国家与人物国籍分别呈现；缺正装仅显示购买偏好与供应原因，不显示禁入/扣薪。前文化的暂名也是可检索稳定标签，不冒充实际语言。

## 3. 完整 registry 与逐对象编辑边界

## 4. 远近地图拾取

观察模式：近景人物代理命中 → Person；建筑/车辆/植物/矿床/道路分别返回真实 EntityRef。中景聚合标记先显示可展开对象列表，不能将聚合体当一个新人；建筑内人物通过住户列表或“选择容纳者”进入人物页。远景国家标签/激活疆域层命中 → State；激活城市层则优先 City；Empire/Alliance 等层只有其显式边界或牌子才返回相应 kind。

叠加冲突顺序为当前工具有效目标 → 显式牌子/标记 → 当前激活层 → 几何对象；长按/快捷修饰键打开候选列表。当前工具是否会清除/搬运必须有明显光标与预览，不能“点开人页”同时杀人。建设/资源等模式中的点击继续服务工具，Esc 先取消预览，再回观察。

所有 render proxy/HLOD/picking ID 绑定发布的 snapshot revision 和 typed ref。相机/LOD 只决定候选可见性；隐藏人物不停止仿真或改变拾取实体身份。GPU ID buffer 的过期结果、拆楼后 HLOD 或已死人物代理需解析当前 ref 生命周期，不能落到复用 ID。战略国家视图不通过当前人物位置推算其法定国籍。

## 5. 搜索、收藏与地图标记

注册表提供按 kind 的名字/别名、关系和状态索引；合并搜索使用稳定排序 `kind + normalized_name + id` 与有界分页。页面请求只查已建索引和需要的列，不每帧遍历全人口/衣柜/全历史。

收藏资料为 `Favorite{world_id, ref, optional_label, note, created_at}`，列表仅存引用，不复制实体。被收藏批次拆分/消耗后显示归档与后继批次链接，不能默默把收藏转给所有子批，造成库存多计。衣物 item 与 cohort 引用分别表明实际物品或批次。无法加载的世界显示未连接，不能把同号对象当原目标。

地图标记可以锚定固定坐标或一个 EntityRef；坐标必须处于世界包界限，跟随锚定与固定点是显式模式。标记是玩家观察数据，没有占用、物权、材料、路径通行或国家身份。死亡目标锚定保留最后已提交位置；列表注明历史位置。

查询默认最多 100 行，用户可分页；生产上限由 profile 锁定并限制请求负载。分页 token 绑定 queryHash、snapshotRevision 和最后稳定排序键，过期返回重查而不是混合两个时刻的成员列表。关系计数可先摘要、展开才读详细页；部分时间桶不可冒充完整周期。

## 6. 世界统计与跨对象比较

统一 MetricDefinition 保存单位、对象范围、取数口径、时间积分/快照类型、分子/分母、聚合方式、数据可用性。首批：人口与年龄结构、Placement/Birth/死亡、粮食真实消费/未满足需求、住房、基本缺衣/替换/正装偏好/自由消费、就业与劳时、产出/库存/运输等待、工程状态、财政、知识/文化/语言/宗教、战争及补给。

国家人口提供至少 legalNationality 与 residentLocation 两种口径；城市可选常住/实际在场。企业资产以所有权计，仓储按保管计并明确代管部分。库存区分 available/reserved/inTransit，移出源后不同时计目的可用；同一实体及所属父对象不得相加形成“全国两倍资产”。Culture/Language 重叠成员统计明示多重关系，不能把各文化人数和当人口总数。

比较对象使用相同 MetricDefinition、时间区间、TimeConfig、规则分段和 denominator；总量与人均分列，stock 存量、flow 期间流量、capacity 能力不能混列为一种数。企业员工统计不替代居民或国民统计；全球汇总按稳定引用去重，不能把一个人因国籍/居留/雇主关系重复计数。跨类型比较仅开放双方共同适用的指标，不以企业员工数冒充国家人口。不能拿月累计产量比较某日库存，不能把缺正装算缺岗位，不能把未完成/未实现的系统显示为 0。图表点击时间桶进入事件/对象列表；仅有事件不能重建未保存的完整历史地图，只有当前夹具快照也不能伪造多年趋势。

WorldRules 改动形成统计分段，图上显示变更位置；跨开关区间的平均值提示其混合规则。每值附 source revision/tick、单位、coverage `complete | partial | unavailable`、derived provenance；0、缺数据和未接入三者有不同表现。长期趋势按日/月/年汇总桶并有界冷索引，不把完整经济重新执行来绘制图表。

## 7. 世界规则与显式人口合同

规则键及默认值固定为 `reproduction=true, aging=true, hunger_consequences=true, ai_new_wars=true`。提交 `SetWorldRule` 保存 key/old/new/revision/effectiveTick/source/commandId；读页不改变状态。排队事务检查提交时的 rule revision，同 tick 的规则与 Birth/战争按稳定 writer 顺序；预览时允许不代表提交可绕过已关闭规则。

|规则|关闭后|重新开启|永不改变|
|---|---|---|---|
|reproduction|新的 Birth 不得提交，真实未用预约释放或停候选，已有儿童保留|未来符合真实繁衍规则者重新进入调度；不补发被阻止出生|Placement 仍需玩家明确命令；无后台人口刷新|
|aging|冻结 simulationAge/成熟/自然老化，保留 bornTick、creationTick 和日历经过时间|从已保存 simulationAge 继续增龄，不补算冻结期间年龄|身体规格、生命来源、历史死亡、战争/神力死亡|
|hunger_consequences|冻结营养欠账增长及饥饿制裁/死亡；食物需求与真实购买/消费仍运行|按冻结的营养状态恢复，显示残留欠账，不能悄悄抹零或重算关停时间|不赠食品、不虚构消费/成交、食物基本预算仍受保护|
|ai_new_wars|拒绝新的 AI 战争发起；已有战争/占领/军令继续|未来符合合法条件的 AI 请求重新调度|玩家合法战争动作不自动禁止；不清仇怨、历史或真实军队|

`PlacePeople` 必须由可信 dispatcher 的 player source 发起；每人 `creation_source=player_placement, initial_age_years=18`，数量/位置预览，合法有效陆地、站位净空、有界数量、稳定 deterministic ID 与希腊识别码。不得自动附赠经济衣物/资金/国籍/文化/语言/雇主；基础遮蔽只是 ADR 0004 fallback。允许选择已存在人的搬运而不是复制；Placement 本身明确登记神意人口来源，不冒充繁衍。

`RegisterBirth` 仅由可信仿真繁衍调度发起；记录真实父母 PersonRef、家庭、出生位置/容纳空间、rule revision；`creation_source=birth, initial_age_years=0`。父母死亡/迁移/容量变化/规则关闭在提交二验；不从 UI 输入假的 parentId 创建人。出生仍是 actual Person，对经济需要和儿童资格作正确年龄判断，即使 mesh 与成年人同尺寸。

人的 shared body spec 固定为同一尺度、骨架接口、collision/portal clearance 和服装 fit 组；禁止根据 age 派生 scale、child rig 或成长换尺码订单。已允许性别遮蔽与有限外观材料不变，物品耐久仍按真实活动/时间消耗。年龄不作为衣物尺码维度；修补、替换和偏好足以形成持续服装需求。

存档保存来源、初始年龄、simulationAge、出生/创建 tick、亲属、规则版本与已提交事件；加载不再次 Placement/Birth。已有真实引用的迁移/殖民/征募/叛军/接替工作绝不调用创建人口接口。过去年龄/体型规则变更必须显式迁移报告，不回写原稿或历史作者。

## 8. 清理工具的事务

过滤类别为 `trees, plants, mineral_resources, buildings, roads, people`，树木是 Plant 的类别子集且同一目标只选一次。笔刷以世界单位显示半径；跨 bucket 查询形成确定排序的 typed refs。清理模式与生命清除的颜色/图标明显可见，提交按钮列目标数和后果；选区/预览可以取消，已提交死亡/损失不可时间倒流。

`PreviewClear` 输出目标集、拒绝组、材料/货物/人、产权/合同、道路与入口影响、迁移/损失方案；preview token 绑定这些相关 revision、rule和导航epoch。独立目标按依赖连通分组，每组原子；首版默认全选组一起拒绝/提交，若提供部分执行选项，界面预先明确策略并显示逐组结果。

|类别|实际操作|不得做|
|---|---|---|
|树木/植物|清除所选 Plant，记录实际剩余资源损失，取消未来照料/收获任务|免费生成木材/纤维，改地形，删除已产出批次|
|地图矿物资源|默认清除矿源：整合至提交 tick 后 rate=0并核销stock；可选仅清当前矿量：核销stock且保留rate|改天然高程/地下路/水陆，删除已开采仓储货，发矿石到玩家|
|建筑/港口|疏散实际容纳者，搬移货物到真实有容量位置或经明确方案核销，处理占用/合同/租赁/损失，保留法人及历史|凭空安置/免费房屋、吞客户货、把拆港口当删除所有船/法人|
|道路/桥|为仍存在的建筑批准并启用替代合法路径，重路由现有交通/运输后移除所选段|断掉旧入口/车库/接货证书，拆邻楼来满足删除，改变人工造陆/天然底图|
|人物|`DivineDeath` 唯一终结 Person，原子退出活动/容纳/职位/军队、遗产/物品保管交接、事件与档案|复活/克隆、清掉历史或债权、删除所有作品、生成补员|

生命清除不要求普通伤害值逐帧扣至零，也不受 hunger/aging 免除；玩家明确选择产生直接死亡。家庭无人、国家无人、唯一熟练者死亡等导致正常后续制度/知识变化，必须有可见原因，不隐藏自动生人救援。

只删建筑/道路时，如果疏散或替代通行不可行，该依赖组拒绝；若用户另行明确把相关人物也列为生命清除目标，采用同一组合预览，不自动扩大笔刷选择。受限物资核销先说明 owner/custodian 与损失责任，余额不会因为清除按钮归零。

当前有限 oracle/展示原型中的矿物清除是资源 record 停用，对应默认“清除矿源”；它不能证明真实矿量积分、损失账本与可选仅清当前矿量已实现。页面必须显示这一实现边界，不能把 record archive 表述为只清存量、矿源仍可再生。

## 9. 编辑提交与接口

沿用 [CONTRACTS](CONTRACTS.md) 的幂等、强异常、预览过期和单写者。`EditField` 本身只是 UI 意图；registry 将明确字段路由到 `RenameEntity`、`SetPersonality` 等已登记专用 payload。泛字段路径、未知字段、不合类型/范围、readOnly 字段一律拒绝；神力来源由 dispatcher 提供，不在 payload 中放 `isGod`。

资产/余额/库存/国籍等程序操作可能跨多个对象，预览应展示所有必要关联修订。名称等小改动也带 expected revision，避免用户以旧面板覆盖新事实。批量允许属性编辑完整预检：先知根与最后文化保护逐人检查；明确原子或分组策略，失败不产生半事实。

结果共用 `Accepted | Rejected | RequiresRepreview`；还未接入的展示动作在 UI 能力层 `unsupported_domain` 明示禁用，不能伪造 Accepted。Accepted 带 commandId、eventIds、changed refs/revisions、createdRefs；Failed/Rejected 不改变权威世界。个人收藏/笔记/标记的持久化与经济 World 分开，只通过受限玩家资料接口；调度/行为不读取它们产生优势。

|边界|最低验证|
|---|---|
|注册与引用|40 kind 皆有对应有内容页面；所有 relation target kind 登记；同名/改名/销毁/归档仍指原 ID；拒绝跨 world|
|只读|重复打开页、搜索/比较/前后导航/预览不改 world hash、RNG 或日历|
|拾取|近人远国、中景列表、国家/占领图层明确区分；过期代理不会选新 ID；UI 与工具点击互斥|
|编辑|允许字段专用命令；实际余额/年龄/来源/作者拒绝；过期预览需重验；同 commandId 重试幂等|
|收藏|死者/拆楼/消耗货物仍可看历史；批次拆分不双计或自动改变收藏目标|
|统计|在途不双计、亲属/文化重叠不重复人口、法定与所在地口径有区别；无数据不能冒充0|
|人口|新世界0人；Placement严格18、Birth严格0且有真实亲属；无其他创建入口；加载不新增人|
|规则|关闭生育拒绝排队Birth；aging不补算；hunger保需求无免费货；AI禁新war不结束旧war；存取续跑一致|

|清理|死人只有一次结算；建/路清理保人货/合同/入口；矿清理不改高程/仓货；不自动删法人或文化|

交付按 `specified / prototype / oracle-covered / world-integrated / measured` 标明。原型只证明信息组织和交互可用；有限 oracle 只证明覆盖的状态与事务；核心范围、资产渲染、全球数据、生产 UI 接入与大人口性能分别验收。不得用 40 页面截图证明 40 仿真领域完整运行。
