# Sonnheide 仿真架构与非平凡突破点

状态：工程设计；以用户提供的[完整设计 v0.6](../design/Sonnheide_Complete_Design_v0.6.md)（2026-10-06）为需求基线。用户新增约束优先：不用游戏引擎；C++20 原生仿真；SDL3 + bgfx 是生产客户端的库层方案；建筑由项目自行制作；开源部件只承担明确边界内的工作。本文描述目标架构，不代表所有模块已经实现。当前可执行内核的具体证明范围以仓库 README 和实际测试为准。

## 1. 问题拆解：必须先突破的七件事

|非平凡点|为什么不能被目录/类型定义代替|需要交付的证据|
|---|---|---|
|一个事实、多种关系|货在广场不等于城市拥有；军队控制城市不等于改变主权；人进船不等于死亡|库存、账户、身份、容纳、控制的事务不变量及跨系统场景|
|多时间尺度、一个时钟|战斗冷却、运输、日生产、月税、几十年文化必须因果一致；加速不能跳过中间事件|统一时间单位、到期队列、时序冲突测试、加速与正常推进对照|
|局部几何变更、全局航路拓扑|填一个海峡格可拆开两个巨大水域；只刷局部网格不能保证全局标签|局部重建 + 门户图更新 + 旧路径失效 + 大分量拆分测量|
|稀疏社会传播仍有真实成员|文化/语言多对多，聚合不能凭空改信、改语言或替换个人|受限接触池、成员稳定ID、文化和语言独立谱系、统计守恒|
|真实经济能从无企业起步|没有大学也要产生基础知识；没有银行也要能建房和搬粮|公共生存闭环运行、依赖图去环、破产后公共恢复场景|
|并行计算仍可重放|任务完成先后、unordered 容器、浮点归约与 RNG 消耗都可能改变世界|单写者提交、固定排序、随机流协议、存档续跑和不同worker数对照|
|战争改变已有世界|士兵必须从居民来，弹药从库存来，投降和占领保留身份与权利|征募产能下降、有限补给、占领/主权分离、和约保留附属国|

这七件事决定框架的主干。经济、宗教、政治和战争以同一身份/资产/知识/任务/空间核心构建，避免日后在三个独立世界之间同步。

## 2. 核心层与依赖方向

### 2.1 建议的构建目标

以下是目标边界，不要求先为每个名字建立空目录或空类。

|目标|责任|可依赖|不能依赖|
|---|---|---|---|
|`sh_foundation`|稳定ID、时间、数值单位、结果类型、可重放随机、哈希|C++ 标准库；明确锁定的小型库|渲染、UI、领域系统|
|`sh_definitions`|商品/建筑/配方/科技/法律/教义/语言规则的只读定义与校验|foundation；离线解析库|当前World；SDL/bgfx|
|`sh_world`|天然掩码、人工造陆、占用、矿格、道路、空间索引、导航门户图|foundation、definitions|城市预算/文化规则、相机|
|`sh_domain`|人、家庭、国家、城市、法人、教会、资产、知识、Army 等记录|foundation、definitions|渲染句柄；文件IO|
|`sh_transactions`|命令信封、权限、修订、预约、写集、原子提交、不变量|world、domain|输入设备、GPU、任意脚本|
|`sh_simulation`|系统读取快照、生成提案、调度、完成屏障、指标|transactions 及以下|窗口、音频、渲染资源|
|`sh_persistence`|已提交状态编码、迁移、验证、日志、重放|sim 的序列化接口|视觉代理、不可审计的直接World写入|
|`sh_client`|SDL3 输入/窗口；bgfx 呈现；场景/动画/拾取/UI/音频|只读SimulationSnapshot、Command API|可变领域对象指针|
|`sh_tools`|地球包、资产烘焙、定义检查、场景生成、benchmark|各离线接口|生产世界的隐藏修改后门|

依赖方向是客户端 → 仿真接口 → 提交器 → 领域/空间 → 基础。领域之间通过共享服务协作，不形成 `economy ↔ religion ↔ military` 的编译环。协调层可以在一次事务中同时读写这些领域，但每个记录的定义只有一个权威位置。

仿真必须能在无SDL、无bgfx、无显示器条件下构建和运行。开源人物、水体 shader、导航/碰撞库不能定义产权、法域或胜负；它们通过适配器消费明确的数据。游戏引擎不作为任何依赖。

### 2.2 五类共享核心怎样真正共用

|共享核心|统一对象/服务|横跨领域的例子|
|---|---|---|
|身份与关系|`EntityId`、`PersonId`、`LegalStatus`、关系表、`LegalPolicyService`|正式国家身份、宗教成员、公司股东、Army成员是不同关系|
|资产与账本|`EconomicActorId`、`AssetId`、`GoodsLedger`、`MoneyLedger`、`Reservation`|教会捐款、公司采购、城市军粮使用同一转账/预约规则|
|知识与许可|`InnovationId`、`SkillBundle`、`ArchiveCopy`、`KnowledgeAccess`|大学研究、教会抄写、人才移民、战后接管档案|
|任务与合同|`Contract`、`TaskGraph`、`Task`、到期/失败/取消协议|造陆、教学、建线、军运、还款使用六种核心动作|
|空间与运输|`Location`、`Containment`、`Route`、`TransportAsset`、拓扑修订|居民通勤、商品运输、先知巡回、移民、Army登船|

共同基础不是把一切塞进一个巨大基类。身份关系是稳定ID索引，资产与账户是记录/分录，移动热数据是SoA列，章程/定义是不可变记录；共享的是同一事实和事务语义。

## 3. 领域数据模型：热列、冷记录与不可变定义

### 3.1 绝不能合并的字段

|对象|必须分开的事实|
|---|---|
|Person|`primaryStateId`、居留资格、居住城市、当前Location、雇主、ArmyId、信仰、文化强度、语言能力|
|City|`sovereignStateId`、`controllerId`、OccupationRecord、预算、官方文化、唯一CitySquareId|
|Building|房屋所有者、法定占地、经营Facility、外观、容量、condition、入口、简化碰撞|
|GoodsBatch|货主、保管人、位置、用途限制、预约、质量/技术配置、状态|
|Ship|直接Port归属、Port背后的经济所有者、当前船长任务/航次、乘客、货舱|
|Knowledge|原作者、知识所有者、实际熟练者、文献保管者、许可持有人、实际采用设备|
|Religion|玩家根创立事实、Denomination、ChurchInstitution、Charter、个人四项信仰资料|
|State|phase、rank、constitution、上级条约、官方文化、官方宗教、神圣化、DivineGrant|

城市主权不能从旗帜颜色反推；人物衣着不能从所在格的占领者推导；船资产不能因为Army包船改变所有权。表现只从这些权威字段派生。

### 3.2 ID与生命周期

- 实体持久身份使用世界内唯一64位ID，永不将已退休ID重新给新实体；索引槽可回收，ID不可回收。
- 强类型ID或受检句柄防止把PersonId误当CityId。存档写稳定ID，运行时解析成稠密索引。
- 每个可改实体有修订号；定义版本、天然掩码哈希、Charter哈希单独保存。
- 死者移出热列，留下可被亲属/作者/历史引用的轻量档案。注销法人、拆除Port和城市解体也需要墓碑/历史引用处理。
- `displayName` 与正式姓名记录、当时名称快照、玩家override不同；所有关系仅用ID。
- 外部存档的实体数量、字符串长度、整数范围和引用深度有上限；先校验后建立可变World。

### 3.3 Person位置是互斥状态，不是布尔组合

建议采用单一带标签位置：

```text
OnSurface { quantizedPosition, motionState }
InsideBuilding { buildingId, slot }
InVehicle { vehicleId, seat }
InShip { shipId, berth }
DivineHeld { relocationDraftId, originalLocation }
InCustody { custodianId, containerId }
Dead { historicalLastLocation }
```

同一人不同时在船和地面寻路；进入矿洞只暂停可见动画，仍计算工作/口粮。`DivineHeld` 从普通空间桶移出并暂停依赖位置的普通任务；Person身份、财产、年龄和Army成员关系保持。批量放置先寻找容量足够的合法地面槽，再一次性提交；放不下的人保留Held并报告剩余，不重叠塞入水里。

`Separated` 是Army成员的联络/集结状态，不是死亡或新人口。自动补员从真实Person挑选并遵守劳力保留量，不能把离队/登船人员当损失重复刷新。

### 3.4 热数据规划

人物高频列只保存ID/位置标签/量化坐标/当前任务/移动状态/生命战伤/所属活动区；关系、姓名、知识、文化、家庭和预算放冷记录/稀疏池。Army战斗参与者另有热列，和平居民不逐tick运行装填/射界。

目标内存核算应按 `人物热列 + 冷记录 + 稀疏关系 + 地图 + 在途/预约 + 索引 + 快照` 进行，不能用 `sizeof(Person) × N` 假称总内存。先给Person全量状态每人1～2KiB的工程预算，再实测修订；10000人约10～20MiB只是人物数据估算，不含地图、路径、视觉资产和调试日志。稀疏文化/语言/知识溢出放池；不建立Person×AllCultures或Person×AllInnovations矩阵。

## 4. 命令、提案与原子提交

### 4.1 唯一写入口

```text
CommandEnvelope {
  commandId, kind, targetIds, expectedRevisions,
  canonicalPayload, previewDependencies
}
TrustedAuthorityContext { source, actorId, permittedActions }
```

权限由调度器/核心提供，前端payload中的 `isGod` 不可信。AI、玩家、自动公共服务使用同一提交入口；AI不能发玩家专属的CreateReligion和ApproveEmpirePetition。

同一commandId + 相同规范化负载返回原结果；同一ID + 不同负载拒绝为 `COMMAND_ID_CONFLICT`。比较精确规范化字节或可靠摘要并核对长度，不依赖低位哈希相等。ID去重记录和结果进入存档/命令日志；不能因重启失去幂等性。未来归档去重记录时必须显式限定可重试epoch，不能静默删除后再次扣款。

预览依赖不限于目标对象的revision。港口预览依赖footprint格版本、造陆层epoch、水路epoch、泊位保护区和许可版本；帝国申请依赖成员同意/宪章/官方宗教/领土版本；企业立项依赖可支付需求配额、劳工/现金/法域。过期返回 `RequiresRepreview`，重新预览不能偷偷改变玩家已同意的预算或对象。

### 4.2 一个基础tick中的逻辑顺序

1. 取已提交World与到期队列；按 `(simTick, sourcePriority, commandSequence, commandId)` 固定排序命令。
2. 独立worker读取同一不可变视图，计算移动/AI/研究/经济等提案；不写World，不扣物资，不消费共享RNG。
3. 对会影响合法性/预算的提案建立读集、写集和预约；按稳定优先级处理冲突。
4. 提交器在当前修订上重新校验权限、前置条件、账本平衡、位置/成员/拓扑不变量。
5. 在不可失败的发布段应用已预分配写集；写实体、账本、到期队列、去重结果、历史事实。
6. 递增修订，更新/标脏派生索引；冻结一致的查询快照，发布仿真时刻。

worker先完成并不先赢预算。争夺一批粮食/一份市场容量由明确的优先级和稳定ID决定，避免线程数改变历史。单写者不是永远单核：昂贵读计算并行，改变事实的较小写集串行。先测量提交成本，再考虑分区事务；初期不引入跨进程服务。

### 4.3 原子性不能只靠“最后一个函数commit”

验证通过后必须仍能保证不会留半状态。实现选择：小事务预分配写集并验证全部，然后无失败发布；或者受限回滚日志。初期可用小World副本/测试夹具证明协议，但大世界不能每条命令复制全部状态。任何异常/内存失败发生在发布前；分配失败后不写账本。对几十万人改法/主权迁移等大动作，先形成过渡计划和分批登记任务，最终法律生效点仍原子切换，不能用多帧半世界状态冒充原子事务。

失败命令的可变状态、余额、库存、槽位和到期任务均应与之前相同；可增加一条拒绝审计，但不能消耗RNG或改变经济。被接受的工程只是建立承诺和预约，并不立即完成建筑/造陆/货运。

### 4.4 六动作合同图

合同动作仅需：供货、搬货、运人、施工/维护、研究/授权、出资/偿还。任务图是有向无环图；节点完成条件是已提交事实，边表达等待，不是任意脚本。

建筑本体的施工节点按[ADR 0002](../decisions/0002-building-construction.md)使用可信Scheduler自动工期，无现场Person施工劳时；依赖节点必须包含真实前侧到货和清场。搬运仍占真实Person时间，填海/道路/桥/维护/拆除/工装的劳动规则独立保留。围网/拆网只消费快照，动画完成不能作为合同节点验收事实。

每个节点包含执行者、地点、最早/最晚时刻、所需权限、预算、已发生成本、输入预约、输出事实、失败码与回退。节点状态建议 `PLANNED → RESERVED → RUNNING → SUCCEEDED`，终态含 `CANCELLED / FAILED / COMPENSATING`。取消只能退未发生部分；已在途货、已吃食物和已施工劳动不得恢复为原始库存。

任务图建立时检查无环；执行时检查等待对象仍存在，超时按合同回退。军队协同令牌、移民住房、港口装船、生产线订单均需要显式超时，不能永远等待已死人员或被拆Port。

## 5. 账本、预约与公共生存闭环

### 5.1 双账本与量纲

货币为整数最小单位。商品数量为每种商品固定的整数最小计量单位，速率/效率允许定点计算；不能把float累计后截断为“凭空少了一点”。比例乘法使用宽中间值、显式舍入方式及余数账户/累计器，检查溢出。食物单位、重量、仓储体积与船位是不同量纲，配方定义其换算。

货币账每笔分录借贷相等；商品账核对 `期初 + 已生产/再生/导入 − 已消耗/损失/移除 = 期末`。矿物原位库存与广场商品库存分开，只有开采事务将原位库存转为货物。货物交易发生时货权可转移，位置到达发生时保管/位置改变；两者不能被单一 `stock[good]` 掩盖。

### 5.2 预约不创建第二份库存

```text
available = onHand - activeReserved
reserved quantity 属于原批次，不能额外计入onHand
escrow funds 属于负债/受限制余额，不能同时算自由现金
```

`ReservationId` 绑定具体货主、批次范围、用途、受益任务、数量、到期时刻及状态。状态单向 `ACTIVE → CONSUMED / RELEASED / EXPIRED`，不可二次消费；失效/取消与释放款项在同一事务。对已经消费部分使用子预约/消费分录，不把整体状态倒回ACTIVE。

物流出发时源仓储可用量下降、在途容器得到同一批次的持有权；抵达时在途量下降、目的仓储上升。港口堆场与工厂投入缓存是唯一Location下的有界容器，统计可汇总，不能重复记为CitySquare库存。CitySquare唯一的是城市逻辑登记/交接服务，不要求每件货物物理躺在同一幢房中。

### 5.3 日结算必须明确先后

一个游戏日界点建议顺序：已到达货验收 → 到期预约/欠款处理 → 人员可用工作时段核算 → 原位矿/森林增长积分 → 投入与劳力分配 → 实际生产/施工/研究 → 输出装卸 → 食物与住房服务分配 → 工资/合同完成结算 → 城市价格/风险摘要。

同一天新生产的粮食是否可当日食用、借款是否可当日支出、工资是否可当日购物必须定义一次，测试固定。首版建议日生产后进入当天配给，现金清算分明确阶段；禁止同一清算轮卖出刚买到的同批货再反复套利。

设施产量取最短板，且受实际投入、劳工时段、安装能力、产出缓存/装卸容量约束。劳动授权表保证同一人的通勤/公共工/企业/研究/服役时段不重叠；Army征募立即减少相应日工作预算。科技可提高单位劳时产率或减少所需劳时，但同一效果不结算两次。

### 5.4 能真正活下来的早期闭环

```text
人口 → 公共耕作/伐木 → 有限食物/木材 → 配给与住屋 → 人口能工作
                    ↘ 公共工坊/基础工具 → 低效率改良
公共建造 + 徒步搬运 → 路/住房/SettlementCore → 扩展公共业务
余粮 + 技能/记述 → 教学/研究任务 → 大学能力与更高知识
```

基础耕作、伐木、住屋、徒步搬运和低阶工坊不依赖正式公司/货币/大学。基础知识可由公共工坊/师徒形成，大学提供规模与档案而不形成自我依赖环。港口需要水运/造船知识及造陆，不能反过来要求先有私营港口公司。

公共后备服务需要真实人、时间、材料、预算/配给权益；它保证有恢复路径，不保证被长期彻底封锁的城市永远不死人。长期饥饿应当归因于具体需求/产能/路径/预算缺口，不添加随机免费食物。退出企业/银行时保留基本服务和客户代管物；不会将所有高级商业风险国有化。

公共住屋/广场建筑起步无需现场砌筑人口：供料和实际搬运齐备后自动按工期建成。搬运、生产、填海和其他服务仍竞争真实劳时；建筑自动工期不创建第二份人物产能，也不由几秒钟的围网表现缩短。

### 5.5 企业与税务的后期边界

企业立项时预约“长期可支付未满足需求”的项目容量，再检查工人、资本、投入、许可和路线；开业重验。需求配额有有效期，失败项目释放。过去24月订单和基础服务满足率是统计窗口，不能用当前一日饥饿/一日订单代替。

税单由原始收入/利润/边界清关事件生成，包含 `taxBaseEventId + taxKind + jurisdiction + period` 唯一键；国家/城市税收分成是同一税单的分配。教会代征记录政府对教会的应付款，不能当政府自由收入。贷款来自自有资本和锁定期限存款，活期托管储备不得重复用于贷款/工资预约。商业门槛对公营、私人、教会持股都适用。

### 5.6 从文明起步存在的服装业

按[ADR 0004](../decisions/0004-clothing-and-makehuman.md)和[服装经济](CLOTHING_ECONOMY.md)，基本衣物先于正式公司、大学和高阶制衣科技存在。早期公共/家庭作坊用真实植物纤维、手工工具和劳时制作少量内裤、胸罩、上衣与短裤；不会为这条起步链新增羊群、石化体系或第41项能力。提取目录F1101～F1106的T015门槛保留用于高级工艺，基础手工配方作为明确的追加规则绕开起步死锁。Genesis形成需求与配色身份，不凭空给每人一套衣服。

衣物是高优先实物消费；缺衣不直接造成死亡，也不新增饥饿倍率。每人先保护食物/住房等基本预算，再比较基本遮蔽、破损替换、正式着装和可选款式。衣物只有一个货主及位置；订单依次预约库存/资金、实际搬运、验收交付、入衣橱、穿用，不能支付后直接换skin。穿用损耗、较慢存放损耗、有限修补、成长换尺码形成持续需求；重穿/转售/洗护不能把剩余寿命恢复为无限。衣橱和同时活动订单有上限，已拥有或已订到的合适衣物抵消需求。

公司在正装知识与款式已采用后可以提出着装规范。没有正装仍能正常上班，岗位、出勤和工资不受影响；规范只提高正装在个人可支付需求中的排序，食物/住房保护仍优先，雇主补贴可选。军装机构发放与此分开：款式原创统一，颜色绑定实际服役国家，法定国籍不改。通用服务、军用供给和私人购买使用同一货物与劳时基础。

服装需求不是永久利润保证。市场用持久需求键抵扣已有衣物、在途订单及已批准产能；多个企业不能重复认领同一缺口。工坊需要周转款、纤维/布料、工人和出货能力，过量供给仍会滞销/退出。生产版用整数损耗余量和到期队列按事件更新，渲染只读穿用快照，镜头与动画不创造衣物或修改耐久。独立C++服装oracle验证有限库存、工资/托管款、交付、损耗与购买排序；尚不代表全世界公共配给、科技传播、道路货运或存档已连接。

## 6. 时间模型与仿真LOD

### 6.1 先锁定时间契约，再设计加速

原稿规定30日/月、12月/年，但未规定战斗tick与游戏日的换算。这是需要实现前明确的设计缺口。建议保存唯一整数 `SimTick` 与只读 `ticksPerDay`；所有冷却/年龄/交货/税务均表示为此时钟上的截止时刻。

首轮验证配置可采用固定20Hz基础tick、1200 tick/游戏日（1倍下60现实秒/游戏日）。这些是试验参数；需要通过走路距离、射击冷却、饥饿/劳动节奏和观看体验共同验证，不能宣称真实时间比例或最终平衡。`TimeConfig` 进入存档与重放哈希，旧存档不能因版本升级被重新解释成另一种日长。

月、年由整数日序推导；计时器不用主机本地时区/真实时钟。暂停不推进仿真；绘制可以继续。加速只增加每现实帧尝试的仿真步数，达到预算上限时显示实际速度，不静默跳过欠薪、冷却或交货。过载时减低可实现速度、降低表现成本，不能改变事实。

### 6.2 三种更新粒度由任务决定

|状态|推进方式|保持的权威事实|
|---|---|---|
|活跃战斗/近距冲突/港口装卸争用|固定基础tick，定频感知/战术|真实Person位置、弹药、冷却、阵位、占用|
|普通道路行程/长途航次|保存路径分段、距离/速度、入口到期与容量预约；按事件推进|同一人/货/资产，路线、法域检查、堵点、到达时刻|
|建筑内工作/教学/慢社会事件|按任务时段/日/到期更新，lazy decay/积分|同一劳时、预算、材料、接触、成员和随机语义|

摄像机距离只决定画多少骨骼/窗户/粒子，不能决定仿真粒度。活动区由战斗、道路争用、施工变化、追击等客观状态决定。即使镜头在另一大陆，战斗仍执行相同裁决。

### 6.3 事件推进不是任意快进

普通行程可以用 `remainingDistance` 与路径分段计算下一段到达；每个道路/桥梁/船舱容量及时间窗口仍检查。发生封锁、造陆、战斗、目的地占领、速度变化时，在该时刻切分行程，先积分已走的距离，再重新判断。不能把出发与最终到达之间的空间全部省掉，使穿桥/遇敌成为瞬移。

若活动区将接触两支队伍，必须在接触前一小段警戒窗口把相关人员解析到合法连续位置；解析来自同一分段坐标，不重新抽样战力/人员/弹药。首版先做全量固定步作为参考实现，之后对无相互作用路段做事件推进，并对比结果；没有等价证据前不启用影响胜负的聚合。

工人工作量来自任务时段而不是每帧走动画。家庭消费批量结算；真实大宗货、港口装卸和Army集结保留运输时间与空间争用。大量居民不用每日强制导航到CitySquare。

## 7. 地理、格网、造陆与导航的拓扑难点

### 7.1 世界建立

离线岸线/ETOPO地球包 → 全球视窗LOD选择 → WGS84选区/EGM2008正高 → 局部方位等距投影 → XYZ单一worldScale → 格心/面积规则掩码与固定三角化高程 → 冻结天然掩码/高程/来源/误差。真实地形覆盖原稿平地限制，具体合同见[ADR 0003](../decisions/0003-terrain-and-site-access.md)和[TERRAIN_AND_SITES](TERRAIN_AND_SITES.md)。

方位等距投影以中心点为参考；不能把“等距”误解成选区中任意两点距离均无形变。PROJ提供该投影及中心参数；超过局部范围需测量形变并提示/限制选区，而不是独立拉伸X/Z。[PROJ官方说明](https://proj.org/en/stable/operations/projections/aeqd.html)

必须另外测试跨180°经线、极地、内陆湖/湖中岛、空选区、过窄选区与海岸小岛的栅格消失。地球选择在经纬度上环绕，经度归一化不能直接把跨日界线选区解释成全球大矩形。天然矢量岸线渲染与逻辑格边界存在差异，选取/建设预览按同一权威格网判断，不能让视觉上可站的岸线却无解释地拒绝放置。

旧存档包含冻结掩码或可恢复的不可变包内容、源版本和哈希；不能只存当前新版数据源引用。数据包升级不移动已建城市/港口。

### 7.2 地图内存与逻辑精度

建议先从64×64格Chunk开始测量；具体格长由建筑模块/门口/人物半径共同决定，不等同世界scale。天然掩码按位，造陆覆盖按位或稀疏块，occupancy/道路索引单独列；矿物只为非零/实际可开采格分配稀疏列。

2048²格有4194304格，1bit掩码约0.5MiB、1byte列约4MiB、4byte列约16MiB。16种矿物若每格存rate+stock两项4byte会达到约512MiB，因此不应复制“一个含所有矿种的巨大Cell对象”给所有水格。世界创建页面必须从实际列布局计算预算；不能仅按地图像素数决定允许范围。

天然掩码只读；人工造陆工程通过完成事务写覆盖层；`effectiveSurface / landOrigin` 由两层推导。矿物rate变化只更新矿场和原位stock，不变更地形、道路或导航。

真实天然高程同样只读，以共享顶点/瓦片保存，NoData禁止静默建址。地基/支撑坡道是独立工程surface/solid；Nav从权威地面与已启用工程表面派生，人/车辆按分别固定的profile检验全宽、坡度、门口连续与净空。每栋楼的完整SitePlan及接入保护域一次预约，邻楼不得改变旧标高或侵入旧通道。临时配送与永久坡道可有同一投影，按claim角色/阶段管理，不能在完工时误释放永久路径。当前独立oracle尚未和本仿真world/填海/全交通/物流合成，完整转弯与多表面导航仍须贯穿验证。

### 7.3 逐格造陆的两次校验

提交时要求天然WATER、无已完成覆盖、无冲突、四邻接天然陆地或**已经完成**造陆、材料/劳动可预约。拖动若预览未来连续条带，UI可以显示等待链，但不能把计划格当已完成陆地提交全部单格；合法做法是先提交岸边一格，其后在完成事件触发下一格请求并重新校验，或者在UI中明确标注尚未可提交。

完成时再验占用/泊位保护区/资金与实际已消费劳动，原子写 `reclaimed=true`、施工完成、材料消耗/释放剩余预约、历史、空间epoch。材料预约不是完工证明；不能以拥有预约直接铺路。

施工中有效地表仍WATER，但工地有临时船舶障碍。开始施工和完成均可能使航路失效，不能只在最终完工更新导航。取消未完成工地释放未消费资源，结算已耗部分；已完成不可拆回水，Port拆除不拆人工陆地。

### 7.4 港口的局部与全局条件

局部：矩形footprint全为RECLAIMED、0/90/180/270°、海侧整排WATER、连续泊位区宽深、陆入口可达、无冲突占用、产权与许可。

全局：泊位区通过**当前有效水域**连到合法航道；远洋模板连到主海域/世界水边界。天然 `seaConnected` 不能作为运行时答案。Port模板中的海侧、陆侧入口、泊位保护区、船半径/所需航道宽度是项目自制建筑的功能元数据，与视觉模型一起校验。

后续造陆侵入强制泊位保护区直接拒绝；先合法停用/改建Port才可修改。船舶登/下船需要舱位、装卸窗口、人员/器材容量及目的地合法容纳，预订客票不能立即变为到达人口。

### 7.5 为什么全局连通不能“纯局部更新”

设一个格是两片海之间唯一水格。造陆删除该格后，它所在的64×64Chunk只发生一次小几何变更，但这个删除可拆开横跨数千Chunk的水域连通分量。局部重建Chunk可以确定新的门户，却无法仅看邻接Chunk宣布整个海域仍连通。

方案：

1. 每Chunk维护局部水域分量、边缘门户、船尺寸/宽度分类和局部epoch。
2. 造陆/工地改变将受影响Chunk及共享边邻Chunk标脏，立即禁止进入已改变的格。
3. worker在版本快照上重建局部分量/门户；结果带source epoch，过期结果丢弃。
4. 单写者发布门户替换，更新跨Chunk门户边；新增陆地通常是水图删除，旧union-find不能直接正确处理拆分。
5. 在**粗门户图**上对受影响旧连通分量做BFS/DFS，或实现可验证的动态连通结构；必要时重算大分量。成本 `O(affected portals + edges)`，不是声称永远只访问局部Chunk。
6. 发布新的 `connectivityEpoch` 和组件索引；索引/缓存状态区分 `VALID / DIRTY / REBUILDING`。

门户图大小取决于海岸/建筑复杂度；只有一个门户代表整条Chunk边不足以处理同边互不相通的航道。门户必须来自局部分量的连续边区段，宽度检查不能仅用“两个水格相邻”。先以2～3种船尺寸离散导航剖面建立预算，避免每船独立全图索引。

### 7.6 异步重建期间如何不穿陆、不假拒绝

- 精确格可通行判断立即使用权威effectiveSurface与施工占用；船在进入下一段前验证段内格/门户epoch。过期路线至少停在最后合法安全点。
- `DIRTY`期间不能使用旧组件标签证明港口/运兵合同可达。预览显示“航路重新验证中”；新合同等新epoch，或发出高优先级受限搜索。
- 受限精确搜索/门户搜索若找到并校验完整路径，可返回一份带读集的可达证书；若预算耗尽，返回 `PENDING`，不能把 `NO_PATH` 当确定事实。
- 正式 `NO_PATH` 必须来自完成的搜索/有效组件；加载快照不能把未知自动解释成不可达。
- 预览证书在提交时再次对照世界/门户/许可证epoch；跨dirty区的合同不先扣款再祈祷路径存在。
- 全局epoch可做首版保守失效；优化后以路线依赖的Chunk版本减少不相关重算。epoch不需要每tick变，只有影响合法性时变。

预算先以“每基础tick处理固定门户/搜索节点数”限制，确定性地续跑；不能用worker现实耗时决定何时产生经济事实。首轮工程目标可设每tick 20000粗图边访问/4000精确节点扩展，独立高优先队列保障已在途船与玩家预览。必须记录p95等待、最大受影响组件和重建内存；这些是待测预算，不是实测承诺。

官方Detour提供瓦片化导航网格与查询工具，可作为局部导航候选；它不替游戏决定造陆产权、全局水域语义和异步版本协议。[Recast/Detour官方API](https://recastnav.com/group__detour.html)

## 8. 文化、语言与知识：稀疏不等于任意简化

### 8.1 人物资格与独立谱系

Culture不持有强制languageId。Person无文化则无正式语言/宗教；有文化则至少掌握一种语言。Primary Genesis在同一事务创建RootLanguage、命名创始人、Culture、共同genesisEvent与首批成员，然后可正式化Settlement/State。Secondary只建Culture；语言分化从实际speech community与有父源的音变历史产生，不能在新文化函数里调用CreateLanguage。

对已存在文化的接纳任务，先积累真实接触/语言学习，再一起提交个人文化、语言、正式姓名；不能给一个完全无语言者先写Culture后等下周补语言。清除最后文化需处理宗教/职位/语言资格，默认拒绝隐式清空；旧名和作者历史保持。

国家和City的官方文化是制度记录，不是对创始人的属性指针。创始人死亡/编辑不删除Culture/Language；文化与语言归档互不级联。

### 8.2 接触池和成员保真

城市/工作/学校/Army/家庭按实际任务汇总接触时间、可理解语言、文化/宗教候选与服务证据。每人只对少量可接触候选更新，而不是两两居民扫描。家庭与亲属的少量边可精确保留；规模传播用 `ExposurePool` 的受限采样。

接触池保存来源与时间窗口，避免同一事件被家庭/学校/城市重复全额计算。候选曝光不是正式成员；转信需要考虑期、根资格、个人拒绝/稳定期。用同一人同一时段的劳动/学习/传教预算，不能既全时上学又全时工作。

人物常用4个以内文化/语言候选是性能目标，溢出时采用显式冷存储/阈值规则；不要无记录剪掉非零文化导致人物恰好变成“无文化”。聚合统计只计算变化量或固定日刷新，不每帧扫描全部历史文化。

### 8.3 自适应文化场的隐藏数值问题

原稿的 `phi_new = exp(-r*dt)*phi + sigma*Noise + excitation` 未规定Noise方差随dt如何变化，也未规定60日更新如何捕获中间波峰。简单改dt会改变随机过程和跨阈概率；lazy decay能精确处理衰减，不能自动处理随机最大值/首次越阈。

分两阶段实现：

1. 首版以“节点每天一次随机样本”作为明确离散定义，独立RNG键为 `(WorldSeed, NodeId, dayIndex, streamVersion)`；Genesis只在日边界判定。平静节点少，先测真实成本，不为漂亮调度提前引入不等价近似。
2. 若必须实现60/15/3/1日自适应，锁定另一份 `FieldModelVersion`，规定时间间隔的创新分布/归一化和触发语义；或保留日样本并批处理，但需要检查所有可能越阈的日，不能仅比较窗口末值。与逐日模型对照Genesis频率/日期/节点增长，接受差异时明示是模型变更。

事件脉冲使用固定少量通道并按时间lazy decay；历史文本不能作为每次计算输入。候选数量首轮Settlement primary 1 + secondary最多4；休眠/合并保留来源与冷状态。事件唤醒由模拟日期触发，UI检查器只能读取快照，不能为了显示更新节点并消耗RNG。

### 8.4 随机与数学可重放

可用counter-based RNG按 `(seed, system, entity, logicalTime, sampleIndex, version)` 取样，减少worker顺序/旁观查询影响。Random123官方实现明确key+counter确定输出，可作为锁定版本的候选库；这仍不保证浮点数学和分布转换跨平台逐位相同。[Random123官方仓库](https://github.com/DEShawResearch/random123)

不用 `std::hash` 生成持久随机键，不用 `std::uniform_real_distribution` 假设所有标准库有同一映射。选择明确算法、采样布局和转换；命名随机、文化随机、战斗随机、科研随机各自分流。无意义查询/重预览不得消费实际随机。

首版重放等级明确分为：同构建/同平台位级一致；跨平台结构/整数事实一致；长期浮点状态容差一致。跨平台位级一致需要定点/受控数学/固定归约和完整测试后再承诺。经济采用整数优先；位置量化与社会场数学单独决定精度。禁止fast-math进入权威裁决。

### 8.5 知识的五状态与安装效果

Awareness、Access、Competence、License、Adoption分开；国家、Culture与Language不能拥有“全量科技布尔表”。普通工人保存职业技能包，核心学者/档案/设备保存具体创新引用。

研究是实际劳时/预算/材料的任务；大学不是唯一知识起点。许可/翻译/抄写/运输生成真实档案或权限；学者迁移只带个人记忆和合法文献。只有已生产、已装备的方案产生效率，同一槽只选一个版本，有限通道加成有上限。设备不因新论文出现自动升级，也不因唯一学者死亡立即消失。

## 9. 法律、宗教、政治：规则必须可执行且有范围

`LegalPolicyService` 返回可操作决定、适用法源、拒绝/过渡原因、成本/程序条件，不能只返回bool。规则优先级：世界硬约束 → 条约明确权限/保留权 → 当地宪制 → 法律 → 行政规则。缓存按法域/规则版本/相关资格失效；私人教会章程只能约束被授权对象。

法律用受限声明式谓词，不运行用户脚本。定义检查规则的循环引用/冲突、生效时刻与主体类型；对现有企业默认形成过渡和合法退出任务。国家称王/帝国/更改官方宗教均为不同事务；帝国需有效Grant绑定根宗教/宪章版本和成员同意。

Religion根只来自玩家，AI只能在根允许范围内推进教派；Prophet根绑定永久。ChurchCharter冻结字段作为规范化不可变blob/哈希；预算可变但不能改变财产归属/任命结构/金融边界。教会财政仍用统一Money/GoodsLedger，restrictedDonation/endowment有用途限制；分裂先裁决资产债务和成员，再创建新教派/新章程，不复制中央资金。

宗教四项个人指标分开，信任下降不等于根信仰消失。国家改教不自动改居民；官方宗教/神圣化/帝国三者分开。Temple、教派分裂是后期长期窗口和项目容量检查，不能只用当前信徒计数触发。

政治从属图每国最多一上级且无环；股权图/语言父源图/任务图也无环，但它们是四张独立图，不能用同一“所属”字段混合。上级法律不自动无限覆盖成员保留权；共同军额/税额由合同和宪章产生。

## 10. 战争与移动：保持因果、空间和真实人

### 10.1 只有Army一层

Army直接引用真实Person、装备、坐骑/火炮、主责City、拨款合同、命令队列、补给容器。角色带/阵位是临时布局，不新增营/连实体。拆/并建立平级Army并一次性迁移成员、装备、预算承诺和供给，不复制武器。

征募校验成年、资格、粮食/配给/运输保留劳力、训练/装备/工资。主责城失陷/指挥官死亡不删Army；产生继任/换供给/投降/解散流程。战俘、伤员、退伍者保留身份和容纳状态。

### 10.2 战术热点与算法边界

空间索引缩小感知/近战候选，不能每个士兵扫描所有敵兵。Army按固定间隔做战术，士兵按基础tick移动/冷却，感知采用本军/合法盟军信息；玩家全知不是AI视野。

阵位生成按角色/训练/ID稳定排序；阵位修正只搜预算内合法邻格，失败缩窄/分段/保持纵队并显示原因。首次实现可用角色带中的贪心匹配 + 限制交换，避免全军O(N³)最优指派。路径/重排预算耗尽返回“正在展开”，不能瞬移。

射击从真实弹药与reload截止时刻判定；遮挡用项目自制建筑/树木/空间元数据的简化射界几何，不从可见LOD网格推导。炮弹粒子/骨骼命中是视觉；权威伤害在核心结算。兵种上限固定到燧发枪/前装黑火药炮，车辆槽不能任意外挂现代武器。

### 10.3 占领和条约

占领必须满足CitySquare与交通节点持续控制、守军有效组织失去、最低占领规模和时间阈值。`OccupationRecord`改变controller/旗帜/通行风险，不覆盖sovereignStateId。占领政府库存也通过受限资产接管事务；私人/企业/教会货不自动成为战利品。

和平条款生成明确作用地/金额/期限/当事人的转移计划。附属国保持StateId/爵位/城市/历史和保留法；殖民新城需要真实定居人口/住房/供给/文化；反叛Army由已有居民/倒戈士兵组成，有预算、支持者、领袖和武器，不刷新免费军队。

## 11. 存档、日志、迁移与验证

### 11.1 记录什么

存档仅取屏障后的已提交状态：schema/build/definition/model版本、SimTick和TimeConfig、地图选择/投影/worldScale/冻结掩码与哈希、造陆层/工程、ID分配器、实体修订、预约/合同/在途货/受限资金、知识/语言谱系/Genesis状态、RNG算法和计数、命名序号、Charter/Grant、装填冷却、人员容纳/Separated、矿格rate/stock/lastIntegration、到期任务和命令去重结果。

空间桶、价格派生摘要、渲染代理、LOD状态和门户缓存可重建；但可达性重新变为VALID之前必须维持合法停船/待验证状态。导航路径可以存其业务行程/分段进度；不能只存不可恢复的运行时nav句柄。

临时编辑预览不进入世界存档。Held是特殊情况：它已暂停Person普通移动，若允许中途存档，就要保存Held批次/原位置/当前容纳并确保加载可继续或取消；若暂不支持，则UI明确要求先放置/取消，不能保存半抓取后丢人。

### 11.2 保存协议

在一致屏障处生成不可变Snapshot → 后台编码到同目录临时文件 → 校验长度/校验和 → 原子替换目标 → 保留上一份成功快照。失败不覆盖旧档。内容规范化：稳定ID排序、固定字节序、固定数值格式、明确optional标签。

加载先验证形状/大小/校验和，再检查跨对象：重复ID、引用丢失、负库存/非有限数、货物两处计数、预约超量、从属/股权/语言环、非法帝国/文化资格/Charter/旗、天然哈希、Port泊位。修复模式只能生成解释性计划并保留原档，不能自动发Grant/造文化/补资金。

### 11.3 重放的证明范围

规范化快照 + 有序命令/AI输入日志 + 同版定义/RNG/model → 重放。HistoryEvent是事实审计，不能默认拥有足够字段反向重建所有物理运动；命令日志与历史日志用途不同。若AI是确定性计算，记录命令可压缩调试；否则必须记录AI决策输入/结果，不能假装完整可重放。

每固定步段输出权威状态hash：按实体/账本/任务/地图稳定顺序序列化；排除临时缓存和视觉资源。测试连续运行与存取后运行、1/多worker、不同渲染帧率、不同摄像机路径；差异时报告第一个分歧tick和子系统hash，不只看最终人口数量。

迁移每版有显式转换与不变量检查，定义/世界规则变更保留旧哈希；无法合法迁移则允许旧版只读/拒绝并保留原档。未提供旧原型文件时不声称已有迁移器。

## 12. 性能边界与阶段门槛

### 12.1 初步预算是测量计划

先建立100/1000/10000人场景，100000人只是后续探索，不能把规格中的100000渲染分离例子当首发容量承诺。参考机器需记录CPU/GPU/RAM/OS/构建类型；统计p50/p95/p99、最长停顿、真实仿真速度与活跃任务数。

|工作|首轮边界/目标|扩展措施|
|---|---|---|
|基础tick|20Hz目标；核心p95≤25ms、p99≤40ms留调度余量|热点分区/读并行，不能跳步|
|慢系统|日/月边界最多固定预算批次；到期顺序稳定|按预定义微阶段拆到期工作，发布完整结算点|
|相机|60fps目标16.7ms；先1000人城市验证近/中/远|表现LOD/HLOD/实例化/动画预算|
|路径|共享路线/门户缓存 + 请求队列；每请求节点上限|同目标flow field/分层搜索；队列时延单独统计|
|文化|每聚落1 Primary + ≤4 Secondary；小候选池|休眠/合并，测增长率；无全人口两两传播|
|长程任务|按道路段/航次/到期更新|客观活动区细化；逐tick参考对照|
|日志|重大事实逐项，普通日结算批次汇总|分块索引/保留策略；不省略必要审计|
|快照|UI摘要≤10Hz；移动视觉块按需要增量|双缓冲/只读块，不整World每帧JSON|

这些数值只是设计门槛，须在完整负载测量。无渲染的空移动benchmark不能证明10000人文明性能；没有宗教/经济/战斗的场景也不能宣称完成该规模验收。

### 12.2 分阶段，不让最难点永远留到最后

|阶段|必须证明的功能|退出门槛|
|---|---|---|
|P0 规则内核|命令去重/冲突/修订/权限、整数预约、造陆/Port、epoch、存取|非法命令无部分效果；合法流程守恒；存取一致。只证明内核覆盖项|
|P1 真实空间切片|地球包/选择/统一比例、3D相机/拾取、人口生存、道路、入口、矿曲面、自制CitySquare/Port资产|跨日界线/岛湖/同选区不同scale；人工格合法；港口+短货运可观察|

|P6 成熟企业/平衡|需求容量锁、税务、退出、集团/保守银行、Temple/罕见分裂、反叛|多城市10000人完整场景；长期守恒/恢复路径/增长率及CPU/GPU预算；参数数据驱动调整|

P1/P2/P3相互交叉迭代，但不能跳过P0守恒/幂等先做宏大展示。每阶段留一个完整历史场景：前文化农具革命、知识教会与帝国、跨国企业与补给战争。仅测试单函数不能证明这些系统故事真的发生。

## 13. 检查器与解释链的核心输出

所有领域统一返回 `ActionAvailability` 与 `CausalReason`：主要瓶颈、全部支持证据、来源实体/规则、实际数量/时刻、可操作替代、snapshotRevision。缺钱/料/人/技能/授权/路不同码；localization只译消息，不改事实。

原因不能每帧构造全世界图；任务在状态变化时更新原因记录，UI展开再取局部因果链。城市摘要聚合粮食、住房、预算、仓储等待、风险前三项；普通出生/小改良进入事件流，只有帝国审批/重大程序风险等需要玩家决定的事才打断。

同一Query不可修改World、补矿、唤醒随机文化或改变AI。资产和建筑选择通过空间索引/可见代理映射到稳定ID；保存/命令提交不使用GPU对象编号。

## 14. 本轮不能提前承诺的结论

- 所有完整仿真系统、三维客户端、长期经济平衡和10000人性能尚需依阶段实现并测量。
- 导航纯局部重建不能保证全局连通；counter RNG不能单独保证跨平台浮点重放；小vector不能单独保证文化/语言数量增长受控。
- 采用开源部件只节省明确职责内的工程。产权、公共闭环、时间语义、社会模型与战争因果仍必须自研。
- 自制建筑不能只做漂亮mesh：每个资产还要提供footprint、入口、容量兼容、LOD、碰撞/遮挡与Port特殊规则元数据，交付规则与视觉的一致性证据。

需求与对象的逐章映射见 [DOMAIN_MAP.md](DOMAIN_MAP.md)。
