# 真三维像素世界、原创人物与资产合同

2026-10-08。本文落实用户最新的视觉与地形改动及 [ADR 0012](../decisions/0012-editable-3d-pixel-world.md)：世界改为可从 360° 观察的真实三维像素风，人物采用原创、高分辨率像素贴图的方块小人；不再使用 MakeHuman 人体或服装作为新人物来源。建筑继续全部原创。用户同时允许山丘、山地、高峰与自由海陆编辑，因此此前“天然地表冻结、普通陆地统一平面”的生产规则被覆盖。原始 [v0.6](../design/Sonnheide_Complete_Design_v0.6.md) 是保留的设计来源，不改写其旧段落。

这是**待实现、待实测的生产合同**，不是已经完成像素世界的报告。现有原生窗口、bgfx 绘制、RmlUi/FreeType 菜单、油画首页与旧地表/天空试验提供可复用的工程边界；旧 PBR 画面和有限 headless 测试不能算作本方案的完成证据。本文件不下载新素材，不增加依赖，不将现有 MakeHuman 文件转换后冒称原创人物。

## 1. 必须实际突破的六个边界

|边界|必须做成的事情|必须排除的错误实现|
|---|---|---|
|三维形体|人物、建筑、地形、车辆有完整体积、背面、侧面与遮挡；镜头连续旋转|正面像素画贴到摄像机朝向的纸片上，或把旧写实画面整体降采样|
|真实可编辑表面|effective 海陆/高度变更后，网格、碰撞、拾取、导航读取同一 SurfaceRecipe 和 revision|只改变地表 shader 或仅把山显示出来，人物仍沿旧平面走|
|细节与规模|几何只表达轮廓、关节、层次和通行；像素贴图表达颜色簇、五官、布纹和小细节|每个纹理像素都生成一个 cube，或全世界存放稠密三维体素|
|人物与衣物|原创 BodyProfile、rig、衣片层次与真实衣物引用一致，全龄规格不变|用外观换装创建商品、复制库存、恢复耐久，或缩小 0 岁人物|
|视觉可读性|近景细像素、远景稳定缩小、明暗与水体可读，透明物不偷走工具命中|所有距离都强制最近邻无 mip，导致闪烁；水色替代 LAND/WATER 事实|
|原创与可复现|原创源、导出配方、工具版本、hash 和许可边界可从仓库恢复|只保存导出的模型、把下载物改名后称原创、给原创内容擅自授予开源许可|

首轮垂直切片必须同时打通“坡地—建筑—入口—人物搬运—服装—360° 镜头”，不是分别出几张静态像素截图。它验证真实形体和空间合同；后续增加居民和款式才能有可靠基础。

## 3. 一个实际表面，不做全世界稠密 voxel

### 3.1 权威高度场与来源分离

世界保存创建来源的 manifest/hash，以及独立的 effective 地形状态。GSHHG 为初始海陆提供出处；它不提供这里的游戏山高。新世界的高度范围、量化单位、海面、坐标比例、格内表面配方和版本作为 `TerrainProfile` 冻结；**冻结的是解释规则，不是 effective 地形内容**。允许玩家在这个有界 profile 内改海陆与高度，提交后保留真实编辑历史。不能因为默认 profile 改版，悄悄重解释旧存档。

与新地形合同对齐的首样本是 `SurfaceCell=2 m`、`heightQuantum=0.5 m`、`chunk=64×64 cells`；它们需要实际准入，不能当作最终性能承诺。浅/近/深水、沙地、土壤、山丘、山地、高峰的八类 preset 消费同一地形定义，中心高度/水深及刷子规则由更新后的 [TERRAIN_AND_SITES](TERRAIN_AND_SITES.md) 定义，不在渲染器维护第二组值。权威整数高度与表面材料决定实际地表；首版静水位 0，低于水位为湿格，水深由水位减海床高度派生。同一提交发布有效 mask、海/湖连通与 revision，不能独立改 mask 制造“深海床却显示可走 LAND”。Height→Y 的转换只有一份，检查有界整数、溢出和非有限输入。

```text
TerrainProfile                     随世界锁定解释规则
  cellSizeMeters, heightQuantumMeters, allowedHeightUnits
  stillWaterY, horizontalProjection/worldScale, surfaceRecipeVersion
  material/presetDefinitionHash, profileHash

EffectiveTerrainSnapshot           同一提交屏障发布
  worldId, terrainRevision, profileHash
  chunks[cell: heightUnits, surfaceMaterial]
  derivedMask/waterDepth/waterBodyTopology
  engineeringSurfaces, obstacle/accessRevisions

SurfaceQuery(profile, snapshot, xz) 权威表面/法向/边界/用途查询
  -> groundSurface, waterSurface, support, traversalClass, revision
```

首版一格一高度列，具有一个量化台面与真实侧壁；需要坡道、楼梯与局部道路过渡时用独立的真实工程表面。SurfaceRecipe 明确列顶/边界及工程表面查询，供所有消费者使用。渲染器不得独自对量化高度作双线性平滑，碰撞器也不得继续用平地近似。高度场只负责有界地表；它不自动提供可挖地下洞穴、任意悬空块或无限深三维矿洞。桥、楼板和建筑 Interior 的有限分层表面依各自合同处理。

采用高度场并不要求每个 cell 生成一个 cube 实例。地表只编译可见顶面、不同高度的侧面、岸壁与必要连接表面；相同材料/高度/UV 规则且不跨必要拾取与拓扑边界的面可合并。底部和被相邻实心地表遮住的面不生成。建筑、植被、人物使用独立 mesh 或原创模块，不塞进全球地形体素数组。

列的高低不增加隐藏竖向 cube 数：96 m 的峰壁可以是一张按米制重复像素材质的真实侧面，而不是 192 层盒子。以 64² chunk、每顶面一个 quad、每相邻高差一张 quad、四边均暴露为例，未合并上界为 `2×(4096+2×64×63+4×64)=24832 triangles`，不含独立水面、拼缝和工程表面；材料分层或额外裂面会增加这个值，必须另计。棋盘高差是可构造的坏输入，生成器不能只按平地只有两片 triangles 估算预算。

一个规模比较说明选择原因，而非游戏规模承诺：2048² 平面×256 层，每 voxel 仅 1 byte 就需 1 GiB，尚未计材料、编辑、索引、导航和 GPU 数据；同平面一份 int16 高度为 8 MiB，一份 1 byte mask 为 4 MiB。高度的类型须根据支持范围选择，不能只为这个估算强制 int16。稀疏块与表面网格仍有开销，要按实际创建范围和可见块数测量。

### 3.2 编辑、构建与显示不得出现两套表面

地形编辑预览使用真实射线与当前表面 revision；提交带 expectedRevision。单写者事务验证影响的支撑、占用、人物/车辆位置、入口和必要通行保护，原子发布 effective 高度/海陆与已确认的空间结果。自由编辑的具体审批和既有实体处理由新地形合同定义；渲染不自行增加旧“天然不可改”限制，也不跳过编辑影响处理。

CPU SurfaceQuery/碰撞与导航数据可以先更新，GPU mesh 构建异步完成；**不能在这段时间绘制与已提交物理相反的旧高程**。首样本选择有界同步局部网格或同新高度生成的简化临时网格，之后异步替换精细版本。若替代路径暂不可用，客户端撤掉受影响旧mesh并清楚显示暂不可见区，暂缓该范围落笔/旧图拾取；绝不容许人物穿过可见旧坡面等几帧。该等待仅在呈现层：权威CPU提交、确定性拓扑ready tick和headless仿真不等待GPU_READY，不因镜头或设备速度改结果。任务携带 world/session、terrainRevision、profileHash 与 chunk generation，过期结果和旧世界句柄丢弃。

chunk 边界共享权威高度样本与确定性边界处理。细粗地形 LOD 的接缝使用显式 stitching；不得用假裙边穿过入口、岸壁或道路来遮住裂缝。保持靠近人物、建筑与工具位置的实际台阶/坡道，不让远景简化跨越通行断面。视距与 LOD 不改变 SurfaceQuery 或导航结论；重要交互区域若误差超限则提升 mesh 精度。

### 3.3 方块台阶也是真实台阶

0.5 m 的高度差不是“像素风可以忽略”的误差。如果运动 profile 不允许这一单步高度，就必须有真实的楼梯、坡道或绕行；地形外观保留高差，不能直接把导航边标为可行。人物、道路、车库采用独立的较细通行/工程粒度，首样本可试 0.25/0.5 m 模块；**2 m 地形格不是人物骨节、门宽或楼梯踏步的尺寸单位**。合法单步、纵坡、横坡、坡折、净宽与车辆转弯量须在运动切片中明确准入。

建房检查完整 footprint 实际支撑域，在非平地上以原创长方体地基建立单一平坦楼板，保存真实顶高、体积、材料与外露范围；完整平地无需额外虚构地基。地基、人门 landing、前侧接货路线、车库车道及永久通行保护须一起批准；房屋贴图和 block 外壳不授予新支撑。后建邻楼和普通文明施工继续保护旧接入，替代路线先证明、再原子交换。明确的破坏 Godterrain 可以撤销旧证书并造成真实损坏，须按 [ADR 0012](../decisions/0012-editable-3d-pixel-world.md) 及地形事务合同同次处理人口、货物和建筑/港口后果，不在渲染侧伪造仍可行通道。人物搬运沿现状可走路线到指定前侧接货点；有车库须真实可驶入，不拿人行台阶冒充车道。

## 4. 单位、像素密度与几何细节分别锁定

资产规范保持游戏米、右手坐标、+Y 向上、默认正面 -Z；人物 rest pose 足底在 Y=0。全球来源按锁定投影转换 X/Z，三维游戏构件保持同一米制，不能为“山看得清”仅把 Y 任意拉伸。相机、窗口 DPI 与浮动渲染原点不改变保存位置、身体尺寸或地形高度。

四种粒度是不同合同：地形 `cellSize/heightQuantum` 表达可编辑表面；建筑模块表达墙体和通行；人物建模栅格表达轮廓和关节；`texelsPerMeter` 表达贴图密度。纹理的一个 texel 不是一个实心几何 voxel。细五官、衣料纹样与砖纹绘在像素贴图上，眼鼻外凸、袖口、帽檐和门窗厚度才按需要做几何。

|类别|首轮 texel density 试样|要验证的结果|
|---|---|---|
|远近地表与大块岸壁|8–16 texels/m|大面积不闪烁，材料边界可读，坡阶保持真实轮廓|
|建筑墙/屋顶、道路/地基/坡道|32 texels/m|窗门、砖木与人物相邻时有一致细节尺度；小字不烘到墙面|
|人物、贴身衣物、军装|128 texels/m|Minecraft 式块状形体上有较细像素五官、衣纹、袖领，不照搬其他游戏模型/纹理|
|特殊近景饰件|按物理尺寸单独准入|只有影响轮廓/辨识的细节提密度，不任意提高全资产纹理|

这些值是带验收的试样，不是所有内容最终定值。以一个 **1.75 m 参考人物、0.5 m 头部正面**为例，128 texels/m 分别约为 224 texels 的高度跨度和 64 texels 的脸宽；这说明“高分辨率像素小人”的起点，不能据此强定所有性别/体型的尺寸。身体形体仍由原创 BodyProfile 决定，几何没有必要细分到 1/128 m。各 profile 的头/手/衣物用相同已准入密度，不能让脸是细像素而衣服是巨大的单色模糊块。

近景采用最近邻放大，像素簇清晰；缩小时必须使用专门的 mip/缩小策略，不能要求所有距离无 mip 最近邻。纹理源是原创像素簇、有限调色方案与明确的色块边缘，不把照片直接缩小作为最终风格。美术允许少量方向明确的中间色和阴影色，不把国家旗帜的有限色目录误当全世界 RGB/光照色彩上限。

## 5. 纹理、光照与远距离稳定性

### 5.1 Atlas 与 mip 的真实代价

以下按未压缩 RGBA8、完整约 4/3 mip 链计算，单位 MiB；实际分配要计 GPU 对齐、数组层数、double buffering 和未释放副本。覆盖/tint 方案暂以两个 R8 mask 为例，不因此强制新格式或宣称所有后端支持相同压缩。

|单页尺寸|RGBA8 无 mip|RGBA8 完整 mip|RGBA8 + 两个 R8 mask 完整 mip|
|---|---:|---:|---:|
|256²|0.25|约 0.333|约 0.5|
|512²|1|约 1.333|约 2|
|1024²|4|约 5.333|约 8|

首样本对同一人物+衣物集合导出三档，记录 texel density、UV 占用、脸/手/衣领最小细节与 GPU 常驻量；预期以 512 档做起点，通过近景轨道检验后再决定。不是每人一页，而是按兼容 body/garment/material family 共用 atlas/数组层，实例传肤色、发色、服色、condition 与 mesh/款式索引。重复国家色不按国家数量生成整套军装贴图；颜色参数不复制商品。1024² 只有实际新增细节或可合并页面数量证明收益后准入。

UV 岛使用 texel 对齐、专用 gutter 和逐 mip 重新填边；不能仅在最高级填一圈就让低级 mip 串入另一件衣服。材质/身体层的 alpha coverage 在各 mip 保存可解释阈值，避免细远景突然裸露或树叶忽隐忽现。首样本可先不压缩，压缩后逐后端验 alpha、像素边缘和色误差。源色彩空间、线性 mask 与 shader 解码明确区分；输出截图差异不能以“都是像素”忽略。

世界贴图寻址锚定稳定世界坐标与面朝向；浮动原点后重复花纹不能滑动。朝向相反的墙面/台阶保持约定方向，不能让一侧砖块镜像后接缝错位。大地表合并面保持 texels/m，不能把一张 tile 拉满整个 chunk。先用同一组 checker/边缘图验证缩放、斜视和 chunk 边界，再替换正式贴图。

### 5.2 真三维光照配合像素外观

使用硬边/分面法线表达 cuboid 面方向，保留真实遮挡和有限阴影。可试简单 diffuse、少量 roughness 类别、2–4 档受控明暗带；这些是 shader 试样，不强制每面只许一种颜色。环境光、有限 AO 与材质响应帮助分辨体积，但不强制全资产提供写实 normal/ARM/PBR 通道。法线贴图不得伪造入口、楼梯或人物可踩表面。

阴影和像素纹理分别设分辨率与稳定规则；阴影跳变会遮住像素细节，优先相机稳定的有限投影、近景关键信号和受控过滤。近景默认不加整屏低分辨率滤镜、强景深、运动模糊或高强度 bloom。可选抖色/色阶仅属于已测试的材质表现，不能用全屏滤镜替代原始像素资产，也不能抖动 pick ID、文字与工具高亮。

Light/Darkness 消费 [LIGHT_AGES](LIGHT_AGES.md) 中已提交环境状态与唯一 SimTick；继续没有每日太阳自转。Light 固定主光，Darkness 较弱环境光和实际可用灯具。自动曝光不能把 Darkness 又抬成 Light；单位颜色、工具指示和读数在两态仍可辨。明暗不修改地形、服装寿命、光照外的新生存机制或菜单画作。已有灯具若要求能源，像素 emissive 也不能凭空点亮不存在的供给。

## 6. 原创高精度方块人物

### 6.1 身体、年龄与版权来源

制作原创头、躯干、骨盆、上下臂、手、上下腿和脚的立体块状形体，按自己的比例、face UV、像素簇与轮廓设计。Minecraft 是用户描述风格的参照，不导入其代码、人物贴图、皮肤模板、Logo 或专有模型。不使用 MakeHuman 网格去体素化后把派生人体归为原创，也不再依赖 MPFB、hm08、targets 或 MakeClothes 进行正式人物生成。

`BodyProfile` 保存米制尺寸、模块原点、共同骨架接口、rest pose、inverse bind、覆盖区、fit envelope 与 mesh/rig/recipe hash。1.75 m 只是一份首样本参考，性别与其他已允许 body variation 的最终尺寸仍待专门准入；若增加合法 profile，明确列出其固定尺寸与衣物适配，不运行时任意拉伸手脚。不同 profile 采用共同 rig 语义和动作接口，门、车座与搬运构件要按其支持范围验证。

**同一 BodyProfile 从出生 0 岁到老死不改变尺寸、骨长、bind、净空或衣物 fit。** PlayerPlacement 初始 simulationAge=18；真实 Birth=0；年龄仍决定成年、学习、服役与生命周期，不能从成人体形推导成人资格。年龄可选择不改变尺寸的脸/头发/老年颜色参数，不制作儿童比例、婴儿缩放或年龄变形目标；也不能因为衣物 fit 相同而免费发衣。

### 6.2 关节与动作

首样本近景尝试 16–24 个语义 joints。cuboid 刚片通常 1 joint，肘/膝过渡的小片以 ≤2 influences 为目标；若 runtime 支持更多 influence，源验收仍按明确上限、归一化和关节范围校验。三角形按**导出后的实际顶点/三角数**计，硬法线、UV seams 和衣片会拆顶点，不能只报 DCC 中的控制点数。

头、胸、骨盆和四肢各有实际 pivot，关节弯曲不让方块像软胶整段拉伸。袖/裤片按相同 joint 语义分段，与 body LOD 配对；关节处采用原创互盖/过渡片，测试最大允许姿态的穿插、缝隙和轮廓。骨架 parent 必须无环，inverse bind 与 rest pose 一致，bounds 覆盖全部合法姿态。

第一组动画为 idle、walk、turn、pickup、carry、place、enter/exit；必要活动追加 farm/chop/sew 等 in-place clip。真实人物位置、路线、货物归属、任务完成和容纳转移来自世界，动画不能结算货物或推 root 穿越障碍。短程足部贴地只在已批准 SurfaceQuery 范围内调整 pose；楼梯/ramp 的脚步不能反向制造通行。搬运货物使用真实已分配载荷的 socket，clip 没有货也不能画一箱并视为交付。

没有在房屋旁砌墙/敲砖的建造人物动作。材料由真实小人送到前侧对应地点；到齐后建筑按自身工期自动施工，详情见第 8 节。动画采样与压缩可复用现有独立库方案或自研有界实现，但本合同不新增、下载或宣称已接入动作库。

## 7. 服装是实际衣物，不是人物换肤

### 7.1 原创衣片与 fit

近景衣物有袖、领、下摆、裤腿、鞋、帽等必要立体层次，与块状身体匹配；布纹、缝线、小钮扣用像素贴图。简单贴身内衣可用共享 coverage 几何/纹理，但宽袖、外套、军帽等改变轮廓的部位不能仅涂在裸身体上。没有复杂实时布料、无限任意衣橱或“每件衣服全身独立模型”的强制要求。

```text
PixelGarmentRenderBinding
  product/recipeVersion -> styleAssetId + compatibleBodyProfiles
  coverageRegions, layerOrder, underlayRemovalMask
  geometryLODs, skeletonInterfaceVersion, atlas/materialFamily
  tintRegions, fixedColours, conditionAppearanceProfile
  source/recipe/runtimeHashes
```

商品与 mesh 是不同 ID：多个合法色款可复用 mesh，不能据此合并实物所有权；同一商品的损耗外观也不能创建新的库存实例。基础衣片、外层与 body 的覆盖移除按明确区域/层次处理，避免身体与衣服共面闪烁。换 LOD 时 body 与 garment 一起切换，覆盖区不跳变；不存在“低级 LOD 漏内衣”的退化方案。

fit 验证姿态包括站立、步行大步、手臂举起、搬运、转身、楼梯、坐入允许的车座与门口容纳；测试 head/body/profile 的正面、侧面、背面、上方与斜视。外壳偏移和关节重叠是资产参数，不能靠任意放大衣服吞掉错误 rig，也不能让袖子侵占通过门的净空。首样本要求完整覆盖且不明显穿插；问题必须回到几何/骨架修复，不将摄像机限制到只看正面。

### 7.2 时期、配色、军装与耐久保留

|阶段/用途|原创表现|世界事实|
|---|---|---|
|前文明最低覆盖|黑内裤；女性另加黑胸罩，全龄都使用相同覆盖合同|共享 fallback，不是可售/可修/有寿命的商品，不满足文明实际衣物需求|
|上古基本衣物|主题色 T 恤、白短裤，少量清晰款式|文明起步实际投入纤维/劳动，交付后才装备；不会自动全人群免费换装|
|后期日常/正装|逐步增加原创衬衫、长裤、裙装、外套、正装与有限鞋帽|已知款式、预算、库存、真实订单与有限衣橱；不是一下子购买所有目录|
|雇主正装偏好|已拥有、适用衣物在视觉上匹配其规范|提高购买优先，不禁止工作、领薪、进楼；没有隐藏宽限期后禁入|
|军装|所有国家使用同一原创版型/几何，国家主题色分 tint 区|使用实际 servingState 与真实 issue contract；法定国籍另存，不按占领区或当前位置染色|

国家身份色与自由物理染色继续分开。换国籍、国家主题或服役关系按既有规则解释 theme binding；不能重置 condition、凭空补一套军装、改变制服所有者或抹除借用归还义务。后期自由色仍由商品/款式与实际染整记录决定，不用 renderer 随机给每人无限颜色库存。

磨损、损坏、维修和替换按唯一 SimTick/真实活动整数结算；LOD、离屏、菜单、像素精度和动画帧率不暂停或加速磨损。renderer 接收 garment stableId、condition bucket 与合法色参数，显示有限褪色/磨损细节。受损外观仍有最低覆盖，condition=0 按权威退役事实处理；不能以撕裂裸露绕过覆盖 fallback，也不以视觉磨损额外扣一次耐久。

原有家庭/公共制衣起步、早期可用纤维链、持续耗损与真实维修/替换需求全部继续。换成原创资产只替换 [CLOTHING_ECONOMY](CLOTHING_ECONOMY.md) 的人物生产绑定，不把完整服装经济重新简化为一张角色皮肤。

## 8. 建筑、地基与矩形施工罩

建筑墙体、厚度、屋顶、门窗、楼梯、坡道、地基、车库、码头和对应时代材质全部自行制作。采用原创模块拼装+必要独立 mesh；模块基准与合法建筑 envelope 明确，实际出口/入口不能由贴图猜测。像素墙砖、木纹和瓦纹保持统一密度；结构不需要按每砖一个 cube 堆积。按用途/时代/文化组合外观时，不改变已批准 footprint、容量、入口高度、合法占用与通行。

近景可见地基侧壁与实体支撑，不只画一圈地面 decal。坡道/踏步具有真实表面，人体与车体的运动 sweep 与可见构件一致。邻楼 eave/栏杆/台阶不能越入旧接入保护域。bridge、矿洞口或 port 的轮廓依各自合同，不因为方块风格自动新增城墙/防御建筑或地下系统。

施工表现依 [ADR 0002](../decisions/0002-building-construction.md)：

1. 人物沿真实配送路线到**建筑前侧**指定接货区，交付真实材料；运输事实在世界事务中确认。
2. 到齐并批准开始后，用原创长方体铁丝网罩，按层向上围起，约几秒的入场动画；覆盖四周与顶部，施工期间整体保持包围。
3. 自动工期中可有受控的预制阶段几何/短动画，不能生成现场砌筑工人；实际施工完成由 World 状态决定。
4. 完成后按层反向拆去，也约几秒。迟到快照/加载恢复由当前阶段与 timestamp 得到合理表现，不重放交付、不延迟世界完成来等动画。

施工罩可以用实几何细杆/线网或已验证 alpha-mask 面；都要测试正反面、远景 alias 和绕转，不把罩做成只在一个角度成立的纹理。罩不授予碰撞/通行，施工 envelope 的占用来自工程合同；它的透明部分也不遮掉真正的入口/运输检查器目标。

## 9. 原创像素水、天空与其他世界物

### 9.1 水体

默认水体使用自己写的有界 surface mesh/shader：稳定世界锚定的像素颜色簇、受控浅深色、少量浪纹/岸边泡沫和有限反射。水面保持实际 stillWaterY；视觉浪幅与频率是表现参数，不改变海陆、高度、航道或地基支持。水下可见地面由 effective 高度决定；WATER 格的浅色/可见底部不自动变可站立 LAND。

优先一个不依赖全 FFT 的低成本版本，在 360° 镜头、浅水、深水、坡岸、人工直岸、船与桥上验收。必要时只加入有限透明/深度衰减，不默认全场景 refraction/reflection 多次重画。泡沫从同版有效岸线/接触面获得，不能持续引用创建时岸线，导致自由编辑后浪花浮在陆地上。

固定版本 [Abyssal Ocean](../research/OPEN_SOURCE_STACK.md) 的原始代码、MIT notices 和已测试数学保留；其频谱/IFFT 可作为后续可选波形资源，通过独立 style/budget 准入才用。保留源码不表示继续以写实原生移植为硬需求，也不能把新的像素 wave shader 称为已有 Abyssal GPU 实现。

### 9.2 天空

天空优先原创分段色阶与简单云形的真实方向采样（解析天空或小型 cube/方向图）；云有自己的受限表现时间，不驱动天气灾害。任意 yaw/pitch 下方向连续，处理 cube 接缝、天顶/地平线和曝光。Light/Darkness 使用各自已准入天空/环境 profile；不默认为每日太阳/月亮轨道。既有 PureSky/HDRI 合法源留作历史/可选参考，不能在未制作像素天空时，把旧 8K 摄影天空冠名“像素风完成”。

### 9.3 八个主题与沙地：三层原创生态资产

用户本次明确的目录是**雪原、花甸、枫原、樱野、湿地、荒原、圣原、炎地八个主题，另加沙地**。地皮、装饰小植物、功能树分别定义；此前研究中的十四类提案没有被采纳，不能据此增加首发必选目录。未指定树种的圣原采用原创圣树，炎地首版无树。下面是生产设计，没有已制作的主题模型、完整果树生长或树光 GPU 实现。

|主题|原创地皮|纯装饰小植被|功能树与特别表现|
|---|---|---|---|
|雪原|像素雪白地皮，受控冷色阴影与雪块边缘|少量与雪地一致的装饰簇，不添加食物/作物|原创松树，完整树干、分枝与针叶立体簇|
|花甸|鲜明草地与像素花色的地皮组合|较多原创热带花小簇；花属于装饰，不发食物|较多原创果树；逐渐周期长果、成熟变色并形成真实可食果量|
|枫原|与枫叶主题一致的地皮色块|有限同主题装饰簇|原创枫树，叶冠/枝干从四面成立，不靠正面枫叶贴片|
|樱野|与樱花主题一致的地皮|有限装饰簇与不堆积成资源的花瓣点缀|原创樱花树，零星、缓慢、有界落瓣|
|湿地|湿润地皮表现；不凭材质改变真实干湿、水深与可航行性|原创芦苇小簇，纯装饰|原创菩提树；位置、根部与实际支撑匹配|
|荒原|savanna 风格的荒地像素地皮|原创枯草小簇，纯装饰|原创胡杨树；不替换成另一套未指定的稀树草原树种目录|
|圣原 Sonnheide|圣洁、克制的像素地皮配色|有限同主题装饰簇，不附赠新的商品或魔法植物|原创圣树，树体内源发光且受控照亮附近材质|
|炎地|原创火山表面，固定少量熔岩色块/裂隙表现|首版无必选小植物|首版无树；不因熔岩扩展喷发、流体或灾害系统|
|沙地|原创像素沙地|**没有小植物**，装饰散布配置必须为空|原创椰子树；不自动混入枯草、花、芦苇或灌丛|

除用户指定的热带花、芦苇、枯草外，表中的“有限装饰簇”仅给同主题原创美术组合的范围，不新增必须列出每个物种的产品目录。装饰密度必须受控，地形边界可读，不遮住入口、接货点和工具反馈；沙地的空集合是明确合同，不能用通用草地散布器的 fallback 补草。主题颜色也不能向邻格扩张而改变已提交的材料或干湿状态。

|资产层|运行绑定与来源|不能产生的事实|
|---|---|---|
|地皮|原创像素纹理/面材质配方，绑定已提交的主题/表层材料与实际高度面；顶面/立面密度匹配|不抬高地面，不造湿格，不发粮、木材、矿物或果实|
|装饰小植被|原创有限小簇 mesh；按 chunk 与稳定显示种子散布，几何贴合真实表面|没有可售库存、果量、可采木材或隐含碰撞；不消耗仿真 RNG，不按每帧重新抽位置|
|功能树/果实|原创树干/枝叶/果实原件与 LOD，绑定真实 `TreeRef`、版本和可信生长/采集状态|画树冠不等于创建树，画果子不等于造库存；不靠贴图色彩推断所有权或成熟量|

主题涂抹与实际树木放置/生长由生态事务合同区分。地皮和装饰变化本身不发售木材，也不把有树图案的 tile 当作实际 TreeRef；合法树木产生有明确来源/阶段，renderer 消费其状态。湿地地皮不是第二份 WATER 判定；芦苇/菩提的显示锚点从同 revision 的实际表面获得，不能为让植物看起来湿润而在碰撞层偷偷改海陆。雪原表现不附赠季节、结冰或新的低温生存机制。

功能树的 trunk、branch、crown 和可见果实是原创真实三维原件：侧面、背面、上方与低角度都有体积，近景不能用面向镜头的整树 billboard 作为最终模型。叶冠采用有限立体簇及必要 alpha-mask 小面，优先控制透明混合；整树近中远 LOD 保留立体轮廓、根部、果实阶段与原 TreeRef。远景可减少分枝/果实代表网格或合并同树的果簇，不把整树切换为朝向镜头的纸片。切 LOD、相机绕转、chunk 重载不会再生木材/果量或分配第二个 TreeRef。

树木 manifest/生成配方除原创 source/hash 外，要列 tree-definition 版本、根部锚点、稳定 bounds、可采/果树身份、像素材质密度、LOD 映射、果实 sockets 与实例上限。叶片、果实和装饰引用自己的源/配方，不从第三方模型体素化后冒称原创。正式原创生态资产制作按现有施工计划放在 foundationGate 后；基础阶段只提前确定这些合同与预算，不增加本轮新资源下载。

**主题构图。** 地皮作为低对比连续底色，小植物形成疏密不同的团簇和花带，树冠成为较大的体积节奏。不要把每一格填满高饱和色点；清楚留出可走的地面、根部和树旁交互区。雪原用蓝灰阴影承托深松冠；花甸在绿底上形成多色热带花簇，以空隙露出挂果枝；枫原用金橙红冠色和暖土形成主次；樱野的粉冠、浅地与零星落瓣保留深枝对比。湿地以深绿底、竖向芦苇和菩提宽冠形成层次；荒原赭黄/枯草与胡杨不规则冠形保留更大裸地；沙地由沙色与椰冠的疏影表达空旷，不补草。

圣原由深地、深树体与少量白金发光部位构成，亮部集中到枝叶与附近小片地面，不把所有树涂成白灯泡；炎地用大面积暗岩、少量暗红裂隙和更少熔岩亮面形成对比。相邻主题的过渡只能在已提交格内处理材质/装饰疏密，保存真实边界，不能以颜色过渡改变高度、沙地资格、水深或树种。所有花带、冠色变体和视觉错落使用稳定美术seed；反复载入与绕视不重新撒花、换树或换果期。

### 9.4 果树：真实逐渐成熟驱动外观

花甸的果树有周期结果表现，但周期、增长、成熟与可食条件属于可信树木/生态调度的仿真状态，使用 SimTick；不能以 GPU 帧数、表现时钟、相机可见性或随机叶色推动产量。果实表现绑定原 TreeRef 和真实 fruit cohort/数量、maturity、已采摘/损失及状态版本。可信调度和采集尚未接入时只能显示标明状态的样本，不能以渲染动画声称可食生产闭环已经完成。

逐渐长果表现来自实际 maturity：从小果到准入的成熟尺寸，按该果种原创阶段配色逐渐变色。成熟可食和未成熟的可食量由世界明确区分；看到成熟色不直接让角色加饱食。真实采集事务从树上可采余量扣除并转入唯一食物位置/库存，采走之后外观跟随新快照减少；renderer 不以果实掉落、动画 marker 或点选替代出库。

不要求每单位果量永久分配一个 GPU 实例。按固定 sockets、稳定排序与明确映射选择有限代表果/果簇：fruitQuantity=0 不显示未收获果；成熟代表只取对应真实成熟 cohort；数量变化可按有界等级/密度显示，准确余量仍来自检查器。不能每个 LOD 都将上限代表数当作实际产量，也不能将一个代表果点采后直接创造其“代表的”全部食物。不同果实 cohort 同时存在时，颜色与数量映射保留其阶段比例，不把全树统一变红当作全部成熟。

成熟/采摘后，下一真实结果周期按照树木定义重新生长；换主题、存档载入、相机远离再回来不重置或补满周期。已有树状态保存/快照缺口须在生态实现中处理，不将当前纯美术配方冒称已可续跑的果树经济。

### 9.5 樱花落瓣、圣树发光与固定熔岩

**樱花落瓣。** 只作零星美术效果，用原创微小薄片/低面数立体瓣及缓慢有界路径；它不消耗树木/商品、不堆积为可采资源、不阻挡人车，也不碰撞或参与拾取 ID。只在近景可见樱树附近发射，绑定原 TreeRef 与轻量表现种子，不使用仿真 RNG。首样可试每近景树同时 ≤4 瓣、全场 ≤128 活跃瓣，寿命/范围有界，按距离逐渐关闭；这是待测表现预算，不是最终容量。离屏不维护逐瓣粒子历史，返回时也不补发一大段积压。降低动态选项将落瓣设为零或保留静态花瓣点缀，树冠仍完整；不能用持续高密度飘雪式粒子表现“零星”。

**圣树内源光。** 原创圣树的树体具有稳定 emissive 区域，光来自树自身，不把它伪装成消费灯具，也不凭空送电、灯具或灯具能源。renderer 从同版 TreeRef/合法树状态产生有限半径、衰减和强度的真实局部树光贡献，照亮附近地皮、树干、人物/衣物和建筑材质；只有树纹理发白而邻近材质完全不受光不算完成。树光不改变经济产率、成熟速度、生命周期或宗教资格，实际灯具仍按原能源合同工作。

发光资格先读取已提交快照中的 TreeRef/generation、treeRevision 与真实存活/伐倒状态，**先于 LOD、光源排序/迟滞、远景聚合和低画质策略**。死亡或伐倒后，首个呈现该 revision 的快照必须将该树全部 emissive 系数归零，移除近景局部树光及远景聚合中的该树贡献；尸树/倒木/残桩可继续显示，但不得保留活树的发光材质。不得等待旧 proxy 被剔除、mesh 重建或平滑灯槽退出来停光，也不得以“低画质保留 emissive”保住死树光。若存在 bloom/光照历史缓存，同一 revision 要使该树的旧贡献失效，不能借历史缓冲留下持续光晕。

异步 mesh/light 工作必须携带 TreeRef/generation 和状态 revision，旧活树结果不能重新点亮已死亡/伐倒的树或复用其 ID 的新对象。死亡资格是不可由表现改写的硬关口；只有仍有资格的活树才使用迟滞/亮度过渡来避免预算切换闪烁。镜头靠近/离开、LOD、低画质、暂停和资源重载都不能复活树、重新发光或改变其木/果存量；神力把地形填回原高度同样不重开旧死树光。

圣感来自克制配色、局部明暗、稳定树冠轮廓与受控周围受光，不靠全屏白、强烈 bloom、频闪、脉冲或高密度光粒子。发光强度/半径、每块与每帧局部树光数量、屏幕贡献、曝光与 bloom 上限进同一 render profile；不能一棵树附一个无限范围光源。密集圣树林采用稳定排序、迟滞与平滑的受控贡献/远景聚合，限制实际受光计算和总亮度，不随机抢灯槽使树光闪烁，也不把聚合光无限灌入全局天空。最低预算下保留稳定 emissive 和受控近景真实材质受光，降低动态只关闭非必要运动，不把“发光”降成闪烁替代品。Light/Darkness 中仍遵守世界曝光与阅读边界，圣树局部光不把整幅 Darkness 强行抬亮。

**炎地熔岩。** 火山地皮只用固定、少量熔岩表面区域/裂隙的原创像素颜色与有限 emissive；首版不流动、不喷发、不扩散，不加烟火粒子作为必选效果。它不是 WATER、不参与 SEA/LAKE 判定，不改变海床、水深或碰撞面，也不自动伤人、产热能/矿料、毁楼、刷库存或触发灾害。若以后要求其中任何物理/经济后果，必须另有明确用户决策与世界事务实现；本轮固定表现不暗藏新规则。熔岩亮度受局部材质与同一曝光上限约束，不与圣树一起把场景照成全白。

生态成本独立记录实际树/果实实例数、装饰 patch 面数/覆盖、各档 LOD、落瓣活跃数、局部树光数量与光照 pass 成本。主题切换、果实量/成熟变更、采摘后空树、沙地无小植物、樱林降低动态、圣树林 Light/Darkness 与 dense worst-case 都有明确验收状态，不能只看单棵树静态正面截图便通过。

### 9.6 其余世界物

马、车、船等采用同一块状轮廓与像素密度体系，保持实际货物 socket、运动净空和经济实体 ID。若后续筛选开放资源，先逐项授权/来源准入再做明确派生，不强制本轮增加素材库。

## 10. 360° 相机、LOD 与透明拾取

透视相机 yaw 连续 360°，pitch/距离限制只用于避免穿地和不可读极端视角，不锁固定等角。近景可见完整前后左右几何、帽檐、袖腿和屋顶；屏幕空间轮廓线可作辅助，不能拿轮廓线遮住不存在的背面。缩放围绕当前真实命中面，地形改变后焦点也要按明确规则刷新，不能继续命中旧 Y=0 平面。

LOD 用实际 drawable 像素的投影尺寸，HiDPI 的逻辑 UI 点与 GPU 像素在一处转换。首样本沿用高度约 160/40/10 px 的可调阈值及约 20% 迟滞，再由实际画面/成本准入；这个规则不能用于精确承诺观察距离。

|档位|人物/衣物外观|不变的事实|
|---|---|---|
|近景|完整原创块状身体、关节、衣片、细像素与必要脸部细节|BodyProfile、人物 ID、衣物实例、寿命、位置/任务|
|中景|减少关节/细片、合并材质，仍是可从四周看的 3D 人物|不能换衣、丢掉军装身份色、删除必要覆盖或改变实际净空|
|远景|低面数立体代理；极远允许稳定点/群体标记|代理仍对应稳定实体/群体查询；不停止模拟或假称完整近景骨骼负载|

body 与 garment 采用配对 LOD，转换保持 pivot、bounds 和覆盖；不在最后一帧才随机重烘每个角色。合批按共享 mesh/material/skin-palette 方案，而不是按同国家把人物混为一个身份。LOD 过渡可用有界、世界锚定的 alpha-mask/短时间替换，必须检验阴影、拾取和 coverage 一致；没有验证前优先迟滞硬切。

拾取先按当前工具/激活图层决定目标域，再用同 revision 的权威表面/实体空间查询，必要时做 ID pass。材质、玻璃、海水、施工网、树叶、粒子和矿物可视化曲面不自动抢走所有输入：

- 地形/海陆编辑命中该工具明确的真实表面；水面与水下地面不同，不能在透明深水点击时随机选两者之一。
- 人物/建筑选择只命中该选择域的真实目标；透明玻璃按明确透视规则，alpha-mask 叶片/衣物与 ID pass 采用相同 coverage。
- 网罩和水波的颜色 pass 不写成假的经济实体；罩内建筑可通过明确选择规则打开工程页。
- 异步 pick 包含 World/session、snapshotRevision、camera/viewRevision 与 viewport generation；命中旧 EntityId generation 或旧地形版本则丢弃/重新查询。

浮动渲染原点与 GPU ID 格式不写进存档身份。UI 先处理自己的命中，工具再消费 world hit，相机最后处理剩余输入；不能拖菜单时又改地形，也不能将点选做成 O(总人口) 每帧全体 ray test。

## 11. 原创源、烘焙与 GitHub 恢复合同

新增正式人物/衣服使用项目自己的原创 source：可审阅的 DCC 文件或参数配方、像素纹理源、rig/fit 定义、动画源与导出配置。沿用 source→中间交换→项目运行包的分层；运行时不加载 DCC 工程，也不导入网页/游戏引擎项目。烘焙像素 AO/色阶/法线等必须标出配方、依赖来源与输出范围；不能以“烘焙了”消除原素材许可。

预期内容结构如下，是生产产物合同，不要求先建空目录：

```text
assets/source/original/characters/<body-profile>/     原创形体、rig、像素纹理源
assets/source/original/clothing/<style-family>/      原创衣片/覆盖/军装与纹理源
assets/source/original/buildings/<module-family>/    原创体块、入口/地基/坡道
assets/manifests/<content-family>.json                source/hash/recipe/license/status
data/content/...                                     逻辑定义、BodyProfile/Fit/LOD 映射
运行缓存或包输出                                     可再生成，不替代必要 source
```

manifest 区分 original/third-party、作者/权利记录、原始文件、固定版本、SHA-256、工具锁与生成关系；没有授权文本就不擅自给原创建筑/人物或画作加 CC0/MIT。保留 MakeHuman 历史原件与 notices，明确 retired-for-new-characters；新运行包依赖图不得再隐式扫描/打包其人体和衣物目录。项目原生库、字体和合法归档继续遵守各自 notices。

Git 保存小源、定义、配方、manifest 和 notices；必要大 DCC/纹理/归档按项目 Git LFS 或本项目 Release 托管，固定文件名、URL/hash、恢复工具与离线失败说明。本机缓存、DCC 安装和未提交的导出路径不能是构建前置。编译器先校验米制/轴、finite 值、indices、bounds、rig parent 无环、bind/权重、coverage、LOD 配对与入口 marker，再产 runtime 包。依赖版本固定不等于跨平台 byte-identical；输出 hash 能否复现要在工具链/环境测试中证明。

## 12. 首轮成本预算必须可测

这些是首样本**上界目标和待验证假设**，不是已有性能结果，也不表示将人口上限设为可见渲染数。

|对象/资源|首样本目标|记录方式|
|---|---|---|
|近景完整人物+当前衣物|2–8k 导出 triangles、16–24 joints、通常 1/局部 ≤2 influences|列 body+各 garment+附件总数，包含 UV/硬边拆点|
|中景人物+衣物|约 0.5–1.5k triangles、8–12 joints 或已验证刚片方案|测成批采样/上传/绘制，不只测一个 idle|
|远景立体人物|约 72–300 triangles，极远改稳定点/群体标记|列数量与档位，不以全点阵冒充完整人物负载|
|普通住宅|约 2–12k triangles；大型公共楼按必要模块另定上界|计地基、接入、屋顶和入口近景，不只计墙盒|
|人物材质页|首验 256/512/1024 三档，共享页和 mask|测实际 GPU 常驻、峰值、导出文件/上传量|
|地形 chunk|64² 首样本，按实际 exposed faces 与拼缝计|同平地/棋盘高差/长山脊/峭壁场景记录 worst-case，不只测平地|
|主题植被/果实|装饰小簇与功能树分开，树/果簇各 LOD 为有限原创立体 mesh|计原 TreeRef、显示果簇、真实余量/成熟比例与空间覆盖；沙地装饰数必须为 0|
|落瓣/圣树光|近景稀疏落瓣、有限局部树光与强度/半径上限|计 active petals/light slots 与 shader/pass 成本，降低动态和密林不能闪烁或全屏泛白|
|动画 pose 上传|可见近景独立计，远景按允许频率降采样|24 joints×3×4 float×250 人约 0.275 MiB/帧，仅示例，不含任务/instance/双缓冲|

总体先以 1080p、60 fps、16.7 ms 作为可玩目标；CPU 与 GPU 并行，不能将各子项预算随意相加冒称已达标。首轮建议 GPU 世界/阴影/水体合计不超过约 10 ms、UI/后处理保留约 2 ms，CPU render preparation 约 4 ms；仿真与导航独立记录实际 tick/峰值及竞争，最低硬件/平台尚需明确后实测。超过时首先缩减可见复杂度与低收益 effects，不改变经济结果、真实高度或衣物 wear。

建立 100/1000/10000 个真实实体贯穿负载，报告每档完整/中景/远景/离屏数量、活动任务、配送、衣物、导航查询、真实提交和绘制数。可用“250 完整、1000 中景、其余远景”作为压力分布试样；这个分布不证明 10000 套全骨骼，也不证明完整经济或最终人口规模。记录 CPU/GPU p50/p95/p99、draw calls、triangles、常驻/峰值内存、shader/资源流送卡顿与编辑 dirty chunks；不使用仅更新坐标的 benchmark 代替游戏场景。

## 13. 验收次序与反例

|关口|必须看到/测到的证据|必须失败的反例|
|---|---|---|
|A：真正形体|原创参考人物/基础衣物/坡地住宅转台，0/90/180/270° 与上下斜视均有体积|背面缺面、旋转时纸片朝向相机、整屏 pixel filter 才有像素感|
|B：同版地形|升降 hill/mountain/peak、改 LAND/WATER 后 mesh/collision/pick/nav revision 一致|人物踩旧平面、编辑后旧 GPU 网格继续显示、岸泡沫留在旧位置|
|C：真实接入|0.5 m 高差不能无条件走过；完整人门/前侧材料路/车库车道含真实坡道/楼梯|贴图楼梯、车走人行踏步、单独房屋等未来邻居修路才有效|
|D：人体与衣物|同 profile 的 Placement18/Birth0/老年同尺寸与 fit；动作组所有角度覆盖无明显穿插|缩小 0 岁、换 LOD 漏内衣、衣服换色重置 condition 或实例|
|E：身份/经济|已交付才装备、军装共用 cut 按 actual servingState、缺正装照常工作/领薪|当前位置或法定国籍替代服务国、按人口定期送衣、UI 换装创造库存|
|F：像素稳定|三档 atlas、不同 DPI、近远/斜视、chunk 边、Light/Darkness、水透明命中录像及数值|近景清楚但远景闪烁、mip 串页、暗态自动曝光为亮态、旧 pick 命中新实体|
|F2：主题生态|八主题+沙地三层映射；树果360°/原 TreeRef/真实成熟和采后余量；零星落瓣降低动态；圣树实际附近受光；固定少量熔岩|沙地补草、装饰发粮木、换 LOD 补果、果色当库存、整树 billboard、树光频闪/全屏白、熔岩偷偷伤人或流动|
|G：规模与恢复|完整工作负载计数/帧时间/峰值；干净 clone 从本项目源托管恢复并重建|只测 idle/坐标更新、源仅本机、退役 MakeHuman 仍潜入 runtime 包|

先做 A–C 的可运行最小切片，再做 D–E 的人物/衣物实际映射，最后做 F–G 的采样与规模；shader、美术与经济必须在这些边界对齐。现有 headless Oracle 可继续作为事务/订单/年龄规则的局部证据，但不能替代新的 GPU、运动与资产验收。
