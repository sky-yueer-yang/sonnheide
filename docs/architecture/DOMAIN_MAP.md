# Sonnheide 领域地图、27章需求追踪与实现门槛

基线：[完整设计 v0.6](../design/Sonnheide_Complete_Design_v0.6.md)，2026-10-06。本文将需求转成领域边界、约束与可执行验收任务，不能替代源设计。用户本次新增“无游戏引擎、尽量利用合适开源部件、建筑全部自行制作、文件GitHub托管”优先于原稿中可使用Unity/Unreal等引擎的候选描述。

原稿提到199条既有追踪、若干JSON目录、TypeScript规则参考和国旗工作台，但本次只提供这一份Markdown；不能假称那些配套文件已取得、已迁移或已验证。仓库中新提取的目录和章节索引只追踪此基线。下面的 `DM-xx` 是本轮章节验收组编号，`INV-xx` 是关键不变量编号；不冒充原稿199条旧ID。

## 1. 第一性边界

Sonnheide是单机的人类文明沙盒。玩家全知观察、合法编辑与有限Divine Hand；人、物、知识、机构通过真正的时间、任务、法律、空间和资源产生后果。国家和文化可以从前文化社会开始；没有全球“已进入现代”开关。

排除野生动物生态、其他智慧种族、怪物、魔法战斗、疾病传播、随机天灾/灭世、复活、山地/高程编辑、空军/铁路/飞机、现代军火、建筑内部漫游、实时股票/外汇、多人服务器。马是被拥有的MountAsset；太阳能自动车是后期民用运输能力，不能外挂现代武器。没有永久城墙/城门/塔/堡垒。不存在独立Market、Warehouse、TownHall三个城市管理对象；一个CitySquare承接行政/唯一逻辑仓储/装卸/公共空间。

这些边界必须同时体现在定义目录、命令入口、存档校验、资产元数据和UI中。只隐藏按钮而允许通用JSON覆写不构成遵守。

## 4. 关键不变量登记

每个INV需要三种落点：提交时约束、加载时约束、至少一个正/反例测试。部分昂贵图约束可增量检查+定期全审计，但不能完全依靠UI。

|ID|必须成立的事实|最低反例测试|
|---|---|---|
|INV-01|稳定ID不复用；实体引用按ID不按名称|同名、改名、作者死亡后新生人不能篡换关系|
|INV-02|查询/预览不改变World/RNG/日历|重复打开检查器之后权威hash相同|
|INV-03|同commandId相同payload幂等；不同payload冲突|重试不扣二次；更改数量用旧ID拒绝|
|INV-04|不合权限/修订的提交不产生半效果|扣材料后校验失败的全状态对照|
|INV-05|货币分录借贷相等、整数/不溢出|最大数值/负值/受限余额不能静默环绕|

## 5. 跨领域事务及真正的依赖断点

### 5.1 Primary Genesis / 国家与城市正式化

读集：GenesisNode/model版本/当前阈值；创始人和成员文化/语言；State/Settlement采纳计划；现有名字序号/旗与库存。

写集：新RootLanguage → 创始人正式名 → 新Culture/共同GenesisEvent → 成员稀疏文化/语言/姓名 → State官方文化/行政语言/phase/正式旗 → SettlementCore/CitySquare登记与原库存产权 → City官方文化 → 正式直属城数量与合法升爵。

断点：名字需要语言、文化默认名需要名字、正式State/City需要文化，必须先RootLanguage再正式名再Culture；不能把循环需求简单画成三张“待做”卡。大群成员准备可批量，但发布点保证所有正式对象不变量。Secondary另用只创建Culture的事务，不共用一个带optional bool的“可能建语言”后门。

### 5.2 造陆 / 水图 / 港口 / 航次

读集：天然位、已完工四邻、材料/劳动、占用/泊位保护、Chunk/全局导航版本。写集：工程预约和进度；施工障碍；完成覆盖层/消耗分录；导航dirty与门户替换；Port footprint/航道证书；船舶分段验证/改线。

断点：水图删除可能拆全局分量；“局部刷新”只描述几何工作量，不能证明连通。全局粗门户图受影响组件重算、过期路线停合法点、预算耗尽返回PENDING不是NO_PATH，方案见 [SIMULATION.md §7](SIMULATION.md#7-地理格网造陆与导航的拓扑难点)。

### 5.3 生产线 / 订单 / 劳动 / 知识

读集：产品family/compatibility、知识Access/Competence/License、工厂槽、材料/资金、有效订单、劳工时间。写集：槽占用、工装预约/已发生投入、停机改装、任务/实际生产设备与安装。

断点：研究成果不是设备；许可证不是技能；筹款不是完成工装；生产线数量不是额外劳工。READY之前不生产，订单取消不退已消耗工装；同slot新方案不叠旧方案。

### 5.4 教会分裂 / 受限财产 / 成员 / 官方关系

读集：根允许边界、原冻结Charter、争议/组织/持续时间、地方资产法权、债务/捐赠限制、成员自愿/合法选择、国家官方关系。

写集：同根Denomination与新Charter、裁决转移资产/债务、服务/员工合同接续、成员归属、国家批准/过渡记录、分裂史实。

断点：追随者数不产生独立财政；改成员不改中央财产；新教会不能回写旧Charter。长期计数窗口和最近分裂冷却存档，不因载入清零/跳过。

### 5.5 Army征募 / 补给 / 包船 / 占领 / 和约

读集：真实成年居民、民用保留劳力、训练/装备/工资、军需货权和路线、Port船位/泊位、军队感知、持续控制、条约同意/保留权。

写集：Person服役/工作时段、Army成员/供给/订单、真实粮弹预约与消耗、乘客容纳与Separated、Occupation、主权或附属条约/法域/税务/补给过渡。

断点：兵不能作为独立另一人口池；航次不能因目的港失陷删乘客；占领不能直接覆盖city.state；和约不必吞并。城市切换法律需要过渡计划，大交易先准备后原子生效。

### 5.6 人才/家庭移民 / 住房 / 知识传播

读集：申请人/亲属、真实准入证据、已有知识与保密/许可、目的地住房/岗位/预算/语言、法律/边境/路线。

写集：唯一申请与承诺、住房/费用/岗位预约、航次/行程、实际到达人口/消费/劳动、临时/定居/主臣籍、个人技能/合法文献传播。

断点：动机不是资格，已批不是到达，记忆不是整家实验室，文化融入不是瞬间改名；工作/教育席位保留到何时和失败返程规则必须配置并测试。

## 7. 用户要求对技术和资产的覆盖

- 2026-10-06建筑施工追加要求见[ADR 0002](../decisions/0002-building-construction.md)：前侧材料实送后本体自动工期，无人物砌筑劳动；原创矩形铁丝网逐层围起、施工全包围、完成后反向撤除。原稿现场建房人工条款按ADR局部覆盖，填海等劳动保持独立。

- 原稿的21.7 TypeScript目录是领域参考，本项目改用C++20实现同一职责，不能照抄几百个空文件作为进度。
- SDL3提供平台/输入，bgfx提供图形API抽象；自研World、调度、提交、经济/社会/军事、场景/相机/资源/交互，保持无游戏引擎。
- 原稿20.10允许Unity/Unreal的选项被本次明确无引擎请求覆盖。Three.js也不作为生产核心；如后续原型使用必须标明展示边界。
- 人物、水、植被/声音/纹理/辅助工具可评估开源与允许再分发许可；每项版本/许可证/署名/原始来源与修改记录进入资产清单。
- **所有建筑及其模块由项目自己制作。** 开源建模软件、纹理、算法可以用于制作，但外部现成建筑mesh不作为正式建筑池；用户需求覆盖任何“下载建筑包快速填满”的路线。
- 自制资产必须同时通过视觉和功能metadata检查：footprint/容量/入口/遮挡/LOD一致。Port必须有海侧/陆侧/泊位定义，CitySquare各部件仍映射一个逻辑对象。
- 源码/配置/文档/测试/工具/自制建筑源文件/可合法再分发的第三方文件/许可证全部进入GitHub管理。大二进制按仓库LFS/发行包策略管理；不能把下载URL当成源文件已托管，也不能把有禁止再分发条款的资源上传。
- build缓存/个人机器临时存档/secret不作为交付源文件。发布或push完成程度以实际GitHub结果报告，文档中的“目标托管”不代表已经上传。

## 8. 从需求到可执行验证

### 8.1 三层证据

1. **规则级**：无副作用拒绝、幂等、revision、整数数量、四邻造陆、完整Port footprint、epoch等有限函数/事务。
2. **场景级**：跨城市公共生存、建线/运输/研究/安装、传教/移民/帝国、征募/封锁/占领/附属。验证完整因果链和失败恢复。
3. **工作负载级**：100/1000/10000人、多城、贸易/宗教/战争同时运行；CPU/GPU/内存/路径/队列及长期平衡指标。

三层互不替代。内核测试通过只证明其覆盖的命令和状态；构建成功不能证明客户端好看，截图不能证明账本，定义计数不能证明技术行为。

### 8.2 三条完整历史的场景检查点

|故事|按顺序验证的状态/资源变化|成功判据|
|---|---|---|
|前文化→农具革命|公共粮/住屋 → Genesis → 根语言/名/文化 → 正式City/旗 → 研究/存档 → 运输 → 工装 → 设备 → 安装|每个阶段可归因；无大学自锁；未安装仍基线；Secondary语言数不自动增加|
|知识宗教→跨国学者→帝国|玩家根/先知 → 奉献 → 教育合同 → 合法学者迁移 → 语言/文献传播 → 成员宪章/同意 → 玩家批准 → 同根分裂资产裁决|每项有资金/路线/资格；根/章程不改；无全图科技；帝国不合并各城库存|
|集团→港口军运→附属和约|当地利润/税 → 港区逐格造陆/Port → 真实征募/武器/补给 → 包船 → 封锁/破产 → 公共托管 → 附属条约|守恒/现金流；船仍归Port；弹药有限；客户货保留；败国StateId/城市/文化存在|

测试工具可构造高年代/资源初态来缩短回归，但夹具标记为测试初态；不能将手工配置的Temple/帝国/改信人口报告为自然模拟成绩。

### 8.3 每次PR/阶段交付需要的追踪字段

```text
requirement_group: DM-xx
invariants: [INV-xx, ...]
implementation: actual source symbols/paths
evidence: test/scenario/measurement file and command
state: specified | kernel-covered | scenario-covered | measured
known_gap: concrete remaining behavior
```

后续可将这结构放入机器可读追踪，而不是现在凭空填写“已通过”。本轮 `data/requirements/chapters.json` 追踪27章来源；需要逐条需求化时从这里扩展，并维护唯一ID/自动引用检查。既有199条追踪未提供，应保留这一事实。

### 8.4 实现优先级由缺口决定

最高优先先证明不变量与单一事实：预约/原子提交/身份与位置/地图冻结/Port/路径失效。随后做公共生存与跨城物流让空间、劳时、账本闭环；再做Primary/Secondary及知识安装让社会系统不靠魔法加成；宗教/法律用同一权限/财政/合同；军队用同一真实人/物流/空间；成熟企业/金融接入已经工作的闭环。

每个新领域接入时都运行前面已有场景，特别是保存续跑/镜头变化/企业退出/路径封闭。不能让后期功能通过给早期系统插入免费资源、自动身份转换或全世界旗标来“完成”。

详细调度、拓扑更新、性能目标和spike门槛见 [SIMULATION.md](SIMULATION.md)。
