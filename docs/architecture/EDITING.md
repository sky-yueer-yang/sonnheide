# 全域编辑与受约束预览

状态：设计合同、浏览器夹具与独立 C++ 交互 oracle。本文件新增的法条参数是对源目录的有界编辑表示，**不是已完成的税务、宪制投票、条约执行或完整经济系统**。源设计 v0.6 保持原样；最新人口、身体和分类清理约束继续按 ADR 0005 执行。机器定义见 `data/interaction_schema.json` 的 `editing_contract`。

## 1. 真正要打通的边界

信息页必须让玩家看懂、找到并实际修改允许修改的状态。把所有字段放成 JSON 编辑器会破坏身份、财产和历史；把所有制度都做成只读又失去用户要求的编辑能力。因此同一页直接呈现三种可操作关系：可自由设定的神意编辑、需要文明真实程序的制度/资产操作，以及仅影响观察资料的备注/收藏。事实栏可以点击追溯来源与打开合格操作，不提供伪造事实的输入框。

每项编辑必须有稳定目标引用、字段范围、专用命令、预览结果和历史。玩家可以把国家改成另一种宗教地位，可以调整法条，可以修改人物的六项性格；这些操作不能顺带赠送技术、自动转信、把仓库货物归给新主人或把新生儿改成成年人。

必须同时守住四个不变量：

1. 观察与语言切换不写 World；所有模拟修改经过单写者事务。
2. 预览不等于批准；提交再次检查相同目标、世界版本、能力、宪制与条约条件。
3. 名称、符号与偏好不改变已经发生的历史、身体规格、真实库存和身份来源。
4. 成功编辑记录明确的前后值与神意/制度来源；失败不留下半改字段、重复收费或假历史。

## 2. 玩家如何使用

底部工具栏的“点选”工具进入地图观察；人物、国家、建筑等直接打开同一信息页。该页概览先显示对象的关键事实，编辑区按实际领域分组。人物的六项性格使用带数值的滑杆；国家的宗教地位使用四个完整文字选项及有效宗教对象选择器；法规使用分组法条列表、搜索与少量明确的选项/百分比/生效日期控件。

普通玩家不用键入实体 ID、law ID 或 JSON。宗教、国家、法律的名称是可点击关联；目标选择器只列当前世界可用且类型正确的对象。高级排错页才显示 typed 引用与机器键。只读字段显示简短原因及“查看来源”/“打开合法操作”入口；能力未解锁时显示具体缺少的能力并链接其信息页。

表单先在玩家视图中保存草稿。编辑后的“预览变更”列出：旧值→新值、受影响对象与统计口径、直接后果、尚无法估计的后果、批准/材料/预算/能力条件、过渡和退出安排。财政预测未接入时显示“未接入”，不能显示 0。允许快速操作的纯名称/备注也保留撤回草稿；提交后的世界变更通过新的反向命令处理，不能删除已经记录的历史。

复合表单必须全部验证后一次提交。国家名称、宗教和法条不能先改一半再发现另一半无权修改。原型的复合草稿是夹具模型；独立 oracle 的三个编辑命令分别验证自己的有限领域，生产复合表单需一个覆盖全部子命令的领域事务，不能由 UI 循环发送多个事务冒充原子提交。

英/汉/德 UI 均使用同一稳定字段、命令、对象和法条定义。选项说明、错误、预览前后值、缺失数据、批准状态及批量结果均须翻译；人物姓名、国家名称、世界中的 Language 和 Culture 保持世界内容，不能因为 UI locale 改变其真实名称或语言能力。

## 4. 人物性格编辑：六个真实轴

使用源设计六轴，机器键固定为 `curiosity`、`piety`、`altruism`、`risk_tolerance`、`orderliness`、`ambition`。每项整数 0–100，默认 50；六项可以组合，不做互斥 RPG 天赋，不伪造“勇敢加生命”“勤劳免费生产”或等级种姓。

编辑只调整未来行动偏好，仍需现实食物、工资、能力、证据和法律。无文化人口不因求知设为 100 获得正式语言/文化；虔诚 100 不自动加入宗教；野心 100 不自动加冕。婴儿拥有相同成人身体规格，但人格修改不改变成年资格。出生来源、年龄、父母、健康、能力、国籍、身体与 fit 都不在该命令 payload 中。

独立 oracle 的 `SetPersonality` 已原子写入六轴并记录前后值；真实行动 AI 使用这些轴仍是生产接入任务。不能把记录数值当作已验证人格行为仿真。

## 5. 国家宗教是否绑定：四个明确选项

|机器值|显示含义|有效对象和资格|提交后的边界|
|---|---|---|---|
|`no_official`|无官方宗教|officialReligion 必须为空；普通国家在无启用宗教依赖政策时可以解除；帝国/神圣王冠须另走合法降爵或改制|居民保留信仰；教会、财产与合同保留|
|`official_tolerant`|官方宗教，容忍其他信仰|当前世界存活 Religion；文化/行政和官方宗教能力；条约允许|调整官方地位，不瞬间改居民信仰|
|`state_faith`|国教约束|同上；具体宗教权利限制需独立有效法律|不凭一个下拉框没收财产或赶走居民|
|`sacred_crown`|神圣王冠|同上，且已有有效 DivineGrant 与该根宗教匹配|神授绑定不能通过通用表单伪造/撤销|

`officialReligion` 是 typed root Religion 引用，不能拿教会或企业 ID 冒充；同根教派是另一个字段。帝国资格、神圣地位、官方宗教是独立状态。帝国换另一根宗教/解除宗教时，普通编辑页显示可执行的“重新申请神授/合法降爵”操作，正式生产通过同一事务同时落实条件，不能先提交非法中间态。

`religionBinding` 和 `officialReligion` 是唯一当前地位；`LAW_OFFICIAL_RELIGION` 只允许保存与当前绑定一致的待执行摘要，不能用其选项绕过根宗教/神授。改变绑定时，与新绑定冲突的旧待执行官方摘要在同事务中明确标作被取代并记录历史，预览先显示这项后果。

若已有启用的教会经营、宗教代征、宗教移民或帝国宪章待执行政策，解除或更换根宗教会拒绝，要求先显式批准停用/过渡；`disallowed`/`closed` 摘要不依赖官方宗教。信仰权利 `state_faith_restrictions` 只允许国教约束/神圣王冠，不允许“官方且容忍”与限制法条并存。

独立 oracle 已验证类型、世界、存活状态、文化/行政能力、能力解锁、条约保留权、根神授与现有待执行政策依赖；居民信仰、亲属、国籍、库存和财产不随国家改教改变。制度完整过渡、宗教税、教会合同调整、移民/反抗后果仍待真实领域服务接入。

## 6. 35 法律如何编辑而不伪造效果

复用 `data/catalogs/laws.json` 的 35 个稳定 law ID 和中文/英文源名称；新德文 UI 名称另放 locale 包，不重写提取目录。机器约束见 `editing_contract.state_laws.definitions`，C++ 的 `law_definition()` 使用相同 ID/选项/税率/最低过渡参数。

每条有 `option`、`rateBasisPoints`、`effectiveDay`、`transitionDays`。选项必须属于条款白名单；有税率的条款必须给整数 0–10000 基点，无税率的条款必须为空；exempt 的率必须为 0。前文化政策即使拿到能力引用也不能启用成熟条款；产权摘要仅 public 可用，mixed/private_open 仍要求文化成熟。

所有 oracle 政策记录保守要求 30–3600 日过渡，生效日不早于当前日+过渡日。这个有界公共摘要不替代成熟税表的免税额、累进分档、豁免、基数或具体宪章；例如所得税的 assessed/率仅是政策摘要，真实累进税款仍需专门领域定义。

所有记录的界面状态为“已批准 · 待领域执行”，不能根据日历过去便改称“生效”。预览人数限 oracle 内实际 Nationality 关联，企业限实际 Owner/Related 关联；正式法域范围/财税后果未接入时显示覆盖限制。

在 UI 中按五组组织，但不改变原始 catalog 顺序/身份：

- 国家治理：继承、集中、立法、财政分成、官方宗教、官方文化、附属保留权、帝国宪章、领土过渡。
- 企业与资产：产权、法人/外国企业/集团/银行/教会经营准入、破产、征收补偿、知识权利。
- 财税与继承：土地、所得、销售、利润、关税、股息、遗产、遗产税、资源费、宗教代征。
- 工作与服役：劳动、征召。
- 居留与信仰权利：普通/投资/宗教/人才准入、信仰权利。

能力资格、宪制批准与条约保留权为可信领域查询，绝不是玩家在表单中勾选“能力已解锁/已批准/忽略条约”。生产流程：保存法案草稿→查询能力和法域→计算受影响对象/预算与存量退出方案→取得真实机构批准→绑定本法案的批准凭据→再次预览→同写者提交。任何相关版本变化都需重预览；不会因为修改法条免费生成资本、删除实物、立即解除已签合同或随意抹除居民权利。

独立 oracle 使用 `AuthorizeStateLaw`（仅可信 Scheduler）对**完全相同的 State/lawId/setting 和世界 revision**颁发一次授权；玩家 `SetStateLaw` 才可提交，成功消费授权。授权后改百分比、改生效日、改国家或任何世界提交导致版本改变都拒绝。新的能力/宪制/条约服务尚未实现；oracle fixture 导入的 trusted context 与 Scheduler 代表既已验证的制度上下文，不等于完整的议会模拟。

现在的提交保存批准的未来政策记录，并记录 law ID、选项、率、生效/过渡时间及此前记录。它不产生税款、不注册企业、不撤销经营资格、不清算账本；时间推进也不把这份摘要假装成全法域执行。正式 `LegalPolicyService` 与过渡作业接入后才计算并原子结算真实效果。

## 7. 批量、历史与错误

批量编辑只显示选中对象共同支持的字段；人物与国家不能出现相同“全部属性”写入器。不同现值显示“多个值”，未勾选的字段保持。预览逐对象验证引用、存活/档案、修订、能力、法域和财产依赖。

默认整批原子提交；存在不能同时执行的对象时，给出明确的允许/阻断列表。只有玩家主动选择“仅提交已预览的可执行组”才允许显式分组，不暗中跳过失败对象。视图收藏/备注是另一数据域，不混进世界批次假装能保证跨存档原子性。仅产生对象自身字段变化的批量仍需各自前后值与关联事件。

错误使用稳定 reason key 与三语言短句，附可执行入口：陈旧→重预览；能力不足→打开能力页；宗教类型错误/已归档→重新选择；保留权→打开条约；神授冲突→打开申请/改制；资金/货物不足→打开对应账户/库存；路线冲突→定位旧证书。失败的世界快照与历史完全不变；去重命令重复提交不会再次改值或增加事件。

已归档人物/企业/建筑保留信息页、旧关系、收藏与历史，编辑区清楚显示归档原因。不能靠重命名复活，不能“清除历史”来抹去死亡、旧国籍、父母、作者或契约。
