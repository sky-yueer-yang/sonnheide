# 高度、真实坡道与冷热暴露合同

2026-10-09。状态：新版生产设计，**没有生产实现或游戏验收结果**。本文件与 [terrain_access_v1.json](../../data/contracts/terrain_access_v1.json) 配对。它落实用户的丘陵/山地、可随时移除的斜坡画笔、所有移动生命不可进入高峰及越高越冷要求；[原始 v0.6](../design/Sonnheide_Complete_Design_v0.6.md) 仅作保留的来源。当前动物/遗传接口见 [生命合同](GENETICS_ANIMALS_AND_UPLIFT.md)。

## 1. 真正需要一起解决的边界

|边界|必须得到的具体结果|
|---|---|
|0.5m 高度量子不能自动变成斜坡|2m 格间相差0.5m仍有竖壁；车辆不能因平均坡度小而跨墙。坡道改变实际承托面。|
|玩家说“上得去”不等于全物种通行|人的宽度、车辆转弯、牛的体积、动物攀爬能力分别校验同一真实表面。|
|高峰不是一个可换颜色的禁行标签|禁区由实际高度裁切，耐寒、飞行、坡道、附身和神力搬运均不能合法进入。|
|“移除坡道”不是回滚世界|只提交新的几何变化；在途生命、财物、旧入口和实际损失同笔处理，不能恢复死者、货物或施工投入。|
|越高越冷必须影响真实需求|高度进入权威温度场；耐寒、湿衣、代谢、保温、疲劳和真实食物共同决定暴露。|
|局部改地可能切断远处城市|旧路径证书与反向依赖索引同时失效；未查清的城市标“待验证”，不能假报安全。|

单写者是唯一提交者。镜头、LOD、鼠标帧率、GPU缓存和后台线程速度不决定地形、通行、生命状态或消耗。

## 2. 高度、水深、材质和生态各自是什么

世界保持真3D的分块单值高度地表，不存全世界稠密XYZ体素。一个水平位置最多一个自然地形上表面，柱下都是实体；不提供地形洞穴、隧道、悬空陆块。桥属于真实道路结构，另有桥面与桥下净空，不由斜坡画笔生成。

首样profile为格边2m、平顶列/目标平台高程量子0.5m、坡角细量子0.125m、chunk边64格。参数仅为工程校准起点，不是最终地图容量、真实地球高度或实测性能承诺；创建后profile冻结。GSHHG只初始化海陆，不导入DEM。Blank和Earth最终都成为同一种有效地形；不做程序世界模板库。

以下是本轮明确的**游戏数值样例**，不能解释成现实地貌分类或气象标准。边界用整数毫米和冻结版本判断。

|派生带|首样范围|笔刷的初始目标|
|---|---|---|
|浅水|床面水深大于0且不大于3m|-2m|
|近海深度|水深大于3且不大于12m|-8m|
|深水|水深大于12m|-24m|
|普通低地|实际干地高程0至小于8m|造陆时+1m|
|丘陵|8至小于32m|中心+12m|
|山地|32至小于80m|中心+48m|
|高峰|80m及以上|中心+96m|

水深名称不决定SEA/LAKE。首版海湖静水位都为0：低于0的表面被水覆盖；四连通到有限外海guard源才是SEA，其余为LAKE。深海笔刷在内陆可以得到深水湖。没有高位湖、瀑布、流体体积、潮汐或自动侵蚀。水深、吃水和通道净宽另验，不因为一条水缝连海就允许大船通过。

Sand/Soil默认只换顶材质，保留实际高度；明确的造陆/固定高度模式才改高程。八个soil主题影响地皮、装饰与未来野生树池；不是高程类别、导航许可或一批食物。雪原贴图不会私自把水结冰，炎地少量静态熔岩不会引入随机喷发或隐藏灼伤系统。普通chunk边不是海岸。

坡面跨过0时，湿区是三角面按高度0精确裁出的多边形，不把整格统一判成水/陆。每格保存可派生的湿多边形；四邻语义水连接要求共享边上有**正长度**的相通湿区间，单个点或对角接触不连通。船型导航还需真实床面、水深、扫掠体积和转弯净空。由此修正旧平顶模型的 `wet(cell)=heightQ<0`：它仍适用于flat格，不能继续套到ramp_patch。

还必须避免“一个湿格只有一个水节点”的隐藏错误：若固定对角NW/SE都在0以上而NE/SW都低于0，两个三角面的湿角区互不连通。一格可包含两个独立 `LocalWetRegionRef`，水图节点为 `(CellRef, localWetRegionId)`；同格三角间也只有共享正长度湿区间才合并。SEA/LAKE、WaterBodyRef按查询点所在真实湿区判断，不能把整个CellRef都标成SEA。导航门户携带具体localWetRegion及湿区间，不凭0.25m采样或像素抗锯齿连接两侧。

LocalWetRegionRef是 `(CellRef, inputTerrainRevision, minimumTriangleIndex)` 的版本化派生引用，不是永久湖泊身份。存档保存权威角高、固定剖分、水拓扑逻辑frontier/inputRevision，以及稳定WaterBodyRef的identityAnchor和split/merge历史；读回按同一规则重建湿多边形/门户，不发放新的同名湖身份。锚点因改地干涸或归属变化时按稳定后继规则登记，旧body引用归档而不重用。可出现同格NE湿区是SEA、SW湿区是LAKE；必须检验保存恢复后的两个查询点依旧不同，不仅比较一张海陆贴图。

## 3. 坡道必须进入权威地形

### 3.1 一列一个表面，增加真实坡面形状

仅保存一个平顶heightQ不足以让轮胎或脚连续受力。因此列增加 `surfaceShape=flat|ramp_patch`：

```text
TerrainColumn
  flatHeightQ                         // flat时唯一顶高
  surfaceShape                       // flat | ramp_patch
  cornerHeightR[4]?                   // ramp_patch: NW, NE, SE, SW，乘坡角细量子
  triangulation                      // 固定NW-SE剖分，不随镜头/LOD改变
  topMaterial, ecologyRef
  rampOwnerRef?                      // 当前坡道几何所有者，不是土地所有权
  mutationSource, mutationEventId, revision

RampRecord
  RampRef, origin                    // DIVINE_EDIT | CIVIC_EARTHWORK
  orderedControlPoints, widthMm, intendedMovementProfiles
  touchedCellRefs, geometryBeforeImages, ownedCellRevisions
  state                              // ACTIVE | FRAGMENTED | REMOVED
  createdEventId, lastEditEventId
```

平顶列和上下目标平台按0.5m量化；坡角必须采用独立细量子 `rampHeightQuantumMm=125`，以 `cornerHeightR` 编码，不能复用flatHeightQ的单位。否则2m格的最小非零角差0.5m已经是1:4，数学上不可能提供1:8车坡。细化坡角避免这个矛盾，不增加全世界水平格密度。平台端点必须与既有真实平台高程精确匹配；细坡角只是运行地形几何，不冒充现实DEM的精度。

三角面内部的高程按冻结的固定点/有理数插值，不能再把每个落脚点四舍五入成0.5m台阶。面下填满实体地形，不能只有一个悬空mesh；表面法线、射线、碰撞、湿区、支承、导航和温度查询共用同一面。渲染可以采用有棱面的原创像素外观，但不可把权威平面画成承托不了人的假斜坡。

每列独占其顶点数据；相邻列允许不同边高形成真正竖壁。通行穿边时校验两边的分段高程是否连续或台阶在profile范围内。两边边高发生交叉时，边面按冻结的有理数交点拆分，所有消费者读同一结果。不能为每个chunk另存可独立修改的共享边高度。

选中Hill/Mountain笔刷会形成实际量化山体；边缘可能陡到不能走。丘陵不等于“全格永远禁行”，低落差或已接通坡道的地面可以走；普通人不能直接翻越超能力的陡台阶。动物的固定物种能力与有界表型可能允许攀爬某些低崖，但不会产生悬空站位。

### 3.2 制作坡道的操作

在底栏“地形与生态”选择“斜坡”，先点真实的下端落脚区，再点上端平台，拖出路径或添加少量转折。默认宽4m；可在紧凑面板改宽、目标平台和“步行/车辆”用途。显示实际净宽、纵坡、转弯和削填范围；按不同profile显示结果，不用一个绿色箭头宣称所有单位都能通行。

候选生成以冻结世界空间控制点、弧长、宽度和量化规则构成唯一patch。拖动帧数、视角变化和预览LOD不会重复抬地。多个转折允许回头坡；车行要求真实曲率/转弯扫掠体积，直角中心线不能靠动画拐弯。上下端都要有合格落脚区域和实际接入，悬空点、被占平台、没有净空的终点直接不合格。

设目标爬升为Δh，最大纵坡为g，则中心线水平总长至少 `abs(Δh)/g`；这是必要而不充分条件。实际每个三角面、所有接边、落脚区、横坡、坡肩、转弯和单位全宽扫掠都再验，量化也可能使所需长度增加。12m爬升的1:3步行理论下限36m，在2m格/125mm坡角量子下可用40m直坡分配合法角高；不能拿平均坡度掩盖个别0.75m/2m超限段。1:8车坡可用96m、每2m升0.25m的实际角高连续通过。坡道过短时显示缺少的长度，可以延长/折返/降低目标；不能偷偷放宽人的能力或补出免费楼梯。

God坡道可以削挖和填筑，写 `DIVINE_EDIT`，不收费工程材料。它只提供真实地形，不赠道路等级、路权、楼基、灯具、矿石或施工退款。文明修坡/填海是 `CIVIC_EARTHWORK`，必须有已有土地权限、到货材料、真实可达劳动和逐阶段完工；未完工时原地形仍在，工程动画不能提前通路。

体积核算对每个新旧三角面差 `afterHeight-beforeHeight` 分别裁正/负多边形，保存实际 `positiveFillVolume / excavationVolume / netVolume`；不能只算净体积把等量削填当免费。平面三角体积按面积乘三顶点平均高差的冻结有理数公式计算。文明填方消耗真实配方建材，挖方有实际劳动/运输/处置；挖到的普通土体不自动变成可售矿石或新商品库存，矿物采收另验真实矿源。

### 3.3 人、车、动物分别验

|首样profile|最大纵坡|最大横坡|最大可跨竖直台阶|最小净宽/净高|另需校验|
|---|---|---|---|---|---|
|普通无负重步行|1:3|1:4|0.25m|0.8m / 2.1m|实际脚底支承、坡肩安全余量、入口权限|
|普通小型轮式车|1:8|1:12|0.05m|3m / 2.8m|6m转弯半径、整车/载荷扫掠、牵引与制动|
|动物|由不可改物种能力＋有界个体表型决定|同左|同左|真实物种身体尺寸及余量|陆行/攀爬/游泳/飞行各有独立能力掩码|

这些是待样本校准的冻结工程profile，非实际车辆/人体安全标准。基因读取 `PhenotypeCapacities`，不得直接用“耐寒”“强壮”trait flag跳过路线检查。负重、疲劳、受伤和湿滑会收紧能力或提高真实能量需求；提高力量不扩大手脚、车宽、桥净空或入口。

导航按地表连续几何求实际可达性，0.25m等细分候选不能创造表面。动物不能因“兔子快”穿墙，牛不能因“力大”越高峰。车不因人路可走就获得通道。私家马、坐骑、马厩、骑乘通勤和horse vehicle profile不在此设计中；动物马即使作为物种存在，也不产生交通资产。

## 4. 高峰是所有移动生命的绝对地形边界

对每个地表三角形按 `surfaceHeightMm >= highPeakStartMm` 裁出精确多边形，把该投影从峰阈值平面到世界允许的生命飞行高度形成 `PeakExclusionPrism`；其内地形实体仍按真实碰撞处理。只禁这个实际多边形：一格的某个角达到80m，不把整格、邻格或山脚都封死。移动单位的实际身体投影/扫掠体积接触该棱柱才失败，中心点在79m但身体伸进高峰也不合法。

高峰检查早于斜坡、攀爬、游泳、飞行、力量、装备和任务规则。人、动物、启智动物、飞鸟、蜂这些**移动生命Actor**都不得合法站立、出生/放置、神力搬入、寻路进入或飞越该柱。镜头、光线、天气表现和非生命装饰粒子可越过；它们不生成可用位置。Plant领域的树由真实寒冷/生境和生长条件约束，不以“不能通行”直接删除；工人无法上峰，因此不能自动采收那里的木果。把峰地皮换成Soil/Snowfield、关闭寒冷伤害、附身控制或提升基因均不解除限制。

坡道可接到高峰下面的最后合法平台，不能给高峰造一个许可例外。若玩家**明确使用降低高度工具**把实际峰顶削到阈值以下，派生高峰区随真实几何缩小；这是一笔可破坏占用的新改地事务，记录削峰事件，不伪装成“斜坡通行”。同样，高峰阈值/profile不能在已有世界中通过一般编辑面板降低。

若允许破坏的God编辑在已有生命脚下升起高峰，不自动把它贴到新峰顶，也不免费搬走：旧合法Standing/行进资格被撤销，真实碰撞进入 `TERRAIN_ENTRAPPED`、坠落或相应已预览危险状态。危险中的原生命仍有唯一位置和身份，但没有峰顶通行、生产、住房或新占位资格；救出依赖明确合法救援。保护模式则拒绝/跳过产生此后果的目标。地图变化造成的强制困住不是允许自己上高峰的通道。

## 5. 移除、重画和交叉坡道

“移除斜坡”选择现存RampRef，生成**新的**改地预览。默认将仍由此RampRecord拥有、版本未被他人改变的几何恢复为记录中的原块阶；保留当前材料、生态、树、GroundResourceRef真实觅食储量、矿源、物权和实物，不恢复整份旧World快照。实际毁坏、断路、淹没和货损照常结算。几何原图不能包含旧食物储量、质量、增长余量或预约，恢复几何不会恢复已经被吃掉、淹坏或埋毁的食物。

已被另一笔改地取代的格不悄悄擦掉他人新地形；Ramp进入FRAGMENTED，预览列出仍可移除的部分。若原几何不完整或版本不可验证，返回 `RAMP_SOURCE_CHANGED`，玩家改用新的降低/平整/斜坡计划。交叉坡道用新几何组合和同一轮接边验证，不能叠放两张悬空表面；后造者也不重复占同一列上表面。

若B坡覆盖的原图本来属于A坡，原图同时记 `priorRampRef + priorGeometryHash`。移除B可恢复A几何，但必须二验A仍为ACTIVE/FRAGMENTED且哈希/定义可验证；在**本笔新事件**中更新A的实际拥有格和版本，不重播A的创建回执或恢复A的旧导航证。A已经被明确移除、来源不完整或归属冲突时不擅自复活旧记录，返回RAMP_SOURCE_CHANGED并提供新的显式平整/高度预览。平顶原图恢复为空坡道归属。新地形mutationSource始终记录本次God/文明操作，不冒充原工程又完成一次。

God移除不退料、不退工时、不恢复人和已损货。文明拆坡按照真实削填/运输/拆除配方收费、消耗劳动；需要回填的旧挖方不能凭“拆除”白得填料。可回收工程构件仅来自原有可回收实物，按有界损耗进入真实批次。删除RampRecord不删除建在旁边的城市或绕过原物权。

一次移除可使上山路不通。尚未走进脏段者停在最后有合法支承的位置并重新规划；正在受改动表面承托者按实际新几何处理，而非统一传送到坡底。人仍在高台且站位未变，只是无法下山，进入“路线中断/受困”，仍需食物和冷热结算。车保留乘客/载荷/合同；未交货不能记完成。

## 6. 一次事务涵盖地形及所有立即后果

`PreviewRampStroke / CommitRampStroke / PreviewRampRemoval / CommitRampRemoval` 都经可信dispatcher进入同一地形提交器；不得另设一个只刷mesh的坡道入口。

```text
RampProposal
  WorldId, SessionGeneration, DraftGeneration, commandId
  expectedSnapshotRevision, terrainProfileHash, movementProfileHashes
  controlPoints, widthMm, targetHeightsQ, intendedProfileRefs
  mode                              // protect | destructive
  canonicalGeometryPatch, RampRef?  // removal时必填
  sortedReadSet, dependencyVersions

RampPreview
  preciseGeometry, endpoints, slopes, usableWidths, peakPolygons
  skippedCells, bodyClearanceFailures, immutableActorProfileFailures
  affectedSupportBindings, occupancyRefs, inTransitRefs
  affectedGroundResourceRefs, reserveSupportChanges, reserveQuantityLosses
  reserveReservationChanges, futureHabitatProductionChanges
  accessCertificateChanges, waterTopologyChanges
  knownDirectLosses, hazardCandidates, unresolvedRemoteConnectivity
  reservationsAndContractChanges, positiveFillVolume, excavationVolume, netVolume
  previewToken, consequenceHash
```

1. 校验有限输入/范围/授权与Godterrain开关；拒绝域外、外海guard、非法profile、未知枚举、溢出和超预算，不夹紧坐标。
2. 在单一当前快照上生成canonical geometry，读集包含每个端点、共享边、落脚区、净空邻居、旧保护域及相关物权/容纳器/货批/移动者。
3. 先确定峰禁区及即时真实支承/碰撞；再处理法定接入、既有必要路线、水连通和工程覆盖。GroundResourceRef（ForagePatch子类）的真实支承足迹、食物储量及取食预约也属于读写集，不是可丢弃的草贴图。仅检查刷区中心或中心单位会漏掉车头、邻房门、受损草场和远港。
4. 保护模式需证明所有受保护旧入口/实际送货/必要海路仍合法或有**已经存在**的合格替代；未完成重证时不可称安全。普通文明施工同样保旧路，不能让后造楼堵先造房的门。
5. 允许破坏模式给出紧凑、具体后果预览，批准绑定patch和consequenceHash；新移动者、到货、入住或定义版本变化返回 `REQUIRES_REPREVIEW`。
6. 提交前准备地形页、RampRecord、实体危险/位置状态、GroundResource支承/储量/质量/生产状态、生态资源损失分录、取食预约变更、实物损失分录、预约释放、施工SUPERSEDED状态、证书失效、派生脏集、事件和幂等回执，检查分配/容量与守恒。
7. 单写者一次publish。新的表面、立即支承/碰撞、在途状态、货损和旧证书不可用同时可见；不得先发布地形后逐帧处理人。
8. 后台只读重建mesh/导航/水图/温度候选。worker不分配世界身份、不签路线证、不恢复生产或自行处死；可信提交器校验当前版本后才发布后续结论。

建筑保持已批准楼板/地基绝对标高，不随斜坡免费上浮、换基或拓宽门。完整SitePlan仍验占地、真实承托、必要原创长方体地基、人路、车库车道、现状前侧接货区和施工/永久claims。材料真实送到前侧后，建筑自动工期；矩形铁丝网逐层围起、完全包围、反向撤去只是表现，不结算材料或决定完工。坡道有一个好的端点也不能免掉整栋房子的接入核验。

### 6.1 改地不能绕过真实草场/种子储量

GroundResourceRef为稳定、不可复用引用。其觅食子类ForagePatch只是同一真实储量的分类，不建立第二份食物。至少保存 `resourceKind / supportFootprint / supportBinding / absoluteQuantity / quality / capacity / productionRemainder / lastIntegratedTick / reservationRefs / state / revision / origin / lastDamageEventId`。储量不决定碰撞体积，装饰草仍没有库存。

地形提交先在旧支承/旧生境上把已经合法发生的生产积分到提交tick（同tick已结算则不重复），再按精确新旧表面裁实际受影响足迹，准备以下同笔后果：

- 只换主题/材质但没有破坏原资源：保留当前种类、绝对储量、质量和预约；仅变未来生产生境/容量。容量变小可形成明确over-capacity，不能把储量归零后换回又补满。
- 新实体填土侵入原资源的暴露/支承位置：受影响部分BURIED并按锁定GroundResource损失profile核销可食储量，不把旧草场整体贴到新坡顶。撤去支承、淹水或不适合的工程占用同样按resourceKind的真实生境更新可食/生产状态、质量及具体损失；允许水生的资源不因wet本身受损，陆生草场不自动转成漂浮货批。
- 部分湿、部分干的ramp格按真实supportFootprint裁分，保留未受损部分；禁止以一个wet bool把整格资源淹坏或将水下部分继续算可食。首样按当前可食足迹的损失面积比例分摊固定点储量，损失向上取最小资源单位且不超过现存量；余量严格为原量减本次损失，保存裁后足迹。这个保守游戏规则防止反复细小笔刷利用舍入免除损失。
- 受损资源的旧取食/收集预约按具体剩余可用量释放或缩减；重试不会第二次核销。所有Consume/Graze/Harvest在执行时二验GroundResource revision、当下实际支承和预约量，过期任务不得从旧显示数直接加身体能量或交出货物。
- 变回干地/原主题或移除坡道后，当前 surviving reserve可以重新具备生境，但已经损失/消费的量不会重现。受限自然恢复/真实播种只从当前tick、当前余量与已保存生产状态向前推进，不补算暂停生境期间的产量。新神力地面不会继承原地储量；若建立零量新资源记录，其INITIAL以外来源、当前tick和未来有界生产一并登记。

对地表根接触、水深/湿区、生产覆盖和取食目的地提供 `cell → GroundResource footprint → reservations/tasks` 反向索引；普通建设也不能把“无Actor占位”的实际草场当不存在。保护模式纳入确定的真实食物损失与必要口粮路径；允许破坏模式预览损失量和受影响取食任务，同笔核销，不先发地形后等某只动物发现饭已经没了。

## 7. 错误优先级与明确反馈

多项错误同时出现时，固定主错误优先级如下；完整诊断列表仍保留。这样重试/三语/不同镜头不会换一种事实。

|优先级|错误类别/典型ID|行为|
|---|---|---|
|1|错误世界/会话、未知版本、malformed、超范围、溢出|拒绝，不算后果，不改任何世界状态|
|2|无God权限/规则关闭、guard/域外、文明法律权限|拒绝，不能靠“destructive”越权|
|3|坡面/控制点/原坡归属无效、体积/预算超限|拒绝，不部分执行|
|4|`HIGH_PEAK_FORBIDDEN`|先拒绝所选用途合法通行；若God造峰本身合法，改地后果另行预览|
|5|端点支承、台阶/纵横坡/宽高/转弯/材料、实际碰撞|明确受阻profile和位置；不以冷热能力补路|
|6|旧必要接入/支承保护、容纳/货物冲突、未完成远路验证|保护模式等待合格重证或拒绝；允许破坏只能经对应后果批准|
|7|`REQUIRES_REPREVIEW` / 定义或依赖已过期|重建预览，不套用旧批准|
|8|提交准备容量/存储/分配失败|强异常无半写，原世界/回执不变|

高峰错误在**移动/放置用途**中最高于能力；Godterrain抬峰命令并不会因此永久禁止画高峰，它只不能承诺那里可住生命。路径可达与冷热生存是不同结论：冷山路可能几何合法但当前装备危险，UI按事实分别展示“可通行”和“暴露风险”。

## 8. 越高越冷的权威温度场

温度只读世界有效位置与锁定ThermalProfile，首样采用：

```text
airTemperature_mC = baseTemperature_mC
                  - lapse_mC_per_m * max(exposureAltitudeMm, 0) / 1000
baseTemperature_mC = 24000
lapse_mC_per_m = 250
```

运算为检查溢出的固定点整数，舍入规则随profile冻结。于是游戏0/12/48/80m约为24/21/12/4°C。这只是小型游戏山体的可感知温差模型，不是现实大气递减率，也不把游戏高程称真实地球海拔。profile提供明确有界温度范围；候选世界超范围先拒绝或要求另一合法profile，不静默clamp当前World。

同一横向气候基准与条件下，增加高度必定不增温。首版不另按soil颜色赠冷热：雪原、炎地的视觉主题与实际温度信息分开。露水/涉水形成的真实湿度增加热损；材料可以有固定湿滑/热交换定义，但颜色本身不写伤害。以后若加入区域气候必须另有可编辑的权威字段与预览，不能藏在shader里。

站地者采用真实脚底标高，楼内采用所处楼层的真实floorY，飞行动物采用权威机体参考高程，涉水者采用静水面热环境；水下不会因海床负高程无限变暖。容纳器遮风/遮水效果来自实际结构和完好状态。增加环境温度必须来自真正运行并消耗能源的取暖设施；没有设施时不能给所有建筑免费暖气，树发光和照明也不赠热能源。

Age of Light/Darkness只控制两种环境光和实际可用灯具表现；不更改温度、代谢、海水位或天文时间。没有昼夜、自转、公转、季节或新增第三种Age。暂停冻结暴露和消耗；离屏、远观或切换语言不冻结生命。

## 9. 基因、衣物、真实能量和冷/热债

生命模块提供已经过不可改SpeciesDefinition能力掩码/上下界裁定的 `PhenotypeCapacities`。本合同涉及的trait为 `cold_tolerance / heat_tolerance / thermal_regulation / wet_cold_tolerance / strength / stamina / ground_speed / agility / climb_capacity / fatigue_recovery / basal_efficiency / fasting_tolerance / energy_storage_capacity`；`strength`读取其正式导出 `maximum_supported_load`，agility/fatigue_recovery读取生命合同的对应版本化导出。游泳/飞行另用对应导出。消费者不得偷读allele/sharedProfile自行重算；完整遗传、subspecies编辑和启智不在温度线程重新实现。

能量沿用生命合同的双来源账：`maintenance_energy_nonrecoverable`为有限初始/安全维持能量，`productive_energy_from_real_food`只能来自实际消耗食物。`energy_total = maintenance + productive`只作只读派生显示，不能另存一个可增减的savedAbsoluteEnergy。脂肪/储能分区也保留来源标签，两个来源间不能通过“储存”转换或重复记账。每次基础/冷热/移动消耗记录每个来源扣量及不可逆损失；增加储能容量不补量，降低容量保留绝对来源余额与明确超容量状态。

每个生命同时保存疲劳债、体湿、冷/热暴露债及下一次生理结算tick。每件衣物保存真实ItemRef、穿戴位置/覆盖率、材质保温和散热、耐久、湿度、修补次数。套件穿戴仅改变实际占位和贡献；不能一个身体槽无限叠上100件大衣。动物皮毛是物种/表型的内在身体特性，不是免费衣物库存，启智不会生成衣服。

固定结算顺序为 `food_absorption → storage → basal → thermal → movement/work`：

- 已真正吃掉并进入消化状态的可食物批次/GroundResource储量按真实营养转入productive_energy_from_real_food，源数量唯一扣减并有一次消费回执；装饰花草、未实际吃/采的果、未交货粮食、贴图雪和一段基因编辑不能作为食物。
- 基础代谢保持正下界；`basal_efficiency`可降低有界需求，`fasting_tolerance`改变真实能量不足到健康受损的速度，不能变成不吃饭永动机。
- 冷负担根据实际气温、内在耐寒、调温、体湿和实际干/湿衣物剩余保温计算。基础维持及冷热调温可先扣有限maintenance余额、再扣productive余额；每笔分别记账，不足部分增加cold/heat exposureDebt。极端热负担、厚衣/工作热量按相同有界规则处理。损耗不能再次变回衣物、奶、肉、蛋、后代物质或可转交饲料。
- 余下maintenance只可支持有限维持移动和直接取得现有真实食物所需的有界bootstrap foraging；取得的食物必须实际扣源。商品搬运/生产劳动、孕育/动物产品转换只由剩余productive来源支付，不能把God放置的安全能量混入生产预算。力量大仍有负重、疲劳和食物代价；能量不足时走慢、休息、寻食或停止工作，不保持免费满速产出。必要路线几何可以仍合法，但个体此刻不具备足够安全能力。
- 暴露超过冻结阈值后按增量、限幅的损伤规则影响健康；回到安全环境，消除后续负担并按真实恢复速率减少债，不立即恢复全部伤势。不能在换基因、换subspecies、读档或重新穿衣时清零债/能量/疲劳。

没有衣服不直接触发死亡。缺衣仍会优先买衣；长期处于实际低温而保温/食物不足才可能产生冷热伤害。正装缺失仍允许上班、领薪和保岗位，只提高真实购买排序，保住基本生活预算。保温需求和礼仪/时尚需求均用真实衣物、耐久、有限修补、真实换购；不能为新冷系统破坏衣业长期需求。

`hunger_consequences`与新增 `thermal_consequences`是独立WorldRule，后者默认on。关闭饥饿伤害不赠食物/能量，也不消除寒冷风险；关闭冷热伤害仍记真实能量、疲劳、体湿和暴露债，仅抑制直接thermal health loss。重新打开按当前状态和新的tick限幅结算，不把关闭期间未发生的损伤/死亡补算回来。峰禁区、碰撞、坠落及地形困住不受这两个开关豁免。

## 10. 路径证书、支承与保存

`AccessCertificate`至少绑定：WorldId、表面及净空版本、峰区域版本、道路/桥/门版本、通行权、movement profile hash、身体尺寸/负重/表型版本、入口/目的地与保护走廊。冷热暴露的路线风险估计是另一个 `ExposureEstimate`；它不把当前寒冷当固定墙，也不能使过期路径证书继续有效。

移动者进入每段前二验当前局部几何、碰撞、峰界与能力。表型变更会使依赖该能力的路线待重证，不能为冷耐受改了数值就解除车宽限制。受影响路径前沿保存确定逻辑工作预算；worker快慢不决定人物走哪条路、有没有饿死或城市是否开放。

存档保存有效flat/ramp形状、所有cornerHeightR及独立125mm细量子、RampRecord/几何原图/残片归属、profile hash、峰/湿区重建输入、绝对Actor位置及支承/容纳、未结危险、真实库存/预约、GroundResource绝对储量/质量/足迹/支承/生产余量与lastIntegratedTick/预约及损失事件、冷热债/双来源能量余额与来源储能分区/体湿/衣物湿度和due ticks。energy_total从双账重算，不从显示百分比恢复。派生mesh/nav不作最终事实；读档重建但不重置伤害、复补树果/草场或重放坡道材料。

候选创建/读档隔离 `WorldId / SessionGeneration / DraftGeneration / CandidateGeneration / sourceRevision`。取消、返回主菜单、开另世界或旧结果晚到只丢弃候选，不能污染当前世界或继续指针。首存档持久写入并读回验证成功后才发布新World。坏版本、坏坡面、丢失必需基底或非法峰生命站位拒绝，不夹紧成“差不多能玩”。旧危险记录可带生命处于强制受困位置，不假冒合法站地。

## 11. 计算量和分区

- flat默认块采用uniform/base-plus-patch；坡面稀疏记录，禁止每个海格分配Ramp对象或网格全XYZ体素。
- cell→support/occupancy/access corridor/GroundResource footprint及其预约/取食任务逆索引覆盖真实足迹与净空halo；变化只扫直接影响范围，再沿组件依赖查远路，不能每筆遍历所有城市，也不能漏远港或仍使用旧草场储量的任务。
- 峰裁切、湿区边区间和坡面片段由同一cell版本派生并缓存；共享chunk边按稳定坐标归属，脏相邻边，不把chunk拼缝当不可通行崖。
- 地表温度基值随变化列/楼层位置按需缓存；每个生命根据dueTick/活动状态有界调度。饥饿/冷热可按冻结区间解析积分，遇到穿衣、湿身、气温变化或运动事件先积分到事件tick，再换参数，不能因低频AI少扣一段能量。
- 地形批次有 `maxStrokeCells / maxAffectedObjects / maxTopologyWork / maxPreviewBytes` 实际准入；超限要求缩小或进入已批准的有限分段任务，不偷偷截掉关联人/车/货。长任务只在明示分段边界提交，旧通路保护仍逐段成立。
- 性能验收必须包含支承、路线重证、货物、能力与冷热结算；仅改变坐标的百万对象benchmark不代表游戏规模。
