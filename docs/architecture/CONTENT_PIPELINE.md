# 内容流水线与自制建筑工程合同

2026-10-08当前裁决：[ADR0012](../decisions/0012-editable-3d-pixel-world.md)/[v0.7](../design/Sonnheide_Design_v0.7_Pixel_World.md)覆盖本文旧地形/人物资产条款。有效高度/海陆可编辑、所有坡地检查必要基础、Port不再RECLAIMED-only、原创像素人体取代MakeHuman、底栏八分区。source provenance与历史只读；普通施工保通，明确Godterrain允许损坏并同事务处理人货/容纳/证书。未改的文明/衣物/法律/typed信息规则继续有效；下文旧oracle与浏览器字段按旧版本保留，不能当新生产实现。当前字段/命令补充见[机器合同](../../data/contracts/pixel_world.json)、[地形事务](PIXEL_TERRAIN_TRANSACTIONS.md)、[像素资产](PIXEL_RENDERING_AND_ASSETS.md)。

版本：初步工程基线，2026-10-06。依据 [Sonnheide v0.6](../design/Sonnheide_Complete_Design_v0.6.md) 第 2、5、13、19–22 章，并落实用户“不用游戏引擎、建筑全部自己做”的追加约束。本文把**待实施的生产契约**写到能够逐项验收的程度；不声称人体、写实建筑、完整资产编译器或生产渲染器已实现。仓库初始的原创 graybox 只验证格式与空间契约。

## 1. 需要攻克的五个问题

1. **外观与真实空间不能混为一体。** 如果模型决定占地或入口，换历史皮肤会暗改路网、容量、射界甚至港口合法性。必须由建筑定义提供权威空间，再让美术在空间合同内表达三时代与文化。
2. **真实来源量化与当前可建设地表必须相容。** 地球源海陆只是初态provenance；最终像素高度列是海陆、渲染、拾取和建址共同事实。量化损失必须在最高预览显示，不能以原矢量窄河掩盖已经变陆的导航。
3. **“开源资源可用”不能停在下载。** 人体网格密度、动画骨架、PBR 通道、shader 后端与允许再分发的文件范围必须可转换到自己的运行时；引擎项目不能直接替代自研子系统。
4. **10000 个真实居民不能变成 10000 套近景骨骼。** 从 shared mesh/material 到骨骼 LOD、动作缓存和群体代理必须是内容合同的一部分；否则资产库会锁死渲染架构。
5. **可重建、全量 GitHub 托管与二进制体量要同时成立。** 源文件、授权证据、工具配方和发布内容包必须可追溯；用“将来再下原始资源”或短期 CI cache 都不满足托管目标。

前三个问题先用一个实际的 CitySquare 组件、通用住屋和港口闭环证明，再扩展内容数量。后续完整内容范围仍保留，避免只做高质量截图却没有能承载游戏的资产合同。

## 3. 坐标、尺度、原点与文件格式

### 3.1 一个 canonical 空间

- canonical glTF 和内容包采用右手坐标，单位为米，`+Y` 向上，`+X` 为投影平面右方向，`-Z` 为投影平面上方向；建筑默认正门朝 `-Z`。在局部方位等距投影的中心，这些方向对应东／北，远离中心不能声称是处处精确的 WGS84 方位。
- 逻辑格索引 `i` 向 `+X`、`j` 向 `+Z`，与图像行向下兼容。角度只在一个变换模块中定义；模型制作者不能自行猜测 90° 正负号。
- 首样本SurfaceCell=2m、高度量子0.5m、64²chunk；楼体模块可用0.5m，人物/导航净空可更细，均待尺寸路径样本准入。profile随World冻结，不能载入时改格距并缩放旧楼。Earth worldScale只同比地理X/Z；游戏Y是明确派生高度，不声称真实正高，人物建筑固定游戏米制。
- 模型局部首层地面Y=0，实例floorY来自联合SitePlan且建成后固定；普通平地无额外基，任何实际坡地需要时采用原创长方体基础/台阶/真实坡道。完整占地支承、人车连接、现状接货、施工包络与永久通行域联合批准。神力刷山不能免费升楼板或伸长旧基，按[地形事务](PIXEL_TERRAIN_TRANSACTIONS.md)停用/损坏。
- 世界仿真位置与渲染相对原点分开。大片世界采用 Chunk 局部 GPU 坐标，源资产保持小的局部值；浮动渲染原点不影响格索引、导航或存档。

### 3.2 建筑 pivot 与旋转

权威锚点是 footprint 格块的最小 `(i,j)` 格角。美术 pivot 放在 footprint 几何中心的局部地面 `Y=0`；世界放置代码从锚点计算X/Z中心，从SitePlan读取固定floorY，并围绕中心作四向旋转。旋转后的 footprint 仍按整数格块重新求最小角，不能用浮点 mesh AABB 反推格数。点坐标、边法线、人行/车库门、前侧接货socket、碰撞和泊位必须使用同一离散变换，避免 90° 后半格错位。

离散 `rotation=90` 表示地图顺时针：海侧EAST（+X）转为SOUTH（+Z）。右手+Y轴数学yaw应使用 `-rotation`；图形桥不能直接把两者同号套用。

首批建筑仅允许 0／90／180／270°。港口这一限制永久是玩法硬约束；其他普通建筑将来若需要更自由朝向，必须先新增合法占地与道路映射方案，不能仅放开编辑器 gizmo。

### 3.3 作者格式与运行时格式

编辑源是 `.blend`、原始纹理、原创参数脚本和配方；交换格式采用 glTF 2.0（生产优先 `.glb` 或不带外链的 glTF 文件集）。运行时消费经过验证与编译的自有内容包，不解析 .blend、FBX、OBJ、DCC modifier 或 Geometry Nodes。

基础 glTF profile 只接受三角面、metallic-roughness PBR、显式 normals/UV、可选 tangents、所需 skin/animation。初期禁止加载未知 required extension；有需要时在能力表、转换器和自研 renderer 中同时支持，不能让 exporter 单方面开启 Draco、meshopt、transmission 或 GPU instancing 扩展。

Blender glTF exporter 会因 UV／硬边拆点而增加实际顶点数；不能用 Blender 编辑模式顶点数做 GPU 预算。复杂 shader 节点应烘焙到规定 PBR 通道，导出之后用自研查看器复核，不以 Blender 渲染结果代替游戏验收。[Blender glTF 导出说明](https://docs.blender.org/manual/en/latest/addons/import_export/scene_gltf2.html)

## 4. 建筑是“权威定义＋表现定义”

### 4.1 权威 BuildingDefinition

```text
BuildingDefinition
  buildingTypeId                    永久物理类型ID；不等同企业业务ID
  capacityTier                      普通建筑的性能档；宗教类型没有可升级tier链
  footprintCells                    整数占用格集合／矩形，含必要施工用地
  volumeClassId                     当前容量必须表达的最小空间类别
  legalCapacity                     住房／教育／生产／装卸等真实容量
  collisionProfile                  权威阻挡／射线／拾取代理，独立于视觉LOD
  entrances[]                       人、货、车辆的入口及各自通达要求
  interiorContainerSlots            抽象容纳能力，不创建可游览房间
  allowedSurfaceOrigins             实际干陆INITIAL/DIVINE_EDIT/CIVIC_EARTHWORK；Port不凭来源豁免支承
  rotationsAllowed                  离散朝向，Port固定四向
  constructionAndMaintenance        建筑材料/自动工期/状态；维护劳动独立，不由动画支付
  deliveryApron, deliveryAnchor      建筑前侧网罩外的合法接货/等待/退出区域
  authorityHash                     玩法空间和容量字段的规范化哈希
```

一个银行、物流公司或研究所只占用 Building 中的 Facility 空间，不新增专用建筑外观家族。牌匾、入口、标识和检查器区分业务；Facility 的租户变化不能重建 footprint 或偷偷移动门。

### 4.2 AppearanceDefinition

```text
AppearanceDefinition
  appearanceId, buildingTypeId
  eraStyle                           ANCIENT/MEDIEVAL/ENLIGHTENMENT表现标签
  compatibleVolumeClasses[]          允许的空间类别，不按“时代=容量”硬编码
  requiredAuthorityHash              所对应建筑空间版本
  moduleRecipe                       原创墙、屋顶、窗、入口、院落构件组合
  materialSet, tintParameters         共享像素图集/色板和材质参数
  entranceSocketBindings             美术门与权威入口的逐项对位
  renderBounds                       视觉边界，不能侵入非法地面／交通净空
  constructionPresentation           合法cageBounds、分层网罩与可选包围中段clip
  lods[], shadowProxy, selectionProxy
  authorshipAndSources                原创作者与开放材质来源链
```

`SwitchBuildingAppearance` 先检查已解锁、类型、volume class、authority hash 和入口匹配，再仅改变表现 ID。不能改变容量、耐久、支付记录、占地、导航或宗教类型。完整的性能升级是另一个建造事务，必要时扩大 footprint 并更新 authority hash；不是换 mesh 名字。

**“高容量也能选中古皮肤”不是“任何小屋都能装一百人”。** 每个容量档定义可接受的占地／层数／楼板面积／入口净空范围；同档三时代都需要相应体量。大容量中古外观可以用多翼楼和足够楼层表达，不能把一栋 3×3 米单屋仅在 JSON 中写成大公寓。有效楼板面积是美术核验指标，不是另一个自动生成住房容量的游戏经济公式。

### 4.3 视觉边界、碰撞与导航

权威占地用于建设事务；碰撞代理用于移动避障与战术遮挡；渲染 mesh 用于图像。三者用途不同，但必须相互包含／对齐：

- 主体墙体、支撑柱和阻挡构件必须在 footprint 内；屋檐只能在明确保留的 envelope 中伸出，不能盖到 WATER、相邻产权、道路净空或港口泊位。
- 地面阻挡代理用盒／凸多面体与少量平面多边形；不从百万三角美术生成每人每帧的 mesh collision。射击遮挡可用单独较精确的低面数代理，仍不依赖当前视觉 LOD。
- 门面 mesh 与入口 socket 的位置／方向对齐。人行最小净宽首轮 1.0m，车辆净宽首轮 3.0m、净高 3.5m，特殊货运用显式 clearance profile；这些是待车辆尺寸回归的值，不是所有车型自动可入。
- `NAV_BLOCK` 是始终有效的玩法代理；视觉变体和 LOD 不改变道路连接。进入门触发 `InteriorContainer` 的可见性转换，人物／车辆／货物 ID 保持存活。
- 出口至少有一个合法等待点和安全释放半径；不能出现门口永久卡住。矿洞同样使用入口容纳，不制作地下导航房间。
- 牌匾、屋顶、窗、饰物、LOD mesh 与 HLOD 代理全部归同一个 BuildingId；近景点击任何组件都能回到同一检查器。

没有永久城墙、城门、防御塔或要塞资产。普通楼群能形成真实街道瓶颈；不是借助一个禁止的城防家族恢复旧玩法。

## 5. 当前像素岸线、文明造陆与港口资产约束

### 5.1 来源岸线与当前离散岸线

GSHHG full是Earth初态来源，记录在只读provenance。量化后、以及每次玩家编辑后的当前高度列决定顶面/侧壁/水深/可站立性；原矢量不以另一个光滑表面覆盖像素岸线。复制地形不复制产权/楼/人/矿stock。Civic造陆完工才写列高并结算实际成本，神力改变为DIVINE_EDIT，两者都不能用美术先呈现可通行陆地。

当前岸距离、水mask、泡沫和mesh缓存按terrain revision失效。权威提交不依赖GPU Ready；客户端新revision使用精确差量/同版替代mesh，暂未就绪则移除受影响旧mesh并清楚显示暂不可见区，不容许几帧旧海陆误导拾取；这仅是呈现层门槛，不改变headless tick/提交顺序。不需重建全球源包。人工岸壁是独立原创建筑构件，神力改岸不会自动免费生成岸壁或伸长基础。

### 5.2 PortDefinition与模型同步

```text
PortDefinition
  coreFootprint                     固定矩形，全部实际干陆且完整支承
  supportedOrigins                  INITIAL / DIVINE_EDIT / CIVIC_EARTHWORK
  seaFacingEdge                     模板唯一水侧边或明确可选边
  berthWaterRectangle               连续正交WATER禁占/泊位区
  vesselClearanceProfile            真正水深、宽度、高度、转弯和接近航道
  landEntrance, loadingSockets       实际陆路接货和有界装卸点
  waterArrivalSocket, dockingSockets 同空间航行/靠泊锚点
  rotationsAllowed                  恰好0/90/180/270度
```

泊位向外长度与水深是两个量：水深来自海床列高与固定水位，不由shader决定。Port核心及陆上设施完整有干陆支承，无悬水免费QuayPlatform；水上船坞工作区不附赠人物可站立面。天然/神力陆均可合法建港，Civic填海后也可建；来源标签不代替真实工程/产权/预算/接入。

升级扩支承/设施/泊位仍须真实工程和权限；外观不扩容量。普通后建项目保既有泊位/接入；Godterrain可明确损坏停运，同事务撤销证书并保持船、人、货、合同、所有权和真实抢救任务。拆港不拆历史陆、不删登记船。

四方向验证任一干陆来源满足全部条件合法；支承/净空/水深不足、未完工程、斜角、泊位被占、海路Pending或不通、陆路不通均拒绝。远方改海峡也会影响运营资格，不能只看Port旁边。

## 6. 原创建筑内容目录与制作顺序

### 6.1 家族及空间模板

|家族|独立模型／原型职责|容量／时代处理|
|---|---|---|
|基础住屋／公寓／通用民用楼|共享原创墙、屋顶、窗、门、庭院模块；租户牌匾区分业务|按空间类别制作三时代表现；成熟大公寓只在有合法知识与工程条件时解锁|
|SettlementCore／CitySquare|Core 原型和正式广场组合；CivicHall、Storage、LoadingApron、PublicSpace、FlagMast 是同一实体组件|8×8／12×12／16×16 格只是原稿推荐；扩建真实面积和容量，外观不能产生第二个 Storage 账本|
|公共工坊／科技工厂|共享结构模块但功能轮廓分别可辨，管线及工位只做有界外部表现|三时代，工厂生产线知识／采用与视觉分离|
|农田／林业设施|原创地块、棚、工具空间；生产作物与主题装饰明确分开|作物／树龄表现读取经济状态，不能模型刷新就补木材库存|
|矿洞|原创入口、支撑与货运等候点|三时代入口；地表可有山地高峰，首版没有可游览地下空间|
|大学|原创专用教学体量与入口，复用墙窗屋顶模块|三时代，不额外创建“研究所”建筑家族|
|港口|原创 PortCore、陆侧仓舍／装卸与岸壁；水区独立|三时代、永久正交；任一干陆均核验实际支承/水深/净空/接入|
|Chapel|独立固定类型；首轮推荐 3×3 格，约 50 活动容量|不升级成 Cathedral；同类型历史／文化变体不改容量|
|Cathedral|独立固定类型；首轮推荐 6×6 格，约 250 活动容量|不升降级，需独立土地／财政／结构许可|
|Temple|独立固定类型；首轮推荐 12×12 格，约 1000 活动容量|不升级，需独立工程及根宗教门槛；不增加第四宗教建筑类|
|道路／桥梁／人工岸壁|原创连续模块，归基础设施而非另一个地产族|桥不把WATER改LAND；岸壁不改来源历史；坡道必须有真实碰撞导航面|

宗教三种类型可共享我们自己的墙、柱、屋顶与材质模块，但必须各自有独立轮廓和 BuildingTypeId；体量大小不能被误编译成 tier 1／2／3。早期 Chapel、美术雄伟的 Temple 都不使用现实宗教符号暗中固化根教义；根宗教标识由自己的图形定义生成。

### 6.2 防止时代×文化×容量爆炸

第一套正式原创构件按四个功能组组织：结构（墙／柱／台基）、覆盖（屋顶／檐口）、开口（门／窗）、公共空间（院落／廊／围栏／标识）。风格配方选择合法模块，不创建“每个混合文化一套楼”。

首批内容预算是制作计划，需实际灰盒验证后调整：

|项目|首轮上限|验收意图|
|---|---|---|
|三个历史表现 profile|上古／中古／启蒙各一套|覆盖时代要求，不全世界自动切换|
|结构与屋顶基础模块|约 30–40 个原创模块|优先复用厚墙、真实屋顶、窗门比例，360°均成立|
|文化可调槽|屋顶、立面、窗格、入口／院落 4 类|每槽最初 2–3 个变化；不枚举全部笛卡尔积|
|PBR 基础材质|约 12 组，普通 1–2K|先石、木、灰泥、砖、瓦、土、少量金属和织物|
|每个空间类别的已认证外观|初始每时代 1 个，文化变体逐个验证|所有配方仍需通过 footprint、入口、体量验收|
|每月内容拓展批次|先上限 10 个新模块或 1 个完整家族|只在上一批预算／验证合格后扩展，避免素材数量掩盖渲染瓶颈|

文化签名是渲染生成种子；选择结果在建筑建成时记录。后来移民、国家易色或 Culture 强度变化不会使所有墙顶自动重建。只让旗帜／合法标识颜色更新；玩家切建筑历史风格走原有解锁规则。

### 6.3 一个真实制作批次

1. 固定功能：容量档、占地、入口、所需道路、合法 surface、构件清单。
2. 原创 graybox，首先验证人／货／车可以从道路到入口，以及全部占地合法。
3. 三时代轮廓方案，逐个确认同容量空间表达合理；模型看起来相同不是必要条件，空间合同相同是必要条件。
4. Blender 原创建模并保留源文件；墙厚首轮至少 0.15m、门窗比例、屋顶厚度与背面成立。关闭近景穿帮面，不做被设计禁止的室内漫游。
5. 选择有来源的 PBR 材质，统一物理 texel 尺寸；纹理损坏／维护痕迹只读 condition，不能由材质湿度自动改性能。
6. 制作 LOD、阴影代理、入口及标识 sockets；检查从每个方向观察和各级相机高度。
7. 导出规范 glTF，经过格式／空间／许可／性能验证，生成审核 turntable 与真实游戏场景截图。
8. 同时入库原创源、许可证链、配方、产物与内容版本；为可见效果牺牲占地或导航时必须退回第 1 步重新设计。

## 7. PBR、贴图与 LOD 预算

### 7.1 材质合同

albedo/baseColor 与 emissive 作为 sRGB；normal、roughness、metallic、AO 作为线性数据。normal 约定与 glTF 保持一致，导入 DirectX 法线贴图需显式翻转 Y 并登记转换。基础 profile 使用一张 baseColor、一张 normal 和统一 ORM 打包（R=AO、G=roughness、B=metallic），不保留未知节点网络。

每张贴图记录真实覆盖米数；不能让相同砖材在一栋楼上是 20cm、另一栋是 2m。建筑普通表面 1–2K，近景重点可使用经预算批准的 4K；避免每栋楼独占 8K 贴图。atlas／texture array 的 page 和 sampler 由编译器统一分配；同材质重复共享，主题色和磨损用参数。

KTX2 等压缩容器属于计划中的平台编译 profile。GPU 格式按目标平台选择，不把某一平台 BCn 写死为源资产格式；保留可重建的原始贴图。先实现简单完整 MIP 流程与缺失纹理 fallback，再按带宽测试扩展虚拟纹理。

### 7.2 几何与提交预算

以下是首轮上限，不是当前成绩，也不是全城所有资产每帧都可见的允许总量：

|内容|LOD0 三角面初始上限|材质槽／draw primitive 初始上限|后续层级|
|---|---:|---:|---|
|普通住屋／民用楼|10K–30K|4|LOD1 约 40%；LOD2 约 10%；城市 HLOD|
|重点 CitySquare 组件／大学／大宗教建筑|40K–100K|6|保留轮廓与关键入口，远景合并代理|
|普通人物，含简单服装和头发|8K–15K|3|中景 2K–4K；远景实例／群体点|
|单株树木|2K–8K（待实机校准）|2|近中远保持真3D体积；不以全树billboard作最终360°轮廓；阴影另分级|
|道路／岸壁重复段|0.5K–2K|2|实例化或 Chunk 合并；格边不得缝开|

实际顶点数、索引数、材质拆分、骨骼矩阵、meshlet 数和纹理常驻大小一起统计。靠 instancing 降 draw call 不会自动消除过度绘制、shadow draw 或大 MIP 常驻成本。

LOD 按屏幕投影尺寸及迟滞切换；起始实验阈值可用对象高度 160／40／10 像素，最终由真实镜头距离调优。跨 LOD 保持稳定 EntityId、pivot、入口和 collision。近景不以 billboard 人物／纯低模屋作为最终视觉；远景允许低成本代理。

HLOD 按空间 Chunk 分组，归属标签与点击仍映射实际 BuildingId 或城市集合。扩建、拆除、外观切换使相关代理失效，原模型先可见再异步重建；不能等待全城 HLOD 才让仿真事务提交。高质量静态阴影按重要度与距离分级，远景人口不投同档动态阴影。

## 8. 人体、年龄、服装与动作

### 8.1 全龄统一身体规格

最新[ADR 0005](../decisions/0005-unified-inspectors-and-world-tools.md)规定：从出生0岁到老死，所有人物使用同一成人身体规格、世界尺寸、骨长度、绑定矩阵、碰撞净空与服装FitProfile。年龄不选择儿童mesh、不整体缩小人物、不改变骨架或衣物尺寸。年龄仍决定成年、学习、服役和生命周期，视觉共用不赋予未成年人成人岗位或兵役。每人有有界的实物衣物引用，人体/服装mesh与材质共享，不逐人创建模型。

全龄共享同一组骨长度与inverse bind matrices。肤色、面部、头发、服色和不改变尺寸的老年外观可作为有界参数；不启用年龄/身高/儿童比例targets，不扩展外貌遗传系统。性别标记与基础覆盖规则独立于统一尺寸规格。

### 8.2 最小骨架与重定向

canonical rest pose为T pose、脚底Y=0、前向-Z，语义含root/pelvis/头/四肢/持物socket；首样本16—24骨，高LOD约2—8k三角。刚性方块优先1权重，关节接缝最多2，不需五指捕捉/高密blendshape；未来更高预算必须设备样本准入。

中景骨架按可见关节进一步减少，保持根、关键四肢和持物 socket；删掉的骨影响合并到保留父骨并重新归一化。中景不能继续上传整套高密骨矩阵再称为骨骼 LOD。远景动画使用共享姿态缓存／实例相位或点代理，而非每个 Person 的完整状态机。

外部动作必须有源骨架、单位、rest pose 和重定向映射记录；重定向后验证脚滑、手与工具接触、膝反折、统一规格步幅、坐骑对位和循环拼接。原始动作与改动后 clip 一起保留来源链。

所有行走／跑步 clip 为 in-place；仿真位置决定实体平移。root motion 可以在导入时用于提取参考速度与步幅，但不让动画轨迹越过玩法导航、瞬移到 WATER 或改变战斗判定。动画帧率、渲染暂停和镜头远近不得改变劳动产出、搬运数量或攻击冷却。动画中的击打 marker 只用于视觉同步，权威战斗已在提交屏障完成。

### 8.3 原创像素人体、实物穿着与原创军装

[ADR0012](../decisions/0012-editable-3d-pixel-world.md)把人物和所有衣服改成原创块状mesh/像素图集/共享成人rig。原ADR0004的实物衣柜与经济规则保留，见[CLOTHING_ECONOMY](CLOTHING_ECONOMY.md)。历史MakeHuman归档与许可不删除、不进入新runtime，不转换后冒称原创。细节密度、atlas/mip、衣层和骨骼预算以[PIXEL_RENDERING_AND_ASSETS](PIXEL_RENDERING_AND_ASSETS.md)为当前准入。

|阶段/使用|真实穿着与颜色|
|---|---|
|前文明基础覆盖|黑色内裤，女性加黑色基础胸罩，替代旧草裙；覆盖fallback不能形成可出售库存或获得满足收益|
|上古文明|真实交付后穿国家主题色T恤+白色短裤；无国籍者沿用最后合法主题色/中性白，不因居住地或占领换色|
|后期普通居民|根据实际买到并穿上的衣物自由选择款式/颜色；有界上下装/整套/外层/鞋等兼容组合，未拥有的目录不允许直接换皮|
|公司正装规范|已发明、可获得且实际采用的正装方案提高员工购置优先级；缺正装仍正常上班、领薪，不作为招工/门禁/扣薪条件|
|Army军装|项目原创统一款式，各国家共用同款/骨架/LOD，主色绑定实际服役/发放国家主题色；法定国籍独立保存，外籍兵不会穿错军服|

基础国家色和军装主题色采用显式theme binding，主题色更新只改绑定材质参数，不生成新衣、重置耐久或增加经济库存；后期自由染色商品保存实际colorway/染料来源，换色服务有真实投入。服役、换雇主、制服归还、死亡/继承不凭mesh颜色推断所有权。实际衣物与同一资产的多个经济实例分别编号，资产不能自带免费体力/防御加成。

原创衣物绑定项目BodyProfile/face UV/rig/层序及有限遮盖mask，验证坐标/单位/rest-pose、所有关节动作和360°近远景。样本16—24骨，刚性部件优先1权重、接缝最多2；不因高分辨率贴图增加每texel骨骼或模型。全龄使用同尺寸fit，atlas/mip与经济item ID分别版本化。未制作款式不以旧MakeHuman衣转换充数。

军装用原创像素衣片/UV/rig配方，共用 `uniform.cut.v1`，不得拿现成军装改颜色冒充自制。各国家只有theme/合法徽记参数差别，当前没有军装成品或GPU装配证据；风格/制作与经济发行分别验收。

服装经济最高支持有界槽组与兼容规则，首个C++oracle只验证上下两槽。GPU从WornItemSnapshot选择mesh/LOD/材质与遮蔽，组合缓存用体型+各槽mesh ID+LOD+layer mask作为key；染色/耐久表现是实例参数，不逐人复制材质或实时重拓扑。隐藏/进楼/离屏/低LOD不暂停损耗；衣柜浏览器显示已拥有、已预约、在途和商品目录的区别。缺衣图像采用适当覆盖fallback，经济仍显示缺口，不显示裸露且不凭空制造真实衣物。

### 8.4 第一批动作集合

先覆盖 idle／walk／run／turn／pickup／carry／putdown／farm／chop／enter/exit／hold/release；人物送材料到前侧后离开，建筑不需要`build`砌筑动作或现场施工工人。建筑本体用原创四面加顶盖的矩形网罩，从下到上分层围起，完成后反向撤除；网罩覆盖完整模型且留在合法工程envelope内，参数与取消/早完成/载入行为见[ADR 0002](../decisions/0002-building-construction.md)。成年军事动作在军事切片接入，儿童没有兵役或战斗武器动作。矿工入矿、车辆进门、人物进入建筑使用同一容纳状态；进入后 render proxy 隐藏但快照仍引用其 ID。

Divine Hand 抓持只是渲染姿态与容纳状态改变；松手后的散布位置由玩法模块提供，动画不能将多人释放到同一点。被抓人物仍保留文化、国籍、信仰、财产与 Army 关系。

## 9. 植被、水体、旗帜与车辆

按[ADR0013](../decisions/0013-layered-surfaces-and-fruiting-trees.md)采用地皮/装饰小植物/真实树三层。所有可砍/可采果树有稳定TreeRef（PlantRef的tree子类）和实际附着储量；有界林地聚合只能作调度/远景索引，不能丢掉每棵可选树的身份。生长、果批、成熟变色、采伐与补种由SimTick决定，mesh/风动/LOD不结算资源。装饰花草按持久配方、密度、seed与clear mask重建，不存在收获、货物、碰撞、导航成本；放置时避开建筑/路/入口/实际农田。采摘视觉读取当前实际果量，代表性果子可映射一小批数量，不凭渲染实例创造库存。

树木使用实例 mesh、共享材质和 bounded wind 参数；叶片 alpha mask 统一阈值与 MIP，近景避免视觉卡片穿帮，中远景以可见成本控制过度绘制。树木返回真实TreeRef，花草不截断对象拾取；点到花草时继续找树/地形，不能开虚构经济植物页。树林对战术遮挡是否生效由明确 gameplay proxy 决定，不能随着叶片 LOD 或风动突然消失。

水体默认原创像素水：固定平均水位、权威水深分档、透明与泡沫/倒影只表现。固定Abyssal MIT源与CPU FFT数学保留为可选研究/复用，只有明确选择复用才验对应原生GPU通道，不把未选FFT移植列成发行阻塞。两创建入口和编辑后的水都消费当前terrain/body revision，不重新程序生成岛屿替代用户地形。

船只依据实际水深/导航/静水位运动，视觉波浪不能改变LAND/WATER、可站立性、航道或泊位。封港来自军令/通路；God改地后处理搁浅/乘客/货物，不能只刷新泡沫。此版没有高位湖、瀑布、体积流体、真实海底高程或潮汐侵蚀。

旗面 mesh、旗杆和 atlas 由原创几何及合法 FlagDefinition 生成；13 模板、23 色及 3:2 比例是图形输入约束，抗锯齿混色不是新颜色。`themeColorId` 使用同源 palette。政治地面 overlay、城市旗杆和国家 UI 小旗共享定义哈希，军事占领标记不能覆盖法定主权字段。

船的模型规格同时声明长度／宽度／停靠净空、bow/stern sockets 和可泊 Port profile；马、马车、汽车声明人／货容纳、足／轮／地接触和车库入口 clearance。开放模型的现实尺寸可调整到玩法定义，但不得让一次材质／LOD 切换改变运输容量。船归 Port，不靠 asset tree parent 或当前坐标推断所有权。

## 10. 从源码到发布包

### 10.1 计划目录与现阶段区别

以下是生产流水线规划，只有随实际内容加入才建目录和文件，不批量生成空类／空素材：

```text
assets/
  source/original/buildings/       原创blend/生成脚本/配方，按family划分
  source/original/characters/      原创军装版型/衣片与人体清理源
  source/third_party/              经批准的具体文件，LFS或Release源包
  manifests/                      定义、外观、骨架、动作及来源记录
  licenses/                       上游完整许可证和保留通知
  fixtures/                       小型原创测试资产，快速CI可用
tools/
  content/                        canonical验证与内容编译
  dcc/                            离线DCC导出脚本，适用工具许可独立
build/content/                    可重建的本机缓存，不是唯一资产来源
docs/research/ASSET_SOURCES.md      选型证据
```

初始仓库的原创 civic_hall／residential／port graybox 是路径和合同示例，具体路径以本仓库实际 manifest 为准。生产全量字段与灰盒最小 validator 是分阶段实现，后者通过不等于前者的全部要求通过。

### 10.2 编译阶段

```text
来源/原创源＋许可 → 注册与固定哈希 → DCC导出／原始格式转换
 → canonical glTF静态验证 → 空间／骨架／风格契约验证
 → LOD/贴图处理 → 平台GPU格式编译 → 空间Chunk/HLOD索引
 → 内容包＋manifest＋通知 → 自研查看器和场景验证 → GitHub Release
```

每阶段记录输入哈希、工具固定版本、参数和输出哈希。Blender、图像转换器、shader 编译器升级要生成新 recipeHash 并在一组 reference scene 回归，而不是覆写旧产物。路径统一大小写／分隔符，禁止 glTF 引用仓库外绝对文件、远端图片或个人下载目录。

资产 ID 稳定，文件改名不改 ID；内容包使用 sourceHash／definitionHash／recipeHash 组合寻址。世界存档引用定义版本和外观 ID，资源新版本不能重解释旧存档中的容量或入口。若只是贴图优化可做明确兼容映射，权威空间改变必须新定义版本／迁移。

不能无条件保证所有 DCC 输出在不同机器上逐字节一致。先固定工具平台，消除时间戳、随机 seed、文件遍历顺序和无关 metadata；几何／动画语义 hash 必须稳定。首批 Python 生成的 graybox 应能 byte-for-byte 重建；生产压缩／shader backend 的输出按具体平台 profile 固定并分别校验。

### 10.3 内容包与资源流送

包头记录版本、目录、端序、内容哈希、每项压缩格式、尺寸和完整性校验；索引与资源 payload 分离读取。不要用一个巨大 GLB 包含全地球、所有人物及全城建筑。

资源状态为 `UNLOADED → REQUESTED → DECODED → GPU_READY → EVICTABLE`，失败回退到合法低 LOD／缺失资产代理并记录错误；不能让“纹理还没到”造成整栋楼玩法实体消失。解析／贴图解码离开 render thread，GPU 上传按每帧预算执行，取消过时相机请求。CPU／GPU 双预算与引用计数按共享内容管理，不按 Person 复制数据。

LOD 与 streaming 的请求顺序优先当前视野主体和低 LOD 完整覆盖，再补高细节；HLOD、地球瓦片与人物动作包都有最低可读代理。存档保存玩法状态，不保存 GPU handle；加载后按 assetId 重建视觉。

## 11. 必須通过的验证

|门禁|验证对象|拒绝条件|
|---|---|---|
|来源与许可|每个源文件与派生链|无许可、源版本未锁、原始文件不能再分发、建筑非原创、来源哈希失配|
|结构|glTF buffers/accessors/indices/images|越界、NaN／Inf、缺 normals／UV、未知 required extension、外链、不支持 primitive|
|空间|footprint/pivot/envelope/sockets|单位错、非整数格、变换未应用、模型越界、入口不对齐、净空不足、替换改变authority hash|
|PBR|通道、采样器、纹理分辨率|颜色空间错、法线约定错、超预算、缺 MIP、材质槽爆炸|
|人物|骨架／权重／动作／覆盖|未归一化、多余权重、骨名不匹配、按年龄改变身体尺寸/骨长度/fit、脚滑／膝反折、服装不符合文明状态|
|港口|四方向、当前支承/水深/通路|任一干陆不足支承、未完工填海、斜角、泊位侵占、水深净空不足、陆水路Pending/不通|
|身份与容量|类型／外观／容纳状态|宗教类型被升级、换外观改容量、Facility租户改楼、进门删除实体或货物|
|LOD/HLOD|每层和变更后的代理|跳动、入口丢失、拾取ID错、隐藏玩法实体、换LOD改变遮挡规则|
|发布完整性|Git/LFS/Release source与内容包|只有LFS pointer没有对象、只有短期CI产物、包哈希失配、缺许可证／来源包|

静态验收后做固定场景：昼间／傍晚、透视近中远景、360°转台、贴岸建筑、造陆完成前后、港口四向、100／1000／10000 人的真实移动与经济负载。记录 CPU／GPU 帧时间、draw call、skinning、纹理常驻和流送峰值；不能用隐藏仿真或全体远景点替代“10000人完整工作负载”验证。

初始最有价值的回归不是每个模块都有一份测试，而是：同一 BuildingId 三时代切换后 authorityHash／容量／导航完全相同；同一 Port 四向变换后海侧边与泊位正确；同一 Person 换 LOD／进门／保存加载后身份和服色正确；所有实际引用内容从干净 clone 与 GitHub 源副本恢复。

## 12. GitHub 托管策略与扩容阈值

普通 Git 保存文档、schema、生成脚本、小型原创 fixtures 和索引；LFS 保存无法有效 diff 的编辑源、贴图与经批准的第三方包；发布后的内容包、游戏二进制和较大的只读源归档按项目 Release 固定版本存放。源对象如果采用 Release 而非 LFS，manifest 必须指向本项目的固定 tag／文件并带 SHA-256，才能满足完整托管。[当前额度与限制](../research/ASSET_SOURCES.md#7-github-全量托管可行性)

首批目标：Git 普通对象控制在约 200 MiB 以内，需 LFS 的源资产和历史增长单独统计；发布包每块不超过 512 MiB。采购前预测：`源集大小 × 历史修改次数` 的 LFS 存储，以及 `实际拉取次数 × 选择性下载量` 的带宽。实际算法不能按“每个 clone 都完整下载 10GiB”来规划免费额度。

在 LFS 实际用量到可用额度 70% 时审查下一批资源的数量、分辨率与不可变归档策略；到 90% 时暂停自动引入大包并明确扩容成本。用户没有授权自动开启付费或删除历史源；技术上先准备可审查的费用预测和完整镜像结果。不能为节省配额把已承诺源文件悄悄移出 GitHub。

LFS tracking patterns 应在首次二进制提交之前确定；不要把素材先放普通 Git 再事后掩盖。`.blend` 等二进制可采用 LFS lock 避免同时编辑；可读配方／manifest 仍能普通合并。缓存、编译临时文件、个人存档、第三方工具安装目录不入源库；它们不属于需要永久托管的项目作者源。

## 13. 切片验收与未解决的实际风险

- **切片 A：** 三个原创空间 graybox＋PBR 测试、人物近中远代理、格网岸线、填海岸壁、正交 Port、旗杆与入口容纳。必须先证明空间／内容合约，再做批量正式写实资产。
- **切片 B／C：** 文化风格持久化、三时代体量兼容、性能升级与外观分离、CitySquare 真实扩建、公共工坊／通用楼／大学与工厂内容。
- **切片 D：** Chapel、Cathedral、Temple 独立制作和门槛接入；共用原创模块但不产生升级链。
- **切片 E／F：** 成年军事动作、坐骑／船／车辆、道路瓶颈与装卸；商业租户只扩展标识与使用状态；长期内容／LOD／资源预算验证。

当前尚需实做验证的风险是：4m 格在狭岸、道路和大型 CitySquare 的真实密度；统一成人规格开放人体清理后的实际成本；容量档跨时代能否用同 footprint 表达可信体量；原始 shader 的移植成本及水面在人工直岸的遮罩；初期纹理／动画常驻量是否超过最低目标硬件预算。这些不是等价改写后的“已解决问题”。每项都要有可运行的资产样本、场景和数字，再决定是否调整初始参数；不用未测的写实截图承诺最终性能。

## ADR 0005：全龄身体与全域信息页

玩家新放置Person固定18岁；自然Birth从0岁开始，但两者共享同一成人身体、骨架、碰撞净空和fit规格。年龄不是外观缩放参数。服装页、衣柜页、企业/订单/运输页通过同一typed EntityRef相互跳转，显示所有者、保管者、位置及预约/在途/已交付的区别；详情见[集中交互合同](INTERACTION.md)。现有服装oracle的add_person是有限测试初始化接口，生产World不得借此自动生成工人、移民或士兵；只能导入已有Person引用。
