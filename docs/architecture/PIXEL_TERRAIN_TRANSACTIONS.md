# 可编辑像素地形、空间后果与事务合同

状态：2026-10-08 的生产设计，按 [ADR 0012](../decisions/0012-editable-3d-pixel-world.md) 和 [v0.7 像素世界设计](../design/Sonnheide_Design_v0.7_Pixel_World.md) 执行。本文件没有交付可编辑地形内核、物理、水路、城市迁移或生产存档实现。原始 v0.6 与旧 ADR 保留历史，不改写源材料；原稿第 2.1、20、21.2、22、24.6 章中的写实、冻结天然水陆、无高度场与禁用地形笔刷要求已由用户新要求覆盖。

目标是实际的三维像素世界：可以绕地图水平旋转 360°，山体、水下地面、立面与建筑都有真实空间；玩家可从空白地图或真实世界选区开始，编辑浅水、近海、深海、沙、土、丘陵、山地和高峰。像素风不允许用镜头、shader 或贴图假装存在可站立斜坡。地形变化必须进入居民、建筑、路网、货物和历史所共用的权威世界。

## 1. 必须同时突破的边界

|边界|看似方便但错误的做法|本合同要求|
|---|---|---|
|编辑地表与保持来源|继续锁死真实地理，或改掉来源文件冒充自然生成|创建来源只作不可变 provenance，运行时列可编辑；神力另记事件|
|八种笔刷与真实空间|把 `hill`、`soil`、`water` 放进一个互斥枚举，再另存彼此矛盾的高度|高度、顶面材质、编辑来源分开；深度、海/湖与形态派生|
|局部笔刷与全局水网|海峡删一个格后只重算所在 Chunk|重建局部组件/门户，再验证受影响旧组件；允许有界 Pending|
|新地面与旧建筑|把房子随新高度抬升，或继续使用冻结地形上的旧接入证书|固定楼板/结构不自动移动；支持、入口、路权和运营逐项失效/重证|
|神力自由与守恒|所有有对象格一律拒绝，或清掉地形时顺便吞人、吞货|提供保护占用和允许破坏两种明确策略；原子登记直接后果|
|神力造陆与真实工程|免费刷地后退回填海材料，或用施工回执证明神力完工|允许神力造岛，但它不是施工、生产、采矿或退款事件|
|暂停、加载与撤销|撤销高度时复活死者、补回已采矿石、重置在途货物|反向编辑是新命令；有后续物理/经济后果的编辑不能简单撤销|

例如，一个 2m 宽海峡即使是 SEA，也可能容不下 3m 宽船；一个 0.5m 台阶在 2m 格上的平均坡度仅 0.25，车辆仍不能跨越竖壁；在房子下面降低地面，即使没有新增体积重叠，也可能撤掉其支承。这些反例分别要求语义连通、运动净空、支承关系三个独立证明。

## 2. 权威地形与八种工具

### 2.1 一列一个顶面，实体仍为三维

每个 SurfaceCell 是一个 X/Z 矩形柱，保存单一量化顶面高度。相邻高度不同处生成完整竖直边面，柱体下方视为实体地面。第一版不存储全密集三维体素，不支持挖洞、隧道、天然悬岩、地下可通行空腔或同一地形列的多个顶面。建筑、桥、道路坡面和人物属于独立三维实体；桥面/地面两层通行通过专用表面层实现，不把高度场扩写成通用体素编辑器。

```text
PixelTerrainProfile
  surfaceCellSizeMm, heightQuantumMm, chunkSideCells
  minHeightQ, maxHeightQ, stillWaterLevelQ
  terrainRecipeVersion, pickingVersion, navigationProfiles
  worldBounds, editableBounds, protectedOceanGuard
  strokeCellLimit, affectedObjectLimit, topologyWorkBudget

TerrainColumn
  heightQ                    // 有界有符号整数
  topMaterial                // SAND | SOIL | ROCK | SEABED，有限定义目录
  lastMutationSource         // INITIAL | DIVINE_EDIT | CIVIC_EARTHWORK
  lastMutationEventId
  revision

TerrainEcologyState          // 独立稀疏层，不能从高度/颜色反推
  biomeId, fertility, moisture, cover
  lastMutationEventId, revision

InitialMapProvenance
  kind                       // BLANK | EARTH_SELECTION
  sourceManifests, sourceHashes, projection, selection, horizontalScale
  conversionRecipeHash, initialPixelMapHash, creationPreviewHash

TerrainMutationRecord
  eventId, commandId, committedTick, source, changedChunks
  patchHash, beforeAfterSummary, directConsequences, linkedProjectId
```

首样本 profile 为 SurfaceCell 2m、高度量子 0.5m、64×64 格 Chunk；参数是游戏校准起点，尚无性能/可玩性承诺。建筑尺寸、人物碰撞、库存位置和导航子格不能被迫等于 2m；导航可使用 0.25m/0.5m 细分候选，但细分不创造地形中没有的坡面。高度边界与世界格预算在创建前明确预览、通过完整准入后冻结；运行时超界输入拒绝，禁止悄悄 clamp。

`heightMm = heightQ × heightQuantumMm`，中间乘法检查溢出。世界内使用相同游戏米坐标；相机缩放、浮动渲染原点和 LOD 不改变列高度、人物尺寸或物理格大小。真实世界选区按冻结投影和统一水平比例转换；像素地形的游戏高度不宣称是现实海拔，也不把历史 ETOPO 25×25 样本当全球高度包。

### 2.2 笔刷预设不是唯一地形状态

八个 canonical preset 为 `shallow_water / close_ocean / deep_ocean / sand / soil / hill / mountain / peak`，与 `data/contracts/pixel_world.json` 相同；shallow/close/deep 仅是描述缩写。首样本高度模式目标如下，均以静水位 0 为基准；数值不是自然地理标准或最终平衡值。

|预设|中心高度/深度示例|顶面材质|必须保持的含义|
|---|---|---|---|
|shallow_water / 浅水|水下 2m|海床，定义可用沙/岩表现|改真实水下顶面，浅水仍是 WATER|
|close_ocean / 近海|水下 8m|海床|这是水深预设；是否属于海必须检查连通|
|deep_ocean / 深海|水下 24m|海床|深度变大不自动获得远洋航路|
|sand / 沙地|默认保留高度；显式造陆模式 +1m|沙|默认涂材质不改水陆；只有明示造陆才将湿格升出水|
|soil / 土地|默认保留高度；显式造陆模式 +1m|土|土质不免费种植或产生农产品；默认不夷平山体|
|hill / 丘陵|中心 +12m|土/岩组合|按明确半径/形态过渡；不是只给单柱贴 hill 标签|
|mountain / 山地|中心 +48m|岩|陡坡和台阶可能不可通行，这不是编辑失败|
|peak / 高峰|中心 +96m|岩|高度上限/半径可见；不自动拓宽以保证可达|

水深与山形预设默认执行声明的高度形状；沙/土默认只改材质并保持原高度，另有明确造陆/目标高度模式。单独“材质”“升降”“固定高度/平整”是同一列模型上的明确模式，不能让一次土质编辑偷偷夷平山体。丘陵/山地预设保存中心目标、半径、falloff、量化/舍入版本；高度与当前基面组合规则属于 canonical payload。界面应显示目标高度和实际范围，不把“丘陵”理解成所有土列都只能处于 12m。

`wet / dry`、水深、岸边、海/湖、地形坡度和形态分类均为派生结果。湿格可保留 SOIL 顶面，干格也可保留 ROCK；两者不矛盾。`landform` 可由局部高差/高度带供显示与 AI 查询，但不能与 height 并列成为另一个可冲突的事实。

生态涂抹单独改变 biome/有界 fertility/moisture/cover，不改 wet 或生成可售批次。草地、林地、湿地、雪原等实际植物仍是独立实体；开启自然植被恢复时只能按可信调度、时间、位置/容量与生态条件产生有来源的成长候选，不能涂完森林就发木材。cover 可改变有限行动 profile，例如积雪地面状态；这种影响必须进入对应版本/证书，不能只在贴图中让车速改变。无自然植被恢复实现时显示未接入，不用地形笔刷自动补树冒充。

在内陆刷“深海”，如果没有连接外海，产生的是深水湖；预览应显示实际 LAKE，不伪造 SEA。第一版不存在盐度、潮汐、降雨、侵蚀、太阳周期或水动力学。原有环境 Age of Light/Darkness 只影响表现，不升降静水位。

### 2.3 稀疏 Chunk 与共享边

Chunk 支持 `UNIFORM / DENSE / BASE_PLUS_PATCH` 的有界编码：空白默认区域可用单一列值，大面积一致海底可用 UNIFORM，真实来源和改动复杂处用 dense 或基底加补丁。所有权/矿物/占用使用各自稀疏页，不为每个未修改海格分配大对象。缺页只有在世界定义明确提供默认基底时才代表默认列；缺少必需 Earth 源块是失败，不用默认土壤掩盖损坏。

列只有一个 owning Chunk；边面归高度较高列，等高时按稳定坐标 tie-break。修改 Chunk 边缘会脏相邻 Chunk 的边面/水边/导航门户，不能把 tile 边当成海岸。渲染 halo 和导航 halo 是派生读数据，不允许第二份共享高度独立写入。满屏锯齿岸线的内存不能仅按“一块一个门户”估算。

真实地理转换后的初始像素图必须随世界保存或引用可验证的只读基底包；世界修改在其上形成权威当前列。新的全球岸线数据、LOD 或转换算法不能重新生成已有世界。provenance 的不可变性保护历史与可复建性，不限制之后的 God brush。

## 3. 有限水体：固定水位、海/湖与通航分开

### 3.1 第一版水位规则

所有海和湖共享固定权威静水位 `stillWaterLevelQ = 0`。对每列：

```text
wet(cell) = heightQ(cell) < 0
depthQ(cell) = wet ? -heightQ(cell) : 0
dry(cell) = heightQ(cell) >= 0
```

`heightQ == 0` 按固定规则为干燥接触面，不提供船舶水深；建筑模板可另要求正的干燥余量。这种 tie-break 不受 GPU 波峰影响。God brush 将地面降到 0 以下会显露该静水面，将其升到 0 以上会露出陆地；这是明确神力改变地表，不是从仓库放出一批商品水。

第一版不承诺有限水体体积守恒、高位湖、不同水位合流、河流流速、瀑布或排水工程。统一水位是明确模拟模型，不能用“湖水以后会自动流平”掩盖未设计的多水位物理。未来多水位需要新的水体库存/出流/溢流/合并合同及 schema；现版带未知湖水位的 payload/存档拒绝，不强制改成 0。

湿格通过四邻接构成语义水组件。连接到有限 World 内受保护外海 source 的组件为 SEA，其余为 LAKE；对角接触不连接。隔断海峡后，内侧湿组件变 LAKE，水不会仅因失去 SEA 标签凭空消失。挖开地峡会合并组件，新的标签由当前列决定，初始 GSHHG 的湖/海类别只作来源证据。

持久 `WaterBodyRef` 与临时导航组件不是同一引用。水体身份记录固定 identityAnchor、历史来源、当前已验证 kind/状态和 split/merge 后继关系；拆分时含原锚的子组件保留原 ID，其余按稳定坐标顺序登记新 ID；原锚已干时按预先冻结的最小存活旧成员规则选续接者。合并优先保留外海源身份，其余取稳定 ID 顺序，其他身份归档并记录 successor，绝不重新分配给无关湖。完全干涸的 body 归档。注册表过渡由可信单写者按已验证 source versions 提交；worker 不自行发 ID/写历史。Pending 期间身份可保留 `UNVERIFIED` 与最后已知资料，但不能把旧 kind 当当前通航事实。

### 3.2 有限域与外海保护带

World 的权威范围 G、可编辑内域 D 和受保护外海 guard 在创建预览中同时明确。D 中的来源地表和已编辑地表都可修改；guard 是预算内实际水格，充当固定海源并防止刷地修改有限域最外闭合，不能作为无限免费实体区。G 外仅表现远海，无人口、货物、矿源、目的地或航路节点。

笔刷碰到 guard/域外时，预览显示实际受限区域；可显式改选“仅编辑内域”，并对裁切后的真实 patch 批准，也可缩小/取消。不得默认夹紧坐标后假装整笔都已生效。普通 Chunk 边不是保护边界。船舶可以按 profile 在 G 内合法航行，但任何路径、碰撞体和目的地都不得越出 G；SEA 连接不是自动生成域外贸易或移民的许可。

### 3.3 两层水图与有界 split/merge

语义 wet 图负责 SEA/LAKE；按船型 profile 建的导航图另验水深、整船 swept footprint、泊位净宽、转弯、桥下净空、实体/施工障碍和权限。浅水、近海、深海既不是船型准入 bool，也不是同一视觉纹理的三个名称。一个一格宽的 SEA 通道不证明任何船能通过。

生产算法采用有限分块图：

1. 对改变列、邻边和 clearance halo 标脏；精确 wet/depth/柱体碰撞立即读取新的权威列。
2. 对受影响 Chunk 分别计算 wet 局部四连通组件和各船型可通行组件。门户是一条 Chunk 边上的连续区间，绑定本地组件、可用净宽及 profile；同一边可能有多个互不连通门户。
3. 在共享边上按相同格/区间精确匹配门户，生成粗图边；不能通过对角点或不足净宽的一线接触连图。
4. 替换相关局部图后，对受影响旧粗组件做稳定排序 BFS/DFS。新增湿格可合并，删除湿格可能拆分；仅使用 union-find 不足以处理删除。
5. SEA 标记来自 guard source 的可达性；各船型独立产生有效路径/无路结论。粗图扩展与精确搜索都受固定节点预算约束，预算用尽返回 Pending。
6. 结果带 terrainChunkVersions、obstacleEpoch、profileHash、topologyGeneration；输入已过期即丢弃。任务先返回不决定权威提交顺序。

最坏情况下，一格删除会重访跨整个 G 的粗组件。有限不等于常数时间；必须给最大格数、局部组件数、门户/边、队列、visited 页和输出内存设准入上限。uniform Chunk 可用一个组件表达；棋盘状水陆、重复狭窄通道是不可省略的坏情况。正确性 oracle 以预算内小图的完整四邻接 flood-fill 对照分块结果，不用随机空海性能冒充真实海岸规模。

ReadyPath、ReadyNoPath、Pending 是三种不同状态。脏图不能返回有效旧 SEA 标签或旧路径；没有查完也不能声称没有路径。UI 可以显示“通航重新验证”，不把未知状态显示为湖或可远洋。默认原创像素水；历史 Abyssal 锁定算法只保留研究，不构成本轮强制 FFT 移植任务。任何获准水面/视觉泡沫只读 wet/depth/已验证组件，不能把浪峰用于支持、吃水或路径结算。

## 4. God brush 与文明工程是两个授权路径

|路径|地形改变条件|真实费用与劳动|地表来源|不得产生|
|---|---|---|---|---|
|CommitTerrainStroke / Godterrain|可信玩家神力、有限 patch、明确后果策略、提交二验|允许不付工程材料/劳动；记录神意|DIVINE_EDIT|采矿收益、生产收入、虚构工程完工、材料退款、人口|
|PlanCivicReclamation / CivicEarthwork|合法地权、知识/工艺、真实到货、劳动、阶段验收、旧通行保护|按真实深度/体积与 recipe 消耗|CIVIC_EARTHWORK|预约即变陆、无限石料、将邻格规划当支承|
|EditMineralStroke|独立矿物命令、速率有界、积分至提交 tick|记录神意资源事件|不改变地形来源|立即赠库存、把地形柱体变可卖矿物|

God brush 可以挖海、造岛、抬山或夷平原始真实轮廓，无四邻接造陆限制。文明填海仍要求从已存在的干燥可支承陆边逐格四邻接推进；这条岸边可以有 INITIAL、DIVINE_EDIT 或 CIVIC_EARTHWORK 来源，来源不替代实际支承与运输。初期公共施工先于私企，不能因为像素化把材料、人员和物流删掉。

工程目标高度、现状水深/填筑体积、允许深度、施工表面、材料换算和工期明确进入方案。以 2m 格、目标 +1m 举例，从 -2m 填至 +1m 是 12m³；从 -24m 填至 +1m 是 100m³，两者不能都按同一免费进度条完成。现有通用建材/石料可承担配方；不为此暗中新建完整砂土商品产业。具体强度/体积换算是待校准游戏定义，不是现实土木保证。

首版未完工的单格工程保留旧地形，仅占临时工地；只有该格COMPLETE事务才写目标高度/材料，不能用部分动画或投料先缩小水深。多格项目可由多个已完工格分期，不引入单格partial-height schema。提交/单格完成均检查现状revision，后继格只能依赖已经完成的支持。God 编辑覆盖正在施工的格时，工程进入 `SUPERSEDED_BY_TERRAIN_EDIT / REPLAN_REQUIRED`，结算已消耗投入并释放未用预约；不自动将其标为完成，不退回已经消费材料/劳时。

普通文明改地、拆路和填筑必须先验证合格替代路径后原子换证；不能破坏仍在使用的邻房接入。God 的允许破坏路径可撤销运营证书并记损失，不受“永远保通”锁死。两者使用同一单写者与账本，不共用一个模糊 `force=true` 后门。

## 5. 笔刷、预览、批准与单写者提交

### 5.1 采样与草稿

屏幕 raycast 命中权威柱顶/竖边，并返回 owning CellRef、命中面、WorldId、snapshot revision。竖面命中归实际拥有该边面的高列，不因相机旋转选到墙后格。实体遮挡与“只选地形”是明确工具过滤；视觉矿物曲面、波浪或过期 HLOD 不参与地形坐标裁决。

pointerDown 捕获高度锚、preset 参数与快照；拖动在 X/Z 记录世界空间线段。按固定空间间距补采样、排序去重，再以固定点 falloff 和确定量化产生 patch；不按渲染帧数、鼠标事件数或 frameDelta 多次增高。同一 stroke 一个草稿/命令，Esc 只取消未提交草稿。镜头转动改变观察，不改变已经形成的 patch。

夷平锁定 pointerDown 的目标高度；平滑读取同一修改前快照及固定邻域，以有界整数权重计算候选高度并按固定 tie-break 量化。相邻格读取必须进入 readSet，不能只校验写入格。一次 stroke 的平滑 pass 数是 payload 中的明确有界值，不随拖动帧数重复整幅滤波；按列顺序读已经改过的邻格会产生方向偏差，禁止作为实现。

吸取/复制是只读 PlayerProfile/clipboard 行为。有限 `TerrainTemplate` 只能包含 `heightQ/topMaterial/biomeId/fertility/moisture/cover`、尺寸/profile/定义版本与必要只读来源说明，不包含 Person、Plant、Building、Road、库存/矿源、claims、身份/法定关系、原 mutation event 或命令回执。粘贴目标一律为新的 DIVINE_EDIT，进入 `CommitTerrainStroke` 的同一种实际 patch/后果二验；不是把源地块历史一起克隆。源与目标量子/格/profile 不兼容时需明确转换预览或拒绝，不能 silently rescale/clamp。粘贴生态与高度的复合变更由一个跨层写集提交，不能循环发送数个独立 biome/terrain 命令冒充原子粘贴。

```text
TerrainEditProposal
  canonicalStroke, presetOrHeightOperation, materialOperation
  ecologyOperation?          // 仅白名单字段，可供复合模板粘贴
  consequencePolicy          // PROTECT_OCCUPANCY | ALLOW_DAMAGE
  explicitRelocationPlan?    // 真实已有 Person/Vehicle/Cargo 引用和目标
  sortedPatch{CellRef, beforeColumn, afterColumn, expectedRevision}
  requestedDomainPolicy      // 必须明确整体/显式内域裁切

TerrainEditPreview
  actualPatch, skippedCells, constraints, changedVolumeSummary
  directlyAffectedRefs, supportAndAccessChanges
  exactDirectLosses, hazardCandidates, plannedLocations
  affectedWaterComponents, routesRequiringRevalidation
  unresolvedConnectivity    // 未完成搜索不能假报精确停航结论
  reservationAndContractTransitions, rightsRetained
  readSet, profileHashes, previewToken, consequenceHash
```

这是接口合同，不是已存在的 C++ 类型。wire 命令为 `PreviewTerrainStroke / CommitTerrainStroke`；生态另走 `PreviewBiomeStroke / CommitBiomeStroke`。wire 模式 `protect / destructive` 分别对应本文件语义 `PROTECT_OCCUPANCY / ALLOW_DAMAGE`。source/capability 由可信 Dispatcher 提供；payload 不接受用户自报 `isGod`，`god_terrain_enabled` 的当前 rule revision 也必须通过提交二验。patch、关联对象/输出大小、顶面范围、数量乘法和队列上限均先校验。超过准入上限须缩小笔刷或进入已明确批准的有界长任务，不能偷偷截断关联住户/货物列表。

### 5.2 两种后果策略

`PROTECT_OCCUPANCY` 是保护占用的安全笔刷：先排除候选改变会破坏已占用实体、施工/永久通道、泊位和实际使用 claims 的支承/碰撞/净空条件的格，明确显示跳过格和真实 patch。仅有地块所有权或行政领土主张不代表物理占用，不因此锁死空地；没有功能影响的材质改变也不应凭“已登记权利”一律跳过。对剩余 patch 仍检查全局影响；没有直接压到物件不等于安全。例如封闭无物件海峡也能废掉远处港口的必要远洋连接。若必需证书无法重证，停止本次提交并提供实际阻碍/转入允许破坏预览；Pending 不假装安全。

`ALLOW_DAMAGE` 允许编辑被占用格、挖掉旧通道或堵塞泊位。抬起鼠标后用紧凑批准动作呈现确定的建筑失效、受困/落水/掩埋对象、货物损失、暂停工程和可能停航范围；批准针对实际 patch 与 consequenceHash，不针对后来偷偷扩大的笔刷。不会自动把普通 brush 变为生命清除工具，也不会把所有占用格都永久禁止。

预览不移动人、占用新仓位、扣钱或产生历史。可选事前撤离通过已有 Divine Hand 显式搬运已有对象，或通过真实移动/运输任务完成；随后重新预览地形。仅有“将来可以撤走”的承诺不证明当前已撤离。神力迁移必须明确列出原/目标位置、容量和来源，不把自动免费安置藏在改地按钮中。

直接风险预览可以暂停模拟供核对；暂停属于会话运行控制，不修改 World/RNG。若模拟继续，提交必须二验移动者、到货、住户、库存、工程与 claims 的最新版本；后果发生变化返回 RequiresRepreview。渲染线程不能因为预览缓存耗时而预先刷权威地图。

### 5.3 一次提交涵盖所有立即后果

提交器按 [CONTRACTS](CONTRACTS.md) 的固定排序、幂等与强异常协议执行：

1. 验证命令/授权、canonical payload、所有 CellRef 与 WorldId、定义/profile 和 readSet。包括相关支持面、物权/容纳/货物、到期任务、旧路线依赖与水图版本。
2. 在新的列图上求所有直接支承/碰撞变化；列出准确对象集、互斥新位置、直接损失/危险状态、预约和合同过渡。原预览不能覆盖新进入刷区的居民。
3. 准备列页、实体状态、损失分录、死亡/危险队列、未用预约释放、证书失效、空间脏集、历史/回执的完整写集和容量；失败发生在 publish 前。
4. 核验商品守恒、每人/载具/批次唯一位置、无虚构资金/人口、支承有效或显式非运营状态、所有无效旧证书禁止使用。
5. 单写者一次 publish；height、实体后果、账本、due tasks、回执、事件、terrain/navigation revision 同屏障出现。不存在“地图已经变海、居民仍站旧地面”的可观察半笔状态。
6. 只读 worker 重建表现/导航。其结果携带完整 generation；只有经当前版本验证的缓存可用于查询。恢复运营、重路由或真正损失结算仍通过可信提案/提交器。

同 commandId 重试返回相同回执，不能再扣一次库存/杀一次人。不同 worker 先完成不改变后果顺序。不得每笔复制全 World；使用受限 copy-on-write 列页、预分配写集和有上限的反向依赖索引。

全局导航未完成时，允许破坏提交可以一次撤销受影响旧组件的相关证书并将服务置 `NAV_UNVERIFIED`，随后逐份重证。已在途对象可沿未改变且仍有有效局部证据的段继续，到脏段入口停在最后合法位置；不能继续使用旧 oceanConnected。受影响远处范围可以保守暂停，但 UI 必须区分确定断路与待验证，不虚构未来饥荒或确定全船损失。安全策略的必需保通承诺则必须等到 Ready 的有效替代证书才可批准。

## 6. 地形改变时，已有实体如何留下真实后果

### 6.1 支承图与绝对位置

每个受地面支承的实体保存 `SupportBinding{supportSurfaceRef, supportVersions, footprint, contactRule}`，并由空间索引提供 `column/chunk → support/occupancy/claim refs` 反向关系。临近高柱变化还会影响通道净空和扫掠体积，不能只查被刷格的中心对象。

建筑楼板、基础、桥面、入口和容纳器保持已批准绝对标高；新地面不能免费抬起整栋楼、补长地基、铺新坡道或更新模板容量。地面与原已批准埋入基础重叠可以是合法支承，必须按原支持 envelope 判断；侵入楼板/内部通行体积或撤走必要支承会导致失效。新地形材料没有自动增加建筑 condition。

### 6.2 人物与载具

|新状态/情况|权威处理|不允许的替代|
|---|---|---|
|当前支承小幅升降且不碰撞|在同 X/Z 按有限 step/profile 重新贴地，记录表面带动；不水平搬运|任意大抬升都免费送上峰顶|
|支承明显下降、原位置悬空|保持原位置/速度进入 FALLING；关闭常规地面任务，排入确定性碰撞/落地事件|瞬移到新低地并跳过坠落|
|新柱体侵入人物/载具体积|进入 TERRAIN_ENTRAPPED/DAMAGED；按已批准直接危险/损失规则处理|把物件穿到柱顶或无声删除|
|人进入可承托浅水|满足最大涉水深度、床面步高/坡度、净空与真实退出路径时可 WADING；wet 仍不变|把整个浅水 preset 自动当干陆或车辆路面|
|人落入超过能力的 WATER|进入 IN_WATER 危险状态；有限救援/岸边到达条件和期限，未获救按真实死亡事件处理|把浅水当无限站位、补船/补人|
|船所在格水深不足/陆地侵入|GROUNDED/受损，保留船、船员/乘客与货物；暂停正常航行|搬回母港、吞乘客、生成替换船|
|车路面被切断/埋入/淹没|停车或危险状态；保留载荷、订单与唯一位置|自动交货、改车库归属、取消全部车资产|
|仍在建筑/船内且容纳器未失效|保持原 Location，按真实容纳状态/出口可用性处理|为重建图把每个人放回地图|

人物和车辆的伤害、可跨台阶、落地阈值、落水救援期限属于锁定 movement/hazard profile 的校准值；不是随机灾害，也不由动画结束判断。地形神力危险不受关闭 hunger/aging 的规则豁免。死亡进入既有唯一终结事务，保留稳定身份、家庭/作者/Army 历史、真实遗产/代管，禁止创建替代居民。

profile 至少列出有限 `maxCarryUpMm/maxCarryDownMm/maxWadeDepthMm/safeFallMm/lethalFallMm/fallDamageRule/inWaterDeadlineTicks/entrapmentRule`。每个危险记录包含 `causeEventId, startedTick, dueTick, physicalContactVersions, rescuePredicate, damageRuleVersion`，避免“先加一个危险 bool，以后再处理”永久悬挂。候选涉水深度可先试 0.5m；2m 的浅水工具目标不等于人物能涉水 2m。可控输入/固定规则决定结果，不按镜头、线程或随机救援自动免灾。已有 DivineRelocate 显式救起后关闭原危险任务，幂等检查阻止旧 due task 随后再杀一次人。

FALLING 使用权威量化位置、起始 tick/速度、固定重力/步进版本与 swept collision。不同仿真加速分段要在相同逻辑采样/碰撞事件上得到相同结果，不能每帧 Euler 更新。再次改地可能改变落地点，需重新校验接触，不能穿过后升起的柱体。允许表现插值；LOD/镜头隐藏不会停止坠落、落水期限或食物需求。

第一版不要求建筑逐砖倒塌或居民逐室室内物理。失效容纳器中的居民可进入 `TRAPPED_IN_DAMAGED_CONTAINER`，保留原容纳槽、最后已提交位置和救援入口；只有合法出口/救援释放后才转 OnSurface。不能用没有室内坐标的模型假报精确全员坠落位置。若后续加入结构坍塌伤亡，需为模板定义受限的内部危险/出口映射和确定性规则，另验收。

### 6.3 建筑、植物与货物

建筑区分 `ACTIVE / ACCESS_SUSPENDED / FLOODED / UNSAFE_SUPPORT / RUINED` 等状态，具体标签通过有限注册表统一。支持/内部碰撞失效至少立刻关闭相应实际服务，显示损伤或封闭状态；不继续给予住房容量、工厂产量或可用出入口。残骸/受损结构由已持有资产表达，不另发一批免费建材。修复/重建需要真实料、钱、路线及工程；填回地形只能恢复接触条件，不能抹掉已发生结构损伤。

仅出口失联与本体损坏是不同原因：旧房仍可保留产权和现有内部人员，但新的入住/通勤/供料停用。既有居民不因 `capacity unavailable` 自动死亡或注销；是否能继续获得内部现有食物按真实货物/任务处理。

植物/农田在被淹、埋入或撤掉支持后按定义进入失效/死亡，记剩余资源损失并停止未来生长/收获；terrain SOIL 不免费创建 Plant。矿物场不随新柱体出生、消失或重置，详见下一节。

货物只有如下明确处置：保留在仍存在的容器；通过批准的真实搬运/神力搬运转到有容量位置；留在原受损/搁浅容器等待恢复；或按批准的实际损失量写 LOSS。`DamagedContainer` 只保管当时已有批次，锁定不可用且不接新货，不能成为免费的无限应急仓库。它保留每批 owner/custodian/location、用途限制、质量与预约；残骸货物恢复不改变所有者。

应计损失针对真实数量/质量，不能“关厂”就删除客户代管货，不能地形变化把整个 CitySquare.Storage 清零。现场/在途/仓库批次仍互斥；保险、政府补偿或新仓储必须有真实出资/容量，不因神力创造货币。钱和债务不从地图柱体派生，地块沉海也不自动将银行余额删除。

## 7. 建筑地基、路权与港区的新规则

### 7.1 联合建址与支承

新房必须在同一个当前 TerrainSnapshot 下批准完整 SitePlan：主体 footprint、固定水平楼板、所需原创长方体地基、人物入口、必要车库接入、现状前侧送货路线/接货点、施工围网与永久/临时 claims。不能先批准屋子，等它在山上建好再寻找任何下山路。

坡地需地基时，楼板 H 至少高于完整 footprint 最高实际地面并满足模板间距，底面 B 按最低支承/有限埋入确定；检查所有相交列与边面，不只查中心/四角。水平楼板并不保证外部可达。需要过高基础、超材料/工程能力或无合格接入时，普通建设可拒绝；玩家可明确改地、移动房子或调整 SitePlan，不能无限加高免费地基绕过。

人行/车辆证书分别验全宽、净空、所有实际台阶、纵横坡、连续接触、转弯/轴距与门口 socket。首样本人物最大台阶 0.5m、车辆 0.1m 是候选校准；需与角色/碰撞验收后锁定。车辆面对 0.5m 像素竖壁必须用实际原创连续坡面/道路连接件，平均坡度足够也不能放行。道路几何可以细于 SurfaceCell，但不能以导航插值替代物理道路。

前侧配送发生在实际当前地面，不能依赖尚未完工的地基或未来坡道。真实材料送到已批准接货点后自动按工期建造；原创长方体铁丝网分层围上、施工全包围、反向分层撤下，继续按 ADR 0002。围网范围涵盖实际基础/接入施工件；地形编辑破坏它时，自动工期必须按现场/项目规则暂停或转重规划，不能仍在到期 tick 发完成楼。

### 7.2 旧接入、路权与新相邻项目

每份有效入口/道路/配送证书保存实际依赖列/表面/门户/profile/权利版本。旧 `RoadPortal` 不能继续作为“地面永远不变”的可信输入：固定网络身份与法定路权可保留，但其地面接触和有效网络连接必须随编辑重证。

普通新项目和文明地形工程不得侵占旧永久/临时保护域；邻楼不会因为重新寻路而获得穿过别人地基的权利。合法改路先预约/建成替代面与权利，证明全要求入口可达，再同屏障换证/退旧 claim。未启用候选路径不算替代证明。

God 允许破坏编辑会撤销旧几何证书、暂停物理道路/入口；法定地块、地役权、主权、所有者和合同不自动消失。路权是一份可受损的法律权利，不是强迫地面永远存在的神力屏障。保留权利与失效原因，防止新公司趁道路被淹“免费认领无主地”。修路/退出权利走真实程序；神力亦可明确再次造陆，但不会免除新施工成本或补偿责任。

### 7.3 Port 不再要求 RECLAIMED-only

新版港口要求完整干燥可支承核心、指定整边连续的足够水深/净宽泊位、泊位障碍/船型/转弯/净空检查、合法陆侧实际接入以及对应水路证书。矩形正交模板可继续使用；天然地、神力地与文明填筑地均可满足同一物理检查，来源仅为 provenance。不能把地基覆盖水面称为干陆，不能只因为按 `deep` 画过就宣布远洋可航。

远洋服务需要当前 SEA 连接及实际船型路线；湖港允许对应模板/服务在 LAKE 中运营，不因此创建外海目的地。God 堵泊位/海峡可暂停港口，保留船、乘客、货物、法人和债务；普通后建项目继续保护必需泊位/陆水接入。拆除 Port 不自动拆其周边地形，改地也不免费新建 Port。

## 8. 人口、矿产、城市、经济与取消闭环

### 8.1 不通过地形创建任何人口或资源收入

只有既有显式 PlayerPlacement 与合法 Birth 能新增 Person。新岛、土壤、CitySquare 或港口不生成居民/工人/水手；受困人口、移民、补员、迁居都必须消费实际已有引用。土地所有者/控制者、人的法定国籍/位置、城市行政归属继续分开，不能从刷出的颜色推导。

地形量只是空间，不是石料、木材、矿石、纤维、食物或资金。将山改成深海不会把“被挖掉体积”发到仓库；将深海变山也不会新建矿源。资源笔刷仍独立修改原位 rate：先积分至提交 tick，增加 rate 不立即补 stock，减少超容量记编辑损失，开采才将真实原位库存转为货物。地形改变仅影响现状开采可达/矿场支承，不重置 rate、stock、lastIntegratedTick 或已采出批次。

矿场被埋/淹时可以停业，但矿源记录仍在该列的独立资源层；新高度下是否能合法开采由现有资源/设施/路线检查决定。不能反复“挖海→抬山→重建矿场”拿到初始一日储量或重复补贴。未来若采用真实地质层，必须新增资源来源与守恒迁移，而不是借本合同暗增矿脉。

### 8.2 城市不因物理损伤失去身份

City/Settlement 的行政 ID、正式文化、法定国家、负责人、居民登记、账户和唯一 CitySquare 引用保持。其广场楼可成为受损/非运营设施；“正式城市有唯一广场实体”不应被解释为“广场必须永远完好，否则删城”。人口实际所在、常住登记、国籍分别更新/显示，受困不等于迁籍，跨水孤立不等于政治独立。

企业 Facility 可停产而法人、员工、客户货和债权仍存在；劳动/采购订单基于真实可达能力重新调度，不保证永恒盈利。公共恢复服务使用真实人、料、时间和预算；不自动补屋、补粮、补工人。运输到达、生产投入、发工资等提交按当时路线/运营/劳动事实二验，不从旧预览继续结算不可能完成的工作。

### 8.3 预约和合同必须知道哪部分已经发生

地形编辑可以释放未出发的占用/容量/材料预约、停止待执行任务或改变真实目的地；只能退未消费部分。已消耗材料、完成劳动、已支付不可退款项、已吃食物不会回到期初。已出发货保留在途容器，进入等待/合法重路由/退回/实际损失流程；不能释放预约后让同一在途货同时出现在源仓库。

改地不自动宣布所有合同违约或全额赔偿，依据条款与已发生事实处理。事件源明确 DIVINE_EDIT 并关联 terrain stroke，既不伪称战争，也不伪称随机天灾。若当前领域没有实现相应结算，生产按钮必须按支持范围显示未接入；不能展示虚构 Accepted。

## 9. 存档、恢复、迁移和受限撤销

### 9.1 必须保存的事实

保存当前权威列/Chunk 编码、独立生态层/版本、基底/patch 哈希、PixelTerrainProfile、有限 G/D/guard、固定水位、水体持久身份/锚点/拆合档案、初始化 provenance、地形事件/幂等回执、编辑版本；同时保存受影响的实体位置/危险状态、损伤、保管容器、预约/在途/合同、基础绝对标高、claims、证书状态、矿物积分与 due tasks。不得只存 brush 日志再要求未来按新版本重新生成全部世界。

SEA/LAKE 连通索引、GPU 网格、边面、波相位和视觉 pixel LOD 是可重建数据，不能成为 height 的另一个权威副本。临时 WaterRegionRef 应绑定 topologyEpoch + componentKey；组件拆合不复用旧引用冒充同一永久水体身份。水体页面/收藏使用持久 WaterBodyRef 与拆合档案，实际地图定位用锚点/当前成员查询，不靠易变组件序号绑定。

**如果导航 Pending 的逻辑工作预算影响什么时候可以继续移动，重建作业也是需要持久化的调度状态。** 保存相关 source versions、逻辑阶段、frontier/visited 或足以确定性重建其同一步进的检查点、已用预算、待发布结果/顺序与 due tick。仅保存地形再把所有 Pending 任务重新从零跑，会改变运输等待与饥饿；加载时立即宣布全部 Ready 也会提前交货。派生缓存可在墙钟加载阶段复建，模拟时刻/逻辑就绪事件仍须恢复原计划，缺必需状态不得悄悄猜测。

加载到隔离 staging：校验 schema/定义/profile/源包 → 数量/高度/编码/哈希 → 当前列 → 实体/互斥位置/物权 → 受损/危险/到期任务 → 预约和双账 → claims/证书与重建作业 → 导航/表现缓存 → 一次发布。载入 FALLING、IN_WATER、GROUNDED 或受困容器不得自动贴新地面/回港/复活，也不按电脑离线时间补损耗/矿量。

旧冻结 mask 的有限 kernel 或 ADR 0011 平陆存档不是新版完整世界存档。显式迁移保留原件，把原已提交地表转换为初始像素列、核验建筑/道路/入口几何并报告损失；不能直接把旧 mask 哈希当“当前高度不可改”约束。迁移不能给已有无证据人口补来源、给地形补矿、退款已完工填海或凭空修通道路。当前未交付此迁移器。

### 9.2 撤销的边界

未提交草稿可无后果取消。仿真保持暂停的静态空地图已提交 brush 可提供反向命令，要求关联列/claims/资源/实体/拓扑依赖的 post revisions 未被后续事实改变，且没有因原编辑发生人员危险、损失、工程投入、开采/生产/交付或资产转移。反向命令恢复列值，但保留原历史并记录 `UNDO_OF`，递增新 revision；不是回滚整个 World。

已有相关后果时，玩家仍可新刷回原高度，但不会复活、恢复 condition、复制货物、清债或恢复原合同。不能把“货物已经落水但没点开详情”当无后果。仅渲染缓存/LOD变化不阻止静态撤销，实际相关事实变化必须阻止；需要一份明确依赖/后果审计，不能用全局 World revision 粗暴禁止一切不相关撤销，也不能只查被刷格的高度。

## 11. 接入顺序与当前实现边界

1. 先形成纯 headless PixelTerrain 列/边、固定水位、八 preset 与单 writer patch 的可重放 oracle；Blank/Earth 经同一种权威像素化与首存档发布。空图可编辑不是城内编辑的证明。
2. 接入 wet/SEA/LAKE 与船型分块图、过期/Pending、guard、最高游戏几何预览和读取当前列的 360° pixel renderer。近岸 shader 不能代替此层。
3. 接入 SitePlan/固定基础/实际路面/配送/占用权利反向索引；证明正常新建保旧通，随后接入 God 允许破坏的完整直接后果。
4. 接入居民/载具危险与受损容器、合同预约/在途/CitySquare/资源反套利，完成城内编辑→实际停业/救援/恢复的贯穿场景，再做全量存载/迁移与规模测量。

现有 FrozenWorld 施工/港口切片、历史 slope SiteRegistry、独立 interaction/clothing oracle 和原生平面/PBR 地理预览都不能证明上述已完成。旧 SITE 把地表当不可变、旧 Port 强制 RECLAIMED，不能只换几种材质就称新版。已有可复用部分是整数/稳定 ID、可信入口、幂等/强异常测试方法、账本/位置语义和限域地理 source 资料；各旧算法必须按本合同重新验收。
