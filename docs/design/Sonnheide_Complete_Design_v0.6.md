# 01 · Sonnheide：范围、冲突裁决与最小核心

Sonnheide 是一个只有人类的、真正三维、可360°自由观察的写实风文明演化沙盒。玩家是世界中的上帝，也是文明／资源编辑和观察者；地球水陆边界不是可编辑对象；重点是文化形成、知识传播、城市经济、宗教政治和可精细指挥的战争。它不再以完整复制 WorldBox 为目标。本文是独立游戏设计，不把任何新规则称为 WorldBox 的真实机制。

**版本：设计基线 0.6，2026-10-06。** 数值均为可配置的首轮平衡方案，不是已经跑过完整文明模拟的结论。交付的参考规则代码和测试，不等于完整游戏或三维客户端。

## 1.1 不可扩张的边界

保留人类、人口生命周期、植物与木材、来自真实地球数据的不可编辑天然水陆底图＋受限人工造陆层、城市、国家、文化、语言、玩家宗教、科技、建筑、企业、物流、法律、移民、军队与历史。删除野生动物、其他智慧种族、怪物、魔法战斗、瘟疫传染、随机天灾、世界时代灾变、复活和大规模毁灭神力。保留一种非破坏性的直接玩家干预工具 `Divine Hand / 上帝之手`：只负责批量抓取并搬运人物，不造成伤害，也不直接改变身份、文化、语言、信仰、财产或Army关系。饥饿、衰老、战伤、物资短缺、政治压迫和失业仍是文明本身的后果，不作为独立灾害系统。

马是明确的例外：作为被拥有的交通／骑乘资产，而不是动物生态个体。没有野马繁殖、捕食和兽医产业。船、马车、汽车均无单独驾驶员职业；士兵骑乘时仍是实际参战的人。太阳能自动汽车是本世界的晚期民用便利设定，不引入现代能源工业、电子工业、现代装甲兵或现代火器。

不增加股票实时交易所、期货衍生品、外汇、空军、铁路、飞机、外交间谍小游戏、疾病医学、建筑室内漫游、独立宗教魔法、逐颗螺丝物流、程序化宇宙或多人服务器。历史真实度不是逐年复刻现实历史；制度与资源的因果一致性才是验收标准。

## 1.2 统一核心，而不是三个互不相通的大游戏

只有五类共享基础机制：**身份与关系、资产与账本、知识与许可、任务与合同、空间与运输**。教会、公司、城市共用资产账本和合同执行器；大学与研究所共用研究项目；军粮、商品、建材共用城市广场仓储账本与运输任务。它们的权限与目标不同，但不另造三套相似引擎。

对象的法定身份、物理位置、所有者、控制者必须分别储存。Culture 与 Language 也必须分别储存：除第一次 Primary Genesis 的共同诞生事件外，两者没有一对一生命周期绑定。某批货位于城市广场仓储区，不等于归城市所有；某家公司总部在王国，不等于所有海外收入都在总部征税；某人加入官方宗教，不等于改变国籍；某支军队占领城市，不等于城市已经合法被割让。

## 1.4 规则、参数和展示的优先级

硬约束优先于预设，预设优先于 AI 偏好。玩家法律编辑改变政策，不自动生产真实物资；玩家授予帝国资格改变合法地位，不自动扩充军队；玩家选择建筑皮肤不恢复建筑耐久、不创造住房容量。每个按钮必须回答“谁支付、谁执行、在哪里发生、哪条规则授权”。

本版不强制玩家管理预算表。默认自动治理负责基础生存、维护、补货、招工和常规投资。玩家通过地图上的方向性命令介入，在检查器展开时才看到账本、法律条文或科研零件。

# 02 · 真实地球地图、世界、人、前文化国家与文化场起步

## 2.1 世界空间：真实地球底图、天然地理冻结、人工造陆覆盖层

Sonnheide 不程序化生成大陆，也没有抬高／降低地面、山丘、山脉、挖海、自然海岸笔刷或自由造岛。**天然地理底图永远只有 `LAND` 与 `WATER` 两类，并且在世界创建后永久冻结。** 没有高度场、坡度或可编辑海拔；写实3D来自建筑、人物、道路、船舶、植被、水面与人工工程，而不是可塑形地形。天然陆地使用统一基准高度，水面略低于陆地。

全球天然水陆边界来自随游戏离线打包的地球海岸线数据。首版数据源建议使用 **GSHHG 2.3.7** 的全球闭合岸线多边形，并在构建阶段只提取水陆判断所需层级，转换为 Sonnheide 自己的多分辨率 `EarthLandWater.pack`。原始数据不需要在运行时全部解压到内存；包按全球空间瓦片和LOD索引。数据源与版本写入 `GeoSourceManifest`。

创建世界仍分为五步：

1. **全球浏览**：连续缩放／平移真实地球水陆预览；低缩放读取粗LOD，高缩放只载入视窗附近高LOD岸线；
2. **框选区域**：玩家拖出轴对齐WGS84选择框；政治国界、现实城市、道路、人口和文化不参与生成；
3. **投影到游戏平面**：把选区岸线转换到局部平面。首版使用以选区中心为原点的局部方位等距投影，过大选区明确提示形变；
4. **等比例缩放**：只调整一个 `worldScale`／目标长边尺寸，X、Z共用同一比例，另一边自动推导；
5. **栅格化与冻结天然底图**：生成 `NaturalLandWaterMask`。这张底图和worldScale成为存档硬事实，游戏内任何命令都不得把天然LAND改水、把天然WATER改成天然LAND或移动真实岸线。

为了允许文明建设港区，世界另有一个极小、稀疏的**人工造陆覆盖层**：`ReclaimedLandMask`。它不是第二套地形，也不会修改 `NaturalLandWaterMask`。有效地表按下式决定：

```text
if naturalSurface == LAND: effectiveSurface = LAND, landOrigin = NATURAL
else if reclaimed == true: effectiveSurface = LAND, landOrigin = RECLAIMED
else: effectiveSurface = WATER
```

因此游戏逻辑仍然只有LAND／WATER两种可站立／航行结果，但任何人工陆地都永久知道自己的来源。存档、历史、港口验证和调试都能区分天然陆地与填筑陆地。

### 2.1.1 人工造陆 / Reclaim Land

人工造陆是**建设工程**，不是自由地形编辑器。玩家在建设模式选择 `Reclaim Land / 人工造陆` 后，只能按不可见逻辑格**逐格**选择天然WATER。可以按住拖过多个格，但系统把它拆成独立的单格 `ReclamationCellJob`，逐格预约材料、施工和完成；不是一笔命令瞬间把大片海变陆。

首版只使用现有资源闭环：每格消耗配置化数量的石料／通用建材和施工劳动，不新增“泥土”“填海砂”等专用商品。城市公共施工可以执行，成熟社会也可由建筑公司承包；材料从 `CitySquare.Storage` 正常预约、运输和扣除。未筹齐材料的格保持WATER，不能提前站人、铺路或建建筑。

为了保持“填海”而不是“凭空造岛”，一个新造陆格在提交时必须通过**四邻接**检查：至少一条边邻接天然LAND或已经完成的RECLAIMED LAND。只对角接触不算连续。玩家因此可以从真实海岸一格一格向外延伸平台，但不能在海中央点击出孤立岛屿。首版不提供完成后的拆海还原；规划阶段和未完成工程可以取消，完成后视为永久公共工程，避免反复填／挖制造路径与库存套利。

施工状态只有：`PLANNED → RESERVED → UNDER_CONSTRUCTION → COMPLETE`。在 `COMPLETE` 之前，该格的 `effectiveSurface` 仍是WATER；施工表现可以显示桩、驳船或填筑进度，但船舶导航会把施工占用区作为临时障碍，避免穿过工地。完成事务原子地设置 `ReclaimedLandMask[cell]=true`，随后局部刷新道路／建筑合法性、水路连接和渲染网格。

造陆格严格与逻辑格网对齐，所以人工岸线天然是横平竖直的阶梯／矩形边。渲染层可以用写实挡墙、石砌岸壁、混凝土或时代对应材质遮掩格线，但**碰撞和港口法律边界仍按格网直边**，不偷偷把它平滑成斜岸。

同一地球选区仍可做成较小或较大的游戏世界。放大worldScale会增加海岸相对于建筑的空间；缩小会减少可用格。界面必须显示最终长宽、逻辑格数量、预计内存／路径预算。相机Zoom只改变观察距离，不能改变worldScale。

普通建筑、道路和人物使用 `effectiveSurface`，因此可以建在天然LAND或已完成的RECLAIMED LAND上；船舶只能在 `effectiveSurface=WATER` 上航行。桥梁仍是Road网络的跨水基础设施，不改变天然水陆或人工造陆层。**Port是唯一额外要求 `landOrigin=RECLAIMED` 的核心建筑**，见5.8。

天然岸线渲染仍使用裁切后的矢量轮廓；人工岸线由 `ReclaimedLandMask` 叠加生成直线挡墙／平台边界。世界不做侵蚀、潮汐、水动力学或天然海岸变迁。人工造陆完成后会改变实际可航水域，因此旧的只读 `seaConnected` 只能作为天然底图提示；运行时港口和船舶使用基于当前 `effectiveSurface` 的 `WaterNavigationRegion`。造陆完成仅标记受影响导航Chunk为dirty并局部重建，不每次重算整张世界水网。

每格最小空间数据为 `naturalSurface, reclaimed, buildOccupancy, roadConnectivity, territoryOwner, mineralRates`。`effectiveSurface` 和 `landOrigin` 可以缓存但必须可由前两者重建。天然岸线附近的 `CoastCoverageIndex` 仍只服务自然边界的快速视觉／建筑预检；人工造陆不修改它。**删除可写terrain、height和slope。** 矿物分布编辑与人工造陆是两个完全独立系统：矿物笔刷不改变水陆，造陆也不会凭空生成矿藏。

## 2.2 人的最小资料

Person 包含稳定 ID、出生日期、存活状态、当前位置或容纳空间引用、家庭、显示身份、正式姓名记录、文化强度集合、语言能力、信仰、职业／雇主、居住城市或聚落、法定身份、财产账户、知识能力、性格、需要和军事服役状态。 服饰不建立复杂库存：可视服装由“是否有文化＋法定国家归属＋性别＋国家主题色”即时派生，避免给每个Person维护独立衣橱。

性格只保留会改变决策的六个轴：求知、虔诚倾向、利他、冒险、秩序偏好、野心。不是六种等级或天赋种姓，玩家可编辑；它们改变行动倾向，不代替工资、食物、证据和法律等实际约束。

需要只有基础食物、住所、安全、家庭联系；晚期才增加舒适与文化消费。快乐消费不会在上古阶段制造对眼镜或乐器的需求。失业不导致瞬间死亡；先转入公共工作、领取有限保障、节约消费或尝试移民。

人必须能出生、成人、学习、工作、迁移、服役、衰老和死亡。无疾病、无遗传怪物、无外貌基因研究树。亲属关系服务继承、家庭迁移和命名，不单独建设宗族小游戏。

## 2.3 前文化人口、聚落和国家是真正可持续的社会

没有文化的人也没有正式语言。人物、前文化聚落和前文化国家都使用**稳定的5个大写希腊字母识别码**作为界面显示，例如 `ΩΔΠΛΡ`、`ΘΑΨΞΚ`。字母从 `Α Β Γ Δ Ε Ζ Η Θ Ι Κ Λ Μ Ν Ξ Ο Π Ρ Σ Τ Υ Φ Χ Ψ Ω` 中伪随机抽取，允许重复；它只是上帝界面的对象识别码，不表示这些人实际说古希腊语。生成必须由 `WorldSeed + EntityId + NameSalt` 决定，保存／载入后不改变。

前文化人口拥有生存性行为：简具耕作、砍木、基础住屋、短距离搬运、照顾儿童、食物储存和共同防卫。不能开大学、教会、成熟公司、银行或正式科研体系；不会因为没有文化就不能播种、建房或组织Army。

国家从一开始就是正式 `State` 对象，而不是另一套 ProtoState。所有新国家仍从 `rank=DUCHY` 开始，同时保存：

```text
phase = PRE_CULTURAL
rank = DUCHY
officialCultures = []
administrativeLanguages = []
displayName = 五字希腊码
flagKind = PRIMITIVE
```

前文化 State 可以拥有领土、统治者、聚落、公共仓储、基础预算、安全关系和Army，也可以战争、占领或迁徙。它不能称王、申请帝国、建立宗教或启用要求文化／正式语言的高级法制。前文化聚落仍叫 Settlement；文化化后才能正式登记为 City。这样保留“国家可以先于文化存在”，又保持正式城市一定有官方文化。

## 2.4 Cultural Genesis Field：文化不是经验条，而是局部相变

Sonnheide 不使用“人口达到500就生成文化”或“文化点涨满100”的机制。文化诞生来自一个低成本的随机动力系统：**Cultural Genesis Field（文化生成场）**。

每个有持续人口的聚落只维护少量 `GenesisNode`。默认有一个代表无文化人口的 Primary node；已经有文化的人群只有在长期形成真实独立共同体时才创建 Secondary candidate。每个聚落同时活跃的 Secondary candidate 有很小的硬上限（首轮建议4个），相近候选会合并，长期失去人口或差异的候选会休眠。系统因此不为每个人、每个地图格、每对文化建立场。

每个节点只有少量状态：

```text
phi              当前随机涨落振幅 Φ
mu               临界性 μ
kappa            社会耦合 κ
socialExcitation
migrationExcitation
conflictExcitation
achievementExcitation
contactExcitation
lastUpdateDay
nextUpdateDay
rngState
lastGenesisDay
```

`phi` 始终无规则波动；`mu` 描述无文化／既有文化状态是否仍稳定；`kappa` 描述该群体彼此形成共同体的程度。事件不是直接增加“文化经验”，而是给局部场一个会衰减的脉冲。

一个实现上足够便宜的离散更新可写成：

```text
phi(t+dt) = exp(-r·dt)·phi(t)
          + sigmaEff(population, kappa, supercriticalAge)·Noise(seed, step)
          + decayedEventExcitation
```

其中人口增加和高耦合提高随机波峰的尺度，而不是线性增加进度；事件脉冲提高短期波峰并可推动 `mu` 向不稳定区移动。Noise 使用独立的确定性随机流，不能依赖渲染帧率。

文化诞生只有在两个条件同时满足时才可能发生：

```text
mu < 0
abs(phi) >= nucleationThreshold
```

也就是说，社会先进入一个文化相可能稳定存在的超临界状态，然后某一次真实随机涨落或多个历史事件的叠加越过阈值，才发生 Nucleation。没有倒计时，也没有给玩家看的“97%文化进度”。

## 2.5 哪些事件会激发场

高价值事件包括：大规模迁徙、长期共同服役、战争胜败、建立第一个稳定政体、大型公共工程完工、重要技术突破、首次远距离贸易网、形成持续大学共同体、重大制度重组、具有极高影响力的人物出现。中小事件包括人口聚集、跨群体婚姻、持续交易接触、道路连通、普通工程和共同劳动。

所有事件只向少数固定通道累加数值，不保存成几万条每帧衰减的“文化波对象”。查询某节点时按经过时间一次性应用指数衰减：

```text
E(now) = E(last) · exp(-lambda · dt)
```

历史系统仍可保存重要事件文本／结构化记录，但文化场不逐条扫描历史。

## 2.6 自适应调度：性能必须优先于漂亮方程

文化场完全运行在 Slow Tick，不参与渲染帧。建议调度：远离临界的节点每60个游戏日更新；活跃节点每15日；接近临界每3日；`mu<0` 且接近阈值时每天更新。事件到来可提前唤醒一个节点，但只更新该节点。

节点使用 lazy decay：长期平静的聚落不每一天执行乘法；再次访问时根据 `now-lastUpdate` 直接求衰减后的值。文化浓度仍按人的稀疏 small-vector 保存，城市传播先聚合 exposure pool，再低频作用到人，禁止 Person×Person 全连接传播。

所以文化系统主要复杂度近似：

```text
O(active settlements × small bounded cohort count)
```

而不是 `O(map tiles)`、`O(population²)` 或“每帧解连续场”。三维文化场视觉只是节点状态的GPU插值／着色，不反向决定仿真。

## 2.7 两种文化诞生事务必须严格区分

### Primary Genesis：无文化者第一次创生

当被选中的文化创始人在相变发生前 `cultures=[]` 且 `languageSkills=[]`，本次是 Primary Genesis。**只有这一种情况，文化和一门新的根语言必须在同一个原子事务中同时诞生。**

顺序：锁定创始群体→创建根语言→用根语言给创始人产生第一个正式姓名→创建 Culture→记录两者共同 genesis 事件→给首批成员分配文化浓度和至少一种语言→生成正式姓名→若国家采用该文化则把前文化 State 正式文化化→把符合条件的 Settlement 正式化为 City→切换正式国名和正式旗帜。

任何一步失败都回滚，不能留下“新文化存在但根语言没有创建”的半状态。

### Secondary Cultural Genesis：已有文化的人形成新文化

如果创始人已经有至少一种文化和正式语言，本次只创建**新的 Culture**。它**绝不因为新文化诞生而自动创建新语言**。新文化的初始成员继续使用他们原来实际掌握的一种或多种语言；一个新文化完全可以与父文化共享同一种语言，也可以天然多语。

语言之后是否分化，由独立的 Language Evolution 系统根据真实使用群体、隔离、接触和音变历史决定。反过来，一门语言也可以在没有任何新文化产生时自行演化成分支。文化和语言从 Primary Genesis 之后就是多对多关系，不再绑定生命周期。

## 2.8 不可缺少的公共兜底

正式城市永远拥有一个唯一的 `CitySquare`。它既是城市的政治／公共中心，也是城市唯一的逻辑仓储与跨城物流交接节点；`CitySquare.Storage` 按产权、用途、预约和在途状态记账。广场不是无限容量，仓储翼、装卸面和临时露天周转区都有容量。即使城市大楼局部损坏，系统仍保留最低应急登记与周转能力，使城市可以恢复；扩建始终扩同一个 CitySquare，不创建第二个“城市仓库”。

公共建造和徒步搬运永不永久消失。私营建筑公司倒闭后，城市可恢复小规模基础建造；全部物流公司退出后，仍能雇用公共搬运工。它们效率低、有真实人工和材料成本，不凭空创造高级产品。征服、宗教冲突和企业破产都不能把基本粮食领取接口关掉。

## 2.9 时间和观察

战略时间使用30日／月、12月／年的统一游戏历。移动／战斗用固定 tick，经济按日，工资和供给可按日结算，税务／企业评估按月，文化候选与宗教结构变化按低频自适应调度。所有频率是配置参数。

时代不是世界时钟。玩家可暂停、单步、加速；加速必须按实际完成的模拟步推进，不能跳过欠薪、射击冷却或货物到达。远景只简化显示，不能因为镜头移开就替换成另一个经济世界。



## 2.10 全球水陆数据包与许可边界

首版建议把GSHHG shoreline polygon作为构建输入，而不是运行时API。设计只需要L1海陆边界及形成正确岛／湖嵌套所需的层级；政治边界、河流线和现实地名都不导入文明世界。游戏发行包保留数据源版本和许可证文件。为超远景预览也可以使用同包的crude／low分辨率，而不是再依赖联网地图。

`EarthLandWater.pack` 是预处理产物：空间分块、压缩、多LOD、带包版本哈希。全地球数据可以随游戏一次性安装，但世界创建时只解码用户视窗／选区相交的瓦片，因此“拥有全地球”不等于“把全地球所有顶点同时塞进内存”。

# 03 · 复合文化、独立语言谱系、相变与命名

## 3.1 文化是一组独立浓度，不是单选标签

每人维护稀疏 small-vector `cultureStrength[CultureId] ∈ [0,1]`。各项**不要求和为1**：一个人可以同时高度属于两种文化。只在计算建筑风格、教育偏好或群体统计等混合权重时临时归一化。全为零才是游戏意义的无文化状态。

传播渠道只有真实接触：家庭抚育、邻里、工作、学校／大学、Army共同服役、移民、教会活动和长期共同政治生活。每个渠道有接触时间、语言可理解性、接受度与政策成本。文化强度提高不是自动改变国籍、宗教或技术拥有权。

文化的有效属性限定为会产生可观察后果的维度：建筑与公共空间审美、命名传统、知识保存习惯、教育偏好、公共仪式、合作规范和有限的制度倾向。禁止用“某文化固定+50%粮食”代替经济基础设施。

## 3.2 Culture 与 Language 在第一次创生后彻底解耦

必须区分**实体诞生规则**和**人的文化语言资格**。

唯一绑定点是 Primary Genesis：一个此前没有任何文化、也没有正式语言的创始人触发第一次文化相变时，系统必须同时创建一个 Culture 和一个新的 root Language。这是为了避免“没有语言却要给第一种文化命名”的死锁，也是 Sonnheide 的第一次文明化仪式。

从这一刻以后，Culture 与 Language 是多对多关系：

- 一个文化可以同时由多门语言承载；
- 多个文化可以长期共享同一门语言；
- 新文化可以诞生而没有任何新语言；
- 新语言可以独立分化而没有任何新文化；
- 国家官方文化变化不自动创造、删除或重命名语言；
- 语言消亡不删除仍存在的文化历史，文化消亡也不删除其语言记录。

因此 `Culture` 数据结构**不保存强制 `languageId` 字段**。实际语言关系从人口的 LanguageSkill、城市语言使用统计、学校／行政实践和历史索引推导。

## 3.3 Primary Cultural–Linguistic Genesis

Primary Genesis 只允许创始人满足：

```text
hasCulture(founder) == false
hasFormalLanguage(founder) == false
```

相变成功后执行一次原子事务：

```text
Create RootLanguage
→ assign first formal name to Founder
→ Create Culture
→ register common GenesisEvent
→ assign initial culture affinities
→ assign initial language proficiency
→ name initial members
→ formalise adopted settlements/cities
→ if a PRE_CULTURAL State adopts it, establish official culture and formal naming
```

根语言从八套作者编制的古语言风格资源中选择一个起点，再根据本次文化场 signature seed 生成具体音系／词形偏好。语言包只是风格化命名材料，不声称是历史语言重建。

Primary Culture 和 Root Language 会互相记录同一个 `genesisEventId`，便于历史页面说明“它们在同一相变中诞生”；这不是生命周期上的永久所有权绑定。

## 3.4 Secondary Cultural Genesis 不产生语言

一个已经有文化和语言的人群，因为边疆生活、军队共同体、移民混合、城市独立、大学社群、宗教运动、职业共同体或其他历史过程，仍可形成 Secondary Genesis。

当场越过阈值时，只创建：

```text
New Culture
Founder
Parent-culture provenance
Initial members
Style / practice signature
Genesis history event
```

**不调用 CreateLanguage。**

新文化成员继续使用他们原先真正会说的语言。例：A文化和B文化长期混居后产生C文化，C文化最初可能同时使用 A-Language 与 B-Language；也可能大多数人只使用A-Language。是否后来形成 C-Language，是另一套语言分化过程的问题。

Secondary Culture 的 parentCultureIds 只是历史来源，不表示属性做算术平均。新文化的初始特征由创始群体实际实践、场 signature 和继承来源共同生成。

## 3.5 人的“无文化→有文化”仍要求同时获得可用语言

实体 Culture 与 Language 不绑定，不代表个人可以“有文化但完全没有任何可交流语言”。游戏保持以下人物不变量：

```text
no culture  => no formal language
has culture => at least one language competence > 0
```

一个无文化者如果不是自己触发 Primary Genesis，而是加入已经存在的文化，他必须从家庭、收养群体、学校、工作或所在地真实取得至少一门现有语言，随后才完成正式文化接纳和命名。这里没有创建新语言，只是个人掌握现有语言。

已经有文化的人获得第二、第三文化时不需要获得新语言；只要社会接触允许，他可以维持原语言，也可以后来学习别的语言。

## 3.6 Language Evolution 是独立系统

Language 维护自己的使用者网络、地理／社会隔离、接触来源、音变历史和互通度。只有 Primary Genesis 能创建无父源的 RootLanguage；后续语言只能通过合法派生形成，并保留 parentLanguageId 或有限 parentLanguageIds。

语言分化候选不按“新文化出现”启动，而按真实 speech community 形成：长期隔离、稳定代际传承、足够使用者、重复音变、与母语互通度下降。跨文化边界不必导致语言分裂，同一文化内部也可以出现语言分支。

`SoundChange` 包含查找模式、替换、词首／词中／词尾条件、环境、启用年代、例外表和 ruleId。例如 `sh→sch`、`^i→j`、`us$→∅`、`ct→tt`。一代语言按顺序各执行一遍受限变换，禁止递归替换造成字符串爆炸。

音变不回写死者旧名或旧文献。新生儿和新命名对象采用当前语言版本；历史显示可同时保留当时写法和现代读法。语言谱系页面显示 Root→Branch→Sound Changes，但文化谱系另画，不把两棵图强行合并。

## 3.7 五个希腊字母是前文化“识别码”，不是正式名字

大写字母池固定为：

```text
Α Β Γ Δ Ε Ζ Η Θ Ι Κ Λ Μ Ν Ξ Ο Π Ρ Σ Τ Υ Φ Χ Ψ Ω
```

前文化 Person、Settlement 和 State 的当前显示名均为五个字符，允许重复，例如：

```text
ΩΔΠΛΡ
ΘΑΨΞΚ
ΑΑΠΩΓ
```

生成采用稳定伪随机：

```text
GreekCode = Generate5(WorldSeed, EntityId, NameSalt)
```

它必须跨存档、跨帧稳定；用户改游戏速度或打开面板不会重新掷码。内部一切关系永远引用 EntityId，不引用这5个字符。

对于 State，这五个字符就是文化化以前的**完整国家名**，不能在前面偷偷加一个自动地名；爵位只在信息副行显示，例如 `ΩΡΔΛΞ · Duchy / 公国`。

## 3.8 第一次正式姓名如何出现

Primary Genesis 中，创始人原先可能显示为 `ΨΛΡΘΑ`。系统先创建 RootLanguage，再由该语言给创始人生成正式 given name 和 surname。例如他第一次被正式称为 Friedrich。之后以这个正式身份生成文化默认名，并供国家／城市正式化时使用。

历史记录同时保存：

```text
previousDisplayCode = ΨΛΡΘΑ
formalName = Friedrich ...
nameAssignedAt = tick
nameLanguageVersion = ...
genesisEventId = ...
```

对后来加入已有文化的无文化者，正式姓名由他实际接纳的语言产生。再次获得新文化不会重新生成身份。玩家改显示名只增加 override／alias，不改 PersonId、发明署名或历史快照。

## 3.9 国家、城市、文化、宗教与技术命名

|对象|默认模板|冲突范围|
|---|---|---|
|Primary/Secondary Culture|创始人正式名词根＋文化后缀|Culture 世界范围|
|Root Religion|玩家指定或首位先知正式名词根＋信仰后缀|Religion 世界范围|
|正式 City / State|正式化创始人名词根＋实际使用语言的地名／政治后缀|对象类型世界范围|
|企业／城市创办设施|创始人姓氏＋创立时国家短名＋业务类型|同法域法人／设施目录|
|Army|驻籍城市短名＋Army＋序号|驻籍城市|
|Technology|发明者第一个 givenName＋技术／零件名＋罗马序号|世界范围，同规范化 givenName 与 familyId|
|Denomination|首位组织者正式名词根＋教派后缀|所属 Religion|
|Derived Language|主要 speech community 的既有地名／人物词根＋语言后缀；可由玩家改名|Language 世界范围|

科技第一次不显示I，第二次显示II；序号只处理撞名，不表示技术强弱。企业所含国家名保存创立时快照，后来迁址、征服或改国名不会让历史企业自动改名。

## 3.10 前文化国家旗与正式国旗

`PRE_CULTURAL` State 不能使用13种正式模板。系统生成：

```text
单一纯色背景 + 国家五字希腊码的第一个字母
```

背景默认只能从黑、白、正红、正黄、正蓝五色中选；正黄 `#FFAF00` 明显偏橙，正蓝 `#0096AD` 偏青。文字自动用黑／白高对比色。玩家可在这五个背景中修改，但不能在前文化阶段偷偷使用正式多色模板。

当国家第一次采用非空官方文化后，`phase` 从 PRE_CULTURAL 变为 CULTURAL，正式13模板与23色编辑器解锁，并生成第一面正式国旗；原始单色希腊字母旗保留在 FlagHistory 中。

## 3.11 性能规则

文化浓度不建立 Person×AllCultures 矩阵，人物通常只保存最强的数个 CultureAffinity。语言同样只保存实际掌握的少数 LanguageSkill。城市每个慢速周期先聚合 CulturalExposurePool 和 LanguageExposurePool，再让居民低频采样；禁止每对居民逐一碰撞计算。

文化生成场只对稀疏 GenesisNode 更新；语言分化只对真实活跃 speech community 更新。文化和语言虽然历史上丰富，但两套系统都不能成为三维城市、战争和经济之外的隐形 O(N²) 性能税。

# 04 · 公国、大公国、王国、帝国与法制

## 4.1 爵位、政体、隶属关系分离

`rank = DUCHY | GRAND_DUCHY | KINGDOM | EMPIRE`；`constitution` 描述治理；`dependencyTreaty` 描述与上级的关系。帝国不必中央集权，王国也不必独立。殖民地和附属国是法律关系，不是第五／第六种国号等级。

所有 State 创建时一定是公国，包括前文化国家。`phase=PRE_CULTURAL` 时允许 `officialCultures=[]`，国家完整显示名是稳定的5字希腊码，且只能使用单色字母旗；此时只有 Settlement，没有可计爵位的正式 City。国家第一次采用文化后进入 `CULTURAL`，必须在同一事务建立非空官方文化和至少一种实际行政语言。

拥有第二座**已完成正式归属的直属 City**后自动升为大公国；仅有 Settlement、军事占领、殖民地或附属国城市不计，防止刚占一个敌城就马上自动升格。一个前文化公国若已拥有多个聚落，文化化后只有完成正式 City 登记的城市参与升格判断。

称王是君主发起的政治行动，不需要上帝审批，但只对 `CULTURAL` 国家开放。程序由合法宪制决定：绝对君主可直接宣布，受约束君主要取得规定批准。首轮 AI 建议门槛是国家稳定、能承担加冕费用和拥有足够支持，降低反复改国号。称王可能降低邻国关系或激发内部异议，但不会凭空产生城市与军队。

失去城市不自动反复降爵位：大公国剩一城仍可保留历史称号，国家灭亡／另行解体才处理身份。王国和帝国的资格撤销按宪制和帝国授权规则，而非人口大小实时上下跳。

## 4.2 神授帝国

帝国永远必须处于 `CULTURAL`，具有非空官方文化、非空官方 Religion 引用和有效 `DivineGrant`。普通国家也可以有官方宗教；**官方宗教、国家神圣化、帝国身份是三个不同字段**。

申请对象 `EmpirePetition`：申请国家／申请联合体、官方宗教、根宗教创立记录、拟定帝国宪章、统治者／候选程序、成员同意证据、领土范围、稳定性和财政摘要、提交时间、重复申请冷却。玩家看到地图中拟定帝国范围及一张请求卡，选择批准、拒绝、暂缓；暂停中的请求不自动获批。

批准只在提交时再次验证：官方宗教仍存在、成员仍同意、领土／政体未被偷偷替换、没有父子从属环路。神授凭证绑定帝国实体、根宗教和宪章版本。帝国内部日常法令变化不必重新申请；更换根官方宗教、从一个成员集合强行创建另一个帝国，必须重新获得有效授权。

用户编辑器不能直接写 `rank=EMPIRE`。拥有有效帝国但准备废除官方宗教，必须在同事务退回王国／解散联合帝国，不能先进入“无宗教帝国”。更换同根教派可按帝国法办理；改信另一根宗教要先取得新授权。

默认神授授予国家与王冠，而不是单一君主寿命。正常继承／选举产生新皇帝不重复请求玩家；根本改变帝国成立条件才重新审查。这样保留君权神授而不制造每次换君主的弹窗。

## 4.3 帝国结构

提供四个预设，底层仍是一份宪制数据：中央统一帝国、选帝侯联合帝国、世袭复合帝国、议会约束帝国。它们不是四个独立系统。

联合帝国用实际 CrownElection，不造贵族层级树。选举团成员是符合宪章的既有成员国家统治者；席位、票权、候选资格、法定人数和同票规则写进宪章。皇帝负责宪章授予的外交、共同战争和税项；成员保留本国城市预算和 Army。帝国命令只能征用宪章承诺的军额／款项，不得直接花成员所有钱。

中央帝国的城市直接归中央行政体，但城市仍是经济与招募预算单位。复合帝国允许部分成员保留爵位与法律；中央和成员的税收按分成规则结算，不能同一税项无限层层叠加。

帝国内成员退出、继承争议和欠缴可以形成政治争端，走仲裁、谈判、有限强制或战争；不因为一次欠款立刻全国开战。上级关系图必须无环，一个国家在同一时刻最多有一个政治上级，经济集团和教会网络不受这棵政治树约束。

## 4.4 最小宪制轴

|轴|允许选项|实际作用|
|---|---|---|
|王冠产生|世袭／选举／限定候选选举|继承和稳定性|
|行政集中|中央／地方自治／成员联合|城市税权、征兵、建设权限|
|立法约束|君主法令／等级会议／宪章会议／议会批准|法律通过门槛和速度|
|财政权|地方优先／固定分成／中央预算|城市和国家可支配资金|
|宗教地位|无官方宗教／官方但容忍／国教约束／神圣王冠|教会任命、移民、合法性|
|产权|公共主导／混合／私人开放|谁能申请企业、持有资产|
|地方特许|一致法／有限自治／成员保留法|法律作用域和冲突处理|
|国民资格|居留／定居／臣籍的准入规则|工作、地产、服役和政治权利|

绝对君主制、君主立宪、选举君主制、等级议会制、中央官僚制、封建自治、联邦王冠等作为上述轴的合法组合。没有必要为每个组合再写一个 Government 子类，也不添加用户未要求的共和国国号。

## 4.5 法律不是装饰文本

每条 law 有 jurisdiction、subject、trigger、predicate、permission/prohibition、rate/limit、effectiveDate 和 legalPriority。前文化 State 只启用最小生存／土地／安全规则集；成熟法条需要文化、可用语言和相应行政能力。创建公司、借款、迁移、战争宣告、国有化、宗教征税都向同一个 `LegalPolicyService` 查询可操作权限。

冲突优先级：不可变世界约束→帝国／从属条约明确保留或授权的权限→当地有效宪法→正常立法→行政规则。不存在“帝国法律永远自动覆盖一切”的偷懒逻辑。教会章程能限制本教会，不能在未授权的地方自动禁止所有居民。

法定修改需要技术／行政能力解锁、机构批准、过渡期和冲突检查。初期只开放口粮分配、基本土地使用、服役义务、简单进贡；成熟后才开放公司法、合同法、税表、银行许可和跨境规则。

编辑预览必须列出受影响对象：多少企业失去资格、多少人受到限制、预算差额、是否违反条约。存量企业默认有过渡期和合法退出路径；禁止“改法瞬间把资产清空”。

# 05 · 城市、建筑、外观、道路与公共服务

## 5.1 城市是日常经济和军政的基本单位

前文化阶段只有 Settlement；完成文化化登记后才成为 City。每个正式 City 必须拥有且只能拥有一个 `CitySquare`。City 拥有土地、人口／住房记录、公共预算、公共服务部门、建设队列、维护计划、招募额度、**非空官方文化集合**、实际使用／行政语言统计和实际控制状态。国家提供法律、税收分成、外交与共同政策，不直接执行每一块农田生产。

State 在前文化阶段仍可为 Settlement 安排基础公共供给；文化化后的国家可拨款给 City 或签订合同，但不能隔空抽取各城市 `CitySquare.Storage` 中的货物。帝国战争产生需求后，应发出军额／采购／运输合同，由各城市真实筹集。

## 5.2 City Square：城市唯一核心

`CitySquare / 城市广场` 取代旧设计中的独立 City Warehouse、独立 City Hall 和任何拟议 Market 建筑。它不是一栋巨大仓库，而是一块可扩建的城市核心复合空间，由同一个逻辑实体管理：

- `CivicHall`：城市行政、公共记录、预算、征募、合同和城市级法律执行；
- `Storage`：城市唯一逻辑仓储账本、公共储备、产权分区和跨城物流交接；
- `LoadingApron`：装卸、运输公司交接、军需集结；
- `PublicSpace`：公告、庆典、政治／宗教公共活动和有限的人群集结；
- `FlagMast`：显示城市当前政治归属／占领状态对应的旗帜；
- `CityMarker`：远景城市名称、状态和地图选取锚点。

每座 City 永远只有一个 CitySquare。它可以扩建面积与容量，但不能复制第二个城市核心。推荐的首轮尺寸不是硬规则：小型约 8×8 格、中型约 12×12、大型约 16×16；扩建必须检查道路、现有建筑、LAND/WATER合法性和可达用地。广场是行政和物流中心，不强迫它永远位于城市几何中心；城市发展后人口重心可以偏离老广场。

**不存在 Market / 市场建筑。** 交易价格、需求撮合和零售结算是经济系统的逻辑过程，不要求居民在一栋“市场”里完成。日常小额消费使用批量结算与低频领取，避免成千上万人每天都为一份食物寻路到广场；大宗货物、军需和跨城运输仍真实经过 CitySquare.Storage 和 LoadingApron。

前文化 Settlement 有一个简化 `SettlementCore`：可储存基础粮食／木材并组织公共事务，但没有正式 CivicHall、正式旗制和完整城市行政。文化化并建立正式 City 时，SettlementCore 原地升级或迁址为 CitySquare，旧库存和产权原子迁移，不能复制物资。

## 5.3 建筑与经营主体必须拆开

`Building` 是物理空间；`Facility` 是在空间中进行的业务；`LegalEntity` 是所有者或经营者。一个银行破产不代表楼瞬间消失；一座混合办公楼可出租给物流办公室和投资公司；同一公司可经营多个城市的多种设施。

统一民用建筑外观池供物流公司、银行、建筑公司、消费品公司、总部、普通办公室和公寓使用。业务区别来自牌匾、小图标、入口和检查器，而不是每一业务单独制作整套楼。农田、港口、矿洞、林地、工厂、大学、CitySquare 和三种宗教建筑需要不同功能轮廓。

“学院／研究所”不是强制独立建筑类：ResearchFacility 可驻大学楼、通用民用楼或 CitySquare 的合法办公空间。University 是兼具教育席位和研究席位的专用建筑；Institute 只是研究功能及其人员／预算。如此满足两种业务而不重复研究引擎。

## 5.4 三时代是逐对象能力，不是全世界开关

时代标签：上古、中古、启蒙。某个城市拥有启蒙工厂，不会把邻国或本城所有住屋自动换装。建筑可升级取决于**当地可用知识、建造者技能、材料、资金、合法空间和维护能力**，不是所属国家的一枚时代布尔值。

普通建筑保存 `capacityTier`、`unlockedAppearanceIds`、`activeAppearanceId`、`condition`。性能升级支付成本并改变容量；外观选择只从已解锁集合中选，不改变性能。玩家可以把高容量公寓切换成已解锁的中古风格外观，但外观几何必须能够表达该容量，不允许把一百人逻辑塞进一间小屋。

CitySquare 同样把容量升级和外观选择分开：扩大仓储翼、装卸面或CivicHall能力需要实际工程；玩家在已经解锁、且几何兼容的历史风格之间切换只改变表现。宗教建筑例外：Chapel／Cathedral／Temple 是三个独立类型，不构成升级链。

## 5.5 正式物理建筑目录

Sonnheide 不为每一种公司业务创造一栋专属楼。当前核心物理建筑／空间家族保持在最小集合：

|建筑／空间|出现条件|时代形态|主要功能|
|---|---|---|---|
|基础住屋／公寓|基础住屋无需文化；公寓需城市成熟和结构技术|上古／中古／启蒙；大型公寓可只在后期出现|住房、家庭资产、私家交通入口|
|City Square / 城市广场|正式City必有；由SettlementCore升级或新建|三时代；面积和容量可扩建|CivicHall、唯一城市仓储、装卸、国旗、公共空间、城市地图锚点|
|公共工坊|基础公共工艺可用；成熟后可与企业并存|上古／中古／启蒙|基础制造、维修、公共施工支持|
|农田|无文化也能耕作|田块及时代工具／设施表现|粮食生产、劳力、工具使用|
|林业设施|基础公共伐木最早可用，经营设施后解锁|三时代|林地、植树、伐木、工具|
|矿洞|采掘技术、正产率、可达|入口形态三时代|矿工入口、可开采格覆盖|
|港口|造船和水运知识；必须先形成足够的RECLAIMED LAND港区，并有合法临水边|上古小港／中古港区／启蒙港区；始终正交|固定港口建筑、临水装卸面、泊位、船坞、海运|
|大学|文化、记述教育、稳定余粮、足够教师|早期学舍／中古／启蒙|学生、研究员、知识存档与研究|
|科技工厂|专用制造解锁|早期工坊式／中古／启蒙；复杂生产线后期才有|生产线、劳工、投入缓存|
|通用民用楼|相应结构知识|三时代|公寓、办公室、企业总部、银行、物流／建筑／消费品公司等租赁空间|
|Chapel|根宗教成立、合法土地、基本预算|同类型风格变体，不分等级|地方礼拜、传教、有限救济|
|Cathedral|教会组织成熟、结构与财政能力|同类型风格变体，不分等级|地区行政、教育、大型集会、救济协调|
|Temple|极苛刻的长期条件，见宗教章|同类型风格变体，不分等级|跨城朝圣、大会和共同体象征|

`Research Institute` 是 Facility，不是独立建筑家族。银行、投资公司、物流公司、建筑公司、消费品公司、集团总部也不是独立建筑家族；它们优先租用或拥有通用民用楼。Garage／Stable 是入口组件；Road 是基础设施；港口堆场是港口与 CitySquare.Storage 的有界转运区。

**永久城防设施彻底删除。** 不存在城墙、城门、防御塔、堡垒、要塞圈或城防建筑升级链。城市边界是动态行政／实际控制边界，不围绕永久防御建筑生长。战争防御来自 Army、道路与桥梁瓶颈、岸线和水陆阻隔、建筑密度、港口、CitySquare、补给、士气与实际占领控制。

## 5.6 建造、维护、闲置

建造路径：地图预览→合法性与路网检查→筹资→材料在 `CitySquare.Storage` 预约→城市公共施工或建筑公司接受合同→现场投入劳动→验收→转为使用状态。建筑公司既能新建，也能维护和拆除。

只有高级建筑收取低额定期维护费用，初始建议每游戏年为重建成本的 0.5%～1.5%，分月发生；价格会受实际材料和工资变化。没有维护时先出现延期标记，然后容量／效率缓慢下降，最后关闭危险部分；不几天就坍塌。基础住屋、SettlementCore 和早期公共设施不被这一费用锁死。

经营停止后分离三个问题：公司是否还存在、设施是否继续运作、建筑如何处置。空楼先保留／转租，再拍卖、改作公用、依法收购或拆除；存在的租户和私人住所不能被公司的经营破产自动抹除。

## 5.7 道路和入口

道路按合法格网铺设，显示为连续写实路面。基本土路、中古整修路、启蒙铺装路改变速度、运输容量和维护成本。陆路只允许在 `effectiveSurface=LAND` 上铺设，因此天然陆地和已完成的人工陆地都可承载道路；跨越WATER时必须使用合法BridgeSegment，桥是Road网络的一种基础设施段，不改变天然水陆或人工造陆层。

车辆必须有合法路线和目的地停车位；家庭车库／马库是楼上的入口组件，不是房间模拟。入口动画后车辆从世界可见列表移入 `InteriorContainer`；Person、Vehicle、Cargo ID 和行程状态仍在模拟中。矿工入矿和人员进建筑采用同一机制。

CitySquare 的 LoadingApron 需要直接连接车辆可达道路；港口陆侧入口与广场之间必须有可达运输路径。道路可以穿过或绕开城市行政边界，边界变化不强制重铺道路。

文化影响屋顶、立面、窗格、庭院／入口配置的默认组合；不用为每个混合文化制作一整套素材。建筑竣工时记录风格来源；后来移民改变文化结构，不会让整座城市的建筑瞬间换样式。

## 5.8 港口：只能建设在人工陆地临水边缘

Port 不再尝试适配天然曲折海岸。**建港的第一步永远是先造陆，第二步才是放Port。** 港口核心建筑及其陆上装卸区必须完整落在 `landOrigin=RECLAIMED` 的已完工格上；天然LAND即使就在海边，也不能直接承载Port核心。

首版Port由一个固定、矩形、轴对齐的 `PortCore` 和水侧 `BerthWaterZone` 组成，不再拥有会悬在水上的 `QuayPlatform` 建筑层。人工陆地本身就是码头平台和港区地基，水侧只保留泊位／船坞所需的真实WATER空间。这样同一块空间不会既被称为“水上平台”又被称为“人工陆地”。

港口只允许 `rotation ∈ {0°, 90°, 180°, 270°}`。模板声明一条唯一或可选的 `seaFacingEdge`；旋转后整栋PortCore仍严格贴格。合法放置必须同时满足：

1. PortCore footprint **每一个格都是已完成的RECLAIMED LAND**；天然LAND、未完工造陆、WATER都不合法；
2. 指定 `seaFacingEdge` 外侧紧邻的一整排格必须仍为 `effectiveSurface=WATER`，形成完整直线临水面；
3. 从该海侧边向外存在当前模板要求宽度和深度的连续 `BerthWaterZone`，其中没有建筑占用、人工造陆或其它阻塞；
4. BerthWaterZone通过当前 `WaterNavigationRegion` 连到可用航道；远洋港要求连到世界边界／海洋主水域；
5. 陆侧入口可以接道路，产权、城市法域和建设许可有效；
6. 任何后续造陆如果侵入现有港口的强制BerthWaterZone必须被拒绝，除非先依法停用／改建该Port。

港口升级只能扩大在**人工陆地上的**陆侧设施、增加平行泊位能力或使用更高效装卸技术。若升级需要更宽PortCore，玩家必须先继续逐格造陆；系统不会自动替玩家填海。Port可以沿人工直岸形成非常规整的港区，但不能斜放、弯折或跨到天然岸坡上。

建港UI只显示四件事：人工陆地footprint、海侧边、BerthWaterZone和陆侧道路入口。预览失败时只给首要原因，例如“港口只能建在人工陆地上”“海侧边必须整排临水”“泊位区被造陆阻断”“水路不连通”“只能旋转90°”。玩家无需理解天然海岸多边形覆盖细节。

Port拆除只删除Port建筑与设施，不删除已完成的人工陆地；港区仍是普通RECLAIMED LAND，可改作道路、通用建筑或未来另一座港口。首版完成的人工造陆本身不可拆回海水，因此建造前必须有清楚预览和确认。

# 06 · 经济核心：公共起步、产权、账本、生产与需求

## 6.1 三个制度阶段，不是一个“市场经济已开启”开关

**共同供给期**：原始聚落／初期城市直接组织耕种、林木、住房和搬运。按需要和公共任务分配物资，没有工商注册、股票和银行。公共工艺升级可以发生，不要求先有私人资本。

**公营专业化期**：城市开始按业务记录成本、劳动和产出，出现人工造陆公共工程、市营港口、大学／研究所、矿洞、工坊和承包作业。记账、定价、标准货币、契约和所有权逐步解锁；不因有了价格就立刻开放有限责任公司。

**混合企业期**：社会同时拥有稳定剩余、成熟记录、合同执行、储蓄和持续订单之后，法律才可能允许私人公司、合资和集团。国家可继续经营所有基础业务；私营不是必定更优，也不是必定取代公营。

解锁只意味着“允许申请”，不自动创建企业。企业成立还要通过项目可行性、劳工、路网、资本、市场容量和法定许可检查。高级金融和文化消费公司另有更高门槛。

## 6.2 账本比GDP数字重要

所有经济主体使用统一 `EconomicActor`：Household、CityTreasury、StateTreasury、LegalEntity、ChurchTreasury。资产所有者和使用者可以不同；租金、工资、股息、采购款都必须有对手账户。

资源账本记录 kind、quantity、legalOwner、custodian、location、reservationId、quality/version 和状态。货物进入城市广场仓储区时属于 `WAREHOUSED`，运走后变为 `IN_TRANSIT`；不能同时在源 CitySquare.Storage 和目的 CitySquare.Storage 中计入可用库存。银行余额不是食物，采购订单不是已经生产的物资。

货币账本使用整数最小单位，不用浮点金额。每笔交易借贷相等，并可追溯到合同、工资周期、税单或股息决议。货币和物品是两套有关联的账本：付款不等于货已到，货已到也不一定价款全部结清。

货币尚未解锁时，用实物配给和劳动记录，不用虚假零元公司支撑早期经济。首次货币化是显式的 MonetaryInitialization 事件：按受控总额向公共储备、居民既有权益建立账户，之后不因重载存档或升时代重复发钱。首版只用一种记账单位，不做外汇或央行政策小游戏。

## 6.3 有限商品目录与丰富显示品类

基础商品目录保留：食物、木材、石料、铁矿、铜矿、煤、盐、硅砂、黏土、金矿、铁材、铜材、砖、织物、通用工具、机械组件、武器、军需弹药、包装材料，以及少量高级消费类别。金矿不是凭空铸币按钮；所有转换必须通过已定义配方和授权。

机器、私家车、船舶和军用装备可以拥有独立 AssetId，因为它们会被订购、使用、维修或转移。机器内部的螺丝、齿轮、轴承等大多是**技术槽位和配置参数**，不用每颗都发运。普通消费品按批次／品类存在；乐器、镜片和衣物无需世界中逐件显示。纺织／衣物经济可以保留为抽象消费类别，但人物可见服饰严格服从第20章的最小闭环，不随商品目录膨胀。

一条实际生产配方最多消耗少数材料类别，科技细节改变配方成本系数、产率、寿命、精度、载量或功能许可。显示的数百种发明不能把库存目录同步膨胀到数百种互不替代的小物件。

## 6.4 生产只取最短板

每日有效生产量：

`Q = nominalCapacity × min(laborRatio, inputRatio, installedCapabilityRatio, dispatchCapacityRatio) × condition × adoptedEfficiency`

其中产量不得超过土地／矿物再生和储位上限。缺少运走能力的工厂只能使用有限本地投入／产出暂存区，不能无限生产；矿洞不能提取格子中不存在的储量。

科技提高农业效率后，可表现为同样土地和劳动产出更多粮食，或满足同样产量所需劳动更少。两者只按同一效率因子结算一次，不能同时给予全额产量和全额节劳双重加成。

基础需求采用实际人口和家庭预算，公共需求来自住房缺口、维修、教育和军队合同。消费品需求仅在基础需求长时间满足且家庭拥有可支配收入之后生成，且有预算上限。虚构“潜在需求”不能当成厂商已经收到的订单。

## 6.5 城市价格清算与需求撮合（无 Market 建筑）

不存在独立 Market／市场建筑，也不做逐秒交易所。经济系统从 `CitySquare.Storage`、合同和居民／机构需求汇总每类商品的可售库存、实名需求和近几个月成交，按日清算合格订单。底层由卖方最低价、买方最高价、真实数量、交货能力和法律限制匹配。

建议价格调整采用平滑受限的供需比：每日变化封顶、需求用移动平均、极小样本保持参考价。买不到粮食时优先产生供给任务和公共保障，而不是只把价格推到无限大。所有兜底补助由预算或受控透支规则支付，不能自动制造收入。

用于企业可行性判断的是长期**未满足的可支付需求**，扣除现有企业、在建项目和已预订产能。不能让十个 AI 同时看到一份订单，各自建立一座满负荷工厂。立项时就锁定项目配额，到期未融资释放。

## 6.6 工人、工资与早期公共劳动

劳动者只在实际工作日贡献产出。通勤、缺粮、服役、受伤和迁移会占用时间；同一人不能同时在矿洞、工厂和军队领取全时产能。早期公共劳动获得口粮／住房权益；货币化后可转为工资。

不需要让玩家手工分配每个工人。城市按照粮食→应急物流→必要维修→住房→正常生产→科研／非必要项目的自动优先级安排公共任务；企业按合法工资与偏好招聘。玩家只改优先级、预算和设施位置。

## 6.7 最低生存保护不等于所有企业不破产

粮食、住屋、CitySquare最低仓储／配给、基本施工和短途搬运有低效率公共后备服务。它保护居民和游戏继续运行，不保护所有股东。商店可能停业，厂房可能出售，投资者可以亏损；基本城镇不因一次资本链断裂永久失去造房能力。

对于被封锁／贫困城市，系统先降非必要消费、冻结低优先级投资、释放闲置库存、尝试进口、调配公共劳动，再出现人口迁移和政治后果。绝不靠每年随机赠送无来源粮食掩盖设计死锁。

# 07 · 企业、工厂、集团与退出机制

## 7.1 法人不等于业务，不等于一幢楼

`LegalEntity` 有总部法域、所有权份额、治理规则、账户和章程；`BusinessUnit` 是农林、港口、制造、运输、建设、研究或金融业务；`Facility` 是一项业务所在的具体场所。集团用控股关系连接法人，禁止持股环和超过 100% 的表决权。

初期城市业务由公共部门直接执行。成熟后可把部门转成国有法人，或者城市与居民／教会共同投资。私有、国有、教会所有和合资不是四套算法，都是同一所有权表和法域规则。教会的不可变章程可以禁止它持股某类业务。

每个法人必须有总部，但总部可以租用现存办公楼中的一个合法办公单元；不得要求所有小公司先建一栋高楼。总部迁移需要新的注册地址、旧法域结清／保留义务和生效日期，不改掉历史税务记录。

## 7.2 成立门槛和迟滞

首轮建议：私营准入所在城市至少 600 人、记述和合同执行已稳定、过去 3 年基础食物满足率≥95%、住房满足率≥90%、可支配剩余稳定、公司法和产权登记均已生效。不能仅通过人口达标解锁。

具体项目还需：过去 24 个月存在持续有效需求；扣除现有和已批项目后可支持目标产能至少 60%；资本覆盖建设／生产线与 12 个月固定费用；已确认投入来源、至少 70% 的起始劳工、可达 CitySquare.LoadingApron 及基本订单。数字都是首轮测试参数。

成立检查在项目批准时锁定市场容量，开业时重新核验。轻微衰退不立即关门；退出使用更低的持续阈值与更长时窗形成迟滞。例如持续缺乏业务 6 个月进入整顿，12 个月仍无可行计划再清算。短期亏损但现金充足的企业可以存续。

银行、投资集团和高级消费品公司要求更晚的制度节点和更长观测期。首版建议银行需成熟公共清算、可靠债权登记、足额实收资本和 5 年稳定存款／贷款需求；不存在“识字刚出现就自动开十家银行”。

## 7.3 业务目录

|业务|核心服务|成本／容量|跨系统作用|
|---|---|---|---|
|农田|粮食生产|土地、农工、工具|CitySquare供粮、军粮、人口生存|
|林业|砍伐、补种、小型自有林地|工人、树龄、木储量|建筑、船、包装与制造|
|矿厂|在许可格集合开采|工人、设备、实际矿物储量|加工和结构材料|
|港口|造船、货运、客运、军运|泊位、船坞、装卸工、归属船队|殖民、移民、军队远征|
|大学／研究所|教育、保存和研发|学者、学生、预算、知识|科技、语言、教会传播|
|科技工厂|按配置制造资产或商品|已建生产线、劳工、材料|工具、车、武器和民用品|
|运输公司|城市间配送及合同组织|车辆／资产槽、装卸与组织劳力|所有合法供给|
|建筑公司|施工、修缮、拆除|工人、工具、项目并发|住房、宗教建筑、工厂与公共设施|

|银行|保管、转账、期限融资|资本、结算储备、法定许可|现金管理和受控信用|
|消费品公司|乐器、光学、织物等批量消费|相应工艺与成熟收入需求|晚期快乐和文化活动|

高级业务出现不增加新办公楼美术类别。每项业务都能由允许的公营／私营／教会／合资主体承担，但不得绕过行业出现条件。

## 7.4 科技工厂与生产线

生产线状态：`PLANNED → FUNDED → TOOLING → READY → PRODUCING ↔ IDLE → RETIRING → REMOVED`。失败和取消必须释放预约和结算已经消耗的部分，不把完整成本都退回。

首次生产某种**产品家族**要建线：在常规产品投入之外，一次性支付显著工装材料和组装劳动。默认示例：工装材料相当于约 8 批标准产品的材料投入，外加专用机械组件；具体由配方配置。只在 `READY` 前支付一次，不每轮重复扣料。

同一机器家族的小版本／零件改良可以花较少停机和调校费换配置；农具线改造为汽车线属于新家族，必须完整建线。以 familyId 和 compatibilityGroup 判定，而不是根据用户改过的产品名字。

工厂性能等级的线槽建议 1／2／4；每线有产能和人手要求，不能认为四线就能在同一批工人下四倍生产。拆线须先停止接新单、处理在制品、释放订单、等待资产和工人腾退；回收比例小于全部投入，禁止建拆刷材料。

生产出的机器独立记录所使用的技术配置。新知识不会自动改写所有已售机器；用户／企业可以预约升级维修或采购替换。研究所只产知识，不自动产出免费新汽车。

## 7.5 森林与矿洞的显示简化

一棵成熟经济树代表可观的木材资源包，因此小片经营林地即可支持业务。连续砍伐会降低成熟木储量，补种经过延迟才恢复。不能同一棵树无成本无限反复提供原木。

矿工进入矿洞后隐藏渲染，只在工作容器中推进产能。矿洞 footprint 决定可许可的周围矿格，开采量对各格实际储量逐一扣减。矿物出现在哪里由可编辑速率场决定，而不是凭矿洞等级制造矿物。

## 7.6 运输资产、私家交通与港口船舶

运输公司的楼提供车位／资产管理槽；新增车辆需要合法车位，车多于业务时产生持有和维护成本。自动车辆没有司机工资，但购置、装卸、道路拥堵、维修和总部容量仍是真成本。

家庭可以购买私家马、马车和晚期太阳能自动车。必须先有居所交通槽或合法共享停车契约；车辆无处存放时不得自动无限堆积。私家交通不自动成为公共物流车，需自愿出租／征用合同。

船的直接归属对象一律是 Port。港口可以属于公司、城市或教会，因此实际收益最终归港口所有者。政府付费包船送 Army，只获得约定航程的使用权，不因此改变船籍。港口建筑被摧毁时，Port 登记暂为无设施状态，船仍归该登记，直到合法转移／重建，不生成无主永久船。

## 7.7 破产、转营与国有化

企业状态：正常→观察→整顿→重组／清算。项目失败不是建筑失败；财政主体、业务设施和物理楼分别处理。

清算顺序按法律配置，但必须明确已代管他人的财产不属破产财产，城市广场代管货不能被公司债权人随便拿走。工资、担保债权、税款、普通债权和股权按明确次序结算；不足部分确认损失，不让负债永远挂在已删除公司上。

闲置设施可以挂牌转让、拍卖、合并、改用途或拆除。政府可按法律购买、临时接管基本服务或征收；购买要花钱，征收形成可记录的补偿债务或违约后果，不是免费的万能按钮。建筑存量回收优先于新建，避免城市很快满是废楼。

若不可缺少业务退出，城市启动最低公共托管服务。它不自动继承全部高档金融业务，只维持粮食、CitySquare最低仓储／配给、基础交通和必要建造。公共托管也有预算、工人和材料限制。

# 08 · 物流、灵活合同、税收和资本

## 8.1 一个 City Square，一套城市仓储账本，不是一份混同财产

每个正式城市只有一个 `CitySquare`，其 `Storage` 是城市唯一逻辑仓储账本。Storage按产权、用途、质量／版本、预约和在途状态分区记账；广场可以扩容，但不会生成第二个城市核心。港口堆场是与 CitySquare.Storage 对账的有界转运区，不是另一个可重复计算的库存。

生产设施把完成的批次送到本城 `CitySquare.Storage`；居民、企业、公共工程和军队从该账本提取已付款／获配／受委托的批次。跨城运输只做 `OriginCitySquare.Storage → DestinationCitySquare.Storage`。当事人在本城最后一段自行提货或委托工作人员，避免每家小店都成为复杂国际路径节点。

设施可以有有限在制品和投入缓存，但它们计入同一所有者的实物账；不得借“缓存”绕开 CitySquare 交易、所有权和运输要求。货物从采掘／生产现场到 CitySquare.LoadingApron 也要花搬运时间。

## 8.2 预约和承诺可追踪

配送流程：需求发布→找到真实供给→预约源 CitySquare.Storage 库存与买方资金→选承运者和路线→源 CitySquare.LoadingApron 验货装载→转为在途→目的 CitySquare 验收→入其 Storage→释放付款与通知提取。

`Shipment` 保存货权、保管责任、路线、承运合同、当前位置、数量、预计到达、损失与索赔。若被封锁，重算路线并通知双方；若损失，记录损失账户；若目的 CitySquare.Storage 已满，等待／转运／依法退回，不瞬移也不吞货。

同一 Reservation 只能消费一次。货款托管、税费托管、运输费与货值分别列明。订单取消只释放未发生部分；已在途不能像撤销笔刷一样恢复到源 CitySquare.Storage。

## 8.3 一套合同组合所有业务

只需要六种核心合同动作：提供货物、搬运货物、运送人员、施工／维护、研究／授权、出资／偿付。复合合同用有向无环任务图连接它们，不编写“宗教远征专用全新系统”。

例：政府派兵远征。城市征募并发军粮采购→工厂交付武器到本城 CitySquare.Storage→物流送军需到港口城市的 CitySquare.LoadingApron→港口接受军人和物资航次→目的地 CitySquare.Storage 或合法临时登陆补给容器接管→军队从补给点领取。无城市的登陆滩头只能有有限 ArmySupply 容器，不能当成新城市广场仓储区无限贸易；建立正式城市时再接入标准网络。

例：教会办学。教会出资→研究所接受教育／抄写合同→建筑公司扩建获许可的校舍→物流送教材材料→得到真实完成的教学与知识传播。教义决定谁可接受和是否开放成果，而不是直接给全体人增加科研分数。

例：跨国集团建厂。母公司注资到有当地许可的项目法人→当地注册税务→租楼／购地→建线→本地雇佣→跨境采购→利润按当地生产活动结算→在合法时分红回总部。

## 8.4 税收只对已经定义的税基征收

|税种|最早解锁|税基与归属|防重复规则|
|---|---|---|---|
|实物贡赋|早期正式国家|公开配给后剩余粮／木，按城市记录|不能扣最低生存保留量|
|土地／物业税|产权登记|所在地土地或建筑评估值|国家／城市分成同一税单|
|工资／个人所得税|货币和工资记录|个人实际已赚收入，允许分档|同一收入事件只计一次|
|营业销售税|稳定市场|最终销售价|首版选择单阶段销售税，不同时再造完整VAT链|
|企业利润税|公司法和会计|收入－允许成本－折旧－可用亏损|税率作用于正税基；无利润不伪造利润税|
|关税|边境与海关|真实跨境货物合同价值|记录已清关边界，重复过同一站不重复征|
|股息预扣|跨境股权|分红支付额|总部居民税额允许依法抵扣|
|遗产税|成熟登记|死亡继承的法定财产|先剔除他人物品／代管款|
|资源特许费|矿权登记|实际采出数量或销售价值|区分税款、地主租金和矿权费用|
|教会什一奉献|宗教章程允许|信众合格收入及免征底额|与国家税分开，是否代征必须有授权|

基础税率、免税额、分档和豁免均为数据。国家获得官方宗教不会自动让教会拥有国家全部税收；是否免税、享受拨款或获代征权由法律明确决定。

企业按设施所在法域核算利润和工资税，总部只处理本部活动、集团分红和法人义务。首版允许选择“境外已纳税抵扣”规则：应补居民税 = max(0, 居民应纳额－允许抵扣的来源地税)，避免同一利润无界叠税。没有跨境税收协定时允许较高负担，但要在合同预览里说明。

关联交易使用可解释的参考市场价格区间限制内部作价；不制作避税策略小游戏。城市财力不足要削减支出／融资／上调合法税项，不能静默从所有企业账户直接扣钱。

## 8.5 公共预算与财政反馈

CityTreasury 的收支分为最低公共服务、经常支出和项目投资。先保CitySquare最低仓储与配给／粮食／必要维护，再拨科技、豪华项目和战争。国家可要求贡献，但贡献上限由宪制和保留权约束。

税率越高并不等于无限收入：会减少可支配收入、投资可行性和迁入吸引力；这些是现金流变化产生的结果，另加的合法性影响必须有上限，避免同一税负被四重处罚。

## 8.6 银行不引入无限金融复杂度

首版采用透明的保守金融模型：活期托管款百分之百保持结算储备；贷款资金来自银行自有资本与**明确锁定期限的投资存款**。不做无约束信用创造、货币政策和中央银行。这不妨碍存款、项目贷款、违约、利息、抵押、资本损失和挤兑压力的可理解模拟。

期限存款不能被承诺随时无损提取，界面展示锁定期限和提前退出损失。银行不能贷出寄存的客户货物、托管税款或已经预约的工资。每笔贷款有真实转账、借款人、利率／费用、期限、抵押和违约处理；利息来自借款者支付，不是银行定时生成现金。

投资公司用真实股权和项目份额投资。估值来自现金流／资产与有限风险折扣，不是玩家需操控的实时股票价格。集团股息只能来自可分配现金与法定利润；同一笔内部转账不能同时算两个独立利润。

## 8.7 防卡死与反套利

同时检测库存为负、重复付款、循环股权、无主城市广场仓储账本、行业垄断供应断裂、税收总扣款超过合法税基、工厂拆线全额退款、总部迁址重复免税、同一人口反复领移民奖励等情况。

自动化并不保证人人富裕，而是保证失败可解释且有恢复路径。项目因资本不足停工，应清楚显示“缺资金”，不要静默停止几十年；企业申请因需求不足被拒，允许租用旧楼或接小合同，而不是只有新建大楼一个按钮。

# 09 · 矿物再生曲面：真正可交互的三维资源编辑

## 9.1 速率即一日容量

每种矿物有非负速率场 `r_m(x,z)`，单位“资源单位／游戏日”。每个格子 i 的权威数值取格心：`rate[i,m] = r_m(centerX, centerZ)`。

最大原位储量 `capacity[i,m] = rate[i,m] × 1 day`。例如 5 单位／日的格子最多积存 5 单位；不是经过 100 日变成 500。用显式的 1 day 保持量纲正确。

每次推进 `Δd` 日，按当时速率积分：`stock = min(capacity, stock + rate×Δd)`。开采 `min(requested,stock)` 并扣减。开采和再生必须分时／限流，使一天中的总产出不超过当日再生量加开始库存；不能通过暂停／恢复反复获得一日储量。

提高速率只提高未来再生和容量，不立即赠送库存。降低速率使库存超过新上限时，超额作为“编辑移除”记录，不能变成城市广场仓储中的矿石。归零会把该格剩余原位储量归零；这是明确世界编辑，不属于开采收益。保存、载入和离线恢复采用游戏模拟经过的时间，不用玩家电脑真实时钟偷偷补矿。

## 9.2 可视化与交互分离

选矿物后，用半透明三维表面覆盖平坦的LAND/WATER地图：水平坐标对应地图，高度 `surfaceBaseY + baseOffset + visualScale×rate`。该曲面只是资源可视化，不改变水陆掩码、建筑地基或道路。可以开等值线，数值 tooltip 永远显示真实 rate 而不是屏幕高度。

原始逻辑值保存在格心网格；显示网格在格心之间做非负插值，峰值范围不因平滑产生负数。地图边缘明确延展规则。插值只为显示，实际矿洞始终取格心数值，不对视觉网格做另一轮积分。

## 9.3 四个画笔

曲面抬高（提高矿物刷新速率）：在笔刷覆盖内按时间与衰减函数增加速率。曲面压低（降低刷新速率）：同样减少且不低于零。归零：覆盖的格心直接置零。夷平：在 `pointerDown` 时锁定第一次接触点的原始场高度 `anchorRate`，整个 stroke 扫过的格心全部设为该值，不能每帧重采样锚点。

夷平的边缘不作隐蔽混合，否则违背“所有扫过的地方都一样高”。抬高／压低可选择软硬边；只修改笔刷真正覆盖的格心。按住拖动不会受鼠标采样频率影响，路径段要补采样，避免快速滑动留下间断。

一个 stroke 对应一次可撤销命令，保存变更前后稀疏格值。编辑时默认暂停与矿业结算，防止撤销速率却不撤销期间开采造成复制。恢复模拟后不允许把已经发生的经济后果当作简单笔刷撤销；用户可以作反向新编辑，历史保留。

## 9.4 360°相机下如何避免画错地方

资源编辑模式使用独立的不可编辑世界平面raycast，矿物可视曲面不拦截后续位置计算；否则抬高高峰后画笔会落在前方曲面而不是期望的地图位置。屏幕同时画出地面圆环、曲面光标、当前格数值和预览上限。

滚轮默认调整笔刷半径；相机缩放改为显式修饰键／相机模式。空格临时切换平移，中键拖动旋转，松开回到原工具；顶部持续显示“正在编辑铁矿速率”。Esc 取消尚未提交的 stroke。

用户不会看到采矿井下动画，但在矿洞检查器能看到覆盖格、总再生能力、当前储量、人员能力和实际出矿三个不同数字。CitySquare.Storage容量不足、矿工不足和矿脉不足应给出不同原因。

# 10 · 科技、零件、大学与知识传播

## 10.1 丰富的名字，有限的有效机制

科技分成三层：少量**能力突破**解锁行为和建筑；中等数量的**产品／工艺谱系**决定有什么东西可造；大量**槽位改良**提供发明者姓名、零件故事和渐进效率。目录见 `data/technology_catalog.json` 与科技附录。

本版目录固定为 16 个研究方向、每方向 6 个谱系，共 96 个谱系；每谱系 3 个改良槽，共 288 个改良模板；另有 40 个能力突破。总计 424 个定义项，不等于 424 个独立模拟系统。每个模板允许产生不同发明者的版本，但同一实际用途只采用当前安装／掌握的有效版本。

例如农业谱系包括犁、播种器、收割器、灌溉器、脱粒器、育苗工艺。犁的连接件、刃具和受力结构都能出现发明，最终通过农业效率、劳动利用或工具寿命等有限通道起作用。螺丝不必成为一条单独的跨国货运链。

## 10.2 一个发明的完整生命周期

研究项目取得题目→验证前置知识和研究条件→实际研究员投入时间→消耗研究预算与材料→形成原型／论证→验证→登记作者与名称→保存知识载体→授权或公开→有人学习→工厂建线或改装→生产设备→被农田／居民／军队实际采用。

发现技术不是把全世界的一个百分比立即加上去。大学发明 `Friedrich农具II` 后，只有使用已生产并装备的对应工具的人／设施才获得提高。研究人员去世不会抹掉已经保存的文献；技术未保存且唯一熟练者死亡时，重建能力可能消失。

基础技术必须能在公共工坊、家庭师徒和无专用大学的学者群体中产生，否则会发生“研究大学需要大学”的循环。University 提供更高研究容量、正式教学和档案，不垄断所有发现。

## 10.3 技术版本和效果计算

每项创新记录 id、familyId、slotId、inventorPersonId、givenNameAtDiscovery、nameOrdinal、parentInnovationIds、discoverySite、discoveryDate、quality、effect、knowledgeOwner、publicationPolicy 和 archiveCopies。

同一槽只能装一种方案，旧版和新版不相加。不同槽的加成按有上限的聚合函数处理；已经衰退／损坏的工具按使用率折减。建议同类设备一个时代内总效率改善封顶，再通过真正的时代突破解锁更高基线，防止一千种螺丝无限乘出天文粮食。

`effectiveBonus = min(branchCap, Σ selectedSlotBonus × adoptionShare × condition)`。

一项明确写着“食物产量提高2%”的农具，在其他条件不变且完全采用时令100单位基线成为102单位；不是2个百分点再乘一次作物增益。未采用时为100。同样名为II的发明不一定比另一人的I更好；名字序号解决撞名，不是质量。

## 10.4 五种知识状态

|状态|实际含义|是否能立即生产|
|---|---|---|
|知晓 Awareness|听说某技术存在|不能|
|可访问 Access|能接触文献／老师／原型|不能保证|
|熟练 Competence|人或团队能按工艺执行|仍需物资和设备|
|合法授权 License|在该法域／合同中允许使用|不能代替熟练|
|实际采用 Adoption|设备／建筑／岗位已装用该方案|此时才产生对应效果|

文化不拥有全部科研成果。国家也不天然知道境内所有私人实验室的秘密。法律上的知识所有者、实际掌握者、档案保管者和研究资助者分别记录。

## 10.5 传播渠道

师徒教学：老师有熟练度、学生可理解语言、实际教学时间；消耗双方劳动时间。

大学与研究所：可以批量教学和保存副本，但受席位、教师、经费与语言限制。人口不必逐条储存全世界科技，普通职业技能按技能包记录，核心学者持有具体创新引用。

公开文献：作者／所有者决定公开，经过抄写／印刷和运输进入档案；有副本不等于已经读懂。

教会网络：依据知识教义安排抄写、讲授、奖学金和传教附带教材；会花钱和时间，向目标教会或大学传递副本，而不是远程直接改变技术标记。

贸易与许可：购买专利式使用权／生产方案；进口成品可使用，但不自动获得制造能力。研究进口成品可成为学习任务，不自动瞬间复制。

人才迁移：个人携带自身记忆与合法携带的文献。迁移不抹除旧雇主档案，也不把整家公司一键复制到目的地；保密与竞业规则影响是否合法使用，而不让人神奇失忆。

征服：获得可接管的档案和设备，只代表接触能力；需语言、人员合作和实际培训。焚毁或弃置档案会损失副本，不删除别处已有知识。

## 10.6 保密、翻译、流失与再发现

公开、机构内部、成员限定、商业许可、严格保密五档足够。许可范围可以绑定法人／城市／期限，严格保密必须支付组织与档案成本，也减少外部改良和传播带来的收益。

跨语言传播由 bilingualCompetence、translationProject 和词汇对应支持。Culture 不拥有科技，Language 也不属于某个 Culture；共享文化不保证同语，共享语言也不保证共享文化。翻译是有成本、有持续时间的知识任务，不再开一套出版企业链。相近派生语言有较高理解度，但不自动完全相通。

技术知识可以稀缺、局部流失、被独立再发现。再发现使用同一 familyId，产生新的作者和创新记录，不创建第二套不可比较的“同样技术”。已经装用的机器继续工作到需要熟练维修时，不能因一位科学家死亡就全部停机。

## 10.7 时代和军備上限

上古／中古／启蒙由本地可执行的突破集合计算，是一种摘要标签；条件锁定在具体能力，不用时代标签代替能力检查。最先进文化不自动使所有无文化人得到正规技术。

武器链结束于燧发枪和同档黑火药火炮。不得生成后装枪、金属定装弹、机关枪、现代炸药武器、坦克、飞机、导弹或激光。晚期太阳能自动车仅属于民用交通能力，可以运货、接驳人员，不能通过模组槽变为现代武器。

# 11 · 宗教根、教义与不可变章程

## 11.1 所有根宗教由玩家创立

Religion 的创立事件必须由 `PlayerCreateReligion` 发出。AI 无权调用这一接口。每个根宗教都解释同一个玩家神权，不额外生成神灵单位或可战斗超自然实体。

创建时玩家指定名称／自动以首位先知命名、首批先知、根教义、可接受教派差异范围及首个教会组织。先知选择人数无硬上限，但无文化者不可选；选择页会预览不符合资格的人和原因。

先知永久忠于其 Religion 根，不会被普通传教、贿赂、迁移或国家改教转换到另一根。先知仍会衰老、受伤、饥饿、被拘禁和死亡，不是无敌单位；其日常职责始终优先服务传教，必要休息／躲避危险是保持任务持续的条件。新增先知同样只能来自玩家指认。

## 11.2 根宗教、教派、教会不是同一个对象

Religion 保存玩家创立事实、根身份、根教义边界和全部教派。Denomination 保存具体解释、成员归属、可修改教令和与母派的关系。ChurchInstitution 是实际管理人财物的组织，其 Charter、分支机构、资产、人员和财政网络负责执行。

个人最多有一个正式教派归属，同时保存对其他信仰的接触／理解和转信进度。复合文化不意味着复合国籍、无限同时信奉所有宗教或重复领所有教会福利。独立的信仰指标允许“很虔诚但不信任教会领导”。

## 11.3 不作无效加成的教义

下表每条都会改变行为、预算、权限或政治约束，而不是单纯的图标和百分比。具体取值目录在 `data/doctrines.json`。

|教义轴|可选方向|真正影响|代价／冲突|
|---|---|---|---|
|关怀范围|本派优先／全宗教／博爱全人类|救济、奖学金、难民与战俘援助资格|博爱覆盖更广，财政摊薄且可能与排外法律冲突|

不得把教义编码成“善教／恶教”数值。教义效果来自具体组织与资源约束，且可在不同社会产生不同后果。所有教义都是虚构游戏参数，不是对现实宗教的评价。

## 11.4 永久锁定的是组织性质

教会诞生时冻结：行政结构、最高权威产生方式、财产归属机制、是否允许商业持股、可从事金融范围、债务权限、收入方式边界、地方保留权、解散资产规则。`charterHash` 写入历史；任何变更命令必须检验这些字段完全一致。

可调整：年度预算、具体项目、在已允许范围内的奉献比例、传教目的地、人员任命、既有合法范围内的教令和教学重点。不可把“预算滑杆”当作从分散教会变为绝对中央教廷的后门。

玩家依然能编辑宗教的名称、显示、允许调整的教义权重和活动；不能把已冻结组织性质当普通属性覆盖。需要另一种性质时，建立新的被允许教派／教会并通过合法资产处理接续，而不是悄悄改变旧机构。

## 11.5 组织结构预设

强中央：中央统一任命和预算，地方按配额执行，中央是主要财产控制者。决策快、跨境行动一致，但中央财政／继任危机会影响整个网络。

会议制：最高决策由代表会议形成，地方保有部分预算。决定慢一些，规则有稳定程序，代表分配会产生政治议题。

联盟制：地方教会独立财产和预算，共同缴纳约定服务费，中央只处理共同教义／仲裁。不能因中央缺钱就擅自没收地方资金。

会众制：每个地方教会自治，网络主要靠互助协议和共同信仰；跨城Temple需要自愿筹款与合同，不能像中央预算一次划走所有财产。

四个预设共用 Actor、Ledger、Contract、RuleScope；没有四套教会代码。组建后的结构永久锁定，界面把锁定字段与可调整字段明显区分。

# 12 · 教会经济、国家关系和罕见分裂

## 12.1 教会是有约束的法人网络，不是免费资源池

每个教会机构可以持有现金、城市广场仓储货物份额、土地、建筑和被章程允许的公司股权。其财富来自实际奉献、捐赠、合法国家拨款、资产租金、许可商业活动收益和有条件的投资。信众人口不是每月自动生成的无限收入。

早期没有私营公司的社会，教会只能经营章程允许的非营利职能：礼拜、救济、抄写、教学和有限公共委托；不能通过“教会财产”提前开启银行和跨国商业集团。公司法、行业准入和资本门槛对教会控股企业仍然生效。

账本分 unrestricted、restrictedDonation、endowmentPrincipal、operatingReserve 和 designatedProject。捐给Temple的限制性款项不能直接拿去买军事公司股票；有保本／不可动本金的捐赠也不能被年度亏损自动耗尽。

## 12.2 什一奉献、捐赠与代征

“什一税”是可选名称，不要求所有教会固定10%。应纳基数为章程和法律定义的合格收入，扣除免征底额／基本生存保留量。例：合格收入100、受保护底额40、奉献率10%，应奉献6，而不是同时从工资、存款余额和购买食物再收三次。

自愿模式：信仰、信任、可支配收入与可见服务决定缴纳；欠缴不产生世俗强制债务。

会员承诺：加入时形成有限宗教内部承诺，可限制非必要会员服务，但不能无授权没收居民财产。

合法代征：国家按具体协议代收并把款项记入教会应付款，行政费公开列示；政府只是代收方，不把全额记成自身可花收入。撤销协议不自动修改教会永久章程，只改变在该国家的法律实施渠道。

## 12.3 预算是教义落地的位置

预算模板有礼拜／人员、传教、教育、救济、维护、储备、象征工程和允许的商业投资。每项承诺都生成合同或薪酬任务；同一笔钱不能在多个类别重复使用。

缺钱时先执行章程定义的受保护支出和法定义务，减少扩张与大工程。不能一边拖欠牧职人员和断粮，一边无成本推进Temple进度。大教会可以承担跨国教育／移民网络，但规模带来管理成本和语言协调，而不是单纯的全图加成。

商业利润进入教会时先按企业税务、股息和章程分配走流程；教会免税只对法律明确豁免的收入有效。不能给商业集团套教会名字就消失所有税。

## 12.4 政治性来自机构和利益

官方宗教可能取得礼仪资格、学校合同、免税、代征和咨议席位，反过来承担政权背书。国家治理恶化、压迫信众、没收教产或拒绝救济时，教会可能选择抗议、撤回道德背书、谈判、支持自治或合法反对派。

国家的神圣化是一项正式绑定／仪式状态：要求已有官方宗教和合法认可程序，影响君主合法性与神授申请材料，不直接增加攻击力或粮食。普通王国可神圣化，但只有玩家批准才能是帝国。

教会跨越敌对国界时，会遇到人员通行、资产冻结和忠诚冲突；不能因为共同宗教就让两国必定永不交战。中央教会也不能默认直接指挥各国军队，除非国家法律／合同授予明确范围。

## 12.5 分歧不等于分裂

本版分歧分为教义解释、任命权、财政分配、文化语言和政权关系五类。每类有 grievance、支持团体、领袖、合法申诉渠道和持续时间；它们先产生会议、地方例外、仲裁或改革议案。

真正分裂必须同时满足：存在持久实质分歧、合格组织者、足够追随者与多地组织、独立财政存续能力、普通解决途径长期失败，以及脱离在根宗教允许的教派范围内。建议起点：至少100名支持者且占母派20%以上、3个地方教会、12年持续分歧、24个月独立运营储备，并且最近20年该网络没有刚发生同等级分裂。小宗教可能根本达不到条件，这是“罕见”的一部分。

有足够条件仍经过告知、谈判、最后表决和资产裁决，不能一次事件突然生成十个教派。无文化群体不能成为宗教分裂的成员。

## 12.6 分裂提交和财产

创建新 Denomination（保留 ReligionId）→按照根允许范围创建新的冻结 ChurchCharter→将自愿／依法转入成员转移→分配经过裁决的地方资产→保留负债和限制性捐赠目的→更新服务合同和官方宗教关系→发布历史。根宗教不是AI新建的。

旧教会章程保持原样。地方加入新教派不自动带走不属于它的中央资金；产权争议和宗教归属是两件事。分裂可能形成长期并存而非必定爆发战争；开战仍需国家／军队法定动作。

先知对根忠诚不变。其受任教派任务可以由玩家在同根允许范围重新指派，但普通AI不能用一次分裂事件把先知转成另一个神授根的信徒。

## 12.7 信任与腐败控制

只加入最低必要的财政滥用风险：预算实际用途偏离、关联交易不当、承诺服务长期未完成。透明审计提高发现概率与可信度，消耗管理成本。不得用无因随机“腐败−50信仰”事件代替可追踪的财政问题。

教会信任下降主要影响自愿奉献、合作与机构忠诚；根信仰确信并不必同步归零。一个虔诚信徒可以反对腐败主教、要求本派改革而不是立刻信另一个宗教。这是宗教政治深度的重要来源。

# 13 · 个人信仰、传教网络与三类宗教建筑

## 13.1 四项信仰资料

每人分别记录 beliefConviction（根信仰确信）、institutionalTrust（对本教会信任）、practiceParticipation（实际参与）、doctrinalAlignment（与具体教义的一致）。正式教派归属之外，再记录少量已接触宗教和转信进度，避免为每人存全世界宗教矩阵。

传播强度由实际接触时间、共同语言、传道者能力、看到的服务、家庭／社群关系、既有信仰和教义匹配综合产生。对不同宗教不能每帧反复掷骰子：候选只有在持续进度超过门槛并经过考虑期后才改变正式归属。转信后有长期稳定性和社会成本，避免信众每天摇摆。

无文化者只能接触日常帮助与共同生活，不能提前记正式信仰或语言熟练度。慈善可按博爱教义帮助他们，但宗教成员资格和正式转信要等文化资格成立；不能把救济作为自动文化创建按钮。

## 13.2 传教不是一个无限半径光环

任务包括本地讲授、家访式接触、公共服务、学者交流、流动巡回、长途布道、移民社区牧养和文献传播。每个任务有执行者、目的地／路线、语言、时间、经费、所需许可、风险和可服务人数。

先知始终优先推进传教任务，但不是每个tick都在同一地点立即转化一百人。极大量先知会消耗供给和社会劳力，且相同听众有接触饱和；无限点击不能凭空制造无限信众。普通传道人由教会培训和任命，不享有先知的永恒根忠诚。

学校／救济不隐藏强制转信：受助资格由教义与法律规定；“博爱”允许帮助非信徒，产生信任和接触机会，但不保证他们转信。人口有拒绝、保留原信仰或不加入宗教的状态。

## 13.3 传教规划的地图操作

玩家选一个先知／传教团或教会，在地图画巡回路线／涂抹目标城市。系统预览语言障碍、开放边境、经费和预计服务能力。拖到封闭国境时显示法律原因，而不是无声寻路失败。

只提供三个常用策略：本地巩固、开放传播、服务与教学。详细面板可调语言培训、访问优先级和预算。宗教热图默认显示分布，展开可切换信任、教派、机构网络和财政来源，不同时覆盖五种颜色。

## 13.4 Chapel、Cathedral、Temple 是独立类型

Chapel：地方集会、基本教导和小规模救济。建议3×3格、约50人活动容量；不代表50个居民只能信教。

Cathedral：地区性教会行政、正式教育／大型集会／救济协调。建议6×6格、约250人活动容量；需相关结构知识、稳定组织和财政，不能由Chapel点击升级得到。

Temple：大型共同圣所、跨城朝圣／大会及长期共同体象征。建议12×12格、约1000人活动容量；体量大，必须通过苛刻门槛，不能每座城市随意复制。

类型永久不变，容量不作等级升级。可修复、维护、改名、变更允许的同类型风格；不同类型必须独立建设并真实取得土地。宗教建筑不增加第四种修道院／神殿类。

## 13.5 Temple 的明确门槛

建议同时要求：所属根宗教至少延续30年、稳定信众至少1000人、跨至少3座正式城市、申请教会有共同圣所的教义许可、适当的高阶结构／运输能力、48个月经常预算稳定且不拖欠基本救济、至少80%工程材料和全部首期人工有可验证筹措、完工后的维护储备、连通且不占用必要住房／粮田的12×12合法地块。

此外同一根宗教在首版默认最多一个在建Temple项目；第二座需第一座长期正常运营和独立的地理服务需求，不能靠同一份捐赠反复立项。首版可把“第二座”作为更高门槛规则，不另开建筑等级。

失败不让全部工程瞬间消失：筹备暂停、材料仍属原捐赠／项目账户；长期无法继续时按捐赠约束退款、转换合法用途或拆除，不能把募捐直接变成教会自由利润。

Temple 的效果是增加大会／接待和组织能力、降低远距离共同体协调成本、形成象征合法性；不会自动让整个世界信教或为皇帝增加超自然战斗伤害。过度建设可能挤压教育和救济，产生真实政治争议。

## 13.6 国家改教与个人自由

国家修改官方宗教改变官方礼仪、补助和法律资格；居民不会瞬间改信。旧教会资产、教育合同和居民权利按法律／条约处理，过程可导致迁移、财政压力和反抗。神圣国家转向另一根宗教还会触发原神授资格检查。

玩家能编辑普通人的信仰，但必须符合文化资格且不是被禁止的先知根改信。编辑行为被记录为神意事件；它与真实传教过程区分，不能把手工设定的成员当作传教效果测试结果。

# 14 · 移民：动机、准入、旅程和融入

## 14.1 迁移动机不等于法律资格

家庭评估的动机包括食物短缺、住房不足、工资／就业、战乱和服役风险、税负、宗教限制、文化／语言联系、亲属团聚、教育和科研条件、投资机会、个人野心与生活质量。税率、就业等因素先通过实际预算与机会产生效果，不额外重复计算任意巨大移民奖励。

目的地效用为收入及可及公共服务、亲属联系、信仰／文化接受度、住房与安全收益，减去路费、失业风险、语言障碍和旅行风险。只比较已经知晓且法律可达的目的地；世界中有更富城市不等于每个人自动全知。

无文化者可以迁居、建立Settlement和组成前文化State，但没有正式语言、宗教移民、正式大学人才移民或语言资格。他们显示5字希腊码，迁居优先考虑生存和共同生活，不因为没有正式姓名而禁止移动。加入既有文化时必须通过真实接触同时取得至少一门现有语言；这不是创建新语言。

## 14.2 法律可组合的准入路径

|路径|要验证的事实|主要承诺和成本|
|---|---|---|
|普通就业|真实岗位、雇主资格、住宿|工资与雇佣期限|
|家庭团聚|真实亲属和接纳能力|住房、基本保障|
|人才／科研|实际技能、大学／研究所邀请|研究岗位、档案与许可边界|
|留学|教育席位、费用或奖学金|就学期限和毕业后转换|
|创业|通过可行性检查的项目|资本、订单、住房、法律资格|
|投资|真实投资到合格项目且锁定期限|投资风险，不保证盈利|
|捐赠|钱／物实际转入指定公共用途|不可立即撤回的捐赠与反重复认领|
|宗教皈依|已有文化、真实归属／参与期、宗教赞助|目的地法律认可、教会经费与安置|
|宗教职务|合法传教／教育派遣|具体任务和期限|
|参军|已成年、符合招募要求、岗位和服役契约|真实服役，不能申请后立即退役重复领奖|
|避难／战争安置|安全风险、接纳配额、路线|临时住所和公共开支|
|殖民／边地定居|有供应保障的合法定居项目|长途运输、住房、维生准备|
|公共工程契约|合法公共工作和配额|劳动期限与退出规则|
|普通开放居留|当地法律许可、基本住宿和负担能力|登记和一般纳税义务|

不是所有路径开局可用。投资和创业要等相关制度成熟，大学路径要有真实大学；公国从早期就可制定基本接纳和家庭迁居，不必等成为王国。

## 14.3 从申请到安置

状态：Interested→Eligible→Applied→Approved→ReservedHousing→InTransit→Arrived→ProvisionalResident→Settled/Citizen。拒绝、放弃、边境变化和遣返各有合法出口；不会因为目的地被占领就把在途家庭删除。

每个申请用 PersonId／HouseholdId 和路径 ID 去重，财务承诺只结算一次。重复出入境不会反复获得同一笔安置金；用于投资移民的资本不能在另一申请同时抵押。捐赠不是点一次宗教图标即可申请无限次身份。

临时居留、定居、臣籍和本地政治权利分开。信仰改变不自动消除国籍，入籍不自动清零原文化。两个国家是否承认双重身份由合法规则决定，首版可只允许一个主臣籍和多个居留资格，避免无限国籍组合。

## 14.4 安置与知识的实际改变

到达前预留住房、生活费用与必要工作／教育席位。失败时先寻找合法替代或延长临时安置，再按法律返程；不把人瞬移到空房子。

人口实际到达后才更新城市劳工和消费，不在审批时就增加产能。研究者的个人知识随人到达，但机构秘密、文献货物和使用许可各自处理。移民传播文化依赖长期接触；新来十个人不立即重命名目的地文化。大规模迁入会向 Cultural Genesis Field 的 migration/contact 通道产生脉冲，并可能孕育 Secondary Culture；即使新文化最终诞生，也不会因此自动生成新语言。

教会可以保荐跨国信徒，运输公司／港口可以收取旅费，政府可以补贴，企业可以提供职位，城市负责住房和登记。使用统一合同系统，不为每种移民另建一套特殊资金流。

# 15 · Army：组织、招募、装备和补给

## 15.1 只有一层军队

Army 是唯一持久可指挥军队单位。没有军团、师、旅、团、营、连等嵌套对象。一个 Army 直接引用指挥官、士兵 PersonId、装备／坐骑、驻籍城市、所属国家、预算合同、补给、当前命令和阵形。

弓手、枪兵、骑兵、炮手等只是士兵岗位／装备角色，阵内的角色带是临时布局集合，不是新的行政部队。拆分一部分士兵只创建另一个平级 Army；合并需要归属和补给兼容，不能把敌军与本军简单圈选合并。

军队由城市征募、支付和补员；国家／帝国可以拨款或依照宪章调遣。多城联合供兵时，士兵原籍用于记录家庭和义务，但军队必须有一个明确主责城市及各拨款合同，避免每个城市都以为别人负责发饷。

## 15.2 招募必须留下社会代价

来源只有合法成年志愿者、按法律征召者和具有服役准入的移民。人口不从兵营刷新；服役会减少真实劳力，并影响家庭收入、产出和迁移意愿。默认成年人阈值为18游戏岁，可按世界规则统一配置；不做儿童部队。

城市默认保留最低农业、CitySquare装卸／配给、运输和护理劳力，AI不得自动征走所有农民。玩家可以超额征募到法律允许上限，但预览会显示粮食与经济后果，不隐藏成本。

训练使用现有公共训练场／城市开放用地功能，不新增强制军事公司。武器使用要求个人训练和足够装备，民兵不因拿到枪就立即获得成熟齐射纪律。

## 15.3 有限兵种、丰富组合

八类装备角色足够：简装民兵、盾剑步兵、长枪兵、弓手、弩手、火绳枪手、燧发枪手、骑乘战士。火炮是 Army 直接拥有的器材，分配现有士兵操作，不成为第二套军队层级。

战力来自人数、装备质量、训练、士气、疲劳、凝聚、空间位置／道路／水陆阻隔、补给和命令执行。不用几十种元素抗性或稀有魔法武器。军用技术到燧发枪／前装黑火药火炮封顶；民用太阳能车不能挂武器转为坦克。

武器耐用、维护和改良可由科技配置影响。士兵死亡后装备处于战场回收状态，归属和保管明确；胜者也要花时间回收和运输，不能同一件装备同时回到两国各自的 CitySquare.Storage。

## 15.4 补给体系

ArmySupply 包含食物、军需弹药、装备备件、有限携行容量和补给来源。军事供给使用统一货物／运输账本，不另造免费“补给点数”。士气低、射不出弹药和吃不到食物要有不同提示。

军队在 CitySquare 的集结／装卸区域领取已分配的军粮、弹药和装备；野外由合同运输补充到有限 ArmySupply 容器。补给路线必须地面可达或经合法港口船运，敌军控制道路、桥梁或港口会改变成本和到达时间。

供给优先级由预算和紧急度决定。政府可以签高优先级军运合同，但是否挤占民用口粮由法律和城市保留量约束。战争期间全军优先可能造成家庭不满，这是城市经济真实变化，而非无缘由的叛乱骰子。

## 15.5 自动化与解散

自动补员从驻籍城市符合资格的人中补充，需装备、工资与训练；战场上不会直接刷新一个满训练士兵。退伍恢复居民身份与可工作状态，处理装备归还、欠薪和交通。

指挥官死亡不删除 Army。按简单继任规则从合格成员中选一个，短时影响凝聚；用户可以合法改任。驻籍城市失陷时军队继续存在，尝试更换补给承担城市；无主国家或长期欠薪可能促成投降、解散或反叛，但有过程和通知。

## 15.6 港口军运

Army 提交运兵合同，港口估算人员／装备舱位、船籍、合法航线、装卸时间、费用与抵达岸点。先在港区集结，再按容量登船；离开地面可见列表但保留实际容纳状态。没有“军队在船上还能隔岸用近战攻击”的漏洞。

船依旧属于港口，Army只是乘客和约定作战器材的使用者。可以为船下运输、护航、封锁三种任务，船不单独创建海军多层编制。必要舰炮效果使用同档火炮规则，不增加现代海战科技。

目的港遭占领时重新选择合法卸载点／等待／返航。没有城市的登陆只能携带有限补给，建设殖民地要继续满足正式城市的条件。

# 16 · 战斗、阵法、城市攻防与战术AI

## 16.1 战术来自空间，不来自按钮堆积

每个士兵有真实可导航位置；射界、遮挡、侧翼和阵形完整度都由空间计算。世界地表没有坡度或高地战术：空间优势来自LAND/WATER阻隔、岸线、道路、桥梁、树林遮蔽、建筑体量、街道宽度、港口与交通瓶颈，不另开复杂天气／泥泞／疾病系统。

战斗核心状态是 `cohesion`、`morale`、`fatigue`、`suppression`、`reloadProgress`、`ammunition` 和 `formationSlot`。这些都能在解释器中指出变化原因。新命令不能把疲劳／装填清零，暂停和存档也不能重置射击冷却。

## 16.2 六个主要阵形

|阵形|用途|代价和反制|必要条件|
|---|---|---|---|
|横列 Line|展开射界与正面防守|转向慢，侧后脆弱|足够连续的可站立LAND空间|
|纵队 Column|道路行军、通过门桥|展开前正面作战效率差|最通用，拥堵时回退|
|方阵 Square|抵御骑乘冲击、多向防守|移动慢，火炮／远射暴露|足够长兵／近战与纪律|
|楔形 Wedge|集中冲击局部|遭侧击或过窄障碍会散乱|有冲击角色和空间|
|散兵 Loose|分散远射、利用遮蔽|近战凝聚和抗骑能力低|相应训练|
|斜线／阶梯 Echelon|保留一翼、侧向推进|协调需求高，调整慢|训练与可见战线|

不增加“万能阵形＋20%一切”。各阵形改变具体位置、朝向、速度和暴露方式。混合 Army 内可把长兵放前／侧、射手后置、炮位后置，都是布局算法，不是新增可命名团级编制。

## 16.3 拖动生成阵位

玩家在地面拖出正面线段，两端定义宽度，中点定义阵地；朝向箭头由敌方方向默认推断，可拖动旋转。人数和间距决定纵深，预览显示当前可站立LAND／道路空间可容纳人数与阻挡位置。

算法：将士兵按装备角色、已有位置和训练作稳定排序→生成所选阵形的局部槽位→转换到世界坐标→投影到合法导航格→检查LAND/WATER合法性、通路与障碍→预算有限的局部修正→计算预计展开时间。不能满足时缩窄、分段或保持纵队，必须在预览说明，不瞬移穿墙。

实际展开通过 Movement 系统抵达槽位。军队遇窄门可以临时纵队通过，再在目标区恢复预期阵形；转形过程降低凝聚，敌人可以利用，但不能因为布局变更直接丢失士兵。

## 16.4 射击与近战

远程攻击检查目标是否被本军感知、射界／遮挡、射程和装填完成，消耗真实弹药。命中结果由训练、距离段、遮蔽、凝聚、疲劳和目标状态影响；参数全部是抽象游戏数值，不涉及真实枪械制造资料。

齐射等待可射成员准备到设定比例，再执行一次批量开火；自由射击各自冷却。军官可选择近距开火、保留弹药和指定目标角色，但无需点击每个射手。

近战单位寻找可接触的敌人和合法进攻位置。长兵对正面冲击、盾对特定远射、骑乘对散乱侧翼、火炮对密集静止目标形成情境优势，而不是保证某兵种永远赢另一兵种。

炮弹表现可以是简化轨迹与落点，真实伤害在模拟内结算；演示弹道不可决定游戏结果。每次开火都有弹药与器材操作约束，不能借粒子效果变成免费地图毁灭。

## 16.5 士气、溃退与投降

士气受近期损失、被侧后威胁、凝聚、指挥官、补给、优势／劣势感知和战斗目标影响。加成有上下限，避免某位领袖制造永不溃逃的无限战斗机器。

低士气先导致迟疑和防守倾向，再退向选定安全方向，最后才可能溃散／投降。玩家撤退命令与自动溃逃不同：有序撤退保留较多凝聚，但需要空间和时间。被堵死时可以投降，不无限在墙角寻路。

伤员暂时降低劳动／战斗能力，回城休整；不添加医院产业。战俘是被容纳的人，有看管和食物成本、交换／释放／招降的法定选择，不删除原身份。

## 16.6 开放城市防御、封锁与占领

Sonnheide **没有永久城防建筑**。城市不会被一圈城墙定义，边界可以随着人口、土地使用、征服、分裂与行政调整快速变化。防御来自实际空间：守军 Army、道路／桥梁／岸线瓶颈、密集街区、港口、CitySquare、补给距离、士气和居民合作程度。

攻击者可以从多个方向切断道路、控制桥梁、封锁港口、击退野战Army、进入城市街区并争夺 CitySquare 周边的实际控制。这里的“封锁”是切断人员和货物流动，不需要城墙才能成立。火炮可攻击合法军事目标或在城市战中压制敌军，但首版不做可逐块炸毁的复杂建筑破坏模拟。

防守 AI 的优先级通常是：保持与补给源连接→控制关键道路／桥梁→保护港口或登陆点→保护 CitySquare 与撤退路线→必要时撤出城市。城市没有一个神奇的“防御值”；道路被切断、军粮耗尽、守军溃退或援军到达都会真实改变局势。

城市进入 `Occupied` 必须同时满足：攻击方在 CitySquare 及主要交通节点维持足够控制、守军已失去有效组织或撤离、占领力量达到最低规模，并持续达到占领时间阈值。一个侦察兵冲到广场旗杆下不能瞬间改城。占领后 CitySquare 的旗帜显示实际占领者，但法定主权仍可属于原国家，直到条约、归并或其他合法事务改变。

占领者可以依法接管 CitySquare 中属于政府的库存和行政能力；私人、企业、教会等其他所有者的物资仍按战争法／本国法律处理，不因“占了广场”就自动变成战利品。广场局部受损时启用有限应急周转区，避免城市因为一个建筑节点受损而永久停止基本生存。

## 16.7 战术AI的最小可解释模型

ArmyAI 每个决策间隔比较五项任务：守卫关键位置、维持补给、支援友军、接敌／侧击、撤退整补。选择需要可达路径和真实资源。短期评分加入滞后和命令锁定时间，避免不断来回改道。

AI感知不采用玩家上帝视角。它根据本军视野、盟军依法共享的信息和历史最后已知位置行事。玩家默认可全知观察，但全知不会让AI自动透视树林。

性能上远处的士兵可批量计算感知／攻击机会，结算仍用相同单位、弹药和空间条件。不得在镜头远近切换时改变胜负算法或随机流。

# 17 · 干净而深入的军事地图交互

## 17.1 默认只出现与当前选择有关的操作

普通视图不铺满战争面板。点击一个 Army 的小旗牌，底部只出现六个常用动作：移动、攻击／接敌、防守、阵形、补给、撤退。点击空地恢复普通地图工具。未选军队时不显示几十个灰色军事按钮。

左键选取，Shift追加，地面拖框多选同侧Army；右键地面移动、右键敌军接敌、右键本方补给点补给。相机旋转使用中键／明确按键，不占用军事右键。界面选择模式与绘图模式互斥，不能画阵线时意外转相机。

## 17.2 三种直接手势

点地面：下达移动终点。拖动正面：指定阵地宽度和朝向。按住路径修饰键画折线：指定行军路径／多个途经点。鼠标按下后先显示预览，松开提交，Esc取消。

攻击目标可点敌军，或在城市战中点选桥梁、港口、CitySquare周边等合法关键控制区域；不要求在弹窗选十几个参数。长按或展开一次才显示交战距离、射击纪律、追击范围和撤退阈值。默认有可理解的方案，不要求用户先研究军队管理表。

## 17.3 队列与协同而不写脚本

Shift把新命令加入队列。每张队列卡只有目的、执行条件和失败回退。可选触发限制为“到达该区域”“某友军就位”“敌军进入指定距离”“补给达到阈值”“指定时刻”；简单AND连接，首版不开放任意编程逻辑。

多个Army可临时框选协同，仍各自保存队列，不新建永久军团。同步命令会生成同一协调令牌；任何一军失败／取消时清楚标注“协同等待原因”，有超时后回退，不能永远等待一个已经覆灭的军队。

允许暂停后布置多个命令，再统一继续。计划未提交之前只修改预览；实际战斗命令不能免费撤销已经发生的开火和死亡。

## 17.4 必须看得懂的预览

路径用浅线，预计被敌控制／缺补给部分用警示纹理；颜色之外有图形区分。阵地显示正面、朝向、人数密度、遮挡、可用射界和预计展开时间。补给线显示来源与瓶颈，不每辆车都画一条贯穿全图的线。

命令不可执行时，在光标旁说明一个主要原因和可操作替代：没有桥、需要港口运兵、缺军需、没有权限、敌城尚未达投降条件。点“使用港口方案”可以把需要的运兵合同加入预览，不把用户丢进深层物流菜单。

常规Army信息只显示人数、士气、补给和当前任务；点开才显示装备、岗位构成、训练、财政来源和战斗日志。人数损失与失联／登船分别用不同状态，避免玩家以为进船就是死亡。

## 17.5 三种交战规则预设

谨慎：保留补给、优先守关键道路／桥梁／岸线瓶颈、较早撤退。均衡：默认组合。进取：较高追击与风险上限。预设只设置明确参数，用户展开后可编辑合法范围。

针对射击单独选择自由射击／齐射／近距保留。阵形轮盘只展示当前士兵与训练可用的六类，未解锁项显示准确所需能力；不因为所有科技目录存在就开局显示密集空壳图标。

## 17.6 手机上或触控设备的同义操作

首版开发优先桌面，但命令模型不依赖右键。触控通过点选Army→点地图→短动作条提交；双指用于相机，单指用于当前工具，长按出现等价上下文菜单。一次只能使用一种模式，持续显示当前模式名。

触控适配属于输入层，不另建军事逻辑；所有权限、路径和队列验证仍在模拟核心。键鼠和触控都应可完成“选军→画阵地→安排补给→协同攻击”的同一验收任务。

# 18 · 战争目标、殖民、附属国与反叛

## 18.1 先有战争目标，后有和约

War保存双方、授权、目标、参与Army、军事占领、伤亡、持续成本、谈判意愿和条约草案。战争目标可为吞并某城、确立附属、取得殖民管辖／定居权、独立、解除宗主关系、索赔或执行条约。它不是一份“谁与谁敌对”的简单列表。

所有四类爵位国家原则上都能拥有殖民地或附属国，实际受运输、补给、法律与实力约束。不能用爵位门槛强制只许帝国殖民，也不能让一城公国无成本支配世界。

## 18.2 吞并、殖民、附属不混为一谈

吞并：城市主权正式转给胜者，开始法律、税务、驻軍与居民权利的过渡；不自动消灭当地文化、企业和宗教。

殖民管辖：某地属于宗主的殖民辖区，地方城市仍有CitySquare、预算和日常职能，自治与贡赋依条约／特许。建立新殖民城需要定居人口、住房、供给和官方文化；不能只插旗就制造人口。

附属国：保留StateId、爵位、统治者、城市和法律中的保留权，通过 DependencyTreaty 接受进贡、外交限制、军事协助或港口权限。宗主不能默认直接扣其所有CitySquare.Storage资源。

释放／独立：解除特定隶属条约，结算债权、军队驻留和关税关系。合法分离不删除成员国家历史。

## 18.3 最少必要的和平条款

领土割让、从属地位、殖民特许、赔偿、有限期限军事／港口通行、解除封锁、战俘交换、保证已有文化／宗教权利、停战期。条款必须有明确当事人、作用地、金额／期限和可执行条件。

赔偿按支付能力分期，可以违约并形成政治后果，不能让战败国被设为无穷负数。和约不能凭空让一个不存在的国家取得领土；受影响城市、居民、企业税务和军队补给在同一个主权转移流程处理。

## 18.4 反叛有准备、组织和回退

不满来源限定为实际税负／欠薪、粮食与住房失败、被限制的文化／宗教、占领、违法征收、过量征兵、继承／宪制争议以及宗主违约。相同事件只进入一次对应账，避免某项政策被重复放大。

流程：不满积累→集体请愿／地方反对→形成组织和明确目标→谈判／改革窗口→持续条件达到门槛后叛乱。需要真实支持者、领袖、武器／物资或可动员公共组织；不在空地刷新一支免费军队。

AI使用缓冲阈值和冷却：一月缺粮不独立，一次税率微调不内战。玩家能从城市牌看到“主要风险：粮价、征兵、宗教限制”三项原因，直接定位问题，而不是只能反复杀叛军。

叛乱 Army 与普通Army同级，人员来自实际居民／倒戈士兵。谈判能产生减税、自治、官员替换、释俘或独立条约。失败的叛乱也要处理人员回归、债务和财产，而不是全部从世界删除。

## 18.5 帝国特殊冲突

选帝侯争议先进入宪章规定的复核／同票／摄政程序，再在合法性严重破裂时导致内战。中央可征用多少钱、成员要派多少兵，在战前就可查。神授凭证给帝国以合法形式，不替代成员履约、财政和战争能力。

教会可以斡旋、资助救济、拒绝背书或在法律允许范围支持政治目标。禁止把“教会不满”直接变为无成本瞬间改国，所有政治后果仍需人、资产、组织和时间。

# 19 · 国旗编辑器与政治地图

## 19.1 恰好23色

六条色轴：红、黄、蓝、橙、绿、紫。每条轴只有深色、正色、浅色三种可选色，共18色；共享黑、白及三档灰，共5色，总计23色。

每条色轴的五节点为黑→深色→正色→浅色→白。深色取正色与黑的中点，浅色取正色与白的中点，采用固定8位色值，不随显示器或用户屏幕取色改变。三档灰为#404040、#808080、#BFBFBF。正黄使用明显偏橙的#FFAF00；正蓝使用偏青的#0096AD。完整固定色表见 `data/flags.json`。

国旗自身不允许自由RGB、渐变、照片、外部贴图或额外透明色。地图上的半透明是国旗展示层的透明度，不是增加国旗可选颜色。边缘抗锯齿产生的显示混色也不登记为新增调色板色。

自动随机生成只从BLACK、WHITE、RED_BASE、YELLOW_BASE、BLUE_BASE选择。用户手动编辑可以使用全部23色。随机按钮绝不能产生深红、浅蓝、橙或紫，即使它们在手动调色板中存在。

## 19.2 恰好13种模板

横双色、横三色、横四色、横五色、竖双色、竖三色、正十字、带边正十字、北欧十字、带边北欧十字、正X形、带边正X形、带边联合十字。

普通条纹分别需要2／3／4／5个色槽；普通十字／X形是底色＋图形2色；带边十字／X形是底色＋描边＋内色3色。最后一种联合十字用5色：底、X外边、X内色、正十字外边、正十字内色，先画带边X，再画带边正十字。这里是用户规定的模板，不声称复刻真实英国国旗几何。

首版国旗画布固定3:2比例，条纹等分。北欧十字垂直杆位于宽度约三分之一；正十字居中。带边图形必须满足外宽大于内宽；各带边交叠处绘制顺序固定，不能出现取决于浏览器路径顺序的随机颜色。

## 19.3 编辑器

左侧13个模板缩略图，中间实时大预览，右侧只显示当前模板用到的色槽；下方为23色网格。点击国旗某一色区即选中相应色槽，然后点击颜色，不需要用户理解图层面板。

常用操作是换模板、换颜色、随机、重置、撤销、保存。随机只应用五色规则；手工保存校验23色和模板合法性。为降低复杂度，首版不提供自由笔刷、上传纹章和任意文字覆盖。

每个 `CULTURAL` 国家必有一面合法正式旗，自动尽量避免相邻国家完全相同旗。用户可以强行选择相同国旗，检查器提示但不禁止；名称标签和边界仍能区分。`PRE_CULTURAL` 国家使用前述单色希腊字母旗，不暗中赋予正式纹章。

## 19.4 默认政治图

默认显示最高政治行政单元：中央帝国覆盖其城市；联合帝国覆盖成员行政范围；有政治宗主的国家按最高有效政治层显示，允许在检查器看到成员。纯军事占领不改变法定主权底图，用另一种细边／占领标记表示。

“基层政治”视图显示直接管理城市的最底层成员国家，保留公国／大公国／王国等真实rank；中央直辖区按城市显示。不额外发明亲王国rank，也不把所有帝国成员城市硬改为公国。

此外有独立“城市”图层看每座城市，但默认不会同时叠三层旗。选中最高单元可钻入成员层，返回键恢复，不需另开一张政治树大窗口。

## 19.5 一整面国旗被疆域裁切

对当前显示的政治单元，计算全部领土联合范围的固定世界坐标UV：`u=(x-minX)/width, v=(z-minZ)/depth`。该国只有一张整体国旗投影，采样后用精确领土mask裁切；不是每格一面小旗，也不是单一国旗主色填充。

旗面沿地表高度偏移少许绘制，远景透明度约0.2～0.3，近景逐渐淡出，保留国界和地物可读性。视角旋转时UV锁在世界坐标，不让国旗跟着屏幕转。属地／飞地共用本国整体投影，超长跨海范围可能压缩图案，这是整体裁切规则的明确结果；选中时可放大本国范围检查。

地图牌显示小旗、国家短名和必要状态图标。点牌打开右侧国家编辑页并保持地图可见。标签位置使用境内可见点，不直接把凹多边形几何中心放到海里；遮挡／重叠时缩为图标，选中者优先。


## 19.6 国家主题色

每个 `State` 都保存一个 `themeColorId`。对于正式 `CULTURAL` 国家，主题色必须是**当前国旗实际使用的颜色之一**。自动生成国旗时，从旗面当前使用的去重颜色集合中稳定随机选择一个；玩家随后可以手动改成当前旗帜中任意已有颜色。主题色不是第24种国旗颜色，不能输入任意RGB。

如果玩家修改国旗后，原主题色仍存在于新旗中，则保持不变；如果原主题色已经从旗面完全消失，则在提交新国旗的同一事务中从新旗现有颜色中重新选择，并在预览中明确提示。PRE_CULTURAL 国家只有单色原始旗，因此其 `themeColorId` 等于该单色背景，但前文化人物的服饰不使用它。

`themeColorId` 只承担国家视觉识别、人物T恤颜色和少量UI标识，不给经济、战斗、文化、宗教或外交任何数值加成。主题色随法定国家保存，而不是随城市保存；附属国、殖民地和帝国成员继续使用各自国家的主题色，除非法定国家身份实际改变。

# 20 · 真三维写实风与统一交互

## 20.1 视觉承诺：写实，而不是像素化

Sonnheide 现在采用**真正的3D写实风格**。陆地／水面、建筑、人物、马、马车、汽车和船都以真实三维几何、真实尺度关系和可从360°水平观察的体积表现。近景不使用像素贴图、方块化低模或纸片人物作为最终美术风格；建筑应有可信的墙体厚度、屋面、窗户、门、道路连接和材质反应，人物和装备保持现实比例。

写实不等于不计成本地追求电影级摄影扫描。首要目标是**可信、统一、可读、能承载大规模文明模拟**：PBR材质、物理合理的日照／阴影、真实尺度、适度天气感与环境光；但纹理分辨率、材质层数、骨骼复杂度和后期效果必须服从性能预算。禁用会妨碍地图判断的过强景深、运动模糊、泛光和电影颗粒。

三个时代和不同文化影响建筑比例、屋顶、立面、窗型、入口、材料和街道关系，但优先采用模块化构件组合，而不是每一个文化×时代×容量制作完全独立模型。用户切换已解锁历史外观时仍遵守实际footprint和容量兼容规则。

## 20.2 人物服饰：最小国家识别闭环

Sonnheide **不建立复杂服装系统**。不按时代、职业、宗教、财富、文化或阶级生成几十套衣服，不给Person维护上衣／裤子／鞋帽等可交易装备槽。人物服饰只承担最小的文明状态与国家识别功能。

正式有文化人物，只要具有法定国家归属，就统一显示为：

- 上半身：所属国家 `themeColorId` 对应颜色的简单T恤；
- 下半身：白色短裤；
- 不因职业、阶层、Army岗位、宗教、时代或Secondary Culture自动换装。

人物在国外旅行、移民申请中、战争占领区或附属国境内时，仍按**自己的法定国家归属**穿原国家主题色，直到法定国家身份真正改变。已有文化者若暂时无国家归属，则保留最近一次合法国家主题色；从未有过国家归属的极端情况使用中性白色T恤，避免另建服装体系。

无文化人物即使属于PRE_CULTURAL State，也不穿国家主题色T恤。其外观固定为：

- 所有人：黑色草裙；
- 女性：黑色草裙＋基础黑色胸罩；
- 不生成鞋、帽、首饰、制服或其它服装部件。

Primary Genesis 后，人物一旦获得文化并处于某个合法国家身份，就切换为该国家的主题色T恤＋白色短裤。Secondary Cultural Genesis不会改变衣着，因为服饰与国家绑定而不是与Culture绑定；改宗、换职业、进入大学、成为先知或加入Army也不改变这条规则。

实现上，服饰是渲染派生状态：只需要极少量共享服装mesh。T恤用 `themeColorId` 作为材质参数，同色国家／同LOD人物共享材质实例或批处理；不得为每个Person复制一份材质。纺织品仍可作为晚期消费经济类别，但不要求具体衣物商品逐件映射到人物可视服装。

## 20.3 写实世界的距离层级

相机是透视相机，可围绕世界自由水平旋转360°；世界基底本身是平坦的LAND/WATER表面，俯仰只限制穿入基底和极端不可读角度，缩放围绕光标地面点。玩家可聚焦／跟随人物、Army、建筑或城市。

渲染必须采用稳定的距离层级，而模拟保持同一份世界状态：

- **远景战略层**：人物退化为极小点／群体标记；显示国旗裁切疆域、国家牌、城市牌和主要道路；建筑只保留体量轮廓与高等级HLOD；
- **中景城市层**：显示可辨识建筑、CitySquare、道路、车辆、港口、Army阵形和主要人流；
- **近景写实层**：人物、服装／武器、建筑入口、矿洞进出、马车／汽车入库、船只靠泊、CitySquare旗杆与公共活动具有完整三维表现。

LOD切换使用屏幕投影尺寸和迟滞，避免滚轮微动产生闪切。远景隐藏细节不等于暂停经济、战争或文化系统。

## 20.4 写实渲染的性能纪律

为了让写实3D与大规模人口共存，表现层必须明确区分“模拟实体”和“渲染实体”。100,000个Person可以都在模拟中，但不意味着100,000套高骨骼人物都要逐帧渲染。

核心策略：

1. 静态建筑使用模块复用、材质实例、纹理图集／虚拟纹理和批次化；
2. 重复树木、农作、道路附件、远景车辆等使用实例化；
3. 人物按距离切换完整骨骼、简化骨骼、群体实例／点表示；
4. 远景城市使用HLOD／合并代理，不逐窗逐门提交绘制；
5. 阴影按重要度与距离分级，远景人口不投高成本动态阴影；
6. 只有相机附近需要完整动画状态；远处人物的动作由模拟任务状态低频映射到简化表现；
7. UI拾取优先使用空间索引和可见代理，不对全世界所有对象逐帧做射线测试。

设计验收优先检查“写实感在近中景成立”与“远景仍能稳定观察整座城市”，而不是以单张截图的极端材质复杂度作为目标。

## 20.5 六个地图工作模式

观察、建设、军令、社会、资源、编辑。模式用于避免手势冲突，不是六套世界；其中没有“地形编辑”模式。

观察：点人物／建筑／国家直接检查。建设：逐格人工造陆、拖道路、放建筑、看用地与港口临水边是否合法。军令：下达Army命令。社会：文化／宗教／移民网络和任务。资源：矿物曲面、CitySquare物流与资源分布，但不能修改LAND/WATER。编辑：选择对象的合法属性修改，并可切换 `Divine Hand / 上帝之手` 直接搬运人物；其可调半径在地图光标周围实时显示。

任何时刻最多一个占用拖动手势的工具。底部持续显示当前工具、主要动作和取消方式；Esc先取消当前草稿，再返回观察。没有工具时拖空地平移；有工具时使用明确的临时相机修饰键。

## 20.6 所有检查器一个结构

顶部：名称（可编辑）、身份／归属、小旗／符号。中部：最重要四项事实与当前任务。底部：三至六个常用动作。展开：账本、法律、历史、详细属性。用户不打开深层页面也能知道对象在做什么、为什么停下。

人物：住处、文化、信仰、工作和当前目标；技术掌握／姓名历史在展开页。

建筑：经营者与房屋所有者分开、使用率、维护、当前外观、已解锁外观。升级性能与切外观是两个按钮。

CitySquare：当前城市、公共预算摘要、仓储负载、装卸拥堵、国旗／占领状态、主要公共事件；展开才显示产权分区和详细库存。

公司：总部、现金与承诺、主要业务和风险；税务、持股、分支业务在展开页。

教会：信众、信任、财政、教育／救济／传教任务；锁定章程显示锁标，不能伪装成可编辑下拉框。

城市：粮食、住房、CitySquare负载、公共预算和主要风险；国家：制度、成员、外交、官方文化／宗教和神授申请。

## 20.7 CitySquare 是城市最重要的地图交互锚点

远景点击城市标签或国旗区域，默认聚焦其 CitySquare；近景可直接点 CivicHall、旗杆、装卸区或公共空间，但检查器仍汇总为同一个 CitySquare 实体。建设、军需、城市物流、占领和公共活动因此共享一个地图中心，不新增Market、Town Hall或Warehouse三个并列管理窗口。

CitySquare不是所有人的每日强制寻路终点。普通家庭消费使用聚合领取／配送；只有可见的大宗装卸、Army集结、庆典和玩家关注的事件才产生高密度广场人流，避免写实人物全部涌向一个点造成CPU和视觉拥堵。

## 20.8 干净不是隐藏因果

所有进度条必须对应真实任务和可解释瓶颈。缺原料、缺工人、缺授权、缺技能、道路不通使用不同消息。浮层只先显示一个主要原因，展开可查看全部，不把十条错误一起弹窗。

只对需要玩家决定的事项打断：帝国申请、重大宪制冲突、确认征收、极重大控制风险。日常亏损、每次出生、每次小技术改良进入可筛选事件流，不连发弹窗。

## 20.9 中英文

固定界面文本全部走locale key。专有名采用持久名称记录，不随界面语言变换；“Friedrich农具II”切英文只把技术类型译为Friedrich Farm Implement II，序号与作者不变。国号可采用名字＋本地化政治后缀。

数值、日期、复数、错误原因和可用动作也必须有两种语言，不能只翻译首页。生成科技、法律、教义和经营数据项均提供zh-CN与en名称；语言包是世界内容，与UI locale分开。

## 20.10 表现技术保持可替换

仿真核心继续与表现层分离。浏览器／Three.js可以作为规则与UI原型，但**不再把Three.js视为最终写实客户端的硬约束**。生产客户端只需满足：PBR写实材质、360°透视相机、实例化／批处理、HLOD、骨骼LOD、可靠三维拾取、异步资源流送和可替换的快照接口。

若最终采用 Unreal Engine、Unity 或其他高性能三维引擎，Culture、Economy、Religion、Army、CitySquare 和命令协议不因此重写。引擎只消费 SimulationSnapshot、提交Command，并维护视觉代理。只有完整工作负载实测后才决定哪些热点系统需要迁移到原生代码。

## 20.11 文化场观察必须“看起来像场”，但不能真的按格模拟

文化观察模式从稀疏 GenesisNode 读取 `phi/mu/kappa` 快照，由GPU在节点之间进行纯视觉插值：平静区几乎透明，活跃区有极淡连续波纹，超临界区出现更明显但克制的相干变化。玩家默认只看到“平静／活跃／不稳定”等质性状态，不显示 `mu=-0.31` 或“97%完成”。Debug模式才可看数值。

视觉mesh、粒子或shader只负责表现，不创建新的仿真采样点。镜头拉远也不增加文化场计算分辨率；相反降低标签、人物和材质细节。Primary Genesis发生时可以短暂显示一次局部相干收束，再出现正式名称和旗帜变化；Secondary Culture只出现文化事件，不强制播放“新语言诞生”效果。

## 21.5 一个提交屏障

低频任务由到期时间参与同一屏障：再生与经济每日、工资／税与项目评估按月、教育与传教接触按实际任务、文化 GenesisNode 按自适应 Slow Tick、语言分化和教派分裂按低频条件。已完成快照只包含一致状态，不让UI读到“钱扣了但生产线还没建”的半个事务。

# 22 · 验证、平衡、开发顺序和交付边界

## 22.1 必须成立的不变量

`CULTURAL` State与所有正式City的官方文化非空；`PRE_CULTURAL` State允许空官方文化但必须是五字希腊码＋单色字母旗；无文化人无正式语言能力和宗教；RootLanguage只能来自Primary Genesis；Secondary Cultural Genesis不得创建语言；根宗教只能由玩家创建；先知根忠诚不可变；已创建教会章程的性质不可变。

帝国有官方宗教和有效神授凭证；所有普通建国先公国；政治从属图无环；军事占领不能自动代替主权转移。每个正式国家有合法13模板／23色国旗，随机只使用指定5色；`themeColorId` 必须来自该国当前旗帜实际使用颜色，旗帜修改后不得悬空引用已经不存在的颜色。

服饰不建立独立衣橱：PRE_CULTURAL人物固定黑色草裙（女性另有基础黑色胸罩）；有文化且有国家归属者固定国家主题色T恤＋白色短裤。Secondary Culture、职业、宗教和Army身份不得偷偷改变服装规则。Divine Hand抓取只能改变空间状态，不得删除Person或直接重写国籍／文化／语言／信仰；抓取半径必须经过配置边界校验。

每个正式City只有一个CitySquare，且只有一套CitySquare.Storage逻辑账本；物品不能同时作为可用库存存在于源广场和目的广场；代管物不成为保管人的破产资产；账本借贷相等；保留资金和物品不可被重复使用；股权图不成环。

世界建立后 `NaturalLandWaterMask` 永久不可改；没有height／slope gameplay字段，worldScale只能在创建世界时确定且X/Z统一。人工造陆只能在天然WATER格上通过逐格建设事务写入 `ReclaimedLandMask`，并且每个新格必须四邻接天然LAND或既有RECLAIMED LAND；未完成工程仍视为WATER，完成后才成为 `effectiveSurface=LAND, landOrigin=RECLAIMED`。Port只允许0/90/180/270°；PortCore每格都必须是RECLAIMED LAND，指定海侧边外必须保持连续WATER和合法BerthWaterZone。

工厂首次建线成本只扣一次；兼容小改不当全新线；拆线不全额退款；科技未采用不生效；同槽版本不叠加；切外观不改变容量；宗教建筑不升降级。

矿格capacity=rate×1day，增加rate不立即补库存，夷平锚点不随拖动变化；车辆进门隐藏但不消失；每船属于Port；Army无层级子军队，人员服役与民工产能不能双重计算。

## 22.2 设计级场景测试

公共经济运行数十年不靠企业也可存活；零私企世界仍可建设大学和港口。私营法开放但无长期需求时不应批量创建企业。一次市场下跌不应令所有公司同时倒闭。

一个大学的秘密创新不能出现在敌国全体农民身上；知识开放教会应在有经费、语言和人员通路时加速实际传播，没有通路时不能全图广播。唯一熟练者死亡但档案存在时可通过再培训恢复。

逐格造陆不得修改天然底图哈希；未完工格不能提前承载道路／Port；在海中央无四邻接支撑的造陆必须拒绝；人工陆地完成后局部水路索引必须失效并重建。港口放在天然LAND上必须拒绝，只有完整RECLAIMED PortCore＋连续临水BerthWaterZone才可通过。

封锁港口会影响物资和军队，不改变另一大陆城市广场仓储中的货物数量。银行破产不没收客户代管货；企业清算不删除楼里无关住户。

全军征募应压低农业产能；补给充足并不保证穿越狭窄道路、桥梁、岸线或密集街区的进攻获胜。换镜头、暂停和保存不能重置装填。占领城市后和平条约选择附属，必须保留该国而不是先吞并再造一个同名国家。

## 22.3 量化目标是待验收目标，不是实测成绩

小场景验证因果，中场景验证跨城网络，大场景验证性能。建议依次测试100／1000／10000居民，再确定更高规模。10000人必须包含实际经济、宗教、战争和渲染，不用只更新位置的benchmark冒充完整游戏。

关键统计：长期饥饿占比、无住房人口、企业成立／关闭率、城市广场周转等待、合同超期、私人资本集中、教派分裂频率、Primary／Secondary Genesis频率、活跃GenesisNode数量、文化／语言数量增长及二者比率、科技边际收益、军队补给失败、镜头切换的帧时间。没有数据前不声称“经济已平衡”。

## 22.4 六个开发切片

A：离线全球EarthLandWater数据包→全球缩放／框选→等比例世界尺寸→冻结天然水陆底图→写实3D平面水陆、360°相机、格网、人类、基础生存、CitySquare、道路→逐格Reclaim Land工程→只允许建在人工陆地临水边缘的正交Port→入口容纳、矿曲面和国旗。验收必须包含“同一区域不同worldScale仍保持比例”“天然水陆不可改”“人工造陆只能从岸边四邻接逐格延伸”“港口放天然陆地必拒绝”。

B：前文化State／Settlement→稀疏文化场波动→Primary Culture＋RootLanguage共同诞生→正式姓名／City／正式旗→大公国；随后验证Secondary Culture不会自动建新语言，以及语言可以独立分化。先证明文明能自然起步且不爆文化／语言数量。

C：公共经济、合同、运输、研究／学习／采用、建筑性能和外观分离、科技工厂生产线。先让城市在无私营时完整运行。

D：玩家宗教、先知、教义、教会财政、传道和官方宗教；帝国申请、选帝侯宪章与国家法律。Temple和教派分裂在基础运行稳定后接入。

E：Army、装备／供给、阵形、地图命令、城市封锁／攻占、占领／条约、反叛、海运与移民。

F：严格门槛下开放私企、合资、集团、完整税务、晚期金融与消费品，并完成长时间平衡和跨系统测试。

这些是实现顺序，不删除后期要求，也不为了“先做MVP”把宗教和军事永久砍成空壳。

## 22.5 本次交付状态

本次提供完整文字规则、配置目录、命名／语言示例、法制／教义／科技数据、核心TypeScript规则参考和自动测试、独立国旗工作台。它们不是最终三维游戏，不包含全部生产级AI／渲染／经济并行实现。

# 23 · 三条贯穿系统的完整历史

## 23.1 从无文化聚落到第一次农具革命

一群人开始只共同耕作、伐木、搬运和建基础住屋，人物、Settlement和公国都显示稳定的5字希腊码。人口聚集、共同劳动和历史事件让局部 Cultural Genesis Field 的波峰逐渐变大；当 `mu<0` 且一次随机波峰越过阈值，选中的无文化创始人触发 Primary Genesis：RootLanguage 与 Culture 同时创建，创始人第一次获得正式姓名，首批成员被命名，Settlement登记为有官方文化的City，国家从单色字母旗切换到正式国名和第一面13模板国旗。

这个世界在开局前已经由玩家从真实地球岸线中框选并等比例放大；文明无法改变海岸。公共部门扩充粮田和CitySquare仓储／装卸能力，工匠改良基础工具；记述和教育能力形成后建立大学。大学得到真实年度预算，研究员提出播种器改良，随后形成 `Friedrich播种器II` 的知识记录。大学选择公开，但另一城市仍需获得副本、语言理解和工匠培训。

本城工厂没有相应生产线，必须建线并消耗工装材料。生产出的新播种器送入城市广场仓储区，农田领取并安装之后才提高效率。旧工具仍可继续用；国家不是一瞬间整个进入启蒙时代。


多年后，边疆军人与移民在另一座城市长期共同生活，形成独立的 Secondary Genesis candidate。第二次相变产生一个新Culture，但没有新Language：这些人继续同时使用原有两门语言。又过几代，其中一个真实speech community因隔离和连续音变才独立形成派生语言；这个语言事件没有要求再生一个新文化。

粮食增加让更多人可以离开农业从事教育／建造，而不是马上生成资本公司。需求持续、公司法与产权成熟很久之后，才有新的私人制造公司提出成立申请。

## 23.2 博爱知识宗教、跨国学者和帝国申请

玩家选几位已拥有文化的人为先知，创立强调博爱、开放知识和教育的宗教，首个教会采用强中央但允许商业的冻结章程。先知巡回传教；教会把真实奉献用于救济和教材传播，而不是给所有信徒直接科研加成。

一个贫困外国研究者获得教会奖学金和大学邀请，通过人才／教育移民到达另一城市。他携带的个人技能提高当地研究能力，但旧雇主保密资料不自动搬来。教会有外国分支，需要遵守当地传教和税务法律。

数个王国和大公国拟定联合帝国宪章，明确选帝侯、军额、税收分成与成员自治；选定该宗教为官方信仰后向玩家呈递请求。玩家批准时再次校验成员同意，才生成帝国和神授凭证。各城城市广场仓储、企业和Army不合并成一个巨大共享库存。

多年之后部分教会因财政分配与语言问题不满，先申请地方例外和会议；只有长期、跨地区、组织和财政条件均达到才产生教派分裂。旧中央教会的章程没有被改写，财产也不凭空复制。

## 23.3 晚期集团、战争和不崩溃的城市

成熟集团在本国设总部、在另一国经营运输与制造。各地设施按当地利润税结算，分红回总部时按当地规则预扣和抵扣；同一笔利润不重复充当两份可分配现金。

政府为远征签订港口军运合同和物流补给合同。该城市先从天然海岸逐格完成一片规则RECLAIMED LAND，再把正交PortCore建在人工陆地临水边缘；PortCore本身不跨水，海侧连续WATER作为泊位和航道；玩家在地图选Army、画阵地、安排友军到位后齐射；补给线被敌方截断后，预览和实际到达时间变化，枪手不会继续用无限弹药。港口船舶仍属于港口，军队只是合同乘客。

战争导致某制造分支现金流中断。先停非必要线、谈延期和重组；清算时代管货物仍属于客户，楼可以拍卖或转租。城市公共建设队和最低搬运服务重新接管必需业务，因此经济衰退不会使整城永久不能造房。

和约最终不是吞并，而是附属国条约加分期赔偿。败国保留爵位、官方文化和行政，城市按约缴纳。过度征兵和赔偿压力会形成可见不满，先有协商窗口，再可能发展为独立运动。

# 24 · 玩家编辑边界与反绕过

## 24.1 自由编辑

人物和实体显示名、允许的性格值、普通人的文化强度、合法信仰归属、国旗模板／调色板、已解锁建筑外观、任务优先级、合法预算方案、研究题目和地图矿物速率可编辑。**天然LAND/WATER、真实岸线、地球选区和worldScale不是游戏内可编辑字段；人工造陆是唯一允许改变有效水陆结果的受限建设事务。**所有编辑记录来源，不能冒充自然发展结果。

人物文化全部清零、国家更换官方文化、公司迁总部等看似简单的操作有连带后果，必须先预览并原子处理。对象名称自由改不修改身份证明、发明作者、债权人或合同签约方ID。

## 24.2 程序性编辑

国家宪制、税率、公司法、教会合法教令、官方宗教、臣籍准入、征收、企业股权、成员国家关系和军隊主责城市都通过对应命令，不开放任意对象JSON覆写。

“可改的合法的”意味着符合已解锁制度、现行法定程序、章程允许范围、条约保留权和世界硬约束。玩家可选择推动合法改革，不代表可以从经济刚起步直接跳到所有现代工商许可。

## 24.3 不可直接编辑

已冻结教会的组织性质；先知绑定的Religion根；技术实际原始作者记录；历史事件已发生的事实；帝国神授凭证；根宗教的玩家创立来源；Primary Genesis 的文化／根语言共同诞生事实、Secondary Culture不得伪造根语言、语言分支的无环父源；城市广场仓储货物的守恒记录；工厂成本已消费标记。

这些字段由专门合法流程产生或保持不可变。改名称不会绕过；存档加载也执行同样约束。教会新建／分裂能创建另一份允许的章程，不意味着旧章程可以改写。

## 24.4 编辑模式与普通治理

上帝模式可查看全世界并选择合法对象，默认不要求玩家扮演某一个国家。国家／教会／公司视角只是筛选和委托，不改变玩家身份。法律约束仍体现在所选择的文明行为上；资源编辑如矿脉改变另记神意事件。天然水陆不存在普通编辑入口；人工造陆只出现在建设模式，并走真实材料／施工事务，不归入神力或资源笔刷。

不提供修改余额的常用按钮，不提供怪物／闪电／瘟疫／复活／灭世命令。开发者测试工具可以构造测试初态，但不在普通产品界面出现；测试初态必须标记，不得当作自然文明发展成绩。

## 24.5 数据安全和可追溯性

本地存档同样需要验证：非有限数、负库存、环状产权、重复ID、非法正式国旗、前文化旗使用非法模板、无文化者持有正式语言／宗教、Secondary Genesis伪造RootLanguage、非法帝国和语言父环均拒绝或进入明确修复流程。修复不能擅自给用户批准帝国。

名称显示进行文本转义，不把用户输入插入可执行HTML；语言演化规则使用受限语法；源代码、外部图片和脚本不是名称字段。所有重大事务具有唯一ID和修订号，重复点击或网络式重试不重复结算。


## 24.6 天然地球底图冻结；人工造陆是受限建设工程

玩家在“创建世界”界面可以重新选择地球区域、改变目标游戏尺寸并生成**一个新世界**；进入世界以后，`NaturalLandWaterMask`、真实天然岸线和worldScale锁定。普通编辑器仍然没有“把天然陆改水”“挖海”“抬高”“压低”“平整天然地形”等按钮。

唯一例外是建设模式中的 `Reclaim Land / 人工造陆`。它不是修改天然底图，而是在天然WATER上建立 `ReclaimedLandMask` 覆盖层。玩家逐格选取，工程必须四邻接已有陆地、支付材料和劳动、经过施工状态，完成后才把该格的**有效地表**变为LAND。首版完成的人工陆地不能再用普通工具恢复为WATER；未完成工程可依法取消并按已发生的施工结算。

地图来源只决定天然物理水陆，不导入现实国家、现实城市、现实人口、现实道路或现实文化。Sonnheide文明从玩家选中的空白真实地理轮廓上重新演化；之后出现的人工港区属于本局文明历史，而不是现实地球数据。

世界存档记录数据源版本、原始WGS84选择框、投影中心、统一worldScale、`NaturalLandWaterMask`哈希、`ReclaimedLandMask`及其工程／历史记录。即使未来游戏更新全球岸线数据，旧存档仍使用创建时冻结的天然水陆结果；人工造陆在其上继续叠加，不因为数据包升级导致城市或港区改变。


## 24.7 Divine Hand / 上帝之手

`Divine Hand` 是保留的非破坏性上帝工具，用于像画笔一样**批量抓取并搬运人物**。玩家按住工具扫过地图时，落入刷子范围且当前可抓取的Person进入 `DIVINE_HELD`；继续移动可继续吸附更多人物。松开／执行放置时，系统在目标点附近寻找合法可站立位置并分散释放，不能把数百人堆在完全相同坐标、建筑墙体、不可站立WATER或被建筑占用的位置中。

抓取半径由玩家自己选择。工具栏必须提供持续可见的 `radius` 控件：桌面端以滑杆为主，并允许滚轮／快捷键微调；触控端提供滑杆。地图上始终显示真实世界尺度的圆形半径预览。半径采用连续值或足够细的离散步进，而不是只有“小／中／大”三个硬档。最小值允许精确抓少数人物，最大值允许一次扫过较大人群；具体世界单位上下限由性能测试后配置。

`DIVINE_HELD` 期间，Person保留PersonId、生命状态、国家、CultureAffinity、LanguageSkill、Religion、家庭、财产、知识、工作和Army membership，只暂停普通寻路与依赖当前位置的AI。抓起不等于死亡、自然移民、改国籍、改文化或退伍。释放后再根据新物理位置重新触发住房／工作可达性、移民处境、文化接触、语言接触和Army重组等正常系统。

Army成员可以被抓起。若整支Army被搬走，Army仍是同一个对象并在释放后重组阵位；若只搬走部分成员，这些成员进入暂时 `Separated` 状态，Army不得把他们计作死亡，也不得因此复制补员。君主、先知、学者和普通居民默认都可抓取。

性能上严禁每帧遍历全世界Person。上帝之手只查询现有 `HumanSpatialIndex / SpatialHash` 与刷子圆相交的桶；已抓人物暂时从普通空间查询中移出并停止路径请求。大量Held人物在表现层使用实例化／低LOD代理，避免一次抓取数千人时创建数千套高骨骼全细节角色。

所有已提交的上帝之手搬运记录为 `DivineRelocationEvent`，用于历史审计和调试，并明确区别于自然迁徙。尚未释放时允许取消并原位恢复；已经释放并让世界继续运行后，不提供无条件时光倒流。

# 27 · 最小命令协议与跨系统事务

## 27.1 共用信封

每个改变世界的请求带 `commandId, commandKind, targetIds, expectedRevision, payload`。授权上下文由可信调度器提供，不接受前端自己写 `isGod=true`。结果为 Accepted／Rejected／RequiresRepreview，包含实际事件ID、可解释原因和改变的实体版本。前端可做预检，但不能替代核心验证。

普通检查器只拿 QuerySnapshot，不持有可修改的 World 对象。新对象创建、扣钱、预约、归属改变使用同一事务屏障；任何校验失败不得留下半个公司、已扣钱但不存在的生产线、批准但无宪章的帝国。

## 27.3 三个容易出错的多对象事务

**生产线**：预约材料和预算→确认工厂槽→占据槽位→工装任务；投入随着已完成工作消耗。READY前不能正常生产。重复点击同一命令返回原结果；更换成本后复用旧commandId属于冲突，而不是新的扣款。

**Primary Genesis及正式化**：确认GenesisNode已越阈→创建RootLanguage→创始人正式姓名→Culture实体→首批居民语言／文化／姓名→State从PRE_CULTURAL进入CULTURAL并设置非空官方文化→Settlement登记为City→生成正式旗→可能因已有第二座正式直属City升大公国。不能先创建需要名字的Culture再陷入“还没有语言所以不能命名”的死锁。Secondary Cultural Genesis使用另一事务，明确没有CreateLanguage步骤。

**分裂教会资产**：冻结被争议资产清单→确认法律和章程归属→保留有用途限制捐赠→确定各自承担的负债／员工合同→创建同根新教派→签署资产转移→更改自愿／合法成员→发布历史。成员名单更新本身不等于财产被转移。

## 27.4 编辑人物最后一份文化的处理

普通有文化者可调整多种文化浓度；删除最后一份文化会撤销其“当前正式文化成员”资格，并使当前正规语言／信仰资格产生冲突。默认拒绝隐式清空，预览说明需要先处理信仰、官方职位和在职知识任务；已有姓名作为历史身份保留，不销毁发明署名。

先知不能通过“先清空文化，再改宗教”绕过根绑定。现任君主／官方文化创始人被改动时不删除文化实体；官方文化是制度记录，不是对创始人当前属性的实时引用。已经出生的语言也不因创始人死亡或编辑而消失。Culture 与 Language 不作一对一删除级联：删除／归档一个文化不能顺带删除仍有人使用的语言，反之亦然。

## 27.5 规则参考的边界

`reference/src/models.ts` 是目标领域数据接口；其他小模块实现命名、部分文化资格、国家升格、教会不可变校验、矿量、货币／货运账本、科技采用、企业门槛、生产线、外观、语言变换与阵位生成。它没有实现上述所有命令、真实战斗、完整税收结算或整个城镇AI。

JSON Schema负责文件形状；跨对象产权、根授权和历史不可变性仍需事务验证。不能宣称“JSON合法所以游戏合法”。
